## P2

### P2-1（#2201）存檔失敗時，若玩家已經開了另一局，離開的那一局就丟了

回主畫面改成不等自動存檔寫完（PERF-DEVICE 4）。寫入失敗（例如手機滿了）時，如果玩家這幾秒內已經開了新的一局
（新遊戲、示範），`returnToStartInBackground` 只在新局的狀態列寫一句「剛才離開的遊戲沒有存成功：……請再試一次」，
舊局的世界被丟掉，沒有「再試一次」也沒有「不存檔離開」可選；在 #2201 之前，存檔失敗一定留在原局。
同時，寫入期間開的新局被 `SavingCover` 蓋住、它的「回主畫面」按了沒反應（`isReturningToStart` 還是真）。

VERIFIED（Linux 探測測試，`11dca65`；資料夾位置放一個檔案讓存檔失敗，`openDemo()`、`returnToStartInBackground()`、
立刻再 `openDemo()`）：

```
PROBE while writing: isReturningToStart=true secondBackToStart=ignored
PROBE after: session is second=true first kept anywhere=false unsavedLeaving=false
  message=Optional("The game you left could not be saved: The save could not be read or written. Try again.")
```

修法建議（給派工，屬 GamePresentation，Linux 可測）：寫入完成前不讓開新局（主畫面的開局按鈕等 `isReturningToStart`），
或失敗時把離開的那一局留著，讓玩家選回去或存成另一筆；狀態列那句的「請再試一次」改成說得出怎麼做。
新局被 `SavingCover` 蓋住的問題跟著第一種修法一起消失。

## 看過、沒有問題的

- **久候離開（731）**：只在整分鐘、送回家之後判斷；跳過的分鐘也逐分鐘判斷，長跳與逐分結果一樣；`gaveUp` 記在起站，
  守恆檢查（`Boarding.swift`）與存檔驗證都加上了；第一組的 `since` 做快篩是保守的（不會漏判）。
- **活動人潮（730）**：開閉時間只在 120–1350 分、整半小時，波峰最多落到第 23 小時，不會越界；一天總人次不變。
- **年度稅（734、736）**：只有新遊戲寫實規則會開，中途不能切，所以不會同一年又日繳又年繳；資金無限時寫帳不動餘額；
  建物的日地價稅在年稅開著時歸零，沒有重複課。
- **月台清單（740）**：延長月台、拆站移站、反轉路線都帶著 `alternates`；拆軌的檢查也看 `alternates`；
  死結時的「這一次停任何月台」只在清單把車困住時才用。
- **單線輪流（718）與月台先到先用（738）**：等最久的那列不讓給任何車，所以不會互相讓到永遠；死結偵測用的是不含讓位的
  `takingDeparture`。
- **TICK-2 的會車索引（#2157）**：索引只讀站與停靠，錨定只動時間；測試裡有逐筆對照舊掃描的 precondition。
- **#2197**：背景算路線的圖與找工作時是同一個世界（`PassengerRoutesAhead`），共用沒有問題。
- **#2198**：`bodyMayTouch` 與 `bodyStretches` 看的是同一組邊（車頭邊＋尾邊），篩掉的車本來就不會有交集。
- **#2209**：模型逐個上 GPU；上傳失敗時本來就不重試，現在先放掉標準包的頂點也沒有別處要用它（3D 的 LAZY-MODELS
  那串正在改同一段，這裡不再追）。
