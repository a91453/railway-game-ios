## P3

### P3-1 點站插入時，一次點擊最多要算 N+1 次整條線的行程（#2809）

`trackInsertionIndex` 想放的位置不行時，會一個個位置試，每試一次就複製世界、建線、跑一次 `lineJourney`。站多的線（N 站）最壞要跑 N+1 次路徑搜尋，都在主執行緒上。

這可能像 TAP-FREEZE-151 一樣卡住畫面（那次是 3 秒）。這是讀程式推出來的，沒有量（UNVERIFIED）。

建議：下一張動 `LineStopPlacement.swift` 的單，先在大地圖上量 20 站以上的線。慢的話，改成先只看軌道上的順序，最後才跑一次 `lineJourney` 確認。

### P3-2 `LandValue.swift` 的註解被切開（#2806）

新的 `located` 插在 `value(base:...)` 的註解中間。現在 `located` 的註解開頭是「`base + service + ... + civic` within」，`value` 只剩「``minimum`` … ``maximum``.」。

只是註解，但單獨修會跑整個 GameCore 的 CI。跟下一張動 `LandValue.swift` 的單一起修。

### P3-3 地圖包的複本讓空間變兩倍（#2771）

系統的暫存問題還在時，每個地圖包在 Application Support 另有一份複本，用掉的空間是兩倍。刪除地圖包時會一起刪，所以不會越積越多。等 Apple 修好之後，可以再判斷要不要停掉複製。

### P3-4 CI 的 `testflight.yml` 不知道本機已經發了 153

CI 的 build 號是 run 號加 `BUILD_NUMBER_OFFSET`。本機腳本的號碼記在 Mac 的 `~/RailwayTestFlight/last-release.json`，CI 讀不到。

`docs/TESTFLIGHT_LOCAL.md` 原本說本機用 `N.1`，所以不會和 CI 撞號。但 153 是用整數號發的，而 CI 的下一個 run 號也是 153，所以下一次用 CI 發時會撞號，上傳會被拒。這件事原本只記在專案記憶裡。

本 PR 在 `docs/TESTFLIGHT_LOCAL.md` 的〈build 號〉補一段：本機用整數號發過之後，下一次 CI 發版前要先設好 `BUILD_NUMBER_OFFSET`。
