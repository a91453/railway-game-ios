# 玩家意見紀錄

這份記錄 TestFlight 測試者的意見，以及每一則怎麼處理。優先順序（[NEXT_PRIORITIES_2026-10-12.md](NEXT_PRIORITIES_2026-10-12.md)）會參考它。

**repo 是公開的。** 這裡不寫玩家的名字、帳號、聯絡方式，也不放截圖裡的個人資訊。裝置只寫機型與方向，例如「iPhone 橫拿 844×390」。原話只引用和遊戲有關的句子。

## 流程

1. **收集**：每發一版 TestFlight，作者或派工 session 把收到的意見貼進下面的表。一則一列。
2. **分類**：
   - **bug**：照設計應該能做、實際做不到。
   - **設計**：照設計做得到，但玩家覺得難用、太複雜或想要別的做法。
   - **讚美**：玩家喜歡的地方。保留它，改版時不要弄壞。
3. **分工**：
   - **bug**：一律交給派工 session，立刻派修。狀態欄寫修在哪個 PR 或哪個 session。
   - **設計**：累積在這份紀錄裡。同一件事有 2–3 位玩家提到，或作者要求時，才排進優先順序，交給作者決定。
   - **讚美**：寫進「要保留的」，之後改到相關畫面的 PR 要對照。
4. **更新優先順序**：每一版收完意見後，負責優先順序的 session 更新一次 NEXT_PRIORITIES（或寫下一份），並在 §1 寫明這一版的意見改變了什麼。
5. **狀態**：
   - 修在 #N（已合併）
   - 修理中（session 或 PR）
   - 等作者決定
   - 不處理（附原因）
