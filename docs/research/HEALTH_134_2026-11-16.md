## 3. 新退步：簡化規則、不開行車管制的「機捷舊線不動」

**現象**：`tymc-old` 這個世界（決策 605 之前的時刻表買下機捷、跑一天、半夜兩點不改建）在簡化規則、把行車管制關掉之後，
第二天 333 班裡 318 班沒發；逐分與最高倍速都是 318。死結偵測是 0，空車出機廠 48 趟、進 26 趟。

**對照**（同一台機器、同樣的 release 建置、同一個指令）：

| commit | 第二天沒發 |
| --- | --- |
| `49fffa3`（133） | 0/333 |
| `36b5cb5`（134） | 318/333 |

```sh
swift build -c release -Xswiftc -enable-testing --build-tests
DEPOT_RETURN_REPORT=1 DEPOT_RETURN_EPISODES=1 DEPOT_RETURN_EMPTY_RUNS=1 DEPOT_RETURN_SIMPLE=1 DEPOT_RETURN_ONLY=tymc-old \
  .build/release/GamePresentationTests-test-runner GamePresentationTests.DepotReturnReportTests
```

**查到哪裡**（沒查完，不在這個 PR 修）：

- 133 → 134 之間改到模擬的只有 #2289（`FairSingleTrack.swift` 的 60 秒條件）。#2291 只碰台鐵支線與改建清單，
  機捷的鋪法沒變；其餘是 3D 模型、文字、羅瓦涅米地圖包、冬季活動的畫面邏輯。**推定是 #2289，沒有用還原它來證明。**
- 這條規則在行車管制關掉時不生效。但這個世界是「買下後先在行車管制開著時跑一天（新局預設），報告開始時才關掉」：
  兩個版本從第一天清晨就不同（133 第一班出青埔機廠的是列車 2，134 是列車 4），所以是 #2289 改變了前一天收班時列車停的位置，
  關掉管制後從那個狀態走不出來。也就是說**毛病在「沒有管制的簡化規則從某些停車狀態起不來」，#2289 只是把它帶到這個狀態**；
  133 的 0 可能只是剛好。
- 下一步：照 diagnosing-bugs skill，先用 `DEPOT_RETURN_WATCH`／`DEPOT_RETURN_SAVE_AT` 存下兩點那一刻的世界，
  看 134 第二天清晨哪些列車、停在哪裡擋住發車（第一班沒發是 05:56 長庚醫院站 → 台北車站）；再決定修在沒有管制時的發車，
  還是修在收班。會動 GameCore，動手前先在 #2118 登記。

**誰會遇到**：決策 605（機捷直達車）之前買下機捷、沒按「照真實改建」、簡化規則、而且自己把行車管制關掉的舊存檔。
新局與買了之後沒關管制的人不會（簡＋控 5/333）。

五方評分：玩家 3（條件窄，但遇到就是整條線停擺）、開發 3（沒有管制的發車有一種起不來的狀態，別的線也可能踩到）、
