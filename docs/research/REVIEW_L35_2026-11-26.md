## P2

### P2-1 複線工具在「自動」軌距下，從高鐵或 1,435 mm 的軌道接出去，第二條鋪成 1,067 mm（#2671）

- **在哪**：`NetworkSession.swift` 的 `buildNetworkTrack` 與預覽，`parallel.build(..., gauge: networkGauge)`。`networkGauge` 是 `nil`（自動）時，主線接上起點的軌道、拿到它的軌距；第二條是 `DoubleTrack.parallelPlan` 算出來的，兩端是空點（`.point`），沒接上任何軌道，GameCore 的 `joinedGauge` 就給 `TrackGauge.default`（1,067）。渡線從主線那頭接上，又是主線的軌距，於是節點上兩種軌距混在一起。
- **證實**：在 1,435 mm 高鐵軌道的端點用複線工具往東鋪，得到 `["edge(1) 1435s", "edge(4) 1067", "edge(5) 1067", "edge(6) 1435s", "edge(7) 1435s", "edge(8) 1067"]`。
- **玩家看到的**：自己鋪高鐵或捷運的複線，第二條其實是台鐵軌距。高鐵車配到這條線時被拒絕，或在軌距檢查時被悄悄從線上拿下（`releaseTrainsOffTheirGauge`）；畫面上看不出哪條軌不對。
- **很可能同樣的地方**（沒測）：選取工具的「做成複線」（`TrackUpgrade.swift`，`planDoubleChain` 的第二條也沒帶軌距）；描線時不是真實路線的複線（`TracePlan.swift:287` 的 `lineSystem` 為 `nil` 時）。
- **建議修法**：在 GamePresentation 組指令時，`networkGauge` 是 `nil` 的話，第二條與渡線用主線實際鋪成的軌距（在 draft 上先鋪主線後讀 `edge.gauge`；「做成複線」讀被選的那段軌道）。指令裡寫明軌距，執行端的語意不變，紀錄與重播不受影響。不動 GameCore。加 Linux 測試（下面這個改成綠的，再加「做成複線」一個）。

```swift
@MainActor final class ScratchL35Tests: XCTestCase {
    func testDoubleTrackFromHighSpeedTrackOnAutomatic() throws {
        var world = try makeWorld(width: 40_960, height: 16_384, balance: Money(100_000_000), speed: .paused)
        let west = try world.buildTrackNode(at: WorldCoordinate(x: 1_024, y: 8_192))
        let east = try world.buildTrackNode(at: WorldCoordinate(x: 5_120, y: 8_192))
        try world.buildTrackEdge(from: west, to: east, gauge: .shinkansen)
        let session = GameSession(world: world)
        session.selectTool(.network); session.networkBuildsDouble = true; session.networkDoubleSide = .left
        session.tapNetwork(at: PlanPoint(x: 5_120, y: 8_192), reach: 16)
        session.tapNetwork(at: PlanPoint(x: 18_432, y: 8_192), reach: 16)
        session.buildNetworkTrack()
        XCTAssertEqual(session.message?.kind, .success)
        XCTAssertTrue(session.world.network.edges.allSatisfy { $0.gauge == .shinkansen })
    }
}
```

### P2-2 香港與福岡地鐵買下的線畫成第三軌、沒有架空線（#2659）

- **在哪**：`Map3DTrackKind.init(_:)` 把車系是 `.metro` 的車一律畫成第三軌（`hasOverheadLine` 為假），根據的是台北、新北、高雄、台中的捷運。買下的港鐵與福岡市地下鐵路線，`DemoRealLines.trainType(ofLine:system:)` 沒有自己的車，`RealBranchLine.trainType` 給 `.b`（捷運），於是也成了第三軌。
- **實際**：港鐵的重鐵各線與福岡市地下鐵三線（空港、箱崎、七隈）都是架空線集電。146 畫的是架空線，這版反而變不像。
- **建議修法**：軌道種類先看真實路線的系統：`hkmtr`、`fksubway` 等架空線集電的路線畫直結軌加架空線（或道碴加架空線），只有台灣的捷運路線與玩家自己的捷運車照現在畫第三軌。只動 GamePresentation，加 Linux 測試鎖「港鐵、福岡地鐵的線有架空線」。

## P3

### P3-1 找路不看軌距（#2671）

GameCore 允許一個節點接兩種軌距（P2-1 就是這樣接起來的），而路線找路只看通不通、不看這條線的車跑不跑得了。旁邊多一條別種軌距的捷徑時，路線可能改走那條，接著軌距檢查把車從線上拿下。修好 P2-1 後很難碰到；要修就讓找路略過這條線的車跑不了的邊，動 GameCore。

### P3-2 實景地圖上很寬的多股平交道整個不鋪（#2672）

`Map3DRealLevelCrossings` 把一條路穿過的軌道依距離分組，一組的寬度超過 `realCrossingMostSpread`（16 m）就 `continue`，整組不鋪。註解說「更寬的當成每股各自一個平交道」，但程式沒有各自鋪。車站咽喉的多股平交道（例如四股以上）會沒有平交道。修法：超過 16 m 時拆成幾組各鋪，或照註解每股一個。

### P3-3 「一個地方的地圖」的判斷也套到 100 km 內的台灣地圖（#2688）

`FerryTool.lies(in:)` 在地圖寬高都不超過 100 km 時，碼頭在地圖內就提供渡輪，不再等那附近的地讀進來。這是為香港寫的；決策 969 要讓台灣新局也從 32 km 起跳（正在做），做好後旗津、淡水的渡輪也會在地還沒讀進來時出現在選單裡。實際影響小（只是早一點列出來）。修法：條件改成看地圖是哪個地方（香港），不看大小。

### 備註：#2680 描線找路的 memo 鍵沒有含鐵路資料本身

鍵只有兩個點與選項，同一個 session 換了資料（換地圖包）時理論上會拿到舊的路。和既有的 memo 寫法相同，先記下，不排。
