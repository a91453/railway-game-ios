# 拖拉既有鐵軌改線：值不值得做（2026-11-17）

作者 2026-11-17 問：「你覺得要做鐵軌改線嗎，就是在既有鐵軌上拖拉就能改位置，可是感覺動到很多東西」，看完規劃的回覆後說「那先評分好了」。這份只研究、只寫文件：**不動 GameCore、存檔、golden、replay**，也沒有實作。

基準：`main` `8f51287`。程式行為是讀碼得來，**沒有在實機或模擬器上驗證**（UNVERIFIED ON DEVICE）。決策 826（TRACK-CURVE-COLOUR＋TRACK-ALIGN）由另一個 session 在做，這份不碰它的檔案，只把它當成 C 案的一部分。

## 0. 結論

1. **作者的直覺是對的**：完整的拖拉改線（A）會牽動軌道網、轉轍器、月台、列車位置與預約、運轉曲線與時刻、路線指定的路徑、資產帳、地形與結構、買下的真實路線，總共十幾個系統（§2）。
2. **但存檔不一定要動**。GameCore 的每段軌道（`TrackEdge`）本來就存自己的曲線；只要改線時**保留軌道的編號**，存檔格式不變，路線指定的路徑、關閉中的軌道、資產紀錄都還指得到（§3）。真正的成本在規則：改完的線要重跑一次鋪軌的所有檢查，而且要全成或全不成。
3. 五方評分（§4）：
   - **B 縮小版 2.90**：只拖兩段軌道之間的「折點」，兩段都沒有月台、不是買來的真實路線，上面沒有列車也沒被預約；兩段的另一端方向不變，所以轉轍器不受影響。
   - **A 完整拖拉 2.65**：最好用，但開發只有 1 分。
   - **C 拆掉重鋪＋預覽輔助 2.60**：決策 826 已在做大半；這份另提一小項「拆掉後留下舊線的淡影」。
4. **建議：現在不做 A；B 排進優先清單但先不派**。等決策 826 的「彎道依限速上色」合併、作者在實機上用過之後再看：玩家一看到哪段彎道太急，就會想把它拉緩，那時 B 的需求才確定。B 要動 GameCore，佔「同時最多兩張」的名額。

## 1. 現在要改一段線怎麼做（讀碼）

- 只能**拆掉重鋪**：`PlayerCommand.removeTrack` → `GameWorld.removeTrackEdge`，再用鋪軌工具畫一條新的。
- 拆除會被這些擋下（`removeTrackEdge` 的檢查順序）：列車站在上面或車身壓著、有月台、有列車正要開過去或已預約（交通管制）、拆掉後別的列車會互相侵入、兩段軌道會變得太近。
- **拆除不退錢**（`disposeAsset`：「removal refunds nothing」），帳面價值整筆認列損失；重鋪又付全額。所以「把一段彎道拉緩一點」現在等於付兩次錢。
- 拆掉時**路線指定的路徑**（`LineRoutePreference`，存的是軌道編號）不會被擋，但那條路徑從此找不到；重鋪的新軌道是新編號。
- 決策 716 已有「關閉軌道」：關閉中的軌道不再有新的路徑經過，列車開走後才真正關上。這可以當改線前「先清空列車」的工具。

## 2. 改線會牽動的系統

「改線」＝ 一段或幾段軌道的平面曲線、長度、坡度改變，其他東西盡量不變。

| 系統 | 在哪裡 | 改線時要處理什麼 | A | B |
| --- | --- | --- | --- | --- |
| 軌道段本身 | `TrackEdge`（`curve`、`length`、`profile`、`structure`、`sections`、`speedLimits`、`mountain`，全是 `let`） | 換一個新的 `TrackEdge` 但保留 `id`；長度、彎道限速、坡度重算 | 要 | 要 |
| 節點與轉轍器 | `TrackNode.ends[].direction`、`exits`（反方向 1/16 以內才能直通） | 端點方向一變，轉轍器哪條能通哪條就變；移動一個轉轍器節點會改到三段以上的軌道 | 要 | **不用**：只動折點，兩段的另一端方向保持原樣 |
| 月台與車站 | `TrackPlatform`（掛在軌道段上，用離起點的距離） | 長度變了，月台位置要搬；月台必須水平；站房與月台的相對位置 | 要 | **不用**：有月台的段不能拖 |
| 列車位置 | `TrainPosition.onEdge(traversal, distance)`、`trailEdges` | 站在上面或車身壓著的列車，距離會指到錯的地方 | 要（或擋下） | 擋下 |
| 行進中的路徑與預約 | `movement.remainingEdges`、`RouteReservation`、`BlockSections`、`SwitchInterlocking` | 已排好的路徑與號誌區間要重算 | 要（或擋下） | 擋下（可先用決策 716 關閉） |
| 侵入與間距 | `TrackFouling`、`TrackClearance`、`TrackSpacing`、`spacingExemptions` | 新曲線不能壓到別的軌道；雙線一邊被拉走就不平行 | 要 | 要（只查兩段） |
| 運轉曲線與時刻 | `runCurve(of:for:)`、`routeMemo`、`LineRuns`、`Timetable`、`TimetableExecution` | 長度與限速變，行駛時間就變；照真實時刻表跑的線會誤點 | 要 | 要（快取清掉即可；時刻要提醒玩家） |
| 路線指定的路徑 | `LineRoutePreference.tracks`（軌道編號） | 保留編號就還有效 | 保留編號 | 保留編號 |
| 關閉中的軌道 | `closedEdges`、`closingEdges`（決策 716） | 同上 | 保留編號 | 保留編號 |
| 地形、結構、橋隧 | `TrackStructure.automatic` 的 `sections`（決策 282）、地面是否適合（124）、水面（`trackOverWater`） | 自動結構要重切橋、隧道、路堤 | 要 | 要 |
| 土地與建物 | 地圖格要買下（決策 160）、`buildingOnTrack` | 新的線經過沒買的格或公司的建物就擋 | 要 | 要 |
| 資產與錢 | `AssetRecord(.track, owner: 編號)`、`edgeCost` | 要收多少錢、帳面價值怎麼改；拆除不退錢的規則要不要延續 | 要 | 要（平衡要量） |
| 買下的真實路線 | `LineAcquisition`（決策 315） | 真實路線的軌道照真實資料鋪；拖了就不再是真的 | 要決定擋不擋 | 擋下 |
| 存檔 | `SavedGame`（目前版本 107） | 保留編號就**不用**改版本；換編號就要遷移或重建引用 | 不一定 | 不用 |
| 回放與連線 | `PlayerCommand` 的紀錄（`Record`） | 新指令要加一種紀錄；舊的回放檔不受影響 | 要 | 要 |
| Golden | `GoldenScenarios/` | 新規則不改舊行為就不動；加新情境 | 加 | 加 |
| 畫面 | 2D 疊圖、3D 軌道、路堤、高架墩、電車線、`DragLoupe` | 網路一變就重畫（已有），拖曳中的預覽要新做 | 要 | 要 |

## 3. 關鍵：保留編號

`TrackEdge` 存的是 `from`、`to`、`curve`、`profile`、`structure` 等，存檔也存這些。所以：

- 新指令（暫名 `reshapeTrack`）可以**原地換掉一段或兩段軌道的曲線、保留 `id`**。
- 路線指定的路徑、關閉清單、資產紀錄都用編號，全部還指得到。
- **存檔格式不變**，`SavedGame.currentVersion` 不用升，SaveFixtures 不用新增。
- 檢查可以重用 `buildTrackEdge` 已有的那一串（幾何、坡度、地形、土地、建物、侵入、間距），加上 `removeTrackEdge` 的那一串（列車、月台、預約），全部過了才換，否則世界不變（failure atomicity）。
- 移動一個折點會改到兩段：兩段要一起檢查、一起換。

這讓 B 的成本落在「一個新的 GameCore 指令＋測試」，而不是「改存檔＋遷移」。

## 4. 三案與五方評比

尺同 `NEXT_PRIORITIES_2026-10-12.md` §19：玩家 30、開發 25、美術 15、鐵道迷 15、音樂 15。1–5 分。

**A 完整拖拉改線**：在任何軌道上按住拖，線跟著走；可以拖轉轍器、車站所在的段、雙線；有列車也照拖（列車跟著搬或自動等）。

**B 縮小版（TRACK-REALIGN-BEND）**：

- 只能拖「折點」：恰好兩段軌道相接、不是轉轍器的節點。
- 拖動時兩段的另一端位置與方向不動，折點的方向取兩段平順相接；所以兩端的轉轍器能通哪條都不變。
- 這兩段：沒有月台、不屬於買下的真實路線、沒有列車站著或壓著、沒有列車要開過去或預約（可以先用決策 716 關閉，等車走）。
- 保留兩段的編號；新的線要過鋪軌的所有檢查，坡度、地形、土地、建物、間距。
- 錢：變長的部分照鋪軌價收，變短不退（延續「拆除不退錢」）；細節要用 `economy-balance` 量。
- 雙線：只拖一邊會不平行，第一版擋下（間距檢查本來就會擋太近的情況），雙線一起拖之後再評。

**C 拆掉重鋪＋預覽輔助**：維持現在的拆掉重鋪。

- 預覽依彎道限速上色、對齊輔助線，已由決策 826 在做，不重複打分。
- 這份另提一小項 **TRACK-REBUILD-GHOST**：拆掉的軌道在同一次鋪軌裡留一條淡影（只在畫面上，不存檔），玩家可以沿著它重畫或畫在旁邊；離開鋪軌模式就消失。只動 GamePresentation。

五方：

- **玩家**：
  - 現在拉緩一段彎道要付兩次錢、路線指定的路徑還會失效；B 一次解決最常見的情況，給 4。
  - A 多出來的是拖車站、拖轉轍器，用得少、代價是列車與時刻亂掉，所以不比 B 高。
  - C 的淡影只是省一點對位，給 2。
- **開發**：
  - B 是一個新的 GameCore 指令，重用鋪軌與拆除的檢查，保留編號所以存檔不動；但要證明全成或全不成、快取清掉、回放紀錄、資產帳，給 2，而且佔一個 GameCore 名額。
  - A 要處理轉轍器方向、月台搬移、列車搬移或等待、雙線，給 1。
  - C 只動畫面，給 5。
- **美術**：拖曳中的預覽與改好的平順曲線都好看；A、B 同分。C 的淡影只是輔助線，給 2。
- **鐵道迷**：
  - 真鐵路的改線多半就是截彎取直、把彎道半徑放大讓限速提高；B 正好是這件事，給 4。
  - 移車站在真實世界是另一回事（新建站），A 不多加分。
  - 資料來源：無外部資料；限速規則沿用 GameCore 既有的 `CurveSpeedLimit`。
- **音樂**：無。

## 5. 建議與觸發條件

1. **現在不派**。決策 826（彎道依限速上色、對齊輔助線）先合併，作者在實機上鋪幾次軌。
2. **觸發 B**：作者或玩家說出「這段彎道太急想拉緩，但不想拆」這類話；或 826 合併後實機回報。觸發時照 2.90 排進 GameCore 的隊伍（同時最多兩張）。
3. **A 不建議**。B 做完後，若常聽到「想拖車站」「想拖轉轍器」，再分開評「移車站」與「移轉轍器」，不一次做。
4. **C 的淡影**分數低，等有人在 826 之後還說「重畫對不準舊線」再做。
5. 平衡的一個觀察（不在這次打分）：拆除完全不退錢（`disposeAsset`）。B 做的時候，改線收費要跟這條一致，用 `economy-balance` 量一次。
