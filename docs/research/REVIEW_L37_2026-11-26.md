## P2

### P2-1 隱私清單少了「檔案時間戳」一項（已修）

`SaveLibrary.swift` 的 `HeaderCache.Stamp` 用 `FileManager.attributesOfItem` 讀存檔的 `.modificationDate`（加上大小與檔案編號）來分辨存檔有沒有改過。`modificationDate` 在 Apple 的 required reason API 清單上（File timestamp），`PrivacyInfo.xcprivacy` 卻只宣告了 `UserDefaults`；`docs/XCODE_CLOUD_ONBOARDING.md` 10-23 的盤點寫「沒有用到時間戳」，是在標頭快取加進來之前。

TestFlight 的 build 一直有收（148 也過了），但 App Store 送審時 Apple 會對沒宣告的 API 寄 ITMS-91053，嚴重時整個 build 不能送審；11/27 晚上只有一次機會，不值得賭。

修法：加 `NSPrivacyAccessedAPICategoryFileTimestamp`，理由 `C617.1`（讀 App 自己容器、或它的 iCloud 容器裡檔案的時間與大小；這裡只讀遊戲自己的存檔）。不是為了消警告而虛構：用途就是這一個。`ONBOARDING` 補一行。其他 required reason API 重新找過：開機時間（`systemUptime`、`mach_absolute_time`）、磁碟空間、目前鍵盤都沒用到；`MapPackDownloads.swift` 的 `attributesOfItem` 只讀 `.size`，不在清單上；MapLibre 7.0.0 自帶它的清單。

### P2-2 App Store 版的「回報問題」只教玩家用 TestFlight 寄（已修）

`ProblemReport.whereToSend` 與說明的「問題或意見要送到哪裡？」都寫「用 TestFlight 測試的話……寄到 TestFlight App 裡這個 App 頁面上的回饋信箱」。從 App Store 下載的玩家沒有 TestFlight，照著做會找不到地方寄；送審的人也會看到一段只對測試版成立的說明。

修法：`whereToSend(in:testing:)`，`testing` 由 App 傳 `TestBuild.isTest`（決策 338 判斷 Xcode／TestFlight 的同一個）。TestFlight 照舊；App Store 版改成「App Store 這個遊戲的頁面上有『App 支援』連結，照那裡的方式寄出即可」（App Store 一定有 Support URL）。說明那一條不再寫 TestFlight，改成「回報畫面會寫要寄到哪裡」。加 `ProblemReportTests.testWhereToSendNamesTestFlightOnlyToTesters`。

五個角度：玩家：App Store 版的玩家知道去哪裡寄。鐵道迷：無。開發：一個參數，App 端三個呼叫點。美術：無。音樂：無。

## P3

### P3-1 Mac 的 Xcode 一更新，PR 的 iOS build 會一直紅（#2750）

`select-xcode` 在 self-hosted 找不到 27.2 就 `exit 1`；pick 只看 runner 在不在線、有沒有空，不看版本。Mac 的 Xcode 被 App Store 自動更新（27.2.x 或 27.3）之後，每張 PR 的 iOS build 都會被派到 Mac、然後紅，直到有人設 `MAC_RUNNER=off`。模擬器 runtime 不見也一樣。建議：runner 加一個版本標籤（如 `xcode-27.2`），pick 要求它，沒有就 hosted。已轉給 CI 串，由它決定要不要在合之前補。

### P3-2 兩張 PR 同時 pick，第二張會排在 Mac 後面（#2750）

兩個 pick job 幾秒內先後跑時都看到 `free`，第二張的 build job 會等 Mac 而不是退回 hosted。決策 1014 §4「忙的時候新的 PR 走 hosted」在這個窗口內不成立；最多多等一個 build（約 10 分鐘），記在決策就好。

### P3-3 送審的人看得到「測試」區

`TestBuild.isTest` 看收據是不是 `sandboxReceipt`。Apple 審查用的 build 也是沙盒收據，所以審查的人會看到設定裡的「測試」區（E1000 外觀開關，說明寫「只在測試版出現」）與 TestFlight 版的回報說明。玩家下載的正式版看不到，所以不影響玩家；審查因此退件的機會很小（只是一個外觀開關）。要完全避免，得改成 `AppTransaction.environment`（非同步，決策 676 寫了為什麼沒用），不在上架前動。
