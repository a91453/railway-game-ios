## 結論

**沒有 P1、沒有 P2。P3 一項，這一輪就修了**（P3-1）。另有一項 HEALTH-141 已經量到、已在總表的（TYMC-881-ENDS），這裡只補讀程式的看法，不重評。

- **存檔 109–111（866、868、883）**：`Station` 的 `chime`／`departureMelody`／`playerMelody` 都是 `decodeIfPresent`、`encodeIfPresent`；`playerMelodiesProblem()` 檢查號碼遞增、上限 16、車站指到的旋律存在、不和官方旋律同設。
  `setStationDepartureMelody` 清掉自訂旋律、`setStationPlayerMelody` 清掉官方旋律、`removePlayerMelody` 讓設了它的車站回到路線自己的旋律。`v109`、`v110`、`v111` 三個 fixture 與 README 都在；`GoldenScenarios/`、`ReplayFixtures/` 這一輪一個值都沒動。
- **#2495（旋律工作坊，883）**：`PlayerMelody.isValid` 擋音高、十六分音符格、長度、順序；`MelodyDraft.tap` 先拿掉同音高重疊的音再放，到 128 個就不放；六首官方旋律的 `tune(of:)` 都照開始時間排、沒有同時同音。
  合成在 `CuePlayers` 自己的序列佇列上做，不在主執行緒；鋼琴樣本讀不到時改放官方旋律一。WAV 讀法每一段都先檢查長度。
- **#2478、#2488（TICK-REAL、TICK-TAIWAN，878）**：`WorldAnswers` 只在同一秒、列車與路線都相同、佔用表沒換過時借用；`linePlans`／`runTrips` 跟著 `ServiceKey`（路網、路線、車站、設定、列車長度）一起丟。
  `@TaskLocal` 的稽核只在測試開；`trafficPartners` 只略過共站少於兩站的一對（那一對本來就排不出共同的兩點），`first` 取每站最前面的點，和舊的 `firstIndex` 一樣。golden 與 replay 沒動，和 PR 說的逐位元不變一致。
- **#2440、#2449（849）**：`homeLimit` 只給整條線跑全程、每站都停的線，`approachLimit(of:holding:)` 只在已經佔到那裡時才擋；`throatPoint` 的 `along` 可能是 −1（交會跨就在起點），之後 `limit > homeReach` 擋掉。
