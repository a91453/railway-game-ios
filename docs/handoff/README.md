# 每件工作自己的交接檔（2026-11-12 起）

`docs/HANDOFF.md` 開頭原本每個 PR 加一行，同時開著的 PR 全部改同一行，先合一個、其餘就衝突，各自要再併一次 main、再跑一次 CI（2026-11-12 一天三次：#2083 兩次、#2087 兩次）。決策 329 把決策改成一個檔一個決策之後沒再撞過，這裡照做。

- **實作 session 不再改 `docs/HANDOFF.md`。** 做完、做到一半、交給別人時，寫 `docs/handoff/<派工單名>.md`（例如 `ISLAND-LOWRISE.md`；名字照 #2118 的登記，大寫與連字號）。
- 檔裡寫以前那一行會寫的東西：派工單、session、分支、決策、存檔與 golden 動不動、做了什麼、**還留下什麼**、UNVERIFIED 的項目。長的細節照舊寫在決策的「下一步」，這裡指過去。
- 同一件工作換 session 接手，接著寫同一個檔。
- **檔案最上面維持一節「進度」**（2026-11-17，作者：額度用完中斷後，恢復時叫那串「繼續」，它都要重新讀取內容，白花 token；又：不要變成一直在寫交接檔）：固定三行（做到哪、已驗證什麼含數字、下一步的第一個指令），每次覆寫、不累加，只在三種時候寫：(1) 要開始跑超過約 10 分鐘的東西之前（量測、整輪測試），寫指令與結果會存在哪；(2) 拿到重做要超過約 10 分鐘或很難再得到的結果之後（根因、量到的數字、定案的修法）；(3) 看到額度警告時寫一次。其餘靠平常的 commit 訊息；還沒開 PR 時可以推分支（不會起 CI），開了 PR 之後跟著本來就要推的一起推，不為它單獨推。一小時內做得完的小工單不用寫；一張工單大約 3–6 次。中斷後被叫「繼續」時，只讀這一節與 `git status`、`git log -3`，不重讀派工單列的文件，也不重跑已經寫明驗證過的檢查。收尾時這一節改寫成「做了什麼」。
- **研究或評分的 PR 自己把分數寫進優先清單**（2026-11-17，作者同意）：只做研究、只寫文件的 PR，若評出要派的工作，在同一個 PR 把它們加進 `docs/research/NEXT_PRIORITIES_2026-10-12.md`（新的一小節，照 §19 的五方權重），不要只寫「由遊戲規劃排進優先清單」。#2304 就是這樣漏了一天。
- **只有遊戲規劃改 `docs/HANDOFF.md`**：§2.0 的現況，以及整理時把 `docs/handoff/` 裡已經沒有待辦的檔收進 `docs/HANDOFF.md` §4 或刪掉。
- 2026-11-12 之前寫在 `docs/HANDOFF.md` 開頭與 §4 的交接照舊有效，不搬。
