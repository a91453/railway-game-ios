## 樣式

| 名稱 | 用途 |
| --- | --- |
| `ThemeSelectableButtonStyle(isActive:)` | 開／關按鈕：開時填 `primary`，關時只有 `panelBorder` 外框。狀態不只靠顏色區分 |
| `ThemeProminentButtonStyle(isDestructive:)` | 主要動作：`primary`，移除類用 `error`；不能按時用 `panelBorder` 底配 `textSecondary` |
| `.themeCard(padding:cornerRadius:)` | 實色 `panel` 卡片，即使放在玻璃上，文字對比也固定 |
| `.glassBackground(in:interactive:)` | 浮在地圖上的元件：iOS 26 用 Liquid Glass，iOS 17–25 用 `.regularMaterial` |

`.borderedProminent` 固定用白字，在 Dark 的 `primary`（1.85:1）和 `error` 上都不到 AA，所以主要動作改用 `ThemeProminentButtonStyle`。`.bordered` 按鈕沿用全域 tint。

## 玩家看的文字（2026-10-14，作者；CLAUDE.md Workflow）

作者實機看到設定裡「色盲友善配色」的說明寫著「取最接近原色的那一個」「只改畫面」，回報：「怎麼把我的決策都寫到遊戲內？」遊戲裡給玩家看的字（中英文都算：`language.text(...)`、`Text(...)` 與 `Localizable.xcstrings`、說明、教學、提示卡、錯誤訊息、設定、面板）照下面寫：

1. **只寫效果**：玩家看得到、用得到的結果，一兩句講完。例如「路線改用色盲也分得清的顏色，徽章上加上線號。」
2. **不寫理由與做法**：設計理由、取捨、怎麼算的（「取最接近原色的那一個」「只改畫面」「照參考」「依決策」）。這些寫在 `docs/ARCHITECTURE.md` 對應的決策裡。
3. **不寫內部術語與 ID**：遊戲內部的距離單位（1/64 公尺）、軌段 #38、tick、整數、取樣、快取、GameCore、存檔版本、fixture、試作的做法、程式或程式庫的名字（「用 Procedural Tokyo 的繪製程式畫出來」「還沒有接上你的遊戲」）。距離一律寫公尺或公里。
4. **例外，要留的**：資料與授權的出處（OpenStreetMap、TDX、WorldPop、Overture、MIT 授權等，是授權條款要求的）。資料來源頁可以精簡「資料怎麼處理」的過程，但姓名標示與授權名稱要留。回報問題用的診斷資訊（回報附上的版本、存檔版本、錯誤代碼）也留。
5. **說明與教學**（`HelpGuide`、`Tutorial`）可以照步驟教，但同樣不寫內部原因與術語。
6. **畫面上看得到的編號算名字**：決策 201 的軌段編號畫在地圖上（拉近時、進路框線、選取工具），所以在玩家需要找到那段軌道的地方可以寫「軌段 #7」，例如進路選單、選取與拆除工具、建造的訊息。玩家剛點的那段軌道說「這段軌道」就好，不必寫號碼。看不到的編號（節點、列車與路線的內部 ID）不寫，用站名、列車名稱或公尺。

新文字上線前自問：玩家讀完知道「這對我有什麼用」嗎？有沒有哪一句只有開發者才看得懂、才在乎？

## 線號徽章與色盲配色（決策 216）

2026-10-14。決策 205 讓路線附近的標記不靠路線色；這一節讓**路線本身**也不只靠顏色：每條路線有線號，畫在徽章上；設定頁可以改用色盲友善色票。作者請 session 從玩家、開發、美術三方考慮後自己定案（預覽給了徽章三種、色票三種）。

### 線號

- 玩家可以改（路線面板「線號」）：一到三個英文大寫字母或數字（`LineCode`，GameCore 的 `ServiceLine.code`，缺 key＝自動；存檔版本 55）。輸入時小寫、全形字母數字、空白都會自動轉換；留空就回到自動。
- 自動線號照路線顏色的名稱取字母（`LineBadge.automaticCode`），北捷有的顏色照北捷：藍 BL、紅 R、綠 G、橘 O、棕 BR、黃 Y；其他照英文：粉紅 PK、紫 P、淺藍 LB、淺綠 LG、青綠 T、靛 IN、灰 GY、白 W。20 個色票與 6 個自動色各有一個字母；其他顏色照色相。同一個字母的第二條線起加數字（R、R2、R3），不和玩家自己給的線號撞；玩家給兩條線同一個線號就照他的。

### 徽章（方案 B「白底色條牌」）

| | 地圖（站名下、色帶上） | 面板（`LineCodeBadge`） |
| --- | --- | --- |
| 高 | 12 點（站名下）、14 點（色帶，拉遠 12 點） | 14 點（`.small`：列表、車站的路線標籤、跟車列、列車卡）、18 點（`.regular`：路線列表） |
| 字 | 高的 0.66，粗圓體，`ink` | 9／11 點，粗圓體，`ink` |

- **為什麼是 B**：玩家：線號字是藏青在白底上，13.29:1（深色 9.64:1），任何路線色都讀得到；A 的色塊方牌在中間調的路線色上（例如 `#EF5350`）白字 3.49、藏青字 3.81，都不到 4.5。美術：和決策 205 的標記（候車膠囊、等待小牌）同一套「白底藏青框」，路線色只是一小格；C 的色環圓牌和車站的圓徽章、等待環、高鐵的第二圈都是圓，地圖上搶形狀。開發：只有一種字色，不必依路線色挑黑白字。

## 狀態列與跟隨列的寬度（決策 251）

2026-10-16。預覽在 `docs/art/status-bar-width-2026-10-16/`。沒有新的顏色；連假的旗子用 `warning`（圖形，對 `panel` 5.06／6.33）。

規則：**會隨遊戲改變的字，留它最寬時的位置；次要的東西縮成固定大小的圖示；最窄的排法一定放得下；字不縮到 0.75 以下。**

1. **留位置**（`StatusBarWidths`，App 的 `WidestTextRoom`）：每一塊字的寬度是它能顯示的最寬那一個，不是現在這一個。
   - 金額：同樣位數裡最寬的，至少 7 位數，加負號（「$ -8,888,888」）。多一位數（×10）才變寬。
   - 日期：這一年的任何一天（月份、星期的名字，兩位數的日），加上秒（遊戲以 600× 以下的速度跑時，暫停也算）。換年份位數才變寬。
   - 倍速：最寬的倍速；暫停的黃點位置一直留著。
   - 跟隨的列車速度與彎道限速：最寬的「888 km/h」。
   - 數字一律 `monospacedDigit`（每個數字一樣寬，所以只看位數）。
2. **次要的縮成圖示**：天氣的圖示佔固定 20 點（每種天氣一樣寬）；連假不寫名字，把時鐘換成 `warning` 色的旗子（同一個 20 點的位置），名字在預報與 VoiceOver 裡。新聞與委託的數字是疊在鈕上的徽章，不加寬。
3. **排法**：`ViewThatFits` 的四種排法照舊（一列 → 一列短日期 → 金額疊在時間上 → 時間自己一列）。寬度固定之後，同一台裝置、同一個字級、同一年，就固定用同一種，不會玩到一半換。
4. **最窄的一定放得下**：跟隨列最後一種只有線號徽章和「取消跟隨」的叉（約 110 點）；倍速在狀態列也有。
5. **字級下限**：狀態列只有最後一種排法的時間可以縮，最小 0.75（`minimumScaleFactor`）；其他字不縮，用換排法讓位。整個畫面的字級上限是 xxxLarge（`ContentView`）。
6. **不只靠顏色**：連假是形狀（旗子）換掉時鐘，不只是變色。
