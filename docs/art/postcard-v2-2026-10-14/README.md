## 三個方案都改掉的地方

照遊戲規劃 session 從截圖列的五點：

1. **站長圓章拿掉**。沒有任何東西凸出卡片或壓在地圖框上。A 不放站長；B 放在底部帶子裡（圓角方框）；C 放在標題左邊（頭像，`StationMasterAvatar` 的放大：1.45 倍、錨點 (0.44, 0.3)）。
2. **地圖框照路網的形狀**：框的長寬比跟路網一樣，四周邊距相同（30 點），在可用的空間裡置中，不再有灰色側帶。高鐵是直長的框，小路網是橫長的框（最扁 5:3）。實景地圖畫出海（`Palette.water`，取自 App 已附的 `taiwan_water.json`，只畫和框邊相連的水，河與池不畫），框裡就不是一片空白。
3. **路線簡化**：不畫列車；站是小圓點（白底藏青框）。同一段有幾條路線就畫幾條細的平行線（線寬 2.6 點、間距 3.4 點，墊一層 `markerFill` 的底），像捷運路線圖；站的圓點橫跨在這一站停的那幾條線上，所以看得出哪條線停哪一站。站名照決策 205 的底牌（`land` 80%、圓角 3），放在離線最近又不壓線、不壓別的站名的位置，而且一定比別站更靠近自己的站。相鄰的站擠在一起時，站名可以排在鄰站站名的同一列（作者 2026-10-14：高鐵的台北放在南港左邊、板橋放在路線下面）；真的放不下才往外推，拉一條細線回到自己的點。
4. **標題只寫一次**：大字是玩家的公司名稱，拿掉「ALONG THE LINE ・ 沿線」那一行；遊戲名「沿線」只在右下角小小一個。
5. **數字最多三個，是 0 的不顯示**：順序是昨日旅客、路網長度、車站數、路線數，取前三個不是 0 的。高鐵示範剛開局，昨日旅客 0，所以是路網長度、車站、路線；小路網有旅客，就是旅客、長度、車站。三格排滿，不留空格。

署名照舊：實景地圖寫「鐵道：© OpenStreetMap · 交通部 TDX」（`DataSourceCredits.mapCorner(baseMap: false, railways: true)`）。海岸線也是 OSM 的資料（ODbL），已經在同一行的 OpenStreetMap 裡；自己的地圖不寫。

## 定案：C，加一處修改（遊戲規劃 session，2026-10-14）

- 玩家：高鐵示範那張最像能分享出去的圖，路線圖例一看就懂三條線是什麼；站長頭像在標題旁，認得出是《沿線》，又不搶畫面。
- 開發：一套版面依路網的長寬自動切兩種排法，不用玩家選；不動 GameCore。
- 美術：沒有凸出卡片的東西；直長的路網剛好讓出右邊一欄放圖例與數字，留白最少。A 的高鐵圖左右空太多，B 的站長帶把地圖往上擠。
- 音樂：無。

**修改**：橫長的路網原本在標題和地圖之間空了一大段。改成地圖框從標題下面填到數字列上方，路網在框內置中，四周的地面與城市照樣畫滿（這時四周的邊距不再一樣）；卡片維持 4:5，數字列照舊在底部；路線有兩條以上時，圖例放在地圖下、數字上方的一行（`option-C-final.png` 下排）。

## 實作時要注意的

- **灰階**：三條路線的顏色在灰階下差不多（`checks-C.png`），靠的是位置與圖例；圖例和地圖上的線要用決策 216 的線號徽章，色盲友善配色打開時照 `Palette.lineColor` 換色。
- **730.6 km** 是軌道的總長（高鐵是雙線，路線長約 350 km）。數字的名稱照 `CompanyFigures` 寫「路網長度」，這次不改。
- 小路網的地圖上那些淡色方塊只是預覽裡代替城鎮的：實際的卡照決策 215 第 4 點用地圖自己的畫法（`MapArt.drawBase`）畫地面與城市。
- 平行線、只有圓點的站與避線的站名，是明信片自己的畫法（不是 `MapArt.drawMap`）；手機上的地圖不變。
