## 3. 第一個重要轉折：把「突出」定位在正確的結構

使用者指出車頭橘色部分的突出沒有表現出來。早期曾把整個鼻子往前延長，得到過長、偏扁的前端。這個做法把「下肩／前唇突出」誤解成「整個鼻子都要更長」。

有效修法是：

1. 恢復合理的整體鼻長。
2. 中央白鼻罩獨立收窄。
3. 較低的肩部仍保持寬度。
4. 前唇以圓鈍曲面接住中央鼻罩與肩部。
5. 用側／俯／正三方向交叉看，斜視只作確認。

公開配方用不同的 H(x)、W(x) 與局部肩部包絡完成這個關係。這比在鼻尖放一塊獨立板件穩定，也比拉長整個殼更接近參考的結構。

**可移植的是分開控制曲率的思路，不是 700T 的站位、寬度或鼻長。** 另一種流線車必須重新讀它的最大寬度、肩線、鼻尖和駕駛艙分段。

## 4. 第二個重要轉折：風擋黑罩也會改變整台車的比例

前稿黑罩幾乎貼到車頂，看起來像高而方的一整片。重看實車正面與斜視後，先修罩體上緣、長度、寬度與圓角，再補內部分區。

歷史第七版到第八版的原生量測：

| 模型座標量測 | 前 | 後 |
|---|---:|---:|
| 黑罩頂 Z | 約 3.625m | 約 3.326m |
| 黑罩垂直高度 | 約 1.239m | 約 0.974m |
| 距本模型 3.65m 車頂的留邊 | 約 0.025m | 約 0.324m |

後續第九版再把罩四角修圓、下側收窄，分出上玻璃、細緣、下燈區、兩支簡化雨刷與實體支點。罩寬由約 2.349m 收為約 2.209m；第十版保持這些硬體。

這些是交付模型座標，不是對實車的工程量測。它們用來證明「真的修了過高／過寬的模型」，不是證明車型尺寸已核定。

值得學的判斷是：**黑罩、白車頂留邊、玻璃、燈區分別控制，然後沿鼻面貼合；不能用整片黑板代替駕駛艙。**

## 5. 第三個重要轉折：色帶的形狀與面積比色名更重要

使用者明確更正要「白車身，線條的顏色搭黑」。因此白車身列入保護範圍，使用綠松主帶與黑細線，而不是把整台車改成綠黑車身。

第九版形體已改善，但鼻尖中央綠色仍偏厚。第十版再次實看使用者正面模型圖與實車近照，觀察到參考中央只留下窄色邊，較寬色塊集中在肩部。

處理順序：

1. 保存真正第九版及所有來源／配方。
2. 鎖住車殼、風擋、玻璃、燈、雨刷、門窗、輪架與編組。
3. 白鼻罩向下延伸成圓底。
4. 收薄中央綠色，保留肩部較寬色塊，平順接回原車側主帶。
5. 細黑線仍沿白／綠交界，不另掛色片。
6. 重新出同相機、公尺尺度的前後，查看正、側、俯、斜與白模／剪影。

第十版基礎色票保持：

| 用途 | RGB |
|---|---|
| 暖白車身 | `#F2F0EA` |
| 綠松主帶 | `#3E8C8C` |
| 黑細線／深色部位 | `#2E3134` |
| 風擋罩 | `#4F5A61` |
| 上玻璃 | `#6B7A84` |

這是本案 palette／shade 的結果，不是要求所有新車沿用這五個色碼。

### 鼻尖的小突點為什麼要特別處理

鼻端局部寬度接近零時，如果色界一直用「橫向距離 ÷ 當地半寬」正規化，色界可能被擠成很小的一個點，讓中央白區冒出小舌或收成不自然尖端。

本案在最後一段逐漸混合回車身尺度：

    effectiveWidth =
        localWidth + blend × (bodyHalfWidth - localWidth) × smoothstep(tip)

再用這個尺度計算分色。實際配方的 blend 是針對本車反覆看圖調出的值，**不是跨車型建議值**。要看的是這個機制解決了什麼：在很小的鼻端斷面，避免色界隨分母過小而失真。

## 6. 一個看似小修、實際很重要的幾何問題

色帶與黑細線需要連續切兩次。若在第一次產生的新頂點重新計算非線性分色場，第二次切分可能在共享邊產生不同頂點，造成 T 接點或極小退化面。

正確做法：

    原始三角頂點 → 計算一次 d
    切 level=0 → 新頂點保存 d=0
    再切 level=stripeWidth → 新頂點保存該精確值
    各色多邊形 → 共用同一批交點 → 輸出原生三角

再配合一致的端點排序、近界值處理和退化面檢查。只把匯入器的檢查放寬，會把問題藏到其他工具或真機。

這次獨立讀回／匯入與有向邊檢查確實抓過這類問題；修好後才封包。這也是為什麼漂亮的最終圖之外，還需要讀實際原生三角的工具。

## 7. 第十版如何證明沒有順手改掉已接受部分

用 [livery-audit.py](../../../tools/train-shape-refresh/livery-audit.py) 讀真正新舊 M3DM，不只讀配方常數：

| 證據 | 第十版結果 |
|---|---|
| 其他獨立單元 | E200／中車／集電車／既有 Codex 比較車 native 與 GLB 完全同 bytes |
| 頭／尾保護 | 每端 8,286 個未改三角 bytes 一致；其餘修改限鼻部白／綠／黑 |
| 位置範圍 | 頭端 x≥3.7m、尾端對應反向區域 |
| 殼面 | 新舊三角雙向共面交疊面積核對 |
| 故障反例 | 整片面移動 5mm 會被拒收 |
| 外包／組裝 | 所有 bounds 與 placements 相同 |

共面檢查使用 20 微米位置容差與 3e−6 平方米面積容差，是 Float32 匯出管線的比較容差；不是實車精度宣告，也不是所有自交／重疊的形式證明。

模型量測另顯示：

| 模型量測 | 第九版 | 第十版 |
|---|---:|---:|
| 車頭朝前綠色三角的投影和 | 約 2.383957m² | 約 1.454329m² |
| 白鼻尖最低 Z | 約 1.292383m | 約 0.995035m |

投影和可能包含遮擋，不是實際圖片可見像素面積，更不是圖片相似度。它與同相機前後圖一起支持「綠色的範圍確實減少」，不能單獨判定好看。

### 測試也要對應新目標

舊測試曾固定白鼻尖寬度、綠帶高度。使用者要求擴白縮綠後，這些舊塗裝目標不再適用。修訂時保留鼻長、寬肩、輪軌、門窗、組裝與共存檢查；塗裝改檢查仍有窄綠邊與兩側包覆，另加「白鼻罩不能停得過高」的回歸，先在真正前版看它失敗。

這與修改 golden／save／replay 的期望讓測試變綠不同：本案沒有修改那些 fixtures，也沒有拿技術通過取代看圖；修改的理由和來源是使用者新要求，結果還要獨立審查。

## 11. 其他 AI 真正應該帶走什麼

1. 看懂參考的結構，別只認出車名。
2. 比例、輪廓、曲面比微小配件更早決定觀感。
3. 中央鼻罩、肩部、前唇各自控制，再連成同一形體。
4. 車頭黑罩和色帶面積也會改變視覺比例。
5. 每次用實際原生四向與同尺度真前後找問題。
6. 局部修改要能證明保護範圍，不順手改掉已接受部分。
7. 匯出與獨立驗證是外觀流程的一部分，但不替代外觀判斷。
8. 學這套觀察與修正方法，不把 700T 的殼或常數搬成所有車。
