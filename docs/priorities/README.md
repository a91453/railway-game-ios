# 評分檔：一項工作一個檔（2026-11-17 起，決策 832）

研究、量測、交接或任何 PR 評出要派的新項目時，**不再接在 `research/NEXT_PRIORITIES_2026-10-12.md` 最後一節**，改成在這個目錄寫一個自己的檔。2026-11-17 一天 #2355、#2365、#2367、#2371、#2375 都在搶 §29.28–§29.31 的節號，先合一張、其餘就衝突。決策 329 把決策改成一號一檔後就沒撞過，這裡照做。

## 怎麼寫

- **檔名是工作名**：照 #2118 登記的名字，大寫英數與連字號，例如 `E200-REDO.md`。同一件工作再評一次，接著改同一個檔。
- **第一行固定**：`# <工作名>（YYYY-MM-DD，來源）`。來源寫 PR 號（`#2367`），還沒開 PR 時先寫別的，開了再補（`--check` 會提醒）。
- **評分表**至少有這幾欄：`項目`、`玩家`、`開發`、`美術`、`鐵道迷`、`音樂`、`加權`；其他欄（順位、狀態、前置）隨意，欄名含「狀態」的那欄會帶進合併表。
- 每個分數是 1–5 的整數，加權照 NEXT_PRIORITIES §19：玩家 30、開發 25、美術 15、鐵道迷 15、音樂 15，寫到小數兩位。bug 的項目以「bug」開頭，排在功能前面。
- 表後照舊寫五方各一行理由。

範例：

```markdown
# E200-REDO（2026-11-17，#2367）

E200 重做之後留下的，細節在決策 825。

| 順位 | 項目 | 玩家 | 開發 | 美術 | 鐵道迷 | 音樂 | 加權 | 狀態、注意 |
| --: | --- | --: | --: | --: | --: | --: | --: | --- |
| 1 | E200 的菱形集電弓 | 1 | 4 | 2 | 4 | 1 | 2.35 | 未派 |

五方：
- 玩家：……
```

`python3 -I tools/golden-checks/doc_numbers.py --check` 檢查格式（檔名、第一行、日期、欄位、分數、加權）；改到 `docs/` 的 PR，CI 的 `doc-numbers` 工作會跑它（決策 830），錯了 gate 就紅。

## 規劃怎麼併回

```sh
python3 -I tools/golden-checks/doc_numbers.py --priorities
```

印出還沒併回的檔的每一列，bug 在前，再照加權、玩家、開發、鐵道迷排好，附來源連結。規劃把表貼進優先清單（現在是 NEXT_PRIORITIES §29 的新一節，或重排的總表），然後：

```sh
python3 -I tools/golden-checks/doc_numbers.py --priorities --mark "NEXT_PRIORITIES §29.30"
```

在那些檔的標題下寫一行「併回：NEXT_PRIORITIES §29.30（日期）」，之後 `--priorities` 就不再列它們。檔留著，決策與交接連得到；整理時規劃可以刪掉已併回的檔。

只有遊戲規劃改 NEXT_PRIORITIES；2026-11-17 以前寫進 §29 的照舊有效，不搬。
