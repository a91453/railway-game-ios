### 388. 全畫面對齊稽核：一個 UI 測試量每個浮在地圖上的群組與共用邊距的線

2026-10-23，遊戲規劃 session_01H5RHAwnA69n8EfAUSUrH52 派工（86.1 的 PR 2），session_013WiLkQHTAxZL85F5PYxJuL。接著決策 382（`HUDMargins`，四條線）。只動 App 與 GamePresentation；GameCore、存檔版本、golden schema、SaveFixtures、ReplayFixtures 都不動。開始畫面（`StartView`）不在內：#1110 還沒合併時不動它。

**要什麼**：一個讀 `XCUIElement` 畫面框的 UI 測試，每個浮在地圖上的東西，邊緣離決策 382 的線在 1 pt 內；只在 full lane 跑，手動用 `only_testing`。畫面：一般地圖與建設模式；列車卡、車站與路線面板；2D 跟車、3D 跟車與駕駛室；課程卡與站務員泡泡；新聞、設定、說明、成就。裝置：手機橫放、iPad 橫放與直放（手機只能橫放，`project.yml` 的 `UISupportedInterfaceOrientations_iPhone`，所以「手機直放」沒有這個畫面）。

**測試**（`RailwayGameApp/UITests/HUDAlignmentUITests.swift`，11 個測試）：
- 線從地圖畫面本身讀：左線與上線是狀態列玻璃的左上角，右線是右下角那一組（`map.corner`）的右緣，底線是工具欄（或 iPad 的底部工具列）玻璃的下緣。每個讀到的框都印成 `ALIGN|畫面|元素|minX minY maxX maxY|視窗`，CI 的 log 就是量測紀錄。
- 離某條線不到 8 pt 的邊算「應該在線上」，要在 1 pt 內；8 pt 抓得到「16 pt 的一般 padding」（差 6），抓不到旁邊隔一個邊距的另一個控制項（差 10 以上）。
- **讀玻璃，不讀容器**：第一輪（run 39994199691）每個群組都差 3 到 14 pt，原因是 `.accessibilityElement(children: .contain)` 的框是子元素的聯集，而按鈕的子元素是 44 pt 的觸控範圍，不是玻璃。所以加了 `hudFrameMark(_:)`（`Theme.swift`）：只在 Debug 建置、啟動參數有 `-ui-testing` 時，在群組背後放一個和群組一樣大的無障礙元素（`ZStack` 合併，不能只放 `Text`：第二輪 run 40005059194 讀到的是 4×1.5 pt 的字）。正式版與一般 Debug 執行都沒有這個元素，VoiceOver 也讀不到。標了：`hud.bar`、`hud.tools`、`hud.rail`、`hud.panel`（側邊面板）、`hud.card`（細節卡）、`map.quickLayer.strip`、`map.corner`、`follow.bar`、`map3D.followBar`、`stationMaster.bubble`。

**改了什麼**：
1. 3D 畫面的控制項（2D 鈕、速度、幀率、3D 跟車列）原本 `.padding()`（16 pt），改成 `HUDMargins.edge`（10 pt）：從 2D 切到 3D，左上角的鈕不會往內跳 6 pt。
2. 課程卡的邊距 `TutorialCardPlacement.margin` 原本 16 pt，改讀 `HUDMargins.edge`（10 pt）：三輪量到它是唯一不在線上的群組（差 6）。卡片的擺放照舊用成本挑位置，只有離螢幕邊的最小距離變了；`TutorialCardPlacementTests` 裡兩個寫死 `- 32`（兩倍 16）的折疊卡寬度改成兩倍 `HUDMargins.edge`。

**沒改、是設計取捨**（留給遊戲規劃看實機）：
- 手機上開著細節卡時，2D 跟車列夾在圖層列與卡片之間只有約 100 pt 寬，照決策 251 讓到只剩車種章與停止，**3D 鈕跟著不見**。要在手機上從跟車進 3D，得先收起卡片。拿掉圖層列或讓跟車列換到第二排都會改到決策 226 的版面，不在這次的範圍。
- 手機開著面板時，下面那一排縮放與 3D 的下緣仍在決策 300 的位置（決策 382 第 8 點）。
- 系統的 sheet（新聞、設定、說明、成就；手機滿版，iPad 置中）照系統的位置，不對齊地圖的線。

**沒選的做法**：
- 從元素框扣掉每個群組自己的內距（狀態列 14/5、工具欄 4、圖層列 3、跟車列 13/6）：狀態列裡的按鈕用負 padding 撐大觸控範圍，扣不準，而且內距一改測試就得跟著改。
- 在畫面上開一個「把每個框寫成文字」的讀數（像 `map.stations`）：要在每個群組加 `onGeometryChange` 再集中，程式比一個背景元素多。
- 截圖比對：專案不比對圖片（CLAUDE.md），作者在實機看。
- 照參考網頁的 `max(邊距, 安全區域)`：有瀏海的那一邊控制項會貼著安全區域的邊，和沒有瀏海的那一邊不一樣遠；決策 382 已選「安全區域內再 10 pt」。

**五方**：
- 玩家：控制項離螢幕邊一樣遠，從 2D 切到 3D、從地圖進課程，左上角的東西不跳。
- 鐵道迷：無。
- 開發：一個 full lane 的 UI 測試把「對齊」變成會紅的檢查，以後新的浮動控制項加 `hudFrameMark` 就量得到；測試用的元素只在 Debug 加 `-ui-testing` 時存在。
- 美術：課程卡與 3D 控制項和其他玻璃同一條線；改的都是邊距，形狀、圓角、顏色不動。
- 音樂：無。

**Reference check**：railway-reference-private（87a94c7）。`Ci/reference_snapshot/lib/app-core__q_*.css`、`app-panels__q_*.css` 的浮動面板用 `max(16px, env(safe-area-inset-*))`（取大的，不是安全區域再加邊距），各面板 12、14、16 px 不一；沒有讀畫面框比對邊距的測試。`Simulator/`、`MapBuilder/` 的快照是編譯過的網頁，也沒有。可以借的只有「邊距一個值、各處共用」這個做法，決策 382 已經是。測試與 `hudFrameMark` 是本專案自己寫的；外面的專案沒有找（截圖比對專案不用）。
