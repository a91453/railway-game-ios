### 481. 路線面板拆兩層：精簡的路線清單，點一條線推進它自己的頁

2026-10-29，遊戲規劃第 29 任（session_01YGNNunHRtNkV8GUzm1ppB7）派工（派工單 LP），實作 session_01YGNNunF7F1xm5bcPAv9pcL（`claude/lines-panel-two-level`）。只改 App 與 GamePresentation；GameCore、存檔版本、golden schema、replay 都不動。

**為什麼**：作者回報「路線頁面越多條線，要往下滑越久。」面板（`LinesPanel`）是一張長表：整個路網的開關、所有路線、進階、新路線、可收購路線，最後才是選中那條線的列車、機廠、停靠站、設定、營運、各班次（決策 196、383 的順序）。兩個問題：

1. 每條線一列要 4–5 行字（停靠站全名與狀態、班次、昨日報表、趨勢小圖與一句趨勢），線一多，清單就很長。
2. 選了一條線，它的設定在整串清單下面，要滑過所有路線才看得到；從地圖或車站點一條線打開面板，也一樣要往下找。

**做了什麼**：

1. **兩層**（只在「路線在前」時，`GameSession.linesPanelListsLinesFirst`，即決策 196 的 `listsLinesFirst` 搬進 GamePresentation）：
   - **清單頁**：
     - 搜尋、篩選、排序固定在清單上方（`safeAreaInset(edge: .top)`，`.bar` 底），清單在下面捲；篩選和排序放得下時並排，放不下時上下排（`ViewThatFits`）。出現的條件同決策 179、184（6 條線起才有搜尋）。
     - 一組四個入口，在路線上面：
       - 「整個路網」（`lines.network`）：推進一頁，放交通管制、轉乘方式與營運日。這一頁本來就是為營運日開的，所以進階收起時也顯示營運日。入口那一列寫出現在的設定（`NetworkSwitches.summary`）。
       - 「進階」開關（`lines.advanced`，決策 196 後來）。收起時的那行摘要只寫營運日，已經在上一列，清單頁就不再重複；一張表的時候照舊有。
       - 「新路線…」（`line.new`）：照舊在原地展開表單（決策 196）。
       - 「可收購的真實路線（N）」（`lines.forSale`）：推進一頁，放原本的收購按鈕（決策 315、336）。
     - 每條線兩行（`lineRow`）：
       - 第一行：代號徽章、名稱（環狀、高鐵的小圖示）、班次（`line.trainsRow.<id>`，如「12 列 · 每 6 分」）。
       - 第二行：昨日運量與損益（`LineReport.compactRowText`，`line.report.<id>`，虧錢時紅字）和運量趨勢小圖（決策 472 的那條線）。貨運線沒有報表，寫現在的營運時段。
       - 停靠站全名、票收、尖峰、最滿列車條與趨勢的那句話，都移到詳細頁頂端。
       - 列尾一個 ›，點了推進那條線的頁。
   - **詳細頁**（`LinesPanelPage.line`，標題是線名，返回回清單）：
     - 頂端一段：停靠站全名與現在的營運時段、昨日報表那一行（`rowText`）、決策 472 的趨勢條。
     - 「上一條線／下一條線」與「第 2 條，共 5 條」（`LineNeighbours`）：照清單現在的順序（排序、搜尋、篩選之後）；這條線被搜尋篩掉時，照所有路線的順序。換線時頁面原地換內容、回到頂端，不再推一頁。
     - 下面是列車、機廠、停靠站、路線設定、營運、各班次，順序和決策 196 的一張表一樣。
2. **從別處打開一條線就是它的頁**（`GameSession.openLine`、`openedLineID`）：
   - 會進詳細頁的：清單的一列、地圖上按住一條線（決策 276，`holdLine`）、地圖上的提醒泡泡（沒車、虧錢）、站長的建議（決策 194）、車站卡與軌道卡的路線晶片、路網流量的路線列、時刻表的「到路線面板改停靠站」、複線完成後的「看路線」卡（決策 201）。
   - 新路線建好之後，也直接進它的頁（列車在最上面，決策 101）。
   - 只選不開的（`selectLine`）：教學的步驟、新聞的「前往」（只移地圖）、收購完成、UI 測試的開場世界。詳細頁開著時選了別條線（例如「複製路線」選中複本），頁面跟著換成那條線：頁上的按鈕改的是選中的那條線，兩者不能不同。
   - 返回清單就關掉（`closeLineDetails`），那條線仍是選中的（地圖上照舊標它）。刪掉這條線也回清單。開著一條線時關掉面板，再打開還是那條線的頁。
3. **一張表的時候照舊**：沒有路線、正在選站或草稿不是空的、教學中，面板照決策 100、196 的一張表：新路線表單在最上面，選中路線的各段在下面。所以建線流程沒有多一步，第 1–8 課與 UI 測試找的按鈕（`line.staff.start`、`line.addTrain`、`line.depots`、`line.window`、`line.pattern.add`、`lines.advanced` 等，`TutorialTarget`）都在原來的地方。清單列在一張表裡也改成兩行。點一列只選中，不推頁。
4. **改名、代號的對話框與運行圖**跟著放各段的那一頁（`modals(_:active:)`），不會從被蓋住的清單頁彈出。
5. **動畫**（motion skill）：
   - 推進與返回是系統 NavigationStack 的轉場，不是自己寫的動畫。
   - 從別處（地圖、別的面板）打開一條線、刪線回清單，是程式改 `path`：減少動態效果時用 `Transaction.disablesAnimations`，直接換頁不滑。
   - 面板打開時，若已經開著一條線，第一頁就是它的頁（`State` 的初始值），不會先看到清單再滑進去。
   - 上一條／下一條線原地換內容，沒有動畫。
   - 沒有新的 `MotionRule`。「新路線…」照舊用 `MotionRule.change.layout(reduceMotion:)`。

**沒採用的做法**（預覽 `docs/art/lines-panel-481-2026-10-29/overview.png`）：

- **B iPad 左右兩欄**（`NavigationSplitView`）：路線面板在地圖旁邊，寬 min(420, 半個畫面)（決策 106），為的是選站時地圖看得到、點得到。兩欄要 800 點以上，地圖就被蓋掉一半，或者兩欄各剩 200 點，列放不下兩行字。手機上也還是要 A，等於兩套版面、兩套 UI 測試。
- **C 同一張表，每列可展開**（`DisclosureGroup`）：展開一條線後，它下面的線被推得更遠，要關掉才看得到，和作者回報的是同一個問題。從地圖打開一條線時，還要捲到那一列。
- **詳細頁用 sheet 蓋上去**：路線面板已經在地圖旁邊（手機上是全螢幕的面板），再疊一層 sheet 會蓋住地圖，加站時就看不到地圖上的站。

**五方**：

- **玩家**：線再多，清單每條兩行，一眼看得到班次、運量、賺賠；點一條線，它的設定就在眼前，不用往下滑；從地圖點線、從車站點路線晶片，直接到那條線。上一條、下一條可以一路看下去。建線與教學的步驟和以前一樣。
- **鐵道迷**：清單像鐵路公司的路線一覽（代號、名稱、班距），點進去才看停站與運用；和參考網站的側欄、路線資訊面板同一個結構。
- **開發**：GameCore、存檔、golden、replay 不動。哪一層、打開與關閉、上一條下一條、清單的字放在 GamePresentation，有 Linux 測試（`LinesPanelNavigationTests`）。教學走的一張表沒改，教學目標不用動。UI 測試只改要進詳細頁的那幾支，共用 `openLinePage`、`closeLinePage`。
- **美術**：不加新顏色，只用 `Theme` 的色票與系統的清單樣式；固定在上方的搜尋列用系統的 `.bar` 底。列尾的 › 是 iOS 清單的慣例。
