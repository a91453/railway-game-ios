### 1017. 只改發版說明的 PR 不重建 App、只跑讀說明的測試（RELEASE-NOTES-CI）

2026-11-26，規劃3 工作串「讓只改說明的 PR 不重建 App」（分支 `claude/project-thread-s43n4g`），協調者第 5 任派工；
`docs/handoff/CIOPT-17.md` 第 1、6 項（作者 11-26 同意，「好」）。
號碼依 #2118 的登記：決策 1017；存檔版本、golden schema、GameCore、遊戲程式都不動。

## 1. 為什麼

0.6.0 (148) 的發版 PR #2744 從第一次推到合約 3.6 小時，推了 8 次，每次 `ci.yml` 約 31 分。最慢的是 hosted 的 iOS build
job，29.9 分：「這版新增」卡的文字寫在 `Sources/GamePresentation/WhatsNew.swift`，改到它就算改了 App，整個重建、跑 gate
的 UI 測試，gate 等它。Swift 那邊 `WhatsNew` 的 `Line`、`Entry` 名字太常見，決策 1012 的縮小也選到 7 份 GamePresentation
測試（`docs/research/CI_MEASURE_2026-11-26.md` §6）。可是那些條目只是字串，除了卡片上的字，App 做的事一樣。

## 2. 怎麼做

- 新的 `.github/scripts/release-notes-only.py --base <rev>`：PR 的每個檔都是下面幾種，才印 `notes=true`：
  - `WhatsNew.swift`，而且只改了 `entries` 陣列裡面：陣列外面一字不差，陣列裡每一行都是條目的寫法（`Entry(`、`id: "…",`、
    `items: [`、`fixes: [`、`Line(`、`english: "…",`、`chinese: "…"`、收尾的括號、`//` 註解、空行）。字串裡有 `\(` 插值、
    多行字串、呼叫函式，都不算。
  - `WhatsNewNext/new/`、`WhatsNewNext/fixed/` 的 `.txt`（Package.swift 把 `WhatsNewNext` 排除在 target 外，沒有 build 讀它）。
  - `.github/testflight-whats-new.md`（只有 `testflight.yml` 讀）。
  - `docs/` 底下與最上層的 `.md`（App 與 package 都不編；`doc-numbers` 照樣看 docs）。
  - 而且至少一個檔在 `Sources/GamePresentation/`（只改 What to Test 與文件的 PR，本來就不跑 Swift 與 iOS）。
  其他情況、讀不到、出錯，一律 `notes=false`，照舊全跑。
- `ios-build.yml` 的 changes job 多一步「Only the release notes?」：`notes=true` 時 `passed` 也是 true，macOS 的 job 全部跳過
  （和決策 187「這個改動已經過了」同一條路），run 是綠的，`ci.yml` 的 gate 看到就放行。這步失敗（`continue-on-error`）照舊跑。
- `ci.yml` 的 changes job 把 PR 的 base 傳給 `swift-shards.sh decide`（`NOTES_BASE`）。`notes=true` 時 tier 是 `notes`，只跑
  `WhatsNewTests` 與 `ReviewL19FixTests`（讀 `WhatsNew.entries` 的兩個類別），一個 job。`swift-build` 照舊用
  `-warnings-as-errors` 編整個 package，所以條目打錯字還是紅。`stack-frames` 提醒在 `notes` 不跑（字串不加 frame）。
- `full-ci` 標籤、`main` 的推送、手動與每晚的 run 都不看這條：照舊。

## 3. 發版 PR 不用再加 `full-ci`

11-26 加 `full-ci` 是為了繞過 SaveMutationChecks 選錯（#2748 已修）。現在發版 PR 是 `notes` tier，加了 `full-ci` 反而全跑。
發版例行的步驟改成：**發版 PR 不加 `full-ci`**。要確認整個 package 的是 `main` 合併後的推送 run，以及發版前那個 commit 的完整
`ci.yml`（CLAUDE.md 的 TestFlight 條件），不是發版 PR。

## 4. 驗證

- `release-notes-only.py --selftest`：發版 PR、加文件的發版 PR、只加一行 `WhatsNewNext` 都是 true；只改 What to Test、條目旁邊改別的
  原始碼或測試、陣列外的程式碼、陣列裡呼叫函式、插值、多行字串、提早關掉陣列、刪檔、`WhatsNewNext` 裡的 README 或 `.swift`、
  沒有改動都是 false。
- `swift-shards-selftest.sh` 跑上面那個 self-test，再在一個小 git repo 裡測 `decide`：發版 PR 是 `notes`；沒有 `NOTES_BASE`、
  `full-ci`、`main` 的推送、條目旁邊改到程式碼都不是 `notes`。
- 拿 #2744 的合併 commit（9d4a7d2）實際跑：`notes=true`，`decide` 給 `tier=notes`、一個 `selected` job。

## 5. 五個角度

- 玩家：沒有直接影響；發版 PR 從約 31 分降到 Swift 的 build 加兩個測試類別（估約 10 分內），版本能早一點送出。
- 鐵道迷：無。
- 開發：發版日不再為改字等 Mac；判斷寫得很窄，看不懂就全跑，誤判的代價只會是多跑。
- 美術：無。
- 音樂：無。
