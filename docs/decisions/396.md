### 396. Game Center：每週挑戰的每週排行榜、成就同步，entitlement 晚一個 PR 加

2026-10-24，遊戲規劃 session_01XsVqbA1A5wGtJbuAa881oT 派工，實作 session_01V99archiZKLqZkwqTnsajc。作者原話：「那先合併 然後做 Game Center」（選了 Game Center，不架伺服器）。決策 87 當初排的順序就是「先做能公平比較的每週挑戰，再接 Game Center 的排行榜與成就」。GameCore、存檔版本、golden schema、SaveFixtures、ReplayFixtures 都不動；GameKit 只在 App。

**參考**：參考庫 `Ci/` 已停用的挑戰模式（`lib/app__q_c234188b7c397f91.js`）：`metroChallengeLeaderboardPayload` 送 `playerId`、`cityKey`、`eventId`、`rulesVersion`、`scorePassengers` 到自己的 `/api/challenge-scores`，`metroChallengeRenderLeaderboard` 顯示前 20 名與自己的名次或百分位。沒有 Game Center、成就同步或 GameKit 的實作（`Ci/` 全找過，只有音效名稱裡的 `achievement`）。所以 GameKit 的部分是原生（gap → 原生）；欄位照參考的對應：`eventId` → 每週一次的 recurring leaderboard 的那一期，`rulesVersion` → 選哪一個排行榜，`scorePassengers` → 分數的 context。

1. **對照放在 GamePresentation**（`GameCenterMapping.swift`，Linux 測試 `GameCenterMappingTests`）：
   - 成就 ID：`achievement.<遊戲內 ID>`，38 個（決策 181 的清單；派工寫的 226 是外框，成就是 181）。
   - 點數：共 800 點（Game Center 上限 1,000，留 200 給之後的成就），第一步 5–10，長期目標 80。
   - 進度：整數百分比。解鎖了是 100；沒解鎖的照決策 181 的進度無條件捨去、最多 99（100 只由遊戲自己的午夜解鎖決定，免得 Game Center 先說達成）；有或沒有的成就、這局沒列出的成就（沒有景點、沒有車種計價）是 0，不送。平溪線挑戰只算它自己的兩個成就（決策 181 的 `achievementScope`）。示範、教學、無限資金不算（照 `checkAchievements` 原本的條件）。
   - 每週排行榜：`weekly.days.v2`，對應 `ChallengeRecords.rulesVersion` 的 `2026-10-goals-v2`。目標改了換新版本時，對照表裡沒有那個版本就不送，測試會擋，提醒先在 App Store Connect 建新的排行榜，新舊目標的成績不會排在一起。
   - 分數：完成天數，低到高排；當天載客數放 context。決策 87 的比法是「天數少的贏，天數一樣比載客多」，Game Center 只用一個數字排名，所以平手時 Game Center 照它自己的規則排（先送的在前），載客數只跟著分數存。沒有把兩個數合成一個（例如天數 × 10⁹ − 載客），因為 Game Center 會把那個數字直接顯示給玩家，看不懂。
   - 哪一週：送的永遠是「現在這一週」的最佳紀錄（`challenge-records.data` 裡 `weekly.<這週>` 那一筆）。上週的挑戰這週才完成，不送：recurring leaderboard 只收目前那一期，送了會排進這週的榜。週的界線和 Game Center 的週期都是台灣時間週一 00:00。
   - `GameCenterLedger`：App 開著期間記住已送過的，只送變高的百分比、變好的成績；Game Center 自己也只留最高的。
2. **App**（`RailwayGameApp/App/GameCenterLink.swift`）：
   - `GKLocalPlayer.local.authenticateHandler` 在 App 啟動時設定，背景登入，不擋開場。iOS 給的登入畫面先收著，玩家在成就畫面按「登入 Game Center」才顯示；沒有登入、拒絕或沒網路時什麼都不說，遊戲照舊。UI 測試（`-ui-testing`）不登入。
   - 登入後把全部（解鎖的成就、這週的最佳紀錄）送一次；之後 `GameLauncher` 每個午夜檢查成就、每次刷新挑戰紀錄時，透過 `reportToGameCenter` 交給它。成就的 Game Center 橫幅關掉，遊戲自己的狀態列已經說了。
   - 入口：成就畫面最上面的「Game Center」一節，登入後是「本週排行榜」與「Game Center 成就」（`GKAccessPoint.trigger(state:)`，iOS 14 起有）；還沒登入而 iOS 給了登入畫面時是「登入 Game Center」；兩者都沒有時整節不顯示。字串照這個檔案原本的做法放在 GamePresentation（`GameCenterText`，中英兩種，有測試），不進 String Catalog。
3. **entitlement 晚一個 PR 加**。查了 `testflight.yml`：archive 是 ad hoc（`CODE_SIGN_IDENTITY=-`，不用 profile），export 與上傳才用 App Store 的發行簽章與雲端管理的 profile（`-allowProvisioningUpdates` 加 API key）。App 帶著 `com.apple.developer.game-center` 而 profile 沒有這一項時，匯出或上傳會失敗（Apple 開發者論壇的 ITMS-90045 等回報；Apple 的說明：在 Developer 網站的 App ID 打開 Game Center、重新產生 profile 之後 profile 才會有這一項，https://developer.apple.com/help/account/reference/capability-entitlement-updates ）。這要作者在 Apple Developer 與 App Store Connect 先設定，session 驗證不到。所以：
   - 這個 PR 只有程式，沒有 entitlement：GameKit 登入一律失敗（App 不被 Game Center 認得），遊戲照舊，TestFlight 照常能發。
   - 作者照 `docs/GAME_CENTER_SETUP.md` 設定之後，第二個 PR 才加 entitlement（`project.yml` 的 `CODE_SIGN_ENTITLEMENTS`）與 38 張成就圖。合併後的第一次 TestFlight 若匯出失敗，revert 那個 PR 就回到現在的狀態。
4. **隱私**：分數、載客數、成就進度只送到 Apple 的 Game Center；App 不讀玩家的名字或 ID，不送任何東西給開發者或第三方。Apple 的 App 隱私說明：「You are not responsible for disclosing data collected by Apple.」（https://developer.apple.com/app-store/app-privacy-details/ ）。所以 App Store 的隱私標籤維持「不蒐集資料」，`PrivacyInfo.xcprivacy` 不加項目（GameKit 不在 required reason API 的清單上）。`docs/XCODE_CLOUD_ONBOARDING.md` 的「隱私」已補；官網隱私權政策在第二個 PR（真的會送出資料時）同一輪改。
5. **作者的步驟**：`docs/GAME_CENTER_SETUP.md`（App ID 打開 Game Center、App Store Connect 打開 Game Center、建 recurring leaderboard、38 個成就的 ID／點數／中英文名稱與說明、送審版本勾 Game Center）。`GameCenterMappingTests.testTheSetupStepsListEveryAchievement` 確認文件列了每一個成就的 ID 與點數。

**驗證**：Linux 上 `swift build --build-tests -Xswiftc -warnings-as-errors` 與 `GameCenterMappingTests`（8 個）、`AchievementsTests`、`WeeklyChallengeTests` VERIFIED。App 的 GameKit 呼叫、成就畫面的入口、Xcode 專案：UNVERIFIED LOCALLY，交給 macOS 的 `ios-build.yml` 與 `release-archive.yml`。真的登入、送分數、看到排行榜要等作者設定好、第二個 PR 合併之後在 TestFlight 實機看。

**沒有選的做法**：
- entitlement 和程式同一個 PR：作者設定前發版可能壞掉，沒有辦法在雲端先驗。
- 一開場就跳 Game Center 登入畫面：擋住開場，拒絕三次之後 iOS 也不再給。
- 自己畫排行榜（`GKLeaderboard.loadEntries` 取前幾名，像參考的前 20 名）：要多一個畫面與它的 UI 測試；Game Center 的畫面已經有名次、好友與這一期的倒數。之後想在挑戰結果卡上直接顯示名次再做。
- 用 classic leaderboard 自己在 ID 裡放週次：每週要建一個新的排行榜，作者做不完。

**五方**：
- 玩家：每週挑戰終於能和別人比，成就在 Game Center 也看得到；沒登入的人什麼都不會變。
- 鐵道迷：無（排的是天數，不是鐵道資料）。
- 開發：對照與判斷都在 GamePresentation 有 Linux 測試，App 只呼叫 GameKit；entitlement 晚一個 PR，發版不會因為作者還沒設定而壞。
- 美術：入口用系統的 Game Center 畫面與 SF Symbols；成就圖（1024×1024）在第二個 PR 照 art-style 做。
- 音樂：無（成就照舊用遊戲自己的音效，Game Center 的橫幅關掉）。
