### 396（續）. 用 App Store Connect API 一次建好排行榜與成就

作者 2026-10-24 不想在 App Store Connect 手動填 1 個排行榜和 38 個成就，選了「用 B」：寫一個工具，用發 TestFlight 已經在用的 App Store Connect API key 一次建好，作者只在 GitHub 按一次執行。

1. **一份資料**：排行榜與成就的每個欄位放在 `docs/game-center/game-center.json`。`docs/GAME_CENTER_SETUP.md` 的三張表由 `tools/game-center-setup/game_center_setup.py --write-doc` 從它產生，`--check-doc` 在 CI 擋兩邊不一樣。`GameCenterMappingTests.testTheSetupStepsListEveryAchievement` 照舊把文件的 ID 與點數對到程式的 `GameCenterMapping`，所以 JSON、文件、程式三邊一致。
2. **工具**（`tools/game-center-setup/game_center_setup.py`，Python 標準函式庫加 `openssl`，不加依賴）：
   - JWT（ES256）沿用 `.github/scripts/testflight-processing.py` 的 `Client`（用 `importlib` 載入，不抄一份）。
   - 用 App Store Connect API 4.5 的 v2 Game Center 資源：`gameCenterLeaderboards`、`gameCenterLeaderboardLocalizations`、`gameCenterAchievements`、`gameCenterAchievementLocalizations`、`gameCenterAchievementImages`（`POST` 拿 `uploadOperations` → 分段 `PUT` → `PATCH uploaded: true`），讀 `/v1/apps/{id}/gameCenterDetail` 與 `/v1/gameCenterDetails/{id}/gameCenter…V2`。v1 的同名端點從 API 4.3 起標為 deprecated（Apple 的 OpenAPI 規格 4.5.1）。v2 的排行榜與成就各有 version，建立時要在同一個請求裡 inline 建第一個 version（`included` 裡的 `${version}`），語言掛在 version 上，圖掛在語言上。
   - 每週排行榜：`recurrenceStartDate` 是執行那天之後的下一個台灣時間星期一 00:00（UTC 星期日 16:00），`recurrenceDuration` `PT168H`，`recurrenceRule` `FREQ=DAILY;INTERVAL=7`。這兩個字串的格式 Apple 的文件沒有寫（OpenAPI 只說是 duration 與字串），是照 ISO 8601 與 RFC 5545 推的。作者 2026-10-24 第一次 apply（run 40069135297）時 Apple 不收 `P7D`：HTTP 409「'P7D' is not a valid value for the attribute 'recurrenceDuration'. Expected an ISO 8601 duration with time components」，改成 `P7DT0H0M0S` 後（run 40069474297）也一樣 409，所以 Apple 要的是只有時間部分的寫法：改成 `PT168H`（7 天 = 168 小時；Apple 開發者論壇有一則用 API 建每小時排行榜的請求寫 `PT30M`）。`PT168H` 收了；下一次（run 40069787513）換 `recurrenceRule` 被退：「Recurring leaderboard rule 'FREQ=WEEKLY;INTERVAL=1' is not valid. Format must be 'FREQ=[MINUTELY,HOURLY,DAILY];INTERVAL=$INT'」，所以每週寫成每 7 天 `FREQ=DAILY;INTERVAL=7`。這一版 Apple 收不收仍是 **UNVERIFIED**，要下一次 apply 才知道。Apple 不收時只有排行榜那一項失敗（成就可以用 `only: achievements` 先建），排行榜可以照文件的表手動建。
3. **安全**：
   - 預設 dry run：只送 `GET`，列出 apply 會建的完整清單。選 `apply` 才寫入，寫入前先印出同一份完整清單。測試確認 dry run 沒有任何寫入的請求。
   - 已經存在的 ID 一律跳過；**不送 `DELETE`，不 `PATCH` 已經存在的東西**（唯一的 `PATCH` 是把這一輪剛建的圖標成已上傳）。已存在的項目跟表不一樣，只在清單寫「注意（不會改）」。
   - 已存在的項目缺語言或圖時才補，而且只補在還能編輯的 version（`PREPARE_FOR_SUBMISSION`）上，所以中途失敗後重跑只補沒建完的。例外：傳到一半的圖（`AWAITING_UPLOAD`、`FAILED`）只列在清單上，不刪也不補傳，要作者在 App Store Connect 刪掉那張圖再跑（文件有寫）；讓工具自己刪違反「不動已經存在的東西」。寫入的請求不自動重送（斷線時可能其實已經建了），重跑會找到它並跳過。
   - 成就的圖不在 repository 裡（#1158 合併前）時，那個成就整個先不建；排行榜照建。
4. **Workflow**（`.github/workflows/game-center-setup.yml`）：只有 `workflow_dispatch`，job 有 `if: github.ref == 'refs/heads/main'`，`environment: testflight`（真正擋住其他分支的是這個 environment 只允許 `main` 的設定，跟 `testflight.yml` 同一道防線；job 的 `if` 只是讓在別的分支按的人一眼看到沒跑），secrets 的名稱照 `testflight.yml`（`ASC_KEY_ID`、`ASC_ISSUER_ID`、`ASC_PRIVATE_KEY`，variable `ASC_APP_ID`），只交給執行工具的那一步。`testflight.yml` 不動。同時只跑一個（concurrency），不取消執行中的。key 寫進權限 600 的暫存檔，程式不印 key、key ID、issuer ID 或 token（測試檢查所有輸出）。
