### 430. 莒光號的客車換成莒光自動門客車

2026-10-27，遊戲規劃 session_01YGNNuoQekRm2qcVxoPT8ME 派工（派工單 L），實作 session_01JMHz9bX8tiYa28j4W86aAg（`claude/new-session-bj8f8l`）。號碼依 #1041：決策 430；存檔版本、golden schema 不動。GameCore、`GoldenScenarios/`、`SaveFixtures/`、`ReplayFixtures/` 不動，只動 GamePresentation 的列車組與測試。

**為什麼**：#1306 做了莒光自動門客車（`Map3DChuKuangPassenger`，遊戲藏青配米色），合併後沒有接進營運；地圖上的莒光號還是用通用的 `coach(TrainLivery.e200ChuKuang)`（約 1,500 個三角形、橘色）。這個決策只做一件事：把莒光號的客車換成它。

莒光號已在 2026-07-01 退出台鐵營運（決策 425 的出處：自由時報、聯合報）。遊戲照樣提供這個車種，畫的是它最後一代的客車；#1306 的 README 說明這個模型是照片與研究站資料的外觀研究，不宣稱工程復刻或特定年代編組。

**換了哪些、沒換哪些**：

| 列車組 | 車頭 | 客車 | 遠景版 |
| --- | --- | --- | --- |
| `E200CK` | #1201 的 E200，不動 | 莒光自動門客車 | 新增 `E200CKFar`（車頭用同一個） |
| `E500CK` | E500，不動 | 同上 | 原有的 `E500CKFar` 只換客車 |
| `R100CK` | R100，不動 | 同上 | 新增 `R100CKFar` |
| `R200CK` | R200，不動 | 同上 | 新增 `R200CKFar` |
| `SUMMER`（仲夏寶島號） | 蒸汽機車與煤水車，不動 | 同上 | 新增 `SUMMERFar` |

沒換：`BLUE`（藍皮解憂號）、`MINGRI`（鳴日號）、`STAR`（環島之星）、`STEAM`：它們不是莒光客車，各自的塗裝與客車照舊；`Map3DChuKuangIntegrationTests.testTheOtherHauledSetsAreAsTheyWere` 用改之前 main 上的逐頂點雜湊釘住它們每一個模型。EMU800、EMU500、C341 接進營運、`conductor-study`（展示用的角色，#1306 的 README）都不在這張。

**做了什麼**：

1. **`Map3DTrainSet.Coach`** 多一個 `chuKuang` 旗標與兩個方法 `middle(named:far:)`、`tail(named:far:)`；`hauled`、`e500Hauled`、`steam` 改叫它們，並多一個 `far` 參數。非莒光的客車（藍皮、鳴日、環島之星、蒸汽藍皮）走原來的路，輸出逐頂點不變。
2. **莒光客車** = `Map3DChuKuangPassenger.model(.standard, far:)`，原樣取用，顏色已烤在模型裡（藏青 `#262C57`、米色 `#ECE2BC`），不再套 `TrainLivery` 的色；`TrainLivery.e200ChuKuang` 等仍給列車卡片與 2D 地圖。
3. **最後一節** = 同一個模型的頂點，後面接兩顆紅色尾燈（`Map3DTrainSet.chuKuangTail(far:)`）。
4. **遠景**：五個列車組各有遠景版，500 m 外用 `model(.standard, far: true)`，做法照決策 420、422（`far` 指到 `<key>Far`）。機車頭沒有遠景模型的（E200、R100、R200、蒸汽機車與煤水車）遠景版用同一個；E500 用它自己的遠景模型。`nearOnly` 加了 `E200CK`、`R100CK`、`R200CK`（`E500CK`、`SUMMER` 原本就在），這五組近景只畫到 500 m，之後到 900 m 畫遠景版。
5. **`Map3DModels.swift` 沒動**：模型包照 `Map3DTrainSet.all` 的順序登記，遠景版接在各自的近景版後面；路線公車仍在最後。

**尾燈**：照 `tailCoach`（決策 252）的做法：`Map3DPalette.lantern`、`mesh.makeGlowing(from:)`。兩顆 0.10 × 0.20 × 0.20 m 的方塊（各 12 個三角形，一節多 24 個），放在 −x 端：

- 後背貼在端牆（x = −9.65，`bodyHalfLength`），向外突出 0.10 m，不埋進車殼、不浮空；
- 橫向 ±1.0 m：在貫通道框（±0.6 m）外，端牆（±1.44 m）內；
- 離軌面 1.45 m（底）到 1.65 m：端牆下段的素藏青面上，在米色腰線（1.86 m）之下；
- 不改 #1306 的配方：尾燈的頂點接在 `Map3DChuKuangPassenger.model` 的頂點之後（`coach.vertices + lamps.vertices`），所以車殼的每個頂點逐位元相同，模型的長寬高不變。

測試 `testTheLampsStandOnTheEndWall` 驗證：背面距端牆不超過 0.011 m、突出至少 0.05 m；兩顆左右對稱；在貫通道外；在端牆範圍內；沒有任何一個車殼三角形穿進燈裡。

要直說的：遠景版只比近景輕 38 %（4,008／6,476），一列十二節的遠景版仍是原來的 2.6 倍（客車部分 44,112 對 16,186）；近景則是 4.4 倍。五個列車組的近景範圍也從原來的 900 m 縮到 500 m（它們原來沒有遠景版，一個模型畫到 900 m）。這個代價是派工單要的做法（五組都用 `far: true`），幀數只能實機看（UNVERIFIED）；如果實機上太重，下一步是做更輕的遠景客車（#1306 的配方 `far` 只減了窗框與格柵），或把這五組的遠景距離縮短；兩者都不在這張。

**長度**：客車一節 20.0 m（`couplingHalfLength` 10.0 的兩倍）。

- `E500CK`、`SUMMER`（原本就是自己長度的列車組）：每節 20.0 m，原來 19.4／19.59 m；`E500CK` 的客車互相貼著，`SUMMER` 的客車與煤水車之間照舊 0.6 m（`Map3DTrains.carGap`）。一列比原來長約 3 %。
- `E200CK`、`R100CK`、`R200CK`：**沒有加 `ownLengths`**（`Map3DTrainSetTests` 與新測試的「沒有 layout」照樣成立），照舊把每節拉到車長 19.4 m（車距 20 m 減 0.6 m 的間隙），所以模型的長度被乘上 0.97；高度與寬度不變。車數、車距都和以前一樣。

**模型包**：`set-<key>-head／car／tail` 的名字不變；模型總數**變了**，因為遠景版是新的單元：`E200CKFar`、`R100CKFar`、`R200CKFar` 各 3 個、`SUMMERFar` 4 個（頭、煤水車、客車、尾車），共 13 個。`Map3DModelTests` 的算式是 `Map3DTrainSet.all.map { $0.models().count }` 加總，所以不用改；`Map3DChuKuangIntegrationTests` 另外逐組檢查名字與車數。

**回歸測試**（`Map3DChuKuangIntegrationTests`；先寫，在改之前的 main 上 10 個裡 8 個是紅的；綠的兩個，「其他列車組與改之前相同」與「`conductor-study` 不在營運」，本來就是防護）：

- 五個列車組的中間車（近景、遠景）逐頂點等於 `Map3DChuKuangPassenger.model(.standard, far:)`，不等於 `conductorStudy`；
- 客車保有藏青與米色，沒有橘色；
- 最後一節 = 標準客車的頂點 + 只有尾燈發光、紅色；尾燈位置見上；
- 3、6、12 節都排得出來，車款名單與車數和以前一樣；`E500CK` 的 layout 是每節 20.0 m，`SUMMER` 是車頭、煤水車、客車；
- `R100CK`、`E200CK`、`R200CK` 沒有 layout、沒有 `fixedCars`、不是 `ownLengths`；
- 499／500／899／900 m 的近遠景切換、遠景比近景輕、尺寸相同（到遠景屋頂的一公分）；`reach(of:)` 近景 500 m；
- 機車頭與煤水車的逐頂點雜湊和改之前一樣，遠景版的車頭與近景版相同（E500 用自己的遠景）；
- `BLUE`、`MINGRI`、`MINGRIFar`、`STAR`、`STARFar`、`STEAM` 的每個模型的雜湊和改之前一樣；
- `conductor-study` 不在任何列車組裡。

既有測試只改這五組：`Map3DTrainSetTests.testEverySetsCarsAreInThePack` 的三角形範圍照實量（中間車 6,476／4,008，最後一節 6,500／4,032，不放寬別的列車組）、`E200CKFar` 與 `SUMMERFar` 的車頭範圍與高度、長度跟著原來的車頭；`testTheSetsDrawnAtTheirOwnLengths` 的 SUMMER 客車長度 19.4／19.59 改 20；`Map3DPPIntegrationTests.testExistingE500ServicesKeepTheirOriginalCoachesAndLocomotive` 不再把 `E500CK` 當作「原來的客車」；`Map3DE500Tests` 的「近遠景客車相同」只留給鳴日與環島之星，`E500CK` 改成近遠景不同、遠景較輕。

**沒選的**：

- 客車也有 `conductor-study` 混編（車掌車）：#1306 的 README 說它是展示用、子系列沒確定，遊戲的節數是變動的；
- 把客車再拉成 19.4 m 對齊舊的車長：會讓窗列比 #1306 的畫面擠 3 %；`E500CK` 與 `SUMMER` 本來就是自己長度，另外三組照舊的拉伸；
- 為三個沒有 layout 的組加 `ownLengths`：派工單明說不加，它會改變車與車的間距邏輯；
- 在 `Map3DChuKuangPassenger` 裡加尾燈角色：不改 #1306 的配方，尾燈只在列車組這一側。

**五方**：

- 玩家：莒光號的客車從通用橘色換成藏青配米色、有窗列、端門與轉向架的客車，最後一節亮兩顆紅色尾燈；遠景的車也跟著換。代價是遠景距離內的三角形多了 2.6 倍，幀數待實機。
- 鐵道迷：莒光號 2026-07-01 退出台鐵營運（決策 425）；畫的是最後一代的自動門客車外觀（#1306 照片與研究站資料，不宣稱工程復刻），塗裝是遊戲藏青，不是真車的橘色（作者 2026-10-27 的指示）。尾燈的位置與尺寸是自己估的，沒有對照真車的照片。
- 開發：只動一個檔案的建構（`Coach` 一個旗標、`hauled`／`steam` 一個參數、一個函式）；`Map3DModels.swift` 與 #1306 的檔案不動；舊客車的輸出逐頂點不變，有雜湊測試。
- 美術：客車是 #1306 的模型，顏色與形狀不改；尾燈用 `tailCoach` 的紅色與發光做法，和其他列車的尾燈一致；近景圖見 `docs/art/chukuang-service-2026-10-27/`。
- 音樂：無。
