### 857. CI 與發版改用 Xcode 27（iOS 27 SDK）

2026-11-18，雲端工作串「把 CI 升級到 Xcode 27」，分支 `claude/project-thread-uiu8hg`，協調者派工。號碼依 #2118 的登記。不動 GameCore、存檔版本、golden、replay、任何 Swift 原始碼。

## 1. 為什麼

139 版上傳後 App Store Connect 回了警告 90725：這一版是 iOS 26.5 SDK 打包的，**2027 年 4 月起上傳與送審都要 iOS 27 SDK（Xcode 27 以上）**。在那之前 26.5 SDK 的版本照樣收，所以不急；但 CI 一直用 Xcode 26 的話，升版才會出現的編譯錯誤要等到期限前才看得到。

升版前：所有 macOS job 都是 `runs-on: macos-26`，用映像預設的 Xcode 26.6（17F113、Swift 6.3.3、iOS SDK 26.5），沒有任何一處指定 Xcode 版本。

## 2. GitHub 那邊有什麼

2026-11-18 讀 `actions/runner-images` 的 README 與映像說明：

- 沒有 `macos-27` 這個標籤。Xcode 27 在另一個映像，標籤 **`xcode-27`**（arm64，macOS 27.0.1），狀態是**公開預覽**（runner-images #14404）。
- 那個映像有 Xcode 27.0、27.1（預設）、27.2；iOS SDK 與 Simulator runtime 各是 27.0、27.1、27.2。iOS 27.1 的 runtime 只有 iPhone Duo 一台，27.2 的才有整排 iPhone 與 iPad。
- `macos-26` 只有 Xcode 26.x（GitHub 的規則是一個 macOS 版本只放一個 Xcode 主版本），所以留在 `macos-26` 選不到 Xcode 27。

## 3. 改了什麼

- **所有 macOS job 改 `runs-on: xcode-27`**：`ios-build.yml`（建置、UI 測試、iPad）、`ios-compilation-cache.yml`、`release-archive.yml`、`testflight.yml`、`testflight-checks.yml`、`website-screenshots.yml`、`native-glass-metal.yml`、`wulai-cabin-metal.yml`。Linux 的 job 不變。
- **新 `.github/actions/select-xcode`**：checkout 之後選 Xcode 27.2（`XCODE_VERSION` 只寫在這一處）；映像沒有那一版就紅，並列出它有哪些。選 27.2 而不是映像預設的 27.1：27.2 的 Simulator 有 iPhone 與 iPad、和作者手機的 iOS 27.2 同版、和 Mac 本機 Xcode 同一代。
- **新 `.github/scripts/select-simulator.py`**，取代四處一樣的內嵌 Python：原本拿 `simctl` 列出的第一台 iPhone，映像有三個 runtime 時那是哪一台不一定。現在取**和 SDK 同版的 runtime**，iPhone 取 Pro（不是 Max；原本選到的是 iPhone 17 Pro，測試是在這個大小上寫的），沒有 Pro 取第一台不是摺疊的；iPad 取 13 吋的 Pro（原本選到的是 iPad Pro 13-inch (M5)），沒有就取別的 Pro、再沒有取第一台。第一版寫成「同 runtime 的第一台 iPad」，選到 iPad mini，教學的三支導覽測試在那個大小上紅了（#2453 的 run 44265510040）。沒有同版 runtime 時退回別的 runtime，不紅。`--selftest` 在建置 job 選機前跑一次。`website-screenshots.yml` 自己的選機（要 Pro、最小的 iPhone、iPad Pro）沒有動。
- **`testflight.yml` 的版本檢查從「Xcode 26 以上」改成「27 以上」**：之後不會再不小心用舊 SDK 上傳。
- 編譯快取的 key 本來就含 `xcodebuild -version` 與 SDK 版本，換 Xcode 後自動是新的一份；合併後第一次 `main` 的 run 會整個重編並存新快取。

## 4. 沒選的做法

- **只有發版（`testflight.yml`、`release-archive.yml`）用 Xcode 27，PR 的檢查留在 26**：PR 綠了、發版那一刻才知道 27 編不過；兩套 Xcode 的行為差異也沒人測。
- **等 `macos-27` 正式版或等到期限前再換**：期限是 2027 年 4 月，還有時間，但預覽映像現在就能用，早換早看到問題。
- **預覽映像出狀況時的退路**：把這八個檔的 `runs-on` 改回 `macos-26`、`select-xcode` 的版本改回 `26.6`、`testflight.yml` 的檢查改回 26，一個 PR；2027 年 4 月之前都還能這樣發版。

五個角度：

- 玩家：沒有看得到的變化；之後的版本不會因為 SDK 太舊被擋在上架外面。
- 鐵道迷：無。
- 開發：CI 與發版用同一個 Xcode，升版的錯誤在 PR 就看到；Xcode 版本只寫在一處。代價是預覽映像沒有正式版穩（GitHub 說「as-is」）。
- 美術：無（畫面由 iOS 27 SDK 編出來，Liquid Glass 等系統外觀要在實機再看一次）。
- 音樂：無。

## 5. iOS 27.2 的 Simulator 上測試看到的兩件事

換 Xcode 後 App 編得過、沒有新警告；紅的都在 UI 測試，原因是 iOS 27.2 的輔助使用樹和 26 不同，玩家看到與按到的沒有變：

- **測試專用的框線記號會擋住控制項**：`hudFrameMark`（只在 DEBUG 且 UI 測試時畫的 `background` 記號）在 iOS 27.2 排在控制項前面，XCTest 的點擊檢查找到的是記號，`isHittable` 就是假。記號加 `.accessibilitySortPriority(1)` 後恢復。試過不行的：`respondsToUserInteraction(false)`、改成 overlay、`.contain`、`sortPriority(-1)`。
- **原生選單會丟掉識別碼**：放在 `ControlGroup` 裡的項目、和第二層 `Menu` 裡的項目，在 iOS 27.2 只剩標籤，`accessibilityIdentifier` 是空的；第一層的整列（`menu.saveGame`、`menu.backToStart`）還在。測試改用 `menuItems(_:label:)`（`ToolbarSmokeTests.swift`）：識別碼對得上就用識別碼，識別碼是空的才比標籤開頭。選單本身對玩家照常運作（在 Mac 的 iOS 27.2 Simulator 上點過）。

## 6. 合併的條件

**PR 的 CI 綠還不夠，iOS 27.2 上的 full lane 也綠才合。** PR 只跑短的 gate 清單；`main` 每晚的 full lane 跑全部，換了 Simulator 版本而沒先看 full lane，合併當晚就紅。2026-11-18 在分支上手動跑的 full lane（run 44299210747，head f650b28）還有 14 支紅，清單與原因分類在 `docs/handoff/XCODE-27-CI.md`。在那之前 `main` 照舊用 Xcode 26 發版，期限是 2027 年 4 月。
