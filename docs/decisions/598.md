### 為什麼

- **防抄襲**：Wasm 加 JavaScript 的網頁版把 GameCore 以可直接取用的形式放到瀏覽器，有心人容易整包移植。作者寧願用 exe、apk、ipa 包裝，不上網頁。
- **少一套平台**：W0 探針（`Web/WasmProbe/`）只證明 GameCore 能在 Node WASI 與瀏覽器跑 golden，沒有任何出貨計畫；留著就要維護一個 workflow 與 Wasm SDK 的版本對應。
- **堆疊檢查改由 #1840**：決策 577 記過 Wasm 的堆疊上限讓 GameCore PR 紅過；之後由決策 590 下一步 5（CI 列出超過 32 KB 的堆疊框）接手堆疊檢查。安卓是 64 位元，32 位元溢位檢查不再需要。

### 刪了什麼

- `Web/WasmProbe/`（W0 探針：Swift package、Node／瀏覽器執行腳本）。
- `.github/workflows/wasm-probe.yml`。
- 文件：`README.md` 的 `Web/` 說明、`GoldenScenarios/README.md` 的一行、`docs/HANDOFF.md` §1.3 的「動 GameCore 的含 Wasm Probe」。
- 保留：ARCHITECTURE 1–328 與 `docs/` 其他舊文件（決策 51、577、`WEB_PORT_READINESS` 等）的原文是當時的紀錄，不改。`taiwan_heights.dat` 與 `wasManaged` 等字樣只是巧合，不動。這一步不動 `Sources/`、`Tests/`、`Package.swift` 與 `ios-build.yml`、`ios-full-lane.yml`、`ci.yml`，所以 Swift 與 iOS 的 job 都跳過。
