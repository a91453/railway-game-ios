### 338. 列車包：新車的外觀先鎖起來，測試版用開關解鎖，上架前換成內購

2026-10-22。作者問「現在更新的套件組要做成付費內容嗎」「用兌換碼嗎」「列車包不能先用 app 鎖著嗎」「開發版不能先鎖東西嗎 然後我輸碼解鎖」，要五方建議後回「好 照你的做」。遊戲規劃 session_014rYHMtmqA5bEMkBBuKu6PV。號碼依 #231：決策 338；存檔版本、golden schema 不動。

**規則**：

- **列車包**（`TrainPack`，GamePresentation）是一份 3D 列車 set 的清單，現在只有三節都市電聯車（`threeCarUrban`，決策 331 續四）。之後的新車一台一台加進清單。
- **沒解鎖時**，包裡的 set 畫成它出現以前的樣子：三節沒有車種的通勤電聯車照舊畫 `commuter`（`Map3DModelPack.locked`，`Map3DTrainSet.set(forKey:count:locked:)`）。包外的車不受影響。
- **只換外觀**：速度、座位、票價、存檔、GameCore 都不看列車包。一份存檔拿到沒解鎖的裝置上，只是車畫成一般的樣子。
- **現在怎麼解鎖**：設定裡「測試」區的「列車包」開關，只在測試版出現（Xcode 的 Debug 版，或 TestFlight 的版本：收據是 `sandboxReceipt`）。App Store 的版本看不到開關，就算裝置上留著打開的值也不算（`TrainPack.isUnlocked(testBuild:switchOn:)`）。
- **上架前**（作者決定要賣時）：開關換成 Apple 的內購（一次性購買的商品），加「恢復購買」；送人用 App Store Connect 的兌換碼（offer codes）。在 TestFlight 裡購買走測試環境，不扣錢。

**為什麼不做的事**：

- **自己的兌換碼**：App Store 審查準則 3.1.1 不准用自己的機制（序號、QR code 等）解鎖數位內容；而且這個 repo 是公開的，碼寫進程式誰都看得到。
- **送審版本留著測試開關**：TestFlight 的版本就是送審的版本，審查員也走測試環境，看得到開關。所以上架前一定要把開關換成內購，見下面「上架前要做的」。

**五方理由**：

- 玩家：已經在遊戲裡的綠色電車、兩節綠色電聯車不收回；鎖的是還沒人看過的新車，沒解鎖的人看到的仍是完整的車。只換外觀，不會變成付錢才贏。
- 鐵道迷：輕型捷運要看起來是輕軌（決策 331），所以綠色電車不放進包裡；包裡是「多一款車型」的收藏。
- 開發：鎖只在畫面這一層選模型時看一份清單，GameCore、存檔、golden 不動；Linux 測試鎖住鎖上與解鎖時每節畫什麼；開關之後換成 StoreKit 時只換 `isUnlocked` 的來源。
- 美術：沒解鎖時畫的一般通勤車樸素但完整；新車照同一套配色一批批加，包會越來越豐富。開關放在設定的「測試」區，不在主畫面。
- 音樂：無。

**沒有選的做法**：

- **三台新車全鎖**：會把輕型捷運畫回大型捷運，也會收回已經給出去的東西。
- **街景套件（公園、廟、商店）也鎖**：免費的城市會變空。
- **測試版用輸碼解鎖**：公開 repo 裡的碼不是秘密，做法比開關多，上架時一樣要拆掉。
- **現在就接 StoreKit**：還沒有商品、價格與付費 App 合約，接了也測不到真的商品。

**上架前要做的**（寫在 `docs/HANDOFF.md` §3）：

1. 作者：App Store Connect 簽付費 App 合約、填稅務與銀行資料；建一個一次性購買的商品「列車包」，訂價格。
2. 程式：接 StoreKit 2（`Product.products`、`purchase()`、`Transaction.currentEntitlements`），設定裡的開關換成「購買」與「恢復購買」；`TrainPack.isUnlocked` 改看購買紀錄；測試開關拿掉。
3. 送審前確認 App Store 的版本沒有「測試」區。

**驗證**：Linux 的 `TrainPackTests`、`Map3DTrainSetTests`（**VERIFIED**）。設定的開關、TestFlight 的判斷與 3D 裡換車要 iOS 上看（**UNVERIFIED LOCALLY**，`ios-build.yml` 編譯；實機等 TestFlight）。

### 338（續）. 列車包加入五節、七節輕軌：兩節、三節的輕型捷運解鎖後畫成鉸接輕軌

2026-10-22。作者：「列車包順便融入這兩台」（#992 的五節鉸接輕軌 `Map3DFiveSectionLRT`、七節輕軌 `Map3DSevenSectionLRT`）。遊戲規劃 session_014rYHMtmqA5bEMkBBuKu6PV 派工，3D 實作 session_01T8UdZRFmxs93DFtUKX5V73。不另取號碼；存檔版本、golden schema 不動。

**規則**：

- **哪幾節畫哪一台**（`Map3DTrainSet.articulatedByCount`）：輕型捷運（`C`）**兩節**畫五節輕軌（`fiveSectionLRT`），**三節**畫七節輕軌（`sevenSectionLRT`）。一節、四節以上照舊是綠色電車（決策 331）。兩個 set 都在列車包（`TrainPack.sets`）；沒解鎖時兩節、三節的輕型捷運照舊畫綠色電車。
- **一整列怎麼切到每一節**：3D 地圖一節車一個模型，拉到 18.4 m（19 m 減車間 0.6 m）。整列輕軌切成幾段，每段是一節：
  - 五節（34 m）切在中間車段的正中（x = 0，窗的中間）：兩節都 17 m，拉 **1.082 倍**。
  - 七節（45.5 m）切在中前、中後車段的窗與門之間那一小段車身（x = ±7.08 m）：頭尾 15.67 m、中間 14.16 m，拉 **1.174／1.299／1.174 倍**。
- **車間不中空**：每節的長度只算到切口，切口那一片截面再往車間延伸半個車間（拉伸後 0.3 m，`Model.cut(from:to:reach:)`），和下一節在車間正中相接，再把截面封起來（每一塊被切到的零件各自封一個凸包面，顏色取它被切的面最多的那個）。直線上看不到接縫；急彎時只有一道小折痕，不會露出空殼。切口選在沒有門、窗框的平板車身，延伸出去的截面就是一樣的車身。
- **燈**：照決策 331，車頭兩盞白燈、車尾兩盞紅燈亮在兩端的燈座前一指寬（五節 x = ±16.935 m、高 0.79 m；七節 x = ±22.675 m、高 0.81 m）。集電弓只在車尾那節（套件本來就只有 trailing 單元有）。
- **畫的距離**：照輕型捷運的 500 m（`Map3DTrainSet.reach(of:)` 看車種，`C` 一律 500 m）。
- **只換外觀**：速度、座位、票價、存檔、GameCore 都不變。`Map3DFiveSectionLRT.swift`、`Map3DSevenSectionLRT.swift` 不改，只當函式庫呼叫 `formation()`。

**量到的**（Linux，`Map3DModelPack.standard`；含燈）：

**五方理由**：

- 玩家：兩節、三節的輕型捷運看起來是一整列鉸接輕軌，車門、窗的比例和套件一樣；沒解鎖的人看到的仍是完整的綠色電車。
- 鐵道迷：淡海、安坑、高雄的輕軌都是一整列鉸接、不能拆的低地板車；兩節 38 m 的輕型捷運配 34 m 的五節車（接近高雄 Urbos 3 的 34 m）、三節 57 m 配 45.5 m 的七節車，是最接近的兩組。七節拉 1.17–1.30 倍偏長，但比切在鉸接處（1.37 倍）好。
- 開發：只動 GamePresentation 的 `Map3DTrainSets.swift`、`TrainPack.swift`；`Map3DTrains` 不改，靠模型的長度（`minimum`／`maximum`）只算到切口來讓延伸伸進車間。Linux 測試鎖住鎖上／解鎖時每節畫什麼、長度與拉伸、延伸與封面、燈的位置、三角形數。
- 美術：切口落在平板車身，直線上看不出是好幾個模型；兩台各自的綠松、霧藍照套件，不吃路線色（和綠色電車一樣）。
- 音樂：無。

**沒有選的做法**（預覽在 `docs/art/train-pack-lrt-2026-10-22/`）：

- **切在真的鉸接處**：五節 13.4／20.6 m（1.373／0.893 倍），七節 13.4／18.7／13.4 m（1.373／0.984 倍），同一列的車段一節長一節短。
- **七節平均三等分（±7.58 m）**：三節都拉 1.213 倍，但切過門扇，延伸出去的截面把門在車間拉寬。
- **七節切在門中線（±7.83 m）**：1.233／1.175 倍，但延伸出去的是門框，車間多一條 0.6 m 的灰色。
- **兩節的輕型捷運畫七節車**（0.809 倍）：五節車就沒地方用，三節也沒有合適的車。
- **車間補假風琴**：一列多一個不存在的鉸接，而且 0.6 m 比真的鉸接（0.2 m）寬三倍。
- **只延伸車殼、不延伸截面**（第一版）：切口兩側的內容會在車間重複，門變成四扇。
