### 338. 列車包：新車的外觀先鎖起來，測試版用開關解鎖，上架前換成內購

2026-10-22。作者問「現在更新的套件組要做成付費內容嗎」「用兌換碼嗎」「列車包不能先用 app 鎖著嗎」「開發版不能先鎖東西嗎 然後我輸碼解鎖」，要五方建議後回「好 照你的做」。遊戲規劃 session_014rYHMtmqA5bEMkBBuKu6PV。號碼依 #231：決策 338；存檔版本、golden schema 不動。

**規則**：

- **列車包**（`TrainPack`，GamePresentation）是一份 3D 列車 set 的清單，現在只有三節都市電聯車（`threeCarUrban`，決策 331 續四）。之後的新車一台一台加進清單。
- **沒解鎖時**，包裡的 set 畫成它出現以前的樣子：三節沒有車種的通勤電聯車照舊畫 `commuter`（`Map3DModelPack.locked`，`Map3DTrainSet.set(forKey:count:locked:)`）。包外的車不受影響。
- **只換外觀**：速度、座位、票價、存檔、GameCore 都不看列車包。一份存檔拿到沒解鎖的裝置上，只是車畫成一般的樣子。
- **現在怎麼解鎖**：設定裡「測試」區的「列車包」開關，只在測試版出現（Xcode 的 Debug 版，或 TestFlight 的版本：收據是 `sandboxReceipt`）。App Store 的版本看不到開關，就算裝置上留著打開的值也不算（`TrainPack.isUnlocked(testBuild:switchOn:)`）。
- **上架前**（作者決定要賣時）：開關換成 Apple 的內購（一次性購買的商品），加「恢復購買」；送人用 App Store Connect 的兌換碼（offer codes）。在 TestFlight 裡購買走測試環境，不扣錢。

**為什麼不做的事**：

- **自己的兌換碼**：App Store 審查準則 3.1.1 不准用自己的機制（序號、QR code 等）解鎖數位內容；而且這個 repo 是公開的，碼寫進程式誰都看得到。
- **送審版本留著測試開關**：TestFlight 的版本就是送審的版本，審查員也走測試環境，看得到開關。所以上架前一定要把開關換成內購，見下面「上架前要做的」。

**五方理由**：

- 玩家：已經在遊戲裡的綠色電車、兩節綠色電聯車不收回；鎖的是還沒人看過的新車，沒解鎖的人看到的仍是完整的車。只換外觀，不會變成付錢才贏。
- 鐵道迷：輕型捷運要看起來是輕軌（決策 331），所以綠色電車不放進包裡；包裡是「多一款車型」的收藏。
- 開發：鎖只在畫面這一層選模型時看一份清單，GameCore、存檔、golden 不動；Linux 測試鎖住鎖上與解鎖時每節畫什麼；開關之後換成 StoreKit 時只換 `isUnlocked` 的來源。
- 美術：沒解鎖時畫的一般通勤車樸素但完整；新車照同一套配色一批批加，包會越來越豐富。開關放在設定的「測試」區，不在主畫面。
- 音樂：無。

**沒有選的做法**：

- **三台新車全鎖**：會把輕型捷運畫回大型捷運，也會收回已經給出去的東西。
- **街景套件（公園、廟、商店）也鎖**：免費的城市會變空。
- **測試版用輸碼解鎖**：公開 repo 裡的碼不是秘密，做法比開關多，上架時一樣要拆掉。
- **現在就接 StoreKit**：還沒有商品、價格與付費 App 合約，接了也測不到真的商品。

**上架前要做的**（寫在 `docs/HANDOFF.md` §3）：

1. 作者：App Store Connect 簽付費 App 合約、填稅務與銀行資料；建一個一次性購買的商品「列車包」，訂價格。
2. 程式：接 StoreKit 2（`Product.products`、`purchase()`、`Transaction.currentEntitlements`），設定裡的開關換成「購買」與「恢復購買」；`TrainPack.isUnlocked` 改看購買紀錄；測試開關拿掉。
3. 送審前確認 App Store 的版本沒有「測試」區。

**驗證**：Linux 的 `TrainPackTests`、`Map3DTrainSetTests`（**VERIFIED**）。設定的開關、TestFlight 的判斷與 3D 裡換車要 iOS 上看（**UNVERIFIED LOCALLY**，`ios-build.yml` 編譯；實機等 TestFlight）。
