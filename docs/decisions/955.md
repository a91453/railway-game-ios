### 955. 軌道系統的建造介面：鋪軌先選系統、車種選單照相容表、3D 改讀軌道的系統

2026-11-24，雲端工作串 TRACK-SYSTEM-UI，分支 `claude/track-system-ui`，協調者第 3 任派工。決策 951 的第二張 PR（`docs/handoff/TRACK-SYSTEM.md`「第二張 PR」1–5 項）。號碼依 #2118 的登記：決策 955；存檔版本、golden schema、重播檔都不動。

## 1. 做了什麼

1. **3D 換來源**：`Map3DGuideway.edges(in:)` 改成讀每段軌道的 `TrackEdge.system`（`Kind` 對 `TrackSystem` 一對一，`Kind.init?(_: TrackSystem)`），不再從路線上的車推。沒有車的梁也畫成梁；舊存檔混跑而留在一般軌道的導軌車照決策 947 站在鋼軌上。`Map3DGuidewaySignature` 改成「是梁的那些段與它們的系統」，所以車來來去去不再重建場景，蓋了一段梁才重建；`Map3DSharedBuild` 的快取鍵只剩軌道的記號與這個簽名。
2. **鋪軌先選系統**：鋪軌工具的第一顆按鈕是「軌道種類」選單（一般軌道、跨座式單軌梁、磁浮軌道梁、懸吊式單軌梁，`TrackSystem.offered`）。選梁時，結構若是「自動」或「地面」就改成「高架」；再選回一般軌道時，若是因此改成高架的就還原成「自動」；玩家自己指定的結構（例如隧道）不動（`GameSession.chooseNetworkSystem(_:)`）。
3. **指令帶 `system`**：`PlayerCommand.TrackStretch.system`（`TrackSystem?`），紀錄檔欄位 `"system"`，只在有指定時寫；沒有這個欄位的舊紀錄讀成 `nil`，照決策 951「跟著接上的軌道」，所以 `ReplayFixtures/` 不用重錄。鋪軌工具總是帶玩家選的系統；複線的第二條帶同一個系統（`ChainSegment.system`，從指令或既有的軌道讀）；平面交叉切開的兩段帶原本的系統。其他工具（月台線、渡線、待避線、機廠、平交道）照舊不指定，接在梁上就蓋出梁。
4. **預覽報梁的價錢**：預覽在草稿世界裡真的蓋一次，所以總價已含梁的倍數；「縱斷面與費用」多一列「軌道梁」（`TrackCostParts.guideway`），零就不列。
5. **平面交叉先說**：梁和別種軌道在同一高度相交時，預覽直接說「軌道梁和別種軌道不能在同一高度交叉。請把這段改成高架或隧道，從上面或下面越過。」，不再去試平交道（決策 887 的平交道會讓兩者共用節點，GameCore 拒絕）。選了梁時，選單下方一直有一行說明：只有哪種車跑得上去、只接同一種梁、不能平面交叉（`networkSystemNote`）。
6. **車種選單**：列車已配屬路線時，改車種選單只列那條路線的軌道載得動的車種（`GameWorld.runsOnTrack(_:ofLine:)`，照 `TrackCompatibility`）；路線補車的選單同樣（`trainTypeCardChoices(forLine:)`）。路線在梁上時「依路線預設」補的是那種梁的車（`lineStaffingPlan` 的預設）。沒配屬的車照舊列全部，車自己的車種總是列著。
7. **先蓋梁的提示**：把車改成導軌車種、而公司還沒有那種梁時，訊息後面多一句「它只能跑自己的軌道梁：請先在鋪軌工具選「…」蓋梁。」（`guidewayFirstHint(for:in:)`）。

## 2. 幾個判斷

- **鋪軌工具總是帶選的系統，不送 `nil`**：玩家選了一般軌道卻從梁的端點畫出去，會被拒絕並看到決策 951 的那句話，而不是默默蓋成梁。「選什麼就蓋什麼」比「有時跟著接上的軌道」好懂。其他工具不讓玩家選系統，所以跟著接上的軌道。
- **選單放在第一顆按鈕，不收在「選項」裡**：交接說「先選」；收起來玩家看不到能蓋梁。用文字選單，不畫新圖示（art-style 不用動）。
- **平面交叉的檢查放在預覽**：只要被擋下的那段和要畫的系統不同就先說，比讓平交道去試、再給一個一般的「和軌道衝突」好。
- **沒配屬的車列全部**：車庫裡的車還沒有路線，不知道會跑哪裡；配屬時 GameCore 會擋，訊息已在決策 951。

## 4. 五個角度

| 角度 | 理由 | 分數（1–5） |
| --- | --- | ---: |
| 玩家 | 鋪軌時就能蓋梁、看得到梁的價錢；選單只列跑得了的車；不能接、不能交叉在畫之前就說 | 4 |
| 鐵道迷 | 建造時就分清是哪一種系統；梁預設高架，像真實的單軌 | 4 |
| 開發 | 邏輯都在 GamePresentation、有 Linux 測試；舊紀錄不用重錄；存檔、golden 不動 | 4 |
| 美術 | 梁的外觀照決策 947；沒有車的梁也畫成梁；沒有新圖示 | 3 |
| 音樂 | 無 | 1 |

### 沒選的選項

- **選一般軌道時送 `nil`（跟著接上的軌道）**：紀錄檔和以前完全一樣，但「選一般卻蓋出梁」不好懂。
- **系統收在「選項」裡**：卡片短一列，但玩家找不到。
- **畫四個系統的圖示按鈕**：要新畫圖、過 art-style 的審查；文字選單已經說得清楚。

## 6. 留下的

- **收購真實路線鋪成梁**：遊戲裡沒有單軌、磁浮的真實路線可買（那霸單軌在決策 854 沒選）。等有了路線資料，`RealLineAcquisition` 鋪線時帶 `system`。
- **型錄（`RollingStockCatalog`）**沒有依路線過濾：從型錄幫路線選了不合的車，補車時 GameCore 會擋並說明。
  - **後記（2026-11-24，CATALOG-TRACK-FILTER，REVIEW-L34 P2-1＋P3-5）已做**：`RollingStockCatalog(world:line:)` 只收 `runsOnTrack` 為真的車種（含決策 515 的山岳軌道），列車卡（車在線上時用它的線）、整線換車、補車打開的全螢幕型錄都帶線；跑不了時也不列標準車。有濾掉時列表上方寫「只列這條線的軌道跑得了的車種。」，濾完沒有車種時寫「沒有車種跑得了這條線的軌道。」。車隊的「配屬到路線…」（`assignToLineChoices`）也只列這列車跑得了的線。從車隊型錄買車（沒有線）照舊全部列出。不動 GameCore、存檔、golden。測試 `CatalogTrackFilterTests`。
- **追真實鐵路（`RealRailwayTracing`）**的段不帶玩家選的系統（真實路線都是鋼軌），從梁的端點追會被擋。
