### 801. 管制關著時，不禮讓一列自己正被擋著的後車（機廠裡三方互等）

2026-11-16，雲端 session，分支 `claude/day2-dispatch`，派工 DAY2-DISPATCH（HEALTH-134 §3 的退步）。改的是決策 228（管制關著時的行車間隔）的一個條件。

存檔版本不動（107，不存新欄位）；golden schema 不動；`GoldenScenarios/`、`ReplayFixtures/` 與既有 `SaveFixtures/` 一個值都沒變。新增一個存檔 fixture（`SaveFixtures/v107-depot-ladder-ring.json`，格式就是 107，放的是出事前六分鐘的世界）。

## 1. 現象

HEALTH-134 §3：簡化規則的「機捷舊線不動」（決策 605 之前的時刻表買下機捷、管制開著跑一天、半夜兩點把行車管制關掉），關掉後的第二天 333 班有 318 班沒發；133（`49fffa3`）是 0。死結偵測報 0（它只在管制開著時看）。

## 2. 是哪一張帶進來的

- `main`（`76e4d5d`）照 HEALTH-134 §3 的指令：**318/333**（debug 建置，和 release 的數字相同）。
- 同一個 `main` 只把 #2289 的 `turnOwedToHeldAfter` 從 60 改回 0（等於還原 #2289 的條件）：**0/333**（另一個工作目錄，同一台機器）。
- 所以觸發的是 #2289（決策 784）。但 #2289 的規則只在管制開著時生效，出事時管制已經關了一天多：它只改了第一天誰先走，之後每列車的位置、編號與班次的配對都跟著不同，第二天清晨剛好有三列空車在蘆竹機廠裡同時碰上。**毛病在決策 228 的規則本身**，133 的 0 是剛好沒碰上。

## 3. 根因

管制關著時，有班次的路線照決策 228 讓列車互相保持距離（`RunSpacing.swift` 的 `heldUp`）。其中三條：

1. 正要離開月台（機廠的停放股也算）的車，後面同方向、會在下一站前追上它的車，先讓它過（待避）。
2. 要進入和對向車共用的軌道時，對向車已經在上面、或離得比較近，就等。
3. 已經在共用軌道上的照走。

決策 228 寫「兩列車不會互相等」，這對**兩列**成立。第二天 05:46，蘆竹機廠的梯形咽喉（進出共用一條）：

- **6 號**（出庫往長庚醫院，還在停放股上）照第 1 條禮讓後面梯線更裡面的 **13 號**（出庫往體育大學，估計會追上它）；
- **13 號**照第 2 條等迎面入庫的 **12 號**（從機場第一航廈回來，離梯線比較近）；
- **12 號**照第 2 條等 **6 號**（6 號離梯線比 12 號近）。

三列各等下一列，永遠不動。05:57 起再捲進 5、8、18 號（五列一圈）。之後每一班要出庫的空車都排在後面出不來，長庚醫院、山鼻等站等不到車，整天 318 班過了最晚發車時間被放掉。

用 `heldUp` 每分鐘問每一列站著不動的車「被誰擋著」印出來的（探針已拿掉）：

```
05:47  T6  778-  heldBy T13 clear 0
       T12 763+  heldBy T6  clear 0
       T13 784-  heldBy T12 clear 0
```

## 4. 假說與結果

| 假說 | 預測 | 結果 |
| --- | --- | --- |
| A. 管制關掉時（`setTrafficControl(false)`）留下不合法的狀態（半條進路、停在站外的空車） | 關掉後第一天就出事 | **推翻**：關掉後第一天 0 班沒發，出事在 28 小時後 |
| B. 收班後車停在不能接早班的位置（方向反了，管制關著時 `driveRun` 不會中途折返） | 站上有車但 `runTrip` 是 `nil`，機廠照樣派得出車 | **推翻**：車是關在機廠裡出不來，不是站上的車接不了班 |
| C. 出入庫的空車在機廠咽喉迎面互等 | 站著的車在機廠的邊上、`heldUp` 互指 | **證實**，但不是兩列迎面，是三列一圈（第 3 節） |
| D. 還原 #2289 就不會出事 | `turnOwedToHeldAfter = 0` 回到 0/333 | **證實**（0/333），但它是觸發，不是根因（第 2 節） |

## 5. 規則

`heldUp(_:within:near:ways:yielding:)` 的待避那一條加一個條件：**要禮讓的那列後車，自己正被第三列車擋到一步都走不了（`clear == 0`，而且擋它的不是我）時，不禮讓。** 它不會追上來；等它只會把圈接起來。問後車「被誰擋著」時不再套待避（`yielding: false`），所以不會遞迴。

其他都不變：後車真的在跑（或只是被前車壓著慢慢跟）時照舊待避；對向的兩條不動；管制開著時這段程式本來就不執行（`heldUp` 一開始就 `guard !isTrafficControlEnabled`），所以簡＋控、擬實的每一格逐位元相同。不存任何東西，從那一刻的世界推，批次與逐分一樣。

## 8. 五個角度

- 玩家：把行車管制關掉的人，不會再遇到整條線的車關在機廠裡出不來。
- 鐵道迷：待避是讓「正在追上來的車」先過；後車自己被號誌擋在機廠裡時，站務不會叫前面的車等它。資料來源：無（規則）。
- 開發：一個條件、一個參數；管制開著的世界逐位元不變；多一個 0.7 MB 的存檔 fixture（也被 `SavedGameTests.testEveryCommittedSaveStillLoads` 讀）。
- 美術：無。
- 音樂：無。

沒採用的做法：

- (a) 每分鐘在 `assessSpacing` 裡找互等的圈、放掉編號最小的一列：要定義放掉之後誰能安全先走（對向的兩列不能同時放），等於重寫決策 228 的對向規則；這次的圈每一個都經過待避那一條，先修它。
- (b) 機廠的停放股不算「正要離開月台」：機廠接在正線上時，空車出庫禮讓正線上追上來的班次是對的，會把它也拿掉。
- (c) 兩列都還沒離開月台時不禮讓：會改到高鐵示範裡慢車在待避線讓同時停站的快車先走。

## 9. 找過什麼

- 作者的參考 repository：`Railway/site_archive_clean/index.html` 的 `updateBlockHolds` 只有同方向後車延後（決策 228 已記），沒有待避或對向的規則，也沒有互等的處理。沒有可以搬的。
- 外面的專案：OpenTTD（GPL-2.0）用路徑號誌的保留解這類互等，只讀想法；這裡管制關著就是沒有保留，不適用。程式是這個專案自己的。
