### 488. 拖曳放置建物時，預覽不再在世界副本上整個蓋一次，一個位置只算一次

2026-10-29，遊戲規劃第 31 任（session_01YGNNukxseY7eMCvXhjtc4X）派工（派工單 BLD），實作 session_01YGNNuoJrjdfniv6NV8wn7e（`claude/building-placement-drag-perf`）。GameCore 只加一個不改世界的試算；遊戲結果、存檔版本、golden schema、replay 都不動。

**為什麼**：作者在 95.1 真機（iPhone 橫放，2D 地圖，6000× 暫停中）用建設 → 建物 → 商店在地圖上拖曳位置，確認鈕的金額跟著變，fps 掉到 11–50，最長一幀 1,411 ms。幀時間面板的「地圖」每次 100–210 ms，「其他」177–1,411 ms，畫面更新只有 0.1–0.4 ms/s。

**根因**：`GameSession.buildingPreview` 是計算屬性，每讀一次都複製世界（`pricingCopy`），在副本上真的 `placeBuilding`。蓋的時候若拆到城市建物（或照面積收購），會刪土地格、把整張地圖各站的需求重算一次（`refreshLandDemand`，大約是土地格數 × 車站數），還會複製整個土地格陣列。拖曳時位置每幀都變，而地圖的建物圖層（`buildingOverlay`，算在「地圖」裡）、建造卡、卡上文字（`buildingPreviewText` 又讀一次）、確認鈕是否可按、鈕上金額、教學提示，每次畫面更新各讀一次，一幀要算 5–9 次。實機「其他」大約是「地圖」最長一次的 6–9 倍，與讀的次數相符（推論：作者的存檔沒有附上，無法在 Linux 重跑同一張地圖）。

**做了什麼**：

1. GameCore：`GameWorld.buildingPlacement(_:at:look:)` 回答 `placeBuilding` 會蓋出的建物（編號、造價、搬進的居民與工作）或丟出的錯誤，**不改世界**。`placeBuilding` 改成先呼叫同一段檢查與計價（`placement(of:at:look:)`），再做原本的扣款、刪土地、重算需求，所以兩者不可能不一致；錯誤的檢查順序不變，錢不夠在算完價格後檢查，和原本 `economy.spend` 的位置相同。
2. GamePresentation：預覽改用 `buildingPlacement`，並以（`worldRevision`、位置、種類、外觀）為鍵記住結果（`buildingPreviewMemo`）。暫停時拖曳，一個位置只算一次；遊戲在跑時每個 tick 換新的 revision 才重算，與以前一樣跟著現金與土地變。
3. 吸附空隙（決策 144 的 `snappedBuildingSite`）最多試 8 個位置，也改用 `buildingPlacement`，放手時不再重算 8 次需求。
4. 幀時間面板加「建物預覽」（`FrameCostPart.buildingPreview`）：在主執行緒、不屬於別的項目，所以從「其他」扣掉；之後再有拖曳掉幀，看得出是不是它。

**量到的**（Linux release，`BUILDING_DRAG_REPORT=4`，苗栗實景 44 站、約 39,000 個土地格，每站周圍 6 個位置共 66 個，10 個會收購城市建物）：

| | 平均 ms | 最長 ms |
| --- | --: | --: |
| 以前每讀一次：副本上 `placeBuilding` | 0.69–0.93 | 4.5–6.2 |
| 現在每個位置一次：`buildingPlacement` | 0.14–0.15 | 0.34–0.40 |

每讀一次最長快 11–15 倍，一幀讀的次數從 5–9 次變 1 次。實機上土地格與車站更多時，舊算法的需求重算跟著變大，新算法不做這件事。

**五個角度**（選項：A 不改世界的試算加記住結果；B 只記住結果，每個位置仍在副本上整個蓋一次；C 拖曳中降頻，停下才算精確造價）：

- 玩家：A 拖曳時確認鈕的金額每一步都是精確的，而且不卡；B 每步仍可能 100 ms 以上；C 拖曳中金額會落後或不顯示。
- 鐵道迷：無。
- 開發：A 的試算與真的蓋走同一段程式，`BuildingPlacementTrialTests` 掃過上千個位置比對兩者完全相同；B 最小但沒有修到每次的成本；C 要另外處理「停下」的時機。
- 美術：無。
- 音樂：無。

**驗證**：`BuildingPlacementTrialTests`（GameCore，試算與真的蓋在一般收購、照面積收購、錢夠與不夠時結果相同）、`BuildingDragPreviewTests`（拖曳一步只算一次，與重算相同，世界、種類、外觀變了就重算）、既有的建物測試。實機改善 **UNVERIFIED**，要在下一版 TestFlight 用同樣的操作看幀時間面板。

**下一步**：實機拖曳時看「建物預覽」與「其他」；按下建造後那一次（畫面更新 127 ms、地圖 211 ms）是真的蓋好、重算一次需求與重畫，這次沒有改，若實機仍明顯再量。
