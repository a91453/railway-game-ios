### 715. 定期貸款：與決策 67 的貸款並存（規則與存檔；畫面另一個 PR）

2026-11-13，派工單 TERM-LOAN（作者 Mac 的本機 session，作者直接交辦），分支 `claude/term-loans`。存檔版本 93；golden schema 不動（`GoldenScenario` 的結果名多一個 `invalidTermLoan`，沒有 fixture 用到）；既有的 `SaveFixtures/`、`ReplayFixtures/`、`GoldenScenarios/` 一個值都沒變。

## 1. 為什麼

決策 67 的貸款上限固定 NT$15,000,000（決策 499），公司做大以後幾乎用不到。作者自己的桌面版鐵路模擬（私人專案，不在三個 repository 裡；作者 2026-11-13 確認規則是自己設計的）有一套定期貸款：額度跟著公司的淨值走，年期越長利率越高，利息簽約時就固定，提前還要付違約金。作者要把它搬進來。

作者從五個角度比過「並存」與「取代決策 67」，選並存：

| 角度 | 並存 | 取代 |
| --- | --- | --- |
| 玩家 | 銀行多一種商品：隨借隨還的週轉，與金額大、要選年期的定期 | 只剩一種，但少了臨時借一點的便利 |
| 存檔 | 沒借過定期貸款的存檔一個位元都不變 | 玩家存檔裡的貸款要轉換 |
| 平衡 | 補上「額度與公司規模無關」的缺口 | 也補得上，但現有數值要重調 |
| 開發 | 純新增，既有測試與基準不該動 | 既有測試、基準、教學都可能要改 |
| 上架 | 可以分段合併 | 要整套完成才能發版 |

## 2. 規則（`Sources/GameCore/Economy/TermLoans.swift`）

1. **合約**（`TermLoan`）：本金是 `CompanyAccounts.loanStep`（NT$300,000）的整數倍；年期 1–10 年，一年 360 天（`FinancePeriod.year`）；利率與整期利息簽約時固定。到期日 = 簽約日 + 年期 × 360。
2. **利率**（`termLoanRate(years:)`，萬分之一為單位）：基準 5.00%（`termLoanBaseRate`，與決策 67 相同）× 年期係數 100、102、104、106、108、110、114、118、122、126（%），所以 1–10 年是 5.00%、5.10%、5.20%、5.30%、5.40%、5.50%、5.70%、5.90%、6.10%、6.30%。
3. **利息**（`termLoanInterest`）：每年 = 本金（整元）× 利率，無條件捨去到元；整期 = 年數 × 每年。NT$3,000,000 借 2 年：每年 NT$153,000，共 NT$306,000。
4. **額度**（`termLoanCredit()`）：上限 = （資產負債表的淨值 − 定期貸款還沒付的利息）的一半，捨去到元；「還沒還的本金加利息」加上新本金要**小於**上限。最多同時 50 筆（`termLoanSlots`）。淨值已經扣掉決策 67 的貸款與定期貸款的本金，所以借了不會讓額度變大。
5. **借**（`takeTermLoan`）：只有經營模式（`loanNeedsManagement`）；金額、年期、額度不對是 `invalidTermLoan`。餘額加本金，記成當天的借入（`CapitalDay.borrowed`，與決策 67 同一欄）。`termLoanQuote` 是同一套計算，不改世界：畫面先給玩家看，再確認。
6. **到期**（`settleTermLoans`，在每日結算裡、決策 67 的利息之後、所得稅之前）：到期日開始的那個午夜一次付本金與整期利息；餘額可以變負（與當天其他成本一致）。本金記成償還，利息寫一列 `dailyInterest`（項目 `loanInterest`），所以進財報的「利息」，不是營運成本。自由模式不做每日結算：到期的貸款等回到經營模式後的第一個午夜付。
7. **提前還**（`repayTermLoanEarly`，報價 `termLoanRepaymentQuote`）：利息 = 已過天數的利息（整期利息 × 已過天數 ÷ 總天數）+ 剩下的 20%（`earlyRepaymentPercent`），各自捨去到元，合計再捨去到 NT$100。要有錢（`insufficientFunds`）。自由模式也能還（與決策 67 一致），不寫帳。超過到期日才還（上一條的自由模式）付整期利息，不多不少。
8. **資產負債表**：`BalanceSheet.termLoans` 是還沒還的本金；`equity = totalAssets − loan − termLoans`。年結的資產負債表照樣留著。
9. **讀檔檢查**（`termLoansProblem`）：最多 50 筆、ID 照簽約順序且都小於 `nextTermLoanID`、本金是整步、年期 1–10、利率與利息等於該年期算出來的、簽約日不晚於今天。

## 3. 來源對照

| 來源（作者的桌面版，`RailCore`） | 這裡 |
| --- | --- |
| `LOAN_TERM_FACTORS` | `CompanyAccounts.termLoanFactors`（數值相同） |
| `AnnualFinance.loanQuote` | `CompanyAccounts.termLoanRate`、`termLoanInterest`、`GameWorld.termLoanQuote` |
| `AnnualFinance.earlyRepaymentQuote` | `GameWorld.repaymentQuote(of:on:)`（除法與捨去的順序相同） |
| `CalendarFinanceEngine.availableCredit`、`quoteBorrow`、`borrow` | `termLoanCredit`、`termLoanQuote`、`takeTermLoan` |
| `quoteRepayment`、`repayEarly` | `termLoanRepaymentQuote`、`repayTermLoanEarly` |
| `closeDay` 裡到期的那一段 | `settleTermLoans` |

**刻意不同的地方：**

- **日期**：來源用西元日期字串（閏年 2 月 29 日借的到期日順延到 3 月 1 日）；這裡用遊戲日，一年 360 天，沒有閏年。GameCore 不用 Foundation。
- **金額**：來源是「現金單位」的整數；這裡是 `Money`（分），利息以整元計算，捨去的位置與來源相同。
- **本金**：來源任意正整數；這裡是 `loanStep` 的整數倍，與決策 67 一致，畫面好做。
- **基準利率**：來源是 0.01%–7.99% 的輸入，會跟著景氣指數走（`nextRateIndex`）；這裡沒有景氣指數，固定 5.00%。合約存了簽約時的利率，之後基準會變動時不用改存檔。
- **淨值**：來源用它自己的資產評價與待繳稅；這裡用現成的資產負債表（決策 85、94、160）。
- **已還的合約**：來源留著標成已付；這裡移除，ID 由 `nextTermLoanID` 保證不重複。
- **報價後確認時再核對一次時間與總額**：來源的畫面與核心是分開的行程，要核對；這裡畫面同步呼叫，不需要。

## 4. 存檔（版本 93）

`accounts.termLoans`、`accounts.nextTermLoanID` 與年結資產負債表的 `termLoans` 都只在有值時才寫，所以沒借過定期貸款的世界寫出的 JSON 與之前相同。升版本是因為只讀舊版本的 build 會把合約丟掉，借來的錢就不欠任何人了。新 fixture：`SaveFixtures/v93-term-loans.json`（一筆 2 年的借了一年、年結留著、再借一筆 10 年的；讀回來跑一年，第一筆到期付掉，與原世界相同）。

## 5. 限制與下一步

- **還沒有畫面**：這個 PR 之後玩家還借不到。下一個 PR：經濟面板加定期貸款的清單、金額與年期、報價與確認、提前還款，中英文；資產負債表多「定期貸款」一列（`FinancialStatements`）；到期與提前還的那一列目前顯示成「利息」，要不要另給名字到時決定。
