### 684. 鐵道博物館第一步：一座自己蓋的景點，展示公司擁有過的車種

2026-11-11，派工單 MUSEUM（session_01YGNNumVW942N5M7kesb61Z，遊戲規劃第 60 任派），分支 `claude/museum-684`。NEXT_PRIORITIES §25 第 1 名（3.70）。這張單只做設計與規則，畫面接到最小可用；館舍與展示車輛的 3D、新圖示、館內瀏覽是第二步（見「下一步」）。存檔版本 86 → **87**；golden schema（76）與 ReplayFixtures 不動。

## 1. 玩家怎麼蓋、花多少、佔多少地

- 「建設 › 建築」的清單多一種**鐵道博物館**（`PlacedBuildingKind.railwayMuseum`），和廟、夜市同一條路：`GameWorld.placeBuilding(_:at:)`，先試算再蓋，失敗時世界不變。沒有新的指令。
- **一張地圖只能蓋一座**：已經有一座時 `placeBuilding` 丟 `GameError.museumAlreadyBuilt(那一座的 id)`，畫面說「你的公司已經有一座鐵道博物館，一張地圖只能蓋一座。」賣掉之後可以再蓋，但展示的車種跟著館舍走，新館從公司當時擁有的車種重新開始。
- **地與造價**：64 m 見方、兩層（廟是 32 m 兩層，百貨 48 m 八層）。造價照決策 361 的算法：樓地板 8,192 m² × NT$120 ＝ NT$983,040，加上那塊地的地價與拆遷。量測用的第一條線終點站旁，連地一共 NT$6.56 百萬（同一塊地上的廟 NT$4.93 百萬）。選地的限制（不壓軌道、車站、別的建築，不在水上）和其他自有建築一樣。
- 維持費與房屋稅照自有建築的規則，賣掉拿回的錢也一樣。

## 2. 展示哪些車

- 展示的是**公司擁有過的每一種列車**（`TrainType`，圖鑑裡的車種），每種一件：`PlacedBuilding.exhibits`，照圖鑑的順序。
- 蓋的那一刻收進公司當時擁有的車種；之後每天午夜（當天的遊客算完之後）把新買的車種收進來，所以買了沒擁有過的車，**隔天**進館。
- 車賣掉了，展品留著：真實的博物館展的就是退役的車。
- 沒有車種的「標準車」不算展品。
- 不拿走營運中的車、不另外花錢買展品：第一步不讓玩家為了展示少一列車跑。

## 3. 怎麼吸引觀光客

- 博物館是**公司的景點**（決策 361 的 `companySights()`），名字「鐵道博物館」，不在景點目錄裡、ID 是負的館舍 ID，所以沒有紀念品店可蓋、不會被劇本目錄改掉。
- 星等：空館 **1.5★**（地方文物館的大小），每一種展品 **+0.15★**，算到 **12 種**為止，最高 **3.3★**（`Tourism.museumStars(exhibits:)`）。旁邊的飯店（每間 +0.25★，兩間為止）與停靠的觀光列車（決策 286）照一般景點加，五星封頂。
- 遊客數照決策 174 的公式：星等對應的潛在遊客 × 平假日 × 季節 × 天氣 × 搭車比例 20%，而且要有車站在 800 m 內、有班次能到。遊客搭玩家的車來，所以也是票收。
- 同一站旁的廟或夜市不分它的遊客（決策 361 只在同種之間分）。

## 4. 和現有景點、紀念品店、子公司的關係

| 既有的 | 關係 |
| --- | --- |
| 目錄景點（老街、溫泉…） | 互不影響；博物館是另一個景點，在觀光面板同一張清單裡照星等排 |
| 紀念品店 | 博物館不能蓋紀念品店；它自己的門票與館內商店就是收入 |
| 飯店 | 博物館旁的飯店加它的星等，飯店也有它的過夜客，和其他景點一樣 |
| 觀光列車 | 停在博物館那一站會加星等 |
| 一日券 | 博物館的客人只算它自己的遊客（和廟一樣），持券逛站的人不另外加進來；一日券的規則不變 |
| 廟、夜市（決策 361） | 同一種機制、同一列帳；博物館多了「展品」與「只能一座」 |
| 圖鑑 | 圖鑑照舊；第二步的館內瀏覽沿用圖鑑的 3D |

## 5. 每天的收支

- 每位遊客花 **NT$150**（`SubsidiaryRules.museumSpend`）：國家鐵道博物館全票 NT$100，加一半在館內商店與咖啡。
- 變動成本 **50%**（導覽、商品進貨）。
- 人事：造價的 0.04%／天（所有子公司一樣）。
- **展品維護：每件 NT$1,000／天**（`museumExhibitUpkeep`），只算計入星等的前 12 件；有沒有人來都要付。
- 記在子公司那一列帳（`dailySubsidiary`：銷售與成本），館舍自己的帳（`books`）在建築卡片上。只在經營模式結算。

## 7. 存檔

- `PlacedBuildingKind` 多一個值 `"railwayMuseum"`，館舍多一個欄位 `exhibits`（車種名稱的陣列，照圖鑑順序，空的不寫）。
- 讀檔時檢查：只有博物館能有 `exhibits`；要照圖鑑順序、不重複；一個世界最多一座博物館。
- 舊版讀不了新的建築種類，所以升到 **87**；86 以前的存檔沒有博物館，照舊讀進來，沒有要轉的東西。新 fixture `SaveFixtures/v87-railway-museum.json`（`RailwayMuseumTests.testVersionEightySevenKeepsTheMuseum`）。

## 10. 五個角度

- 玩家：買過的車有地方看、有用處；多買一種車，隔天博物館就多一件展品、多一點遊客，是收集的理由。只能蓋一座，選地點有份量。
- 鐵道迷：展的是退役也留著的車，和真實的鐵道博物館一樣；票價照國家鐵道博物館的全票。星等封在 3.3★，不壓過真實的名勝。
- 開發：沿用決策 361 的自有景點與子公司帳，沒有新指令、沒有世界層級的新狀態；一個建築種類、一個欄位、一個錯誤；存檔升一版、空的轉換。
- 美術：這一步不畫新圖，卡片、地圖記號、3D 都暫用百貨的；館舍與展示車輛的樣子留給第二步在 Mac 上做。
- 音樂：無（沒有新的聲音；蓋好時沿用蓋建築的回饋）。

## 11. 沒選的做法（留著給作者看）

| 做法 | 為什麼沒選 |
| --- | --- |
| 展品要玩家捐出一列車（從營運拿走） | 第一步就讓玩家少一列車跑，新手會不敢蓋；可以在第二步當成「特別展示」另加 |
| 展品數照「現在擁有」算，賣掉就下架 | 鼓勵留著不用的舊車佔機廠；真實的博物館展的正是退役車 |
| 博物館放進景點目錄（`Attraction`） | 目錄是地圖給的、劇本會整份換掉；自有景點（決策 361）已經有館舍、帳、遊客數 |
| 另開一個指令與世界層級的 `museum` 狀態 | 多一份要驗證、要存的狀態；建築種類已經有位置、造價、帳與賣出 |
| 車越多館舍越大（佔地變大） | 蓋好的建築改大小要重算佔地與鄰地；先用展品維護費表示，館舍大小留給第二步的外觀 |
| 每件 +0.25★、最高 4.5★、不收維護 | 量過：十二件 75 天回本（第 6 節） |
| 可以蓋很多座 | 參考（§1.7）就是一張地圖一座；多座會變成最划算的子公司 |

## 12. 已知限制

- 展品算「擁有過的車種」是從蓋館那天起算：蓋館之前賣掉的車種不會出現。
- 第 13 種以後的車照樣進館，但不加星等、也不收維護。
- 畫面上博物館長得像百貨（暫用）。
- 隨機 campaign（用 `PlacedBuildingKind.allCases` 抽的）抽到的建築會和以前不同；它們檢查的是性質，不是固定值。
