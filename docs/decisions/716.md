### 716. 玩家手動封閉／開放一段軌道

2026-11-13，派工單 CLOSE-TRACK（作者 Mac 本機；作者決定以這個版本為底，把自己桌面版鐵路模擬的規則一項一個 PR 搬過來，這是第 1 項），分支 `claude/close-track`。存檔版本 94；golden schema 不動；既有的 `SaveFixtures/`、`ReplayFixtures/`、`GoldenScenarios/` 一個值都沒變。這個 PR 只有 GameCore 的規則、存檔與測試，**沒有畫面**，玩家還按不到。

## 1. 規則

1. **封閉**（`GameWorld.closeTrack(_:)`）：把一條軌道邊關掉，不收費。這條邊上有車（車頭所在的邊，或車身壓到的邊）、有列車預約了它的任何一段、或有列車正在走的路徑還會經過它，就拒絕，世界不變，錯誤是 `trackReserved(列車)`，指出號碼最小的那一列。有沒有開行車管制都一樣。已經封閉的再封閉一次什麼都不變。
2. **封閉期間**：
   - 尋路不走它：`path(from:toStation:length:)` 與建在它上面的每一種搜尋（服務的預設路、指定月台、排定路徑、改道、讓車、回機廠、路線的行程 `lineJourney`），以及 `route(from:to:)`。所以沒有任何列車會預約到它。
   - 指令不能把車放上去、也不能給一條經過它的路徑（`placeTrain`、`setTrainContinuation` 等經過 `admit` 的指令）：新的錯誤 `GameError.trackClosed(邊)`，指出號碼最小的那條封閉的邊；有沒有開行車管制都擋。
   - 有別條路（迴避線、另一股道）時，列車把那條路當成自己的預設路，照常預約、照常會車。
   - 沒有別條路時，服務在停靠的車站等（和「找不到路的發車」同一條既有的路：這一次 `advance` 不再問，下一次再問），路線的列車留在站內；不算死結（`deadlockedTrains()` 是空的），服務不會被取消。
3. **開放**（`GameWorld.openTrack(_:)`）：隨時可以，不因列車而拒絕。下一步起尋路又找得到它，等著的列車自己出發、自己消化延誤。
4. 拆掉一條封閉的邊，封閉跟著消失；把封閉的邊切成兩段（`splitTrackEdge`），兩段都還是封閉的；車站咽喉沿線滑動（決策 691）把邊拿掉再放回時，封閉照舊。

## 2. 封閉的單位與放在哪裡

**單位是軌道邊（`TrackEdgeID`），記在軌道網路上：`RailwayNetwork.closedEdges`，照編號由小到大。**

讀過 `TrackResources.swift`、`BlockSections.swift`、`RouteReservation.swift`、`Deadlock.swift`、`ServicePath.swift` 之後的理由：

- 尋路只有一個核心（`ServicePath.swift` 的 `networkPath`），它一步走一條邊的一個方向。封閉以邊為單位，就是在那一步多問一句，其餘每一種搜尋都自動避開，不用一個一個改。
- **不用閉塞區間**：閉塞（決策 212）的邊界是每次從邊長與道岔位置算出來的，不存檔、沒有自己的編號，而且只有開了閉塞的世界才有；拿它當單位就得另外發明一種會隨鋪軌改變的識別。
- **不用 span（`TrackResource`）**：span 會隨月台增減重新切。封閉半條邊對尋路也沒有意義：邊中間沒有道岔，進得去就一定要走完或停在月台。
- **不當成「有一列看不見的車佔著」**：預約的結果是「被哪一列車擋住」（`Reserving.held(by:)`），等待、死結偵測、讓車都靠這個列車編號。沒有列車的封鎖塞進去，死結偵測會去找一列不存在的車。封閉的軌道不是被佔用，是不在地圖上，所以放在尋路那一層。
- **放在網路上而不是 `GameWorld` 的另一個欄位**：行車管制在兩次 `advance` 之間留著的東西（`RouteMemo`：路徑、路線行程、容量）是以「網路沒變」為鍵的；封閉記在網路裡，鍵自然就變了，不會拿到封閉前算的路。月台與間距豁免也是記在網路上的邊的註記，拆邊時一起處理。`closeTrack`／`openTrack` 另外把乘客的行程快取清掉。
- 作者的桌面版也是以邊為單位，兩邊一致。

玩家看到的「一段」多半是兩個道岔之間的一整段（`networkSections()`），那是好幾條邊；畫面那個 PR 可以一次送好幾個指令，規則不需要另一種單位。

## 3. 為什麼拒絕時用既有的 `trackReserved`

封閉被列車擋住時，回的是既有的 `trackReserved(列車)`，不是新的錯誤：它的意思本來就是「這列車佔著指令需要的軌道」，畫面已經會用它指出是哪一列車（`PlacementGuidance`、`LineRemoval`），玩家文字「有列車的路線要經過這段軌道，請等它通過。」也正好是該說的話。新的錯誤只有一個：`trackClosed(邊)`，給「指令要用到封閉的軌道」。

## 10. 續二：預約封閉（第三個 PR）

2026-11-13，派工單 PENDING-CLOSE，分支 `claude/pending-close`，疊在第二個 PR 上。存檔版本 95；golden schema 不動；既有的 `SaveFixtures/`、`ReplayFixtures/`、`GoldenScenarios/` 一個值都沒變。作者在第 9 節末段的問題之後決定先做這一項，再做單線公平輪流。

### 10.1 規則（取代第 1 節第 1 點的「拒絕」）

1. **封閉不再因為列車而拒絕。** `closeTrack` 現在收一組邊（`closeTrack(_: [TrackEdgeID])`；單一條邊是只有一條的那一組）。這組邊都沒有列車在用（`trainUsing(_:)`：站在上面、預約了它、或正在走的路徑還會經過）就立刻封閉，和以前一樣。有任何一條有列車在用，整組都記成「封閉中」（`RailwayNetwork.closingEdges`），一條都不先封。
2. **封閉中的邊**：
   - 尋路與指令把它當成已經封閉：不給新的路（`networkPath`、`route(from:to:)`），指令不能把車放上去或給一條經過它的路徑（`admit`，`trackClosed`）。
   - 已經拿到路徑的列車照走：路徑存在列車身上，不會重找。跟車的列車（Stage U2）只預約了前面一段，之後由 `extendAuthorities` 沿著**原來的路徑**一段一段往前要，那裡不尋路，所以不會卡在半路（測試 `testAFollowingTrainTakesItsPathOverTrackBeingClosed`：和沒封閉時逐分鐘走得一模一樣）。
   - **例外只有一個：從封閉中的軌道上出發的搜尋，可以走封閉中的軌道**（車頭所在的邊是封閉中；指令則看列車現在的車身有沒有壓在封閉中的邊上）。停在這一段中間的車站的列車，下一段路是到站後才找的；沒有這個例外，它會永遠停在封閉中的軌道上，這一段也永遠封不起來。
3. **什麼時候變成封閉**：`advance` 的每一步開頭，以及每次呼叫結束時，看封閉中的邊。在節點相接的封閉中的邊算一群；一群裡沒有任何一條還有列車在用，整群一起變成封閉。按群而不是按邊，是因為一段裡列車還沒到的那幾條如果先封，站在這一段裡的列車就沒有路出去了。
4. **開放**：封閉中或已封閉都一樣，立刻開放，不拒絕。取消封閉中的軌道之後，世界和沒按過一樣。
5. 切邊、拆邊、咽喉滑動：和封閉的邊同樣處理（兩段都還是封閉中；拆掉就消失；滑動後照舊）。

### 10.2 批次等於逐步

封閉中變封閉只讀列車與軌道網路，不讀時間與幾何。它發生在迴圈每一步的開頭、任何決定之前：批次裡列車離開的那個時段結束後的下一步開頭，逐步時是那一次呼叫的結尾，兩邊在下一個決定之前都已經封好。網路一變，這次 `advance` 借來與算出的東西（`DispatchMemo`、找不到路的名單、乘客的放行計畫）當場重來，和新的一次呼叫看到的一樣；不這樣做的話，從封閉中的軌道出發、先前快取下來的路可能經過剛封閉的邊。測試 `testBatchesAndSingleStepsAgreeWhileTrackIsBeingClosed`（四種速度）、`testAFollowingTrainTakesItsPathOverTrackBeingClosed`、既有的 `testBatchesAndSingleStepsAgreeAcrossAClosure`。

沒有封閉中的邊時多的成本是一次空陣列的判斷。

### 10.3 存檔

網路多一個鍵 `"closingEdges"`：封閉中的邊的編號，由小到大，**有才寫**。讀檔時不修、只拒絕：不存在的邊、順序不對、重複、同時在 `"closedEdges"` 裡。存檔版本 95：只讀舊版本的程式會把它丟掉、繼續讓列車開進玩家正在封閉的軌道，所以它要說「存檔比我新」。舊存檔不用轉換。新的 `SaveFixtures/v95-closing-track.json`；`v94-closed-track.json` 沒動、照樣讀得回來。

### 10.6 五個角度

- 玩家：幹線上按得下去了。按了之後看得到它在等列車、可以反悔；不會把車困在半路。
- 鐵道迷：對應真實的「預定封鎖」：先停止辦理進入該區間的進路，區間內與已經開出的列車走完，淨空後才封鎖。資料：無。
- 開發者：只多一份清單與每步一次的檢查；預約、跟車、死結的程式沒動。封閉中在尋路裡和封閉走同一個判斷，只多一個「從裡面出發」的例外。
- 美術：沿用地圖既有的琥珀（`metroAmber`）與牌子底色，沒有新圖示（SF Symbols 的 `hourglass`、`arrow.uturn.backward.circle`）。
- 音樂：無。

### 10.7 沒選的

- 把還沒到的列車的路收回、讓它改道或停下：會讓車停在道岔上，第 7 節已經不選。
- 封閉中的軌道一律不讓任何搜尋走（沒有 10.1 第 2 點的例外）：停在這一段中間車站的列車永遠出不去。
- 一條邊沒人用就先封那一條：同上，站在這一段裡的列車前面的路會先被封掉。
- 列車站著不動就不算在用、把它關在封閉的軌道裡：真實的封鎖要先淨空；而且之後對那列車下的指令都會被 `trackClosed` 擋。
- 另一種錯誤或回傳值告訴畫面「這次是封閉中」：畫面問 `isTrackClosing` 就知道，指令的格式不用變。

### 10.8 已知限制

1. **整條都在封閉範圍裡的路線封不起來**：列車每一段都是從封閉中的軌道出發、走到另一個也在封閉中的車站，永遠有人在用。例如沒有任何道岔的一條線，整條是同一段。卡片會一直顯示「列車通過後封閉」；把列車收掉或停開那條線之後它才會封閉。
2. **停著不走的列車**（沒有班次、停在這一段裡）會讓這一段一直是封閉中，直到玩家把它開走或賣掉。
3. 兩群封閉中的軌道在道岔相接時算同一群，要等兩邊都沒有列車才一起封閉。
4. 從封閉中的軌道出發的列車，可以經過另一處也在封閉中的軌道（例外不分是哪一群），那一處會多等它一列。
5. 3D 地圖還是沒有標示；因為封閉或封閉中而沒有路的列車，列車卡片上還是沒有寫原因（第 9 節留下的兩項）。
6. 高鐵、整個臺灣那種大地圖上只在模擬器上手動看過（PR 的 VERIFIED 一節），沒有自動測試。
