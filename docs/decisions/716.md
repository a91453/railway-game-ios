### 716. 玩家手動封閉／開放一段軌道

2026-11-13，派工單 CLOSE-TRACK（作者 Mac 本機；作者決定以這個版本為底，把自己桌面版鐵路模擬的規則一項一個 PR 搬過來，這是第 1 項），分支 `claude/close-track`。存檔版本 94；golden schema 不動；既有的 `SaveFixtures/`、`ReplayFixtures/`、`GoldenScenarios/` 一個值都沒變。這個 PR 只有 GameCore 的規則、存檔與測試，**沒有畫面**，玩家還按不到。

## 1. 規則

1. **封閉**（`GameWorld.closeTrack(_:)`）：把一條軌道邊關掉，不收費。這條邊上有車（車頭所在的邊，或車身壓到的邊）、有列車預約了它的任何一段、或有列車正在走的路徑還會經過它，就拒絕，世界不變，錯誤是 `trackReserved(列車)`，指出號碼最小的那一列。有沒有開行車管制都一樣。已經封閉的再封閉一次什麼都不變。
2. **封閉期間**：
   - 尋路不走它：`path(from:toStation:length:)` 與建在它上面的每一種搜尋（服務的預設路、指定月台、排定路徑、改道、讓車、回機廠、路線的行程 `lineJourney`），以及 `route(from:to:)`。所以沒有任何列車會預約到它。
   - 指令不能把車放上去、也不能給一條經過它的路徑（`placeTrain`、`setTrainContinuation` 等經過 `admit` 的指令）：新的錯誤 `GameError.trackClosed(邊)`，指出號碼最小的那條封閉的邊；有沒有開行車管制都擋。
   - 有別條路（迴避線、另一股道）時，列車把那條路當成自己的預設路，照常預約、照常會車。
   - 沒有別條路時，服務在停靠的車站等（和「找不到路的發車」同一條既有的路：這一次 `advance` 不再問，下一次再問），路線的列車留在站內；不算死結（`deadlockedTrains()` 是空的），服務不會被取消。
3. **開放**（`GameWorld.openTrack(_:)`）：隨時可以，不因列車而拒絕。下一步起尋路又找得到它，等著的列車自己出發、自己消化延誤。
4. 拆掉一條封閉的邊，封閉跟著消失；把封閉的邊切成兩段（`splitTrackEdge`），兩段都還是封閉的；車站咽喉沿線滑動（決策 691）把邊拿掉再放回時，封閉照舊。

## 2. 封閉的單位與放在哪裡

**單位是軌道邊（`TrackEdgeID`），記在軌道網路上：`RailwayNetwork.closedEdges`，照編號由小到大。**

讀過 `TrackResources.swift`、`BlockSections.swift`、`RouteReservation.swift`、`Deadlock.swift`、`ServicePath.swift` 之後的理由：

- 尋路只有一個核心（`ServicePath.swift` 的 `networkPath`），它一步走一條邊的一個方向。封閉以邊為單位，就是在那一步多問一句，其餘每一種搜尋都自動避開，不用一個一個改。
- **不用閉塞區間**：閉塞（決策 212）的邊界是每次從邊長與道岔位置算出來的，不存檔、沒有自己的編號，而且只有開了閉塞的世界才有；拿它當單位就得另外發明一種會隨鋪軌改變的識別。
- **不用 span（`TrackResource`）**：span 會隨月台增減重新切。封閉半條邊對尋路也沒有意義：邊中間沒有道岔，進得去就一定要走完或停在月台。
- **不當成「有一列看不見的車佔著」**：預約的結果是「被哪一列車擋住」（`Reserving.held(by:)`），等待、死結偵測、讓車都靠這個列車編號。沒有列車的封鎖塞進去，死結偵測會去找一列不存在的車。封閉的軌道不是被佔用，是不在地圖上，所以放在尋路那一層。
- **放在網路上而不是 `GameWorld` 的另一個欄位**：行車管制在兩次 `advance` 之間留著的東西（`RouteMemo`：路徑、路線行程、容量）是以「網路沒變」為鍵的；封閉記在網路裡，鍵自然就變了，不會拿到封閉前算的路。月台與間距豁免也是記在網路上的邊的註記，拆邊時一起處理。`closeTrack`／`openTrack` 另外把乘客的行程快取清掉。
- 作者的桌面版也是以邊為單位，兩邊一致。

玩家看到的「一段」多半是兩個道岔之間的一整段（`networkSections()`），那是好幾條邊；畫面那個 PR 可以一次送好幾個指令，規則不需要另一種單位。

## 3. 為什麼拒絕時用既有的 `trackReserved`

封閉被列車擋住時，回的是既有的 `trackReserved(列車)`，不是新的錯誤：它的意思本來就是「這列車佔著指令需要的軌道」，畫面已經會用它指出是哪一列車（`PlacementGuidance`、`LineRemoval`），玩家文字「有列車的路線要經過這段軌道，請等它通過。」也正好是該說的話。新的錯誤只有一個：`trackClosed(邊)`，給「指令要用到封閉的軌道」。

## 4. 來源對照

規則來自作者自己的桌面版鐵路模擬（私人、不在任何公開 repository；作者確認規則是自己設計的）。只照規則重寫，沒有搬程式。

| 來源的規則 | 這裡 |
| --- | --- |
| 封閉：區間有車佔用或已被預約就拒絕 | `closeTrack(_:)`、`trainUsing(_:)`；多擋一種：列車走到一半、路徑還會經過但還沒預約到（跟車只預約前面一段） |
| 封閉後不再發出通過該區間的行車授權 | 尋路不走（`networkPath`、`route(from:to:)`），所以沒有預約；指令也擋（`admit`、`trackClosed`） |
| 開放隨時可以 | `openTrack(_:)` |
| 來源的路徑寫死，封了正線不會改走迴避線 | 這裡尋路自己改道（測試 `testATrainTakesTheLoopWhileTheMainTrackIsClosed`） |
| 來源沒有的 | 存檔、切邊與拆邊時怎麼辦（第 1 節第 4 點） |

查過的其他地方：參考庫 `railway-reference-private` 沒有手動封閉軌道的實作可搬（它的 `BLOCK_GAP_KM` 是跟車間距，決策 57 已用）。外面的專案沒有搬任何東西；程式是這個專案自己寫的。

## 5. 存檔

- 網路多一個鍵 `"closedEdges"`：封閉的邊的編號，由小到大。**只有有封閉時才寫**，所以沒用過這個功能的世界寫出的 JSON 和以前一字不差（測試比對過；開放回去之後也一樣）。
- 讀檔時不修、只拒絕：不存在的邊、順序不對、重複。
- 存檔版本 94（93 是決策 715 的）。只讀舊版本的程式會把封閉丟掉、讓列車開上玩家封閉的軌道，所以它要說「存檔比我新」。舊存檔不用轉換。
- 新的 `SaveFixtures/v94-closed-track.json`。

## 6. 五個角度

- 玩家：施工、想把車趕到另一股道、想暫時停一條線時有一個直接的開關；封了不會把車困在半路（有車就封不了），開了不用自己重排。
- 鐵道迷：對應真實鐵路的「路線封鎖」：封鎖前區間要淨空，封鎖中不排進路，解除後恢復。封鎖不改號誌與閉塞的規則。資料：無。
- 開發者：規則只加在尋路的一個地方與指令的一個入口，預約、跟車、死結的程式沒動；沒封閉時多一次空陣列的判斷。
- 美術：這個 PR 沒有畫面。下一個 PR 要在地圖上標出封閉的軌道。
- 音樂：無。

## 7. 沒選的

- 封閉時把還沒到的列車的預約收回、讓它在半路停下：來源的規則就是拒絕；半路停下的車可能卡在道岔上擋住別人。
- 封閉有期限、到時自動開放：來源沒有；需要時間與存檔欄位，之後要再加。
- 封閉要收費或影響維修：來源沒有。
- 封閉車站或月台：另一件事（決策 228 的月台佔用）。

## 8. 已知限制、下一步

1. **畫面還沒做**（下一個 PR）：選一段軌道封閉／開放、地圖上標示、被拒絕時指出是哪一列車、等不到路的列車顯示原因。現在 `routeWaits()` 只列「被別的列車擋住」的等待；因為封閉而沒有路的列車不在裡面，畫面要另外問（那列車的下一站 `path(...)` 是不是 `nil`）。
2. 封閉把路線唯一的路切斷時，那條路線的 `lineJourney` 是 `nil`，路線的列車留在站內、不發車；乘客照舊在月台等。沒有另外通知玩家。
3. 單線上把會車站的一股封掉，對向的兩列車可能在站內互等到開放為止（那個站只剩一股，本來就會不了車）；開放後自己解開（測試 `testOpposingTrainsWaitOutAClosureAndThenMeet`）。不開放就一直等：這是玩家封出來的，規則不替他解。
4. 只在單線加迴避線的小場景測過；高鐵、整個臺灣那種大地圖上封一段的行為（路線繞很遠、`detourAllowance` 以外的路）沒有測。預設路本身就是繞過去的那條，所以不受 400 m 的改道上限限制。
5. 作者排的後續（各自一個 PR，不在這次範圍）：單線公平輪流、道岔扳轉動畫。

## 9. 續：接進畫面（第二個 PR）

1. **在哪裡按**：選取工具點軌道出來的軌道卡片（決策 247 的那張），多一顆「封閉軌道」；封閉中顯示「已封閉，列車不能通過」與「開放軌道」。不另開一個鋪軌工具的模式：封閉是營運中的動作，不是施工，選取工具不暫停遊戲。
2. **一次封多長**：點到的那一段所在的整段，從前一個道岔（或軌道盡頭）到下一個（`networkSections()`），整段一起封、有一段被拒絕就整段都不封。玩家看到的是「兩個道岔之間的一股」，不是程式切出來的一小截邊；只封一小截和封整段對列車的效果一樣（中間沒有別的路可進出），整段標示才看得懂。
3. **指令**：`PlayerCommand.Edit.closeTrack(edges:)`／`openTrack(edges:)`（邊的號碼），走 `GameSession.perform`：進指令紀錄、可以復原、被拒絕也記一筆。被拒絕時用 session 既有的訊息（點名擋住的那列車）。
4. **地圖**：2D 地圖在每個縮放層級把封閉的軌道畫成白底紅色虛線，夠長的段中間加一個打叉的圓牌；不只靠顏色。
5. 教學關卡裡，和「升級為複線」同一個時機才出現（`allows(.doubleTrack)`），前面的關卡不多一顆沒教過的按鈕。

五個角度。玩家：點軌道就看得到、按一下就封，地圖上一眼看出哪裡封了。鐵道迷：對應真實的「股道封鎖」，以道岔到道岔為單位。開發：重用軌道卡片、`perform` 與指令紀錄，沒有新的狀態。美術：沿用地圖既有的紅（`metroRed`）與牌子底色，沒有新圖示（SF Symbols 的 `nosign`、`checkmark.circle`）。音樂：無。

沒選的：鋪軌工具加第七個模式（要先切工具、遊戲會暫停）；只封點到的那一截邊（標示太碎）。

已知的問題（模擬器上在高鐵示範地圖看到的）：班次密的幹線上，兩個道岔之間幾乎隨時有列車的路要經過，封閉幾乎每次都被拒絕（「有列車的路線要經過這段軌道，請等它通過」），暫停時也等不到空檔。這是第 1 節的規則（列車還沒走完的路也算佔用）造成的，不是整段或單截的差別。要讓它在幹線上好用，下一步是「預約封閉」：先記下來，等路上的列車都通過、不再放新的列車進來，再生效；那是規則的改動，另開 PR。

還沒做：3D 地圖上的標示；因為封閉而沒有路的列車，在列車卡片上寫出原因（現在只能從地圖上的封閉標示看出來）。
