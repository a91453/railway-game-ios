### 719. CI 第八輪：release archive 的上限 45 分（逐檔編譯試過、沒有用）；rest 的五個重類別移到最輕的 campaigns

2026-11-13，CIOPT-8（session_01YGNNunYM5mSwBDcxy53H9s，`claude/ciopt-8`），遊戲規劃第 64 任派工。號碼依 #2118 登記；存檔版本、golden schema、`GoldenScenarios/`、`SaveFixtures/`、`ReplayFixtures/`、GameCore 都不動。數字在[量測](../research/CI_MEASURE_2026-11-13.md)。

## 為什麼

- **release archive 一天被砍 6 次。** 11-13 的 12 次 PR run 有 6 次在 `timeout-minutes: 30` 被取消，成功的 18.8–28.7 分。整個 run 是一件事：Release 把 GamePresentation（約 178,600 行）當一個模組一次最佳化編譯，快的機器 12.6 分、慢的機器 23.1 分；慢的機器後面還有 App 的編譯，一定超過 30。排隊是 0，沒有套件要抓。
- **rest-1、rest-2 的 job 15.1–17.5 分**（門檻 15），8 個完整 tier 有 7 個；完整 tier 牆鐘中位數 `main` 25.1 分、PR 27.0 分（門檻 25）。三個新類別沒有權重：`HongKongMapTests` 184 s、`Map3DFarViewTests` 135 s、`DemoRealLinesEverySystemTests` 78 s；campaigns 各片只有 189–549 s。
- PR 的 iOS gate、full lane、截圖 workflow 都沒有超過要動手的線（量測 §5、§6）。

## 決定

1. **release archive 的 job 上限 30 → 45 分**，和 `testflight.yml` 的封存 job 一樣。慢 1.7 倍的機器整個 run 要 32 分（下面的 run 43415884921），30 分的上限砍掉的是會過的 run。上限只決定什麼時候放棄，不會讓任何檢查變鬆。
2. **PR 的 run 逐檔編譯：試了兩次，沒有用，拿掉了。** 想法是 PR 的 run 要答的事（Release 編得過、封存的 App 有圖示、兩種語言、隱私清單、執行檔裡沒有 Debug 專用的啟動參數）都和模組怎麼編無關，逐檔編譯能用到每個核心。實際上 Xcode 在 Release 一律把套件的模組整個編：命令列給 `SWIFT_COMPILATION_MODE=singlefile`（run 43412867472）只改到 App 自己的 target，再加 `SWIFT_WHOLE_MODULE_OPTIMIZATION=NO`（run 43415884921）也一樣，兩次的日誌裡 GameCore 與 GamePresentation 仍是 `-whole-module-optimization`。所以 `xcodebuild` 的命令列和原來一模一樣。這一步要變快只剩把 GamePresentation 拆成幾個模組，或改 `Package.swift` 的編譯方式（會連發行的建置一起改），都不是這張單該做的。
3. **五個類別從 rest 移到四次 run 中位數最低的五片 campaigns**（決策 639 的做法）：`HongKongMapTests` → campaigns-1（285 s）、`Map3DFarViewTests` → -8（273 s）、`RealLineRebuildTests` → -2（309 s）、`RealLineListingTests` → -10（317 s）、`DemoRealLinesEverySystemTests` → -12（311 s）。照那幾次的秒數，這五片會到約 390–470 s，rest 兩份合計從約 1,650 s 降到約 1,050 s。
4. **23 個類別補權重**（rest 裡 5 秒以上、沒有權重的，取各 run 最慢的秒數）；`TrainNightLightsReadBackTests` 10 → 18。`Map3DStationExteriorsTests` 231 → 94（決策 679 讓它變快之後這幾次是 74、94 s；留著 231，rest 兩份照各類別的秒數是 433 與 609 s，改了是 484 與 557 s）。
5. **沒有改的**：
   - 沒有跳過、停用、隔離任何測試，沒有縮小任何測試；沒有加片（完整 tier 仍是 19 個 job）；`Swift CI (gate)` 沒動；`testflight.yml` 沒動。
   - `HongKongMapTests` 本身沒有變快（見下一步）。
   - `testflight.yml`、release archive 的 `xcodebuild` 命令列都沒動。
   - release archive 的觸發路徑沒有再縮：11-13 觸發它的是字串目錄、App 進入點與資產，都是它在檢查的東西。
   - 建置快取：整模組編譯只要一個檔變了就整個重編，新 checkout 的檔案時間也都是新的，快取救不了這一步。
