### 471. 跟隨列、財務趨勢與帳目不再每個 tick 重算

2026-10-28，派工單 CH，實作 session_01YGNNuozvGfk5ctgXtuSUbB（`claude/tick-recompute-k`），遊戲規劃 session_01YGNNumoD1XSP8eSkjabCvp 派。UI 健檢 K（`docs/research/UI_UX_REVIEW_2026-10-28.md` 的 2-19、3-21、3-22）。號碼依 #1041：決策 471；存檔版本、golden schema 不動。只改 GamePresentation 與 App；GameCore、存檔、GoldenScenarios、SaveFixtures、ReplayFixtures 不動。

**為什麼**：編輯與跟車的卡頓是玩家回報第一名（`docs/research/PLAYER_FEEDBACK.md` 93.1、92.1）。決策 367、377 讓畫面框架、地圖泡泡與狀態列只在變了才重算；跟隨列與財務面板還沒有。

**2-19 跟隨列**（`FollowBar.swift`）：
- 原本：框架（`ContentView`）讀 `session.followedTrain`，這個計算屬性讀 `world`，所以**跟車時整個框架每個 tick 重建**（決策 367 修掉的事，跟車時又回來了）；跟隨列自己在 body 讀 `world.followBarInfo`、`world.trainCard`、`world.lines`、`world.clock`，每個 tick 重建五種 `ViewThatFits` 排法。
- 現在：`GameSession.followBar`（`FollowBarFacts`：車名、路線代號與顏色、說明文字、班次時間與狀態、目前速度）在世界或跟隨的列車變了時重算，**不一樣才寫回**。框架與跟隨列只讀它。班次進度幾乎每個 tick 都動，放在另一個值 `followProgress`，只有 iPad 寬版那條 72 點的進度條（`FollowBarProgress`，自己一個 view）跟著重算。
- 進度取到千分之一（72 點的條上 0.072 點），看不出差別，但列車沒動到那麼多的 tick 不會叫進度條重算。
- 文字、排法、按鈕都一樣：`TickRecomputeTests.testTheFactsAreWhatTheWorldSays` 每個 tick 比對 `followBar` 與世界現算的 `followBarInfo`／`trainCard`（中英兩種語言、切速度、暫停）。
- 量到的（Linux，`TickRecomputeTests`，100 個 600× 的 tick，`withObservationTracking`）：跟隨列以前讀的值 100／100 叫它重算；現在 25／100，進度條 90／100。這 25 次都是畫面上的字真的變了：測試的線只有 4 站、站距 1.5 km，600× 時一個 tick 一分鐘，列車每幾分鐘就到站、折返，狀態（尚未發車、準點、已抵達）25 次、班次時間 15 次、有沒有班次 10 次。站距長的真實路線變得更少。框架讀的值不多於跟隨列。

**3-21 財務帳目**（`EconomyPanel.swift` 的 `ledgerSection`）：
- 原本：`ForEach(entries.enumerated(), id: \.offset)`，最新的在最上面，所以每寫一列，每一列的 id 都換了，SwiftUI 把整個清單當成新的，VoiceOver 的焦點會跳。
- 現在：`GameWorld.recentLedgerRows()` 給每列一個 `LedgerRow.ID`：時間、種類，和同一時間同一種類在它之前有幾列（同一刻拆好幾棟樓）。帳目照時間寫、只放掉最舊的，所以新的列進來時舊列的 id 不變；只有同一時間同一種類的更舊一列被放掉時才會換（要同一刻寫滿 50 列）。顯示的列與順序和 `recentLedgerEntries()` 一樣。

**3-22 財務趨勢**（`EconomyPanel.swift` 的 `trendSection`）：
- 原本：每個 tick 算一次 `FinanceHistory.make` 與三張圖。
- 現在：`FinanceHistory.Source`（範圍、這個範圍讀的日帳或年帳、今天）當 `TickStable` 的鍵，鍵沒變就不重算也不重畫。
- 健檢寫「資料一天才變一次」，實際上今天這一天也在圖上，每小時的帳目會改它，所以鍵是日帳本身，不只是日期：一小時最多變一次（`testTheTrendSourceChangesOnlyWithTheBooks`：4 個遊戲小時 1–4 次；全年度 0 次）。日帳陣列沒改時 Swift 的陣列比較先比緩衝區是不是同一塊，幾乎不花時間。
- 用 `TickStable` 不用 `.task(id:)`：專案已有，而且圖表是同步畫的，不需要背景工作。

**參考**：這是 SwiftUI `@Observable` 追蹤範圍的問題，與決策 367、377 同一種。參考庫的網頁每幀整張重畫，沒有可以搬的；外面也沒有搬東西進來。
