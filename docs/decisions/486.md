### 486. 手機橫放時，路線清單的搜尋、篩選、排序收成一列跟著清單捲走

2026-10-29，遊戲規劃第 31 任（session_01YGNNukxseY7eMCvXhjtc4X）派工（派工單 LPS），實作 session_01YGNNuokuACFK12zJPuZVJc（`claude/lines-panel-compact-search`）。只改 App 與 GamePresentation；GameCore、存檔版本、golden schema、replay 都不動。接決策 481。

**為什麼**：作者在 95.1 真機（iPhone 橫放）回報「搜尋欄太大了」。路線面板約 270 點寬、272 點高，決策 481 把搜尋欄（帶底色、約 46 點高）、三段的篩選、排序上下疊著釘在清單上面，連同導覽列佔掉約 185 點，清單只剩一列，那一列的名稱、列數、昨日數字還都被截成「集集…」「1 列 ·…」「昨日 1,…」。

**做了什麼**：

1. **矮的面板（`verticalSizeClass == .compact`，手機橫放）**，`LinesListControls.style(compactHeight:)` 是 `.inline`：
   - 搜尋、篩選、排序收成**一列**，放在清單的第一個 section（新路線表單之後、路線之前），**跟著清單捲走**，不釘在上面。
   - 搜尋收成放大鏡按鈕（`lines.search.open`），點了才在那一列上面打開搜尋欄並帶出鍵盤；欄旁有「取消」（`lines.search.close`），清掉字並收起。有字的時候欄一直在（`showsSearchField(opened:search:)`），不會有搜尋在作用卻看不到欄。
   - 篩選改成選單（`lines.filter`），標籤寫目前的選擇（「全部路線」「只看虧損」），有篩掉路線時圖示改實心；VoiceOver 念「顯示：只看虧損」。
   - 排序的標籤只寫順序（「建立順序」），旁邊是上下箭頭；VoiceOver 照舊念「排序：建立順序」（`sortTitle(_:short:in:)`、`sortLabel(_:in:)`）。
   - 大字級放不下一列時，排序換到第二列（`ViewThatFits`）。
   - 清單左右邊距 8 點（`contentMargins`），路線列的內距上下 6、左右 12，讓列寬一點、矮一點。
2. **路線列（每個大小都適用，`ViewThatFits`）**：
   - 放得下時照舊兩行：名稱……列數；昨日數字……趨勢小圖。
   - 放不下時不截字：名稱一行；列數與趨勢小圖一行（再放不下就先拿掉小圖，列數不截）；昨日人次與損益一行，再放不下就上下兩行（`LineReport.compactRowParts(in:)`）。
   - 拿掉昨日數字的 `minimumScaleFactor(0.8)`：放不下改成換行，不把字縮小（ui-review §1）。
3. **直向與 iPad**（`verticalSizeClass == .regular`）：控制項照決策 481 釘在上面，樣子不變。釘住的那塊多了 `lines.controls.pinned` 的識別碼，UI 測試用它算清單從哪裡開始（`linesListTop(under:)`）；橫放時沒有釘住的東西，清單從導覽列下面開始。

**估的高度**（橫放 272 點高）：導覽列 44，剩 228。窄的列約 68 點。打開時先看到入口列（整個路網、進階、新路線）與控制列；往下捲到路線時控制列捲走，看得到 3 列以上。之前同一個位置只看得到 1 列。

**動態**：放大鏡打開搜尋欄沒有加動畫（原地出現）；沒有新的 `withAnimation`。

**五個角度**（選項見 PR 的 `docs/art/lines-panel-486-2026-10-29/overview.png`：A 一列跟清單捲走、B 一列釘在上面、C 搜尋收進標題列）：

- 玩家：A 讓清單在橫放時拿到幾乎全部高度，往上一捲就找得到搜尋與篩選；B 釘住一列仍佔 44 點，只剩約 2.5 列；C 標題列已有圖表鈕、標題、完成，再塞一顆鈕在 270 點寬裡會擠，而且篩選、排序還是要佔一列。
- 鐵道迷：無（列上的數字與名稱不再被截，算是資料看得清楚）。
- 開發：只在矮的面板換版面，直向與 iPad 的程式路徑不變；邏輯（哪種樣式、搜尋欄何時出現、標籤文字、昨日數字拆兩段）在 GamePresentation 用 Linux 測試。
- 美術：拿掉那塊大底色的搜尋欄；控制列用一般的列底色，和下面的路線列同一套外框。
- 音樂：無。
