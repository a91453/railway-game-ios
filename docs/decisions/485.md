### 485. 3D 跟車 10× 的每 tick 主執行緒工作移出去，面板加「main ms」

2026-10-29，遊戲規劃第 31 任（session_01YGNNukxseY7eMCvXhjtc4X）派工（派工單 FPS），實作 session_01YGNNuphxaPGPV7TDzRjjop（`claude/map3d-follow-fps`）。只改 GamePresentation 的 `GameSession`、App 的 3D 地圖與它們的測試；GameCore、存檔、golden、replay 都不動，遊戲結果不變。

**問題**：作者在實機（95.1）用 3D 地圖、駕駛室跟集集線列車 1：1× 60 fps，10× 掉到 36 fps；2D 地圖 6000× 仍 60 fps。面板：CPU 4.6 ms、GPU 9.9 ms（中位數）、wait 0.0、高畫質、314 draws、290,507 三角。

**根因**：3D 地圖的列車資料（`Map3DTrainFeed.update`）在 `session.world.trains` 每次變的時候，在主執行緒上自己重算全部列車的滑行（`TrainMotion(world:previous:time:)`）和車身高度（`Map3DTrains.Heights(world:)`）。1× 列車只在整秒動，一秒一次；10× 每個 tick（一秒十次）都算。兩樣都跟列車數成正比，而且 2D 地圖還在 3D 底下（`fullScreenCover`），它的滑行雖然已經在 tick 裡、主執行緒外算好（決策 379），3D 那份卻沒用到。這段時間不在面板的 CPU（只量畫一幀）裡，所以 CPU 4.6 ms 看起來很閒、fps 卻掉：每個 tick 一段長的主執行緒工作，吃掉兩三幀。

量（Linux，`Map3DFollowTickCostReportTests`，`FOLLOW_REPORT=<ticks>`；數字見 PR）：

- 以前每 tick 主執行緒：3D 的滑行＋高度。
- 現在：3D 拿 2D 已經拿到的那份滑行（同一個 `worldRevision` 直接回傳），高度在 tick 裡主執行緒外算（3D 開著才算）。

**做了什麼**：

1. `GameSession.LoopTick` 多一個 `trainHeights`（3D 地圖開著時為真）。`work()` 在 tick 動了列車時，主執行緒外算 `Map3DTrains.Heights(world:)`；`finish` 存進 `trainHeightsMemo`（帶 `worldRevision`）。
2. 新的 `GameSession.map3DTrainHeights()`：同一個世界只算一次，tick 算好就直接用。
3. `trainMotion(after:at:)`：這個世界的滑行已經給過一張地圖，第二張地圖拿同一份，不在主執行緒再算。
4. `Map3DTrainFeed.update(session:palette:)` 改用上面兩個。
5. 3D 面板（點 fps 展開的那張）多一行 `main X ms · longest Y ms`：主執行緒每幀忙的時間（從醒來到再睡，包括畫幀、SwiftUI 與 tick 的合回）與半秒內最長的一段。`CPU` 只量畫幀，這行才看得到 tick 的工作。只是除錯用的英文數字，跟其他幾行一樣不翻譯。

**Map3DLoadGovernor 沒有降，對嗎**：對。畫質「高」的 `lowersWhenOver` 是 false（決策 417），玩家選了高就不自動降；而且降的是街景人車與遠景的三角數，對 GPU 與畫幀的 CPU 有用，對主執行緒上 tick 的工作沒用，降了也不會回到 60 fps。另外 GPU 9.9 ms 已貼近 `Map3DDrawScale` 的 10 ms 門檻（VTR 研究 #1495 提到），那是另一件事，這裡不動。

**五方**：

- 玩家：10× 跟車順，畫面一樣。
- 鐵道迷：無（列車位置、時刻都不變）。
- 開發：沿用決策 379 的「跟 tick 一起在主執行緒外算」，只多一個 memo；面板多一行能直接看到主執行緒。
- 美術：無。
- 音樂：無。

**另外考慮過的**：

- 10× 時把 3D 的列車更新合批（兩三個 tick 才更新一次）：滑行會變成一頓一頓的，不採用。
- 3D 開著時關掉底下 2D 地圖的滑行：2D 的滑行本來就在主執行緒外，關掉省的不多，關回來還要接上；改成共用一份。
- 讓 governor 在「高」也降：見上，降的東西不是瓶頸。

**驗證**：Linux（Swift 6.4）`swift build --build-tests -Xswiftc -warnings-as-errors`、`Map3DFollowTickTests`、`TrainMotionTests` 等 VERIFIED。iOS 上的 fps、面板新的那一行 UNVERIFIED（要實機）。截圖驗收照作者 2026-10-29 的指示延到發版前。
