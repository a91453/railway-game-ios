### 582. full lane 不再在合併後自動跑，最多同時佔 3 台 macOS（修正決策 265）

2026-11-04，實作 session CIOPT-7（session_01YGNNun3EczixWEZvxFSMz9，`claude/ciopt-7`），遊戲規劃第 46 任派。號碼依 #1579 登記；存檔版本、golden schema、fixture 不動，只改 workflow、說明與決策文件。

### 背景

- 作者 2026-11-04：「每次跑都等一個小時以上全部卡住超浪費時間」。
- 帳號只有 5 台 macOS runner。決策 265 讓 `ios-full-lane.yml` 在每次合併後（最多每 3 小時一次）起 full lane；full lane 的四個 macOS job 同時跑，佔 4 台。
- 量到的（main 的 full lane，2026-11-03 08:54 到 11-04 02:36 UTC 的六輪）：build job 66–110 分、`second` 71–88 分、`lessons` 65–87 分、iPad 教學 21–35 分；整輪約 1.5–2 小時，排隊時更久。這段時間 PR 的 Xcode build 與 `website-screenshots.yml` 只剩 1 台，排隊一小時以上（例：06:10 起的 #1780 Xcode build、05:19 排隊的截圖）。
- 2026-11-04 前最近 5 輪 full lane 有 4 輪紅在偶發 UI 測試，結果沒擋任何合併（full lane 本來就不擋 PR），所以合併後馬上跑換不到什麼。

### 決定

1. **合併不再起 full lane**。`ios-full-lane.yml` 拿掉 `push` 觸發與白天的 cron，只留每晚一次（`17 18 * * *` UTC，台灣 02:17，`ci.yml` 夜間那輪的 40 分鐘後）：main 最新 commit 已有 full run、或還有一輪 full lane 在排隊或在跑，就不起；起的時候附 `verify_missing_button=true`（原本 `ios-build.yml` 自己的夜間排程才做的「少一顆按鈕，smoke 測試要紅」證明）。
2. `ios-build.yml` 自己的 `schedule` 拿掉：它每晚不看 commit 有沒有跑過就跑，改由上面那一輪代替。
3. 其他時候只手動跑：(a) 發版前對 main HEAD（`ios-build.yml` 的 workflow_dispatch，CLAUDE.md 與 `docs/HANDOFF.md` §1.2 的發版條件不變），(b) full lane 紅了二分。`ios-full-lane.yml` 手動按仍是「main 最新 commit 沒跑過才起」，不等正在跑的那輪。
4. **full lane 最多同時 3 台 macOS**：`ipad-tutorial` 改成 `needs: [changes, ui-full-lane]`、`if: !cancelled() && …`，在 full lane 裡等兩個 iPhone UI job 跑完（紅綠都不擋）才開始。PR 與 `only_testing` 不跑 `ui-full-lane`（skipped），iPad job 照舊在 `changes` 後馬上開始，條件不變。
   - 會不會太慢：iPhone UI job 最長 88 分＋iPad 最長 35 分＝約 2 小時 3 分，build job 最長 110 分；整輪多約 10–15 分，遠低於任務設的 3 小時線，所以第 2 項照做。
   - 沒用 `max-parallel: 1` 串兩個 iPhone job：那會變成 88＋87 分，約 3 小時，超過線。

### `full-lane-watch.yml` 與 `tools/ci-watch/full_lane_watch.py`

它們認的是 `ios-build.yml` 在 main 的 `workflow_dispatch` 與 `schedule` run。夜間那輪由 `ios-full-lane.yml` 用 workflow_dispatch 起，照樣被認到；`schedule` 留著認舊的 run。只改了說明文字。

### 五方

- 玩家：合併後的 PR 更快拿到 Xcode build，修好的東西更快進下一版；full lane 每晚與發版前照樣跑，發出去的版本一樣全部 UI 測過。
- 鐵道迷：無。
- 開發：PR 永遠有 2 台 macOS，截圖與 Xcode build 不再排一小時；full lane 的偶發紅本來就不擋合併，改成每晚一次與發版前驗，一樣找得到退步（二分範圍變成一天的合併，用 `only_testing` 縮）。
- 美術：截圖驗收（`website-screenshots.yml`）不再被 full lane 卡住，畫面的審查更快。
- 音樂：無。
