### 423. 乘車導航（第一步：路線資料）

2026-10-26，遊戲規劃 session_01TH2DNkW2meh3EZJ1vxBczC 派工（派工單 B）。NEXT_PRIORITIES §22.2 第 27 名。存檔版本、golden schema、replay 不動；GameCore 不動（只讀它的公開 API），只加 GamePresentation 的 `JourneyPlan`、它的 Linux 測試與這個決策。不做畫面。

**為什麼**：玩家想知道「從 A 站到 B 站怎麼搭、要多久、多少錢」。GameCore 已經算得出旅客真正走的路線（`GameWorld.passengerRoutes(from:to:limit:)`，決策 5C）與票價（`GameWorld.tripFare(from:to:highSpeed:)`，決策 36、137、168），但畫面讀不到一份整理好的結果。導航畫面要先有資料，而且資料必須和旅客實際走的路、實際付的錢一致，玩家照著搭才不會被騙。

**做了什麼**：`Sources/GamePresentation/JourneyPlan.swift`，`JourneyPlan(world:from:to:)`：

- 最多 3 個方案（GameCore 的順序：總分鐘由少到多，同分先比轉乘次數）。
- 每個方案：每一段的線名、上車站、下車站、這一段的乘車分鐘、是否從上一段的下車站走路過來；轉乘次數；總分鐘數，拆成乘車、等車、轉乘、步行；票價。
- 票價用 `tripFare`，與旅客一樣是起訖站的直線距離，不是每一段各收一次；方案裡有高速線就照高速線票價（決策 168）。公司沒有開帳（自由玩法）時沒有人付費，票價是 `nil`。
- 起訖相同、地圖上沒有的車站、一條線也沒有、有線但沒有列車連得到，四種情形回傳空方案，`absence` 說明原因，`message(in:)` 給一句中英文說明，只說玩家能做什麼。
- 玩家看得到的字（`transfersText`、`totalText`、`breakdownText`、`fareText`、`Absence.text`）中英兩種，不寫程式名、ID、內部單位。
- 每次查詢都現算（GameCore 會重建班次圖），不存檔；畫面要放到主執行緒外問，像 `NetworkFlowReport`。

測試 `JourneyPlanTests`（Linux）：直達、一次轉乘、到不了（含沒有列車上線）、起訖相同，另外票價隨票價規則與自由玩法、三個方案的上限與排序、兩種語言的說明。

**參考對照**：查過 a91453/railway-reference-private 的 `Ci/reference_snapshot/lib/app__q_c234188b7c397f91.js` 與同資料夾的 UI 字串。參考裡沒有給玩家用的乘車導航（缺口）；只有開發者除錯用的 `metroDebugPathOptionsAtOD`、`metroDebugNamedODPath`（看一組起訖的路徑選項），它背後的路徑與選擇規則已經在 GameCore（`passengerRoutes` 與 `passengerRouteAllocations`，決策 5C）。所以這一步沒有搬任何參考的程式，整理成顯示用資料的部分是這個專案自己寫的。外部開源專案：沒有找；GameCore 已經有班次圖最短路徑，這裡不需要再造。

**五方**（作者 2026-10-14 的預設）：

#### 第二步：車站面板的「怎麼搭」

2026-10-26，派工單 D。存檔版本、golden schema、replay 不動；GameCore 不動；不加依賴；`project.yml` 不動（只改既有的 `StationPanel.swift`，加 GamePresentation 的 `JourneyPlanRows.swift`，後者在 Swift 套件裡，不進 Xcode 專案）。

**做了什麼**：車站面板在「即將進站」下面多一段「怎麼搭」（`DisclosureGroup`，預設收起）。

- 裡面一個「目的地」按鈕，點開是一張選車站的清單：地圖上其他車站，依名字排序（名字裡的數字照數值比，「2 號站」在「10 號站」前面），不含這一站；其他站達 `ListSearchField.minimumRows` 就給搜尋框。選了之後按鈕顯示目的地名字，可以再改。
- 選了目的地才算：`Task.detached(priority: .userInitiated)` 在主執行緒外算 `JourneyPlan(world:from:to:)`，與 `workOutRidership` 同一種做法。重算的鍵是 `JourneyPlan.Inputs`（起訖站、`RidershipInputs`、各線的名字與是否高速）：只有站、路線、班次、票價規則或日子變了才重算，不是每個 tick。收起或沒選目的地時鍵是 `nil`，什麼都不算。
- 最多 3 列方案。第一行「總分鐘 · 轉乘 · 票價」，第二行線名，第三行小字的分鐘分解；點一列展開每一段，需要走路的那一段前面有一行「步行到 X 站」。沒有方案時顯示 `Absence` 的那一句；算的時候顯示「正在找路線…」。
- 目的地、方案、展開哪一列都是畫面狀態：不存檔、不進 GameCore；選了別的車站就清掉。
- 文字全在 GamePresentation（`JourneyPlanRows.swift`）：`Option.rows(in:)`（三行、每一段、步行那一行、VoiceOver 唸的一句）、`JourneyPlan.findingText(in:)`、`JourneyPlan.destinations(among:from:matching:)`、`JourneyPlan.Inputs`。Linux 測試在 `JourneyPlanTests`（直達、一次轉乘含步行、到不了、自由玩法沒有票價、中英各一、排序與搜尋、重算的鍵）。App 只排版。
- 無障礙：目的地按鈕 `journey.destination`，搜尋框 `journey.destination.search`，清單每一站 `journey.destination.<id>`，方案列 `journey.option.<n>`、每一段 `journey.option.<n>.leg`，說明 `journey.message`，等待 `journey.finding`。一列是一個 VoiceOver 元件，唸出三行，並說明已展開或已收合。
- 動畫：只有展開一列用 `MotionRule.change`（原地的變化，0.2 秒，兩端平滑），減少動態時 `layout(reduceMotion:)` 是 `nil`，直接發生；沒有新增規則、沒有新的秒數。
- 選目的地的清單只由站名畫出（`TickStable`），遊戲每 0.1 秒換一次世界時不會重畫，也不會把輸入中的搜尋字打斷。
