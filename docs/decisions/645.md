## 做了什麼

1. **D5，從遠處進 3D 開在最近的軌道上**（`Map3DHandoff.opening(from:in:station:train:)`）：2D 畫面看得到的範圍不超過 3D 能蓋的寬度（`opensOverTheMiddleUpTo`，2 × `Map3DScene.reach` = 12 km）時照舊開在畫面中間、同樣的遠近。超過時，開在選取的車站，沒有就選取（或跟隨）的列車，都沒有就畫面中心最近的軌道（節點、軌道的幾何點、車站，取最近的一點），鏡頭看約 3 km 的地面（`groundShownOverTarget`）。什麼都沒蓋的新遊戲照舊開在中間。3D 的第一個鏡頭距離照 2D 的遠近（`openingDistance(of:sceneSpan:viewportHeight:)`），最多是場景寬的 0.9 倍。
2. **B5，3D 角落的遊戲時鐘**（`Map3DClock`，`Map3DPreviewScreen.swift`）：速度按鈕下面一個小膠囊，鐘的圖示加 `session.world.clock.shortCalendarText(in:)`，和 2D HUD 同一個來源，自己不存任何狀態。不是按鈕（VoiceOver 讀「遊戲時間 …」），等寬數字，不會隨數字寬度跳動。
3. **D6，遠處的夜窗**（`Map3DShaders.metal` 的 `nightWindowsFar`，`tools/map3d-preview` 畫一樣的）：一個像素跨過的開間（`fwidth(surfaceAt)`）從 0.25 到 0.7 格之間（照 tw3d 參考 `buildFarLod` 的門檻），夜窗從一格一格的亮窗漸漸換成整面的平均：這面亮窗的比例（`rule.x × busy`）× 玻璃占的比例（`1 − texel.a`，mipmap 平均後的）× 1.4。1.4 比近處一格亮窗的平均（0.825）亮：遠處單獨一個亮像素看起來比它的平均亮，平均成一片若照原值就太暗（試了 0.825：1.3 km 外暖色反而比原本少）。`fwidth` 放在分支外面算（導數要鄰近像素一起跑）。
4. **D6，3D 的數據列多一行光**：點開 3D 的 fps 小框，最後一行是這一幀實際畫的光：時刻、夜的程度（0–1）、城市燈光（0–1）。程式靜態看起來光每幀都跟著遊戲時間（`draw` 每幀 `shown = lighting`、60 fps 持續畫、`Map3DLighting(at:)` 和 HUD 的時刻同一個算法），Linux 預覽 20:51 和 03:11 的光一樣；試玩回報的「過了午夜變回白天亮度」在 Linux 重現不了，這行讓實機上一看就知道畫的是幾點。
5. **D8，陡坡的草地不當牆**：`map3dShade` 的牆（`wall`）＝陡的面且表面不是第 0 層（草地）。牆的開間線、較強的細節、牆腳壓暗只給牆；陡的草地照地面畫。
