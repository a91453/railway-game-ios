## 規則

- **app 的 session 裡，試算指令的預覽不在畫面問它的那一刻算**：`lineOpeningPreview`（新路線的價格，地圖 ✓、路線面板、草稿那一行）與 `lineConfirmationPreview`（決策 303 的開線卡片）在快取不是目前這份草稿與世界的時候回 `nil`（「還沒好」），並排一個主執行緒的 `Task` 在下一輪算（`GameSession.waits(for:workOut:)`，`WaitingPreview.swift`）。那個 Task 從主執行緒的事件迴圈開始跑，堆疊很淺；算好後 `previewsWorkedOutLater` 加一，問過它的畫面（讀過這個被觀察的值）再看一次，拿到快取的值。同一個預覽等著時再問幾次都只排一次。

- **草稿那一行（`lineDraftSummary`）價格還沒好時不存快取**，價格到了再算一次，才會補上價格。
- **只有 app 打開**：`GameLauncher.worksOutPreviewsOnTheNextTurn`（app 的 `makeLauncher` 設 true）交給它開的每一局；測試、`HeadlessGame`、GameSim 預設 false，照舊當場算，所以現有的測試與 golden 都不用改。

### 114.1：根本修法

順序照下面，2 是 GameCore（完整 tier），其他在 GamePresentation 與 App；每一步都用這次的量法（`MemoryLayout<GameWorld>.size`、-O 反組譯每個函式的 `subq $N, %rsp`、`StackProbe`）量改前改後。

2. **GameWorld 改成堆上的盒子、寫入時才複製（COW box，上面的選項 A）**。這是根因：GameWorld 是 2,032 bytes 的 struct，「先在副本上試、成功才採用」的寫法遍布 GamePresentation（`var trial = world`、`pricingCopy()`、`priced`、`feasible`、`apply` 的 `attempt`／`placed`），每個副本整塊在堆疊上，一個函式幾十個副本（`apply` 61 KB）。
   - 做法：所有存放的欄位搬進一個 `final class` 的儲存體，GameWorld 只留它的參照（8 bytes）；每個欄位改成 `get` 與 `_modify`，`_modify` 先 `isKnownUniquelyReferenced`，被共用才複製（Swift 的 Array 也是這樣）。欄位名稱、`public`／`internal(set)` 的可見度、`Codable` 的鍵與順序、`Equatable`（比內容，不比參照）、`Sendable` 都不變，所以 GameCore 以外的程式一行不改。不跟著存檔的快取（`passengerPlan`、`passengerRouteMemo`、`routeMemo`、`trackEditDepth`）一起搬，複製時語意和現在相同。
   - 要守住的：存檔版本、golden、replay、SaveFixtures 一個值都不動（只是記憶體的放法）；決定論不變。
   - 要量的：`MemoryLayout<GameWorld>.size` 從 2,032 變 8；-O 下 `apply`、`addTrains`、`tracePreview`、`traceAlong` 等前 20 大的框改前改後；`TICK_REPORT=300 swift test --filter TickCostReportTests` 改前改後（一次讀寫多一層間接，但複製世界從 40 多個參照計數變成 1 個，預期持平或變快；變慢超過 5% 就先查熱點，例如 tick 裡逐欄位的 `_modify`）。這次的 `WaitingPreviewTests` 的「當場算」要從 260 KB 大幅下降，可以把門檻收緊。
   - 做完之後：這次的「等下一輪」機制保留（畫面更新不做模擬，畫格也比較順），但不再是防當機的唯一一道。
3. **畫軌道的預覽與其他在 body 裡模擬的 getter 也等一輪**：`networkDraftPreview` 與讀它的 getter、`networkStationLayoutPreview`、`networkPlatformCrossovers`、`trackUpgradeDraft`（上面「同類的」表）。`WaitingPreview` 加 case，動作裡用 `now: true`；先查每個讀的地方能不能接受「還沒好」（教學的步驟判斷 `isTutorialStepDone` 不能在還沒好時誤判沒完成、`tutorialAdvancesByItself` 不能因此提早或延後），再跑 full lane 的畫軌道與教學 UI 測試。有 2 之後這一步是讓畫格順，不是防當機，可以視量測決定做到哪裡。
4. **拆小 `MapView.timedBody` 那個巨大的 closure**（當機堆疊裡偏移 +34524）：各個疊在地圖上的東西（✓、卡片、標籤、工具列）各自一個 `View` struct，body 只組合它們。它的框只在 Apple 平台量得到：`ios-build.yml` 的 Simulator build 之後加一步，用 `otool -tV`／`objdump` 讀 App 二進位裡 `sub sp, sp, #N` 的大小，列出前 20 大。
5. **防退步**：Linux CI 加一步（`swift build -c release` 之後跑這次的 `frames.py` 做法），GameCore 與 GamePresentation 裡新出現超過 32 KB 的框，在 PR 的 job summary 上列出來提醒（不擋合併）；4 的 App 量測同樣列出。
