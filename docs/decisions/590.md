- **app 的 session 裡，試算指令的預覽不在畫面問它的那一刻算**：`lineOpeningPreview`（新路線的價格，地圖 ✓、路線面板、草稿那一行）與 `lineConfirmationPreview`（決策 303 的開線卡片）在快取不是目前這份草稿與世界的時候回 `nil`（「還沒好」），並排一個主執行緒的 `Task` 在下一輪算（`GameSession.waits(for:workOut:)`，`WaitingPreview.swift`）。那個 Task 從主執行緒的事件迴圈開始跑，堆疊很淺；算好後 `previewsWorkedOutLater` 加一，問過它的畫面（讀過這個被觀察的值）再看一次，拿到快取的值。同一個預覽等著時再問幾次都只排一次。

### 做法

- `GameWorld` 除了 `network` 之外的 70 個存放欄位搬進 `GameWorldState`，放在堆上的 `GameWorldStorage`（`Sources/GameCore/World/GameWorldStorage.swift`，一個 `final class`，狀態放在它自己配置的記憶體裡）。`GameWorld` 只留 `network` 和那個參照。
- 每個欄位改成 `_read`（讀共用的儲存體）與 `_modify`（`uniqueState`：`isKnownUniquelyReferenced` 不是唯一就先整份複製，和 Swift 的 Array 一樣）。欄位名稱、`public`／`internal(set)`／`private(set)`、文件註解、`Codable` 的鍵與順序（`init(from:)`／`encode(to:)` 一行不改）、`Equatable`（`==` 比 `network` 與整份狀態的內容，不比參照）、`Sendable` 都不變；不跟存檔的快取（`passengerPlan`、`passengerRouteMemo`、`routeMemo`、`trackEditDepth`）在狀態裡，複製時和以前一樣跟著複製。GameCore 以外一行不改，GameCore 裡也只改了這兩個檔。
- **`network` 為什麼留在 struct 裡**：全部搬進去時 HSR demo 的 tick 從 59 變 81 ms（+37 %）。Linux 的測試與 CI 是 -O 但不是 whole-module（決策 544），別的檔（`RailwayNetworkTrains.swift` 等）讀欄位要呼叫 `GameWorld.network.read` 這個 coroutine，呼叫端在對讀到的值呼叫方法（`network.edge(_:)`）前會把它整份複製一次，`RailwayNetwork` 是 8 個陣列與字典，每次 8 個 retain／release，而它在每列車每一步都被讀。只讀它的某個欄位（`net.a.count`）只複製那個欄位，所以其他欄位（多半是一個參照的陣列）沒有這個問題。試過的別的寫法：
  - 類別的 `@exclusivity(unchecked) var`：一樣被複製。
  - `unsafeAddress`／`unsafeMutableAddress`（位址存取）：不會複製，但 Swift 6.4 的最佳化（CopyPropagation，「leaked owned value」）在 `LoadJourneyCacheTests`、`TrafficControlPropertyTests` 兩個測試函式上當掉，Xcode 的編譯器版本也可能不同，不用。
  - 用 unsafeFlags 對 GameCore 加 `-wmo`：swift-build 的 index 輸出不接受（「index output filenames do not match input source files」）。
  - 實驗中的 borrow accessor：不能從類別回傳 borrow。
  - App 的 Release 是 whole-module，存取函式會內聯（一個檔內的實驗沒有任何 retain），所以這只影響 Linux 的測試與 CI 時間，但 `network` 留著也只多 64 bytes。

### 114.1：根本修法

順序照下面，2 是 GameCore（完整 tier），其他在 GamePresentation 與 App；每一步都用這次的量法（`MemoryLayout<GameWorld>.size`、-O 反組譯每個函式的 `subq $N, %rsp`、`StackProbe`）量改前改後。

2. **（做了，見上面「續：114.1 下一步 2 做了」；`network` 留在 struct 裡，72 bytes）** **GameWorld 改成堆上的盒子、寫入時才複製（COW box，上面的選項 A）**。這是根因：GameWorld 是 2,032 bytes 的 struct，「先在副本上試、成功才採用」的寫法遍布 GamePresentation（`var trial = world`、`pricingCopy()`、`priced`、`feasible`、`apply` 的 `attempt`／`placed`），每個副本整塊在堆疊上，一個函式幾十個副本（`apply` 61 KB）。
   - 做法：所有存放的欄位搬進一個 `final class` 的儲存體，GameWorld 只留它的參照（8 bytes）；每個欄位改成 `get` 與 `_modify`，`_modify` 先 `isKnownUniquelyReferenced`，被共用才複製（Swift 的 Array 也是這樣）。欄位名稱、`public`／`internal(set)` 的可見度、`Codable` 的鍵與順序、`Equatable`（比內容，不比參照）、`Sendable` 都不變，所以 GameCore 以外的程式一行不改。不跟著存檔的快取（`passengerPlan`、`passengerRouteMemo`、`routeMemo`、`trackEditDepth`）一起搬，複製時語意和現在相同。
