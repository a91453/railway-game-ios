### 622. 方向保護的每段路徑也存進 PathMemo：車停著等時每 tick 不再重找

2026-11-07，實作 session TICKPERF（session_01YGNNupAMJ1MBNjDL9FDooP，`claude/tickperf`），遊戲規劃第 54 任（session_01YGNNupJUx5viUadNmXs45j）派工。號碼依 #1579 登記；存檔版本、golden schema、`GoldenScenarios/`、`SaveFixtures/`、`ReplayFixtures/` 不動。

## 為什麼

作者回報：買下的高雄環狀輕軌，3D 跟車 10× 實際只跑到 0.35–0.50 倍。CABVIEW-3（#1930，決策 379 續四）量到剩下的上限是 GameCore 每 tick 的 `advance` 約 210–270 ms（tick 間隔 100 ms）；決策 620 的修正沒有改變這個數字。

## 量的

指令（Linux，4 核，Swift 6.4.0；GameCore 照決策 544 是 -O，其餘 debug）：

```sh
CABVIEW_REPORT=1 CABVIEW_STEPS=1 CABVIEW_LOOP_SECONDS=40 CABVIEW_CPU=standard \
  swift test --skip-build --filter GamePresentationTests.CabViewTickCostReportTests
```

1. **今天的 `main`（`61da52f`）已經量不到慢**：擬實、簡單都是 1.00 of 10x，每 tick `advance` 5–9 ms。
2. **二分**：在 #1928（KLRT-SPARE，決策 609 續）合併前的 `b921d54`（報告測試從 `5171dc6` 拿來）是 0.36 of 10x、`advance` 212–297 ms，和 CABVIEW-3 量到的一樣；#1928 合併後的 `8454b9b` 是 0.99、5–10 ms。#1928 讓環狀線第二天早上不再卡住（死結 18 分 → 0），慢的就是「車停在站上一直等著出發」這個狀態。
3. **取樣**（在 `b921d54` 上，用 gdb 對跑著的遊戲迴圈每 0.5 秒抓一次所有執行緒的堆疊）：抓到 `advance` 的每一個樣本都在同一條路上：
   `runServices` → `departService` → `reservingDeparture` → `alternativeRoute` → `opposingParts` → `plannedDirections` → `leg` → `preferredPath(from:preference:length:)`（沒有 memo 的那一個）→ `networkPath` → `TrainRoute.shortest`。
   - 等著出發的車每一步都試一次出發；出發要另找一條路（決策 57 的方向保護），就要算每條線整個計畫的走向。
   - `plannedDirections` 的結果只存在這次 `advance` 的 `DirectionMemo.plans`，下一個 tick 又全部重算；裡面每一段（`leg`）都用一個新的空 `PathMemo` 找路，沒有用世界留著的那一份（`RouteMemo` 借給 `advance` 的 `memo.paths`）。
   - 所以卡住的車越多、線越長，每 tick 越重；車都順順地跑時不會走到這裡，所以今天的 `main` 量不到。

## 決定

`leg(of:from:stop:)` 與 `walkedDirections(_:from:stop:)` 改成帶 `paths: inout PathMemo`，`preferredPath` 與 `path(from:toStation:length:)` 都用有 memo 的版本；`workedOutServiceDirections` 裡找到下一站的那一次也一樣。傳進去的就是 `memo.paths`，也就是 `advance` 從 `RouteMemo` 借來、結束時收回的那一份（決策 138 續、#1924、#1932 的規則），沒有另外再存一份。

- 兩個路徑函式都只讀路網與靠左行駛（`PathMemo` 的說明），有 memo 與沒有 memo 的答案相同，所以結果逐位元相同。
- 沒有加計時程式碼到 GameCore，沒有加平台相依。

## 五面向

- 玩家：線上有車停著等出發（死結、等交會、等月台）時，10× 不再掉到三分之一；跟車畫面不再一頓一頓。順順跑時不變。
- 鐵道迷：無（行車結果逐位元相同）。
- 開發：只改一個檔案的參數傳遞，用的是現成的 memo；卡住的狀態本來就是最需要看清楚的時候（作者要看哪裡卡），現在不會因為看而更慢。
- 美術：無。
- 音樂：無。

## 不選的

- **把 `DirectionMemo.plans`／`walks` 也存進 `RouteMemo`，跨 tick 不重算**：它們也只讀路網、線與設定，可以留；但這次改完卡住時已經 17–23 ms，再多留兩種東西要多管上限與鍵。等量到需要時再做。
- **不讓卡住的車每一步都試出發**：會改行車結果（golden、replay 都會動），不是這張單的範圍。

- 外部專案：沒有用到；`PathMemo` 是這個專案自己的。
