### 363. 切速度、點建設、買地不在主執行緒上卡（玩家回報 82.1 #1、77.1 #2）

2026-10-23，遊戲規劃 session_014nUBHbE9mSK4qXHHgm8xCQ 派工（NEXT_PRIORITIES §22.2 第 10h 名的第一個 PR），實作 session_011kVCxFJEULkYyGGU7emgsx（`claude/perf-actions-82-1`）。存檔版本、golden schema、SaveFixtures、ReplayFixtures 都不動；GameCore 不動。

**玩家回報**（82.1，iPad（A16），iPadOS 26.6.2）：「車站過多時 會卡頓／切換時間 會卡頓／……｜切換速度、點擊建設、購買土地」；77.1 #2（同一台）：列車多時跨過 24:00 與 06:00 切速度會卡頓，之後 App 結束。

**量法**（diagnosing-bugs）：只在要求時跑的報告測試 `ActionCostReportTests`，44 站、4 條線（每條 11 站、站距 1.5 km）、第 30 天，Linux release：

```sh
ACTION_COST_REPORT=30 swift test -c release -Xswiftc -enable-testing --filter ActionCostReportTests/testWhatTheThreeActionsCost
```

| 動作 | 改之前 | 改之後 |
| --- | --: | --: |
| 一次編輯（`performEdit(buildTrackNode)`） | 3.8 ms | 0.12 ms |
| 買一格地圖再復原 | 62–76 ms | 60 ms |
| 切速度三次（白天） | 0.01 ms | 0.01 ms |
| 選建設工具再離開（白天） | 0.01 ms | 0.01 ms |

找到兩個原因，各改一個變數，結果逐值相同（每一步都和不記住時算出的一樣，測試裡比對）：

1. **每次編輯都把整張地的車站涵蓋率重算一次**：`noteNextSteps` → `NextSteps` → `CoverageSummary`，走過每一格土地（callgrind：一次編輯 97% 在這裡）。改成 `CoverageMemo`：只在地圖範圍、土地或開著的車站位置變了才重算。回歸測試 `NextStepsTests.testTheCoverageIsCountedAgainOnlyWhenStationsOrLandChange` 數重算次數。
2. **夜裡切速度、離開建設工具、停止選地時，在主執行緒上試跑一整晚**：`isPausedForBuilding` 的 `didSet` 每次都讀 `nightSkip`。夜裡所有車都停著、又剛有過指令（上一次切速度、一次編輯）時，記住的試跑不算數，就在主執行緒上跑 `NightSkip.firstMove`（宜蘭線一晚約 30 ms，跨午夜約 160 ms；車多的世界更久）。所以在同一個 tick 裡第二次點速度、蓋完東西離開工具，每一下都卡一次；跨 24:00 與 06:00 正是它最長的時候。改成 `refreshNightSkipOfferOffTheMainActor()`：記住的試跑還算數才當場更新；暫停中交給背景試跑（決策 330 的「後來」）；在跑時交給下一個 tick 的背景試跑（決策 328），快轉鍵到那時才更新。快轉鍵本身被按下時仍然當場試跑（決策 330）。回歸測試 `NightSkipTests.testASpeedTapOrLeavingABuildingToolDoesNotRunAheadOnTheMainActor` 數主執行緒上試跑的次數（`nightSkipRunAheadOnMain`）：沒改時三次切速度多跑 2 次、離開工具多跑 1 次。

**沒有改的**：

- 買一格地圖約 55 ms 是讀那一格的土地（約 6.5 萬格）：`LandImport` 約 23 ms、GameCore 的 `expandLand` 約 22 ms、涵蓋率約 3.5 ms。一次 55 ms 是一下頓，不是一直卡；要再快可以在玩家點選地塊時先在背景讀好，留在 HANDOFF §7.1。
- 編輯後第一次讀 `trafficOverlay`（約 1.3 ms）、`situationAlerts`（約 1.2 ms）：小，不動。
- 2D 每幀與高倍速整個畫面重算（§22.2 第 10h、25a 名）：Linux 量不到 SwiftUI 繪圖，留給下一個 PR，HANDOFF §7.1。

**參考與開源**：`a91453/railway-reference-private` 的模擬器與地圖編輯器沒有對應的「涵蓋率快取」或「夜間快轉」；OpenTTD、Simutrans 的做法是把昂貴的統計放進每月或每天的批次，不是每次指令重算，和這裡「沒變就不算」同一個方向，沒有可以搬的程式。這兩處是本專案自己的程式。
