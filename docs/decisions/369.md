### 369. 夜間快轉的試跑不放在遊戲迴圈的 tick 裡

2026-10-23，遊戲規劃 session_01H5RHAwnA69n8EfAUSUrH52 派工（PLAYER_FEEDBACK 80.1 #2），實作 session_01GkNBvLaaXepvDwT3tWMTmC。玩家回報（80.1，iPhone 17 Pro，約 30 站、7 條線）：「一般操作增加月台就會當機」。存檔版本、golden schema、SaveFixtures、ReplayFixtures、GameCore 都不動。

**先量**（`.claude/skills/diagnosing-bugs/SKILL.md`）：在 Linux 用示範模式在台北車站鋪真實路線（21 站、7 條線、33 列車、657 段軌道），午夜後用路網工具加一座月台，量每個 tick 與預覽：

| 量的東西（毫秒，Linux） | debug | release |
| --- | --: | --: |
| 平常一個 tick（直接呼叫的路徑） | 62 | 11 |
| 加月台後的第一個 tick | 3,200～6,200 | 613 |
| 開局第一個 tick（同一個原因） | 4,400 | 753 |
| 月台模式的預覽（整平、價錢、文字、覆蓋），每讀一次 | 0.2～6 | 0.02～0.8 |

抽樣（gdb 在那個 tick 裡取堆疊）都落在 `NightSkip.firstMove(after:)` → `GameWorld.advance(ticks:)` → `minutesUntilNextDispatch` → 每條線的 `readyTrain`／`linePath` 找路。月台本身、預覽和 `TrackUpgrade`（#1059）那種以 `worldRevision` 當記憶鍵的每 tick 重算，都不是原因：月台模式的整平預覽雖然也以 `worldRevision` 當鍵，但路網工具會暫停遊戲，量到的每次也不到 1 ms（release）。

**原因**：夜裡所有列車都停著時，夜間快轉（決策 305）要把世界的副本往前跑到第一班車動，才知道快轉停在哪裡。記憶（`NightSkipMemo`）以指令版本當鍵，任何指令之後都不算數。決策 328 把這次試跑移到遊戲迴圈的 tick 工作裡（主執行緒外），但 tick 要等試跑跑完才算完：七條線在午夜時要跑約五個半小時的遊戲時間，Linux release 約 0.6 秒，手機更慢，傍晚更久。這段時間遊戲時間不走；這中間再下一個指令（再加一座月台），那個 tick 就被丟掉（決策 143），下一個 tick 又從頭試跑。所以在夜裡接連加月台，時間會一直停住，看起來像當機。決策 328 量的是三條線、每條一列車的世界（約 20 ms），沒有碰到。

**改法**（GamePresentation）：
1. `LoopTick` 不再帶 `NightSkipProbe`，`TickStep` 不再帶試跑結果；tick 只推進世界與讀交通。
2. 遊戲迴圈的 tick 放回之後（`finish(_:fromLoop:)`），`continueNightSkip(aheadOffTheMainActor:)` 不在主執行緒上試跑：記憶答不了，就交給 `lookAgainForNightSkip()`，暫停或在跑都一樣（以前只有暫停時用它）。它在主執行緒外、一次一個，和遊戲迴圈並行；快轉提示在找到之前維持原樣。
3. `lookAgainForNightSkip()` 找到的結果，只要那之後沒有指令就留下（以前要求世界完全沒變）。中間跑過的 tick 只是把世界照同樣的規則往前推，和試跑一樣，所以記憶在 `covers` 的範圍內仍然對。找到之後再看一次：答得了就更新提示，答不了（列車剛好在那時動了）才再試跑。
4. 「夜裡沒有車時自動快轉」在遊戲迴圈上要等記憶答得了才開始，所以會晚一兩個 tick 開始，停的時刻不變。
5. 直接呼叫的路徑（`advance(ticks:)`、`advance(realElapsed:)`、快轉按鈕）照舊：記憶答不了就在主執行緒上試跑。App 的遊戲迴圈不走那條路。

**改之後**（同一個世界，Linux debug，遊戲迴圈的路徑）：加月台後的 tick 約 160～240 ms（試跑在另一個執行緒同時跑），遊戲時間照常往前；試跑約 6 秒後跑完，提示出現，和主執行緒算的相同。改之前那個 tick 要等整個試跑（debug 3～6 秒）。

**測試**：`NightSkipTests.testTheGameLoopsTickDoesNotWaitForTheRunAhead`（在 `main` 上紅：tick 自己試跑完，沒有另外的試跑）：夜裡在跑的遊戲下一個指令，遊戲迴圈的下一個 tick 時間照走、試跑在旁邊進行、主執行緒沒有試跑、找到的提示和主執行緒算的一樣，中間多跑的 tick 不讓結果作廢。決策 328 的 `testTheGameLoopRunsAheadOffTheMainActor` 測的是 tick 裡試跑，由這個測試取代；`testASpeedTapOrLeavingABuildingToolDoesNotRunAheadOnTheMainActor` 在比對提示前多等試跑跑完。

**沒有改的、還不知道的**：
- 試跑本身的成本（GameCore 每個 tick 替每條線的待命列車找路）沒有動；要再快得改 GameCore 的調度（`minutesUntilNextDispatch` 的記憶），那是完整 tier，這次不做。
- 在台北站加一座月台後，平常的 tick 從 11 ms 變成約 18 ms（release）。看來是大站的月台越多，`berths(of:length:)` 與找路越貴；這次沒有查。
- 白天只要有一列車在動就不試跑；白天所有列車剛好都停著（例如都在終點站折返）時也會試跑，現在一樣不擋 tick。
- 玩家的「當機」也可能是閃退。沿著加月台的路徑（`addNetworkPlatform`、`addPlatformTrack`、車站面板的月台軌道選單）在這兩個世界都沒有抓到 trap；沒有存檔與指令紀錄，無法確定。實機確認見 PLAYER_FEEDBACK 80.1 #2。

**參考**：參考庫沒有夜間快轉或試跑可以搬。這次在 `60a7627` 的 `Simulator/reference_snapshot/`、`Railway/railway_game_reference_clean/`、`Railway/train_loop_reference_clean/` 找 skip to morning、fast forward、night skip、lookahead：只有 `railway_game_reference_clean/docs/logging_and_performance_metrics.md` 提到快轉時記錄速度倍數，沒有往前試跑（決策 305、328 也查過：`Simulator/` 的 runtime 每幀重算）。也沒有找外部專案：問題在這個專案自己的排程。

五方：
- **玩家**：夜裡加月台、改路線之後，時間不再停住；快轉提示晚一點出現。
- **鐵道迷**：無。行車、時刻表、快轉停的時刻都不變。
- **開發**：試跑從 tick 移到既有的背景試跑（決策 330 的後來），少了 `NightSkipProbe` 和 `TickStep` 的一個欄位；記憶的有效條件從「世界沒變」改成「沒有指令」，有測試。
- **美術**：無。
- **音樂**：無。
