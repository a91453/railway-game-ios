## B3：iPhone 橫拿的教學卡把說明切在半行

### 問題

`TutorialCardPlacement.compactMaxHeight` 是固定的 150 點（59.1 玩家嫌卡片太大後定的）。卡片的說明放在 `ScrollView` 裡，可捲的那塊高度是 150 減掉內距、按鈕列和狀態列；那塊又先放步驟列、標題，剩下給說明本文的高度跟行高沒有關係。第 1 關第 1 步在預設字級只看得到「目標：用鐵路連通兩座城鎮。軌道和車站都在」一行，第二行露出上半截（截圖 `iphone-landscape-lesson-card.png`，在 `a91453/railway-assets-private` 的 `game-art-previews/docs/art/ui-audit-2026-10-30/`）。

### 做法

不單純拉高（違反 59.1 的回報），改成**整行對齊**：

- App 量開著的卡片四個數：整張卡、說明那塊（捲動時是看得到的那段）、說明裡本文上面的高度（步驟列與標題）、本文一行的高度（用本文開頭兩個字、同一個字型量，中文的行比系統字型高）。
- `TutorialCardPlacement.compactMaxHeight(chrome:bodyTop:lineHeight:)` 算高度：150 點裡放得下幾整行就放幾行，但至少 `compactBodyLines`（2）行；外框（卡片減說明那塊）與本文上面照量到的加回去。結果一定停在一行的底。
- 還沒量到（剛出現的第一個排版）用原本的 150。
- 本文比算出來的短時，`ViewThatFits` 照舊選不捲動的版本，卡片照本身高度。
- 只用在 iPhone 橫拿（`verticalSizeClass == .compact`）；iPad 與直拿不變。

預設字級時，第 1 步從 150 點變成約 162 點（多出 0.75 行，讓目標的第二行整行看得到）；放得下 3 行以上的步驟反而可能比 150 矮一點（捨去不滿一行的部分）。字放大到連一行都放不下時，仍然給 2 行，再由 `frame(in:measure:)` 原有的「量矮一點讓地圖留一條」決定。

### 五方

- 玩家：第一眼看到的目標是完整的行，不再露出半行字讓人以為卡片壞了；卡片只多約 12 點，地圖照樣看得到（59.1 的回報）。
- 鐵道迷：無。
- 開發：版面規則在 GamePresentation，Linux 的 `TutorialCardPlacementTests.testOnAPhoneOnItsSideTheExplanationEndsOnAWholeLine` 先紅後綠；App 只多量四個數（`onGeometryChange`），沒有新的依賴。
- 美術：卡片外觀不變，只是說明停在整行。
- 音樂：無。

### 沒選的

- 單純把 150 改 170：第 1 步剛好整行，換一步、換語言或字級又會切半行，而且卡片變大（59.1）。
- 第一句以外收進「更多」：要改卡片的結構與 UI 測試，玩家多點一下；整行對齊已經讓目標整行出現。

### 驗證

- VERIFIED（Linux，本機）：`swift build --build-tests -Xswiftc -warnings-as-errors`、`swift test --skip-build --filter TutorialCardPlacementTests`。
- VERIFIED（GitHub Actions，macOS）：PR 的 iOS run（Xcode build、iPad 教學測試）綠；`only_testing` 的 `TutorialJourneyUITests/testTheWholeTutorialOnAPhoneOnItsSide` 綠（run 41038415165）。
- 截圖驗收（`website-screenshots.yml` run 41038424128，新加的 `WebsiteScreenshotTests.testLessonCard`）：第 1 關第 1 步的目標「目標：用鐵路連通兩座城鎮。軌道和車站都在「建設」裡蓋。」整兩行出現，沒有半行（`docs/art/ui-audit-2026-10-30/b3-lesson-card-after.png`）。一輪看完沒有要改的。只拍了 iPhone Pro 橫拿、深色、預設字級；英文、最大字級、iPhone SE 寬沒拍到（UNVERIFIED）。

## B2（續）：遊戲選單（☰）並排的三列給字

2026-10-30，同一個派工單，分支 `uib-b2-menu-labels`。出處：`UI_AUDIT_2026-10-30.md` §3 B2，一起看 `UI_GAPS_2026-10-30.md` 的 B-1、D6、D11、D12。

### 問題

`HUDView` 的 ☰ 第一層有三列並排（捷徑：教學、明信片、成就；說明列：說明、回報問題，加目標／觀光或「更多」；最後一列：放空模式、設定），都是 `.controlGroupStyle(.compactMenu)`（決策 226 之後、383、414：為了第一層留在 6 列）。iPhone 與 iPad 都只有圖示，玩家要猜哪個是「設定」（截圖 `iphone-landscape-menu.png`、`ipad-portrait-menu.png`）。

### 做法

- `GameMenuLayout.itemStyle(compactHeight:)`：高度夠（`verticalSizeClass == .regular`，實際上是 iPad：iPhone 只能橫拿，`project.yml`）時 `.titled`，App 用 `.controlGroupStyle(.automatic)`，系統在選單裡畫成圖示下有字的中型項目；iPhone 橫拿（compact）維持 `.iconsOnly`（`.compactMenu`）。
- `GameMenuLayout.height(itemStyle:)` 估第一層高度（一般列 44、並排列有字 72／只有圖示 48、兩段之間 8）：有字約 364 點，放不進 iPhone 橫拿狀態列與 HUD 下面約 330 點，所以橫拿不給字；iPad 最矮的橫拿也放得進。`GameMenuLayoutTests.testTheRowsSideBySideShowTheirTitlesWhereTheScreenIsTallEnough` 釘住。第一層的列數、順序都不變（還是 6 列，回到開始畫面第 3 列）。
- **B-1**：設定的「規則」一列（`SettingsView.eventsSection`）點了沒反應，因為一局的規則開局就定了（決策 258）。列名下加一行次要色小字「開新遊戲時選擇。」，不再像壞掉的按鈕。
- **D11**：說明多一條「怎麼把路網分享給朋友？」（`HelpGuide` 的 `shareNetwork`，營運組）：遊戲選單 →「做明信片」→「分享路網」（決策 409）。搜尋「分享」「朋友」「明信片」找得到。`GameMenuLayoutTests.testHelpSaysHowToShareTheNetwork`。
- **D6、D12** 不在這一項：D6（快車在單線頁最底）跟 B7 一起做，D12（遊戲中選挑戰）跟 B6 一起做，都改別的畫面。

### 五方

- 玩家：iPad 一眼讀得到「設定」「說明」「教學」；橫拿手機的第一層照舊 6 列都點得到；規則列不再像壞掉；說明搜得到怎麼分享路網。
- 鐵道迷：無。
- 開發：規則在 GamePresentation 有 Linux 測試；App 只換 ControlGroup 的樣式（系統樣式），識別碼不變，UI 測試照舊用 `menu.settings` 等找。
- 美術：用系統選單的中型項目，不畫新圖示。
- 音樂：無。

### 沒選的

- iPhone 橫拿也給字：第一層變高約 70 點，最後一列（設定）又會超出螢幕（決策 226 之後 `SettingsUITests` 紅過）。
- 把「設定」移回第一層的一列：第一層變 7 列，超過 `rowsInReach`。

### 驗證

## B1（續）：iPhone 橫拿打開「路線」先看到線

2026-10-30，同一個派工單，分支 `uib-b1-lines-first`。出處：`UI_AUDIT_2026-10-30.md` §3 B1。

### 問題

決策 481 把路線面板做成「入口列在上、短清單在下」：整個路網、進階、新路線…、可收購的真實路線，再來才是線。iPhone 只能橫拿（`project.yml` 的 iPhone 方向只有兩個橫向），面板約 272 點高，導覽列之後只放得下「整個路網」與進階那列（進階的開關列約 115 點高）；決策 486 把搜尋、篩選、排序改成清單裡的一列也沒救到，打開面板一條線都看不到（截圖 `iphone-landscape-lines.png`）。

### 做法

- `LinesListControls.parts`（GamePresentation）決定清單的部分由上而下的順序：釘住（`.pinned`，iPad 與高度夠的面板）照舊是入口列、新路線的表單、線；清單裡一列（`.inline`，iPhone 橫拿）改成搜尋那列、線、入口列、新路線的表單。新的 `LinesListPart` 列出這四個部分。`LinesPanelNavigationTests.testAShortPanelShowsTheLinesBeforeTheOtherRows` 釘住，先紅（API 不存在）後綠。
- `LinesPanel` 照 `parts` 排（`ForEach` 加 `listPart(_:)`），各部分的內容與識別碼都不變；從一條線的頁回來仍停在那條線（決策 481 之後）。
- 第一輪截圖驗收（run 41073077163 重跑）：線排到前面後，面板打開只看到搜尋那列、「路線」小標題和第一條線的上半截。面板的標題已經是「路線」，所以矮的面板不再給線那一段小標題（`LinesListControls.showsLinesHeading`），段與段之間也改窄（`.listSectionSpacing(.compact)`），讓第一條線整列出現。
- 「新路線…」打開時表單接在它下面，也就是清單最後；開始選站（`listsLinesFirst` 變 false）照舊整個換成新路線在最上面的排法（決策 299）。
- UI 測試：`ToolbarSmokeTests` 的 `setAdvanced` 在 iPhone 不再先往上捲到「整個路網」，直接由 `bringIntoView` 往下找開關；`openLinePage` 找不到任何一條線的列（清單停在下面的進階、路網列，上面的線還沒做出來）時先往上拖到有線的列；`WebsiteScreenshotTests.testLinesListAndLinePage` 從線的頁回來後往下找「整個路網」（不再用 `dragBack`）。第 1 關（`LessonUITests`）還沒有線，面板是新路線在最上面的排法，不受影響。

### 五方

- 玩家：一打開「路線」就看到自己的線和它們的狀況；路網開關、進階、新路線在清單最後，捲到底就有。
- 鐵道迷：無。
- 開發：順序是 GamePresentation 的一個值，有 Linux 測試；App 只換排列，識別碼不變；三支 UI 測試跟著改捲動方向。
- 美術：沒有新元素，列的樣子不變。
- 音樂：無。

### 沒選的

- 入口列收成一列四顆小鈕放在線上面：四個入口有兩個要說明文字（路網的摘要、可收購的數量），只有圖示要猜（B2 才剛為了這個給 ☰ 加字）；而且進階是開關，不是按鈕。
- 「新路線…」搬到導覽列的 ＋：教學與第 1 關的路徑、UI 測試都靠清單裡的 `line.new`，改動大；捲到底就有，先不動。
- iPad 也改：iPad 的面板夠高，入口列在上時線也看得到，不改。

### 驗證

- VERIFIED（Linux，本機）：`swift build --build-tests -Xswiftc -warnings-as-errors`；`LinesPanelNavigationTests` 15 個全綠（新測試先因 API 不存在編不過）。
- iPhone 的 UI 測試與截圖驗收結果寫在 PR。
