## B3：iPhone 橫拿的教學卡把說明切在半行

### 問題

`TutorialCardPlacement.compactMaxHeight` 是固定的 150 點（59.1 玩家嫌卡片太大後定的）。卡片的說明放在 `ScrollView` 裡，可捲的那塊高度是 150 減掉內距、按鈕列和狀態列；那塊又先放步驟列、標題，剩下給說明本文的高度跟行高沒有關係。第 1 關第 1 步在預設字級只看得到「目標：用鐵路連通兩座城鎮。軌道和車站都在」一行，第二行露出上半截（截圖 `iphone-landscape-lesson-card.png`，在 `a91453/railway-assets-private` 的 `game-art-previews/docs/art/ui-audit-2026-10-30/`）。

### 做法

不單純拉高（違反 59.1 的回報），改成**整行對齊**：

- App 量開著的卡片四個數：整張卡、說明那塊（捲動時是看得到的那段）、說明裡本文上面的高度（步驟列與標題）、本文一行的高度（用本文開頭兩個字、同一個字型量，中文的行比系統字型高）。
- `TutorialCardPlacement.compactMaxHeight(chrome:bodyTop:lineHeight:)` 算高度：150 點裡放得下幾整行就放幾行，但至少 `compactBodyLines`（2）行；外框（卡片減說明那塊）與本文上面照量到的加回去。結果一定停在一行的底。
- 還沒量到（剛出現的第一個排版）用原本的 150。
- 本文比算出來的短時，`ViewThatFits` 照舊選不捲動的版本，卡片照本身高度。
- 只用在 iPhone 橫拿（`verticalSizeClass == .compact`）；iPad 與直拿不變。

預設字級時，第 1 步從 150 點變成約 162 點（多出 0.75 行，讓目標的第二行整行看得到）；放得下 3 行以上的步驟反而可能比 150 矮一點（捨去不滿一行的部分）。字放大到連一行都放不下時，仍然給 2 行，再由 `frame(in:measure:)` 原有的「量矮一點讓地圖留一條」決定。

### 五方

- 玩家：第一眼看到的目標是完整的行，不再露出半行字讓人以為卡片壞了；卡片只多約 12 點，地圖照樣看得到（59.1 的回報）。
- 鐵道迷：無。
- 開發：版面規則在 GamePresentation，Linux 的 `TutorialCardPlacementTests.testOnAPhoneOnItsSideTheExplanationEndsOnAWholeLine` 先紅後綠；App 只多量四個數（`onGeometryChange`），沒有新的依賴。
- 美術：卡片外觀不變，只是說明停在整行。
- 音樂：無。

### 沒選的

- 單純把 150 改 170：第 1 步剛好整行，換一步、換語言或字級又會切半行，而且卡片變大（59.1）。
- 第一句以外收進「更多」：要改卡片的結構與 UI 測試，玩家多點一下；整行對齊已經讓目標整行出現。

## B1（續）：iPhone 橫拿打開「路線」先看到線

2026-10-30，同一個派工單，分支 `uib-b1-lines-first`。出處：`UI_AUDIT_2026-10-30.md` §3 B1。

### 問題

決策 481 把路線面板做成「入口列在上、短清單在下」：整個路網、進階、新路線…、可收購的真實路線，再來才是線。iPhone 只能橫拿（`project.yml` 的 iPhone 方向只有兩個橫向），面板約 272 點高，導覽列之後只放得下「整個路網」與進階那列（進階的開關列約 115 點高）；決策 486 把搜尋、篩選、排序改成清單裡的一列也沒救到，打開面板一條線都看不到（截圖 `iphone-landscape-lines.png`）。

### 做法

- `LinesListControls.parts`（GamePresentation）決定清單的部分由上而下的順序：釘住（`.pinned`，iPad 與高度夠的面板）照舊是入口列、新路線的表單、線；清單裡一列（`.inline`，iPhone 橫拿）改成搜尋那列、線、入口列、新路線的表單。新的 `LinesListPart` 列出這四個部分。`LinesPanelNavigationTests.testAShortPanelShowsTheLinesBeforeTheOtherRows` 釘住，先紅（API 不存在）後綠。
- `LinesPanel` 照 `parts` 排（`ForEach` 加 `listPart(_:)`），各部分的內容與識別碼都不變；從一條線的頁回來仍停在那條線（決策 481 之後）。
- 「新路線…」打開時表單接在它下面，也就是清單最後；開始選站（`listsLinesFirst` 變 false）照舊整個換成新路線在最上面的排法（決策 299）。
- UI 測試：`ToolbarSmokeTests` 的 `setAdvanced` 在 iPhone 不再先往上捲到「整個路網」，直接由 `bringIntoView` 往下找開關；`WebsiteScreenshotTests.testLinesListAndLinePage` 從線的頁回來後往下找「整個路網」（不再用 `dragBack`）；`LessonUITests` 的第 1 關在「加入選取的車站」沒出現時才去找「新路線…」（以前只在它已經存在時才點，現在它可能在面板外）。

### 五方

- 玩家：一打開「路線」就看到自己的線和它們的狀況；路網開關、進階、新路線在清單最後，捲到底就有。
- 鐵道迷：無。
- 開發：順序是 GamePresentation 的一個值，有 Linux 測試；App 只換排列，識別碼不變；三支 UI 測試跟著改捲動方向。
- 美術：沒有新元素，列的樣子不變。
- 音樂：無。

### 沒選的

- 入口列收成一列四顆小鈕放在線上面：四個入口有兩個要說明文字（路網的摘要、可收購的數量），只有圖示要猜（B2 才剛為了這個給 ☰ 加字）；而且進階是開關，不是按鈕。
- 「新路線…」搬到導覽列的 ＋：教學與第 1 關的路徑、UI 測試都靠清單裡的 `line.new`，改動大；捲到底就有，先不動。
- iPad 也改：iPad 的面板夠高，入口列在上時線也看得到，不改。

### 驗證

- VERIFIED（Linux，本機）：`swift build --build-tests -Xswiftc -warnings-as-errors`；`LinesPanelNavigationTests` 15 個全綠（新測試先因 API 不存在編不過）。
- iPhone 的 UI 測試與截圖驗收結果寫在 PR。
