## 改法

`GameWorld.resolveDeadlock(memo:)` 在決策 571 續的逆向之後、放棄之前，加最後一步：

- 死結裡有跟車中的列車（`stuck` 裡不是出發的請求）時，才做這一步。
- 照列車編號找：
  - 停在站上、班次已經該開（`departureDue` ≤ 現在）的列車；
  - 它的請求是開往下一站；
  - 不算死結裡那些跟車中列車「等著的軌道」，它整條路都沒人佔、沒人擋（`reserving(_:ignoringClaimsOf:memo:)`）。
- 找到第一列就讓它開（`setOff`、`serve(departureOf:)`），回傳它。

不算的只是死結裡跟車中列車的「等著」。別的列車佔著的、擋著的（fouling）軌道，以及不在死結裡的跟車中列車等著的軌道，照舊擋。

`TrackHolders.ignoringClaims(of:)` 回傳同一份佔用，只拿掉那幾列的等待；決策 308 的 `released` 照舊。

閉塞開（擬實，決策 212）時跟車中的列車沒有「等著的軌道」，所以這一步不做（`reserving(_:ignoringClaimsOf:)` 在 `blockSections` 時回傳 nil）。

那列跟車中的列車之後照常：等開出去的班過了再走。在小世界裡，它最後拿到整條路。

## 慢（派工單的第三項，沒修）

決策 556 續的下一步 3：擬實 25 小時逐分跑了 2,723 秒，每遊戲分鐘約 1.8 秒。

- 擬實，從 08:00 的檔跑到 08:30，用 gdb 取樣 24 次。
  - 24 次全在 `trafficPlan(parts:)`。
  - 約 21 次在 `planTrafficOvertakes` → `overtakeTrackFree` → `trafficOvertakeTracks` → `trafficTrack(_:at:berth:)` → `trafficPath` → `networkPath` → `TrainRoute.shortest`（Dijkstra）。
  - 3 次在 `planHeadwayOvertakes` → `headwayOvertake`。
- 簡單＋行車控制時，文湖線與機場捷運第 6 小時以後也是同一處（gdb 看兩個都在 `trafficOvertakeTracks` → `trafficTrack` → `networkPath`）。

原因：`TrafficPlanKey` 一變（任何一列車到站、出發、執行狀態改變），整份計畫就重算。`plan.sidings`、`plan.moves` 的快取只活在一份計畫裡，所以每次重算，每列車每個停靠的找路都再做一次。

修法（建議，另開 PR）：

- 把 `trafficTrack` 的結果跨計畫快取在 `TrafficParts`。
  - 鍵：列車編號、車長、時刻或進路偏好的輸入、前一個月台、點、月台、下一個點。
  - 列車停在第一站時的第一段不快取：它的車身位置會影響結果。
  - 改到路網的指令（鋪軌、拆軌、月台、轉轍器）就清掉。
- 結果要和現在逐一相同：golden、replay 不動，用 `TrafficControlPropertyTests` 比對。
