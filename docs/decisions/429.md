### 429. 3D 路口的紅綠燈照時鐘換燈

2026-10-27，遊戲規劃 session_01YGNNuoQekRm2qcVxoPT8ME 派工（派工單 K，NEXT_PRIORITIES §22.12 第 1 項的第一步），實作 session_01JMHz9YG6gwHn5qzj9T7myX。號碼依 #1041：決策 429；存檔版本、golden schema 不動。GameCore、`GoldenScenarios/`、`SaveFixtures/`、`ReplayFixtures/` 不動：號誌只在畫面上。接在決策 355（路面標線與街道小物）之後。

**之前**（決策 355）：3D 地圖路口的號誌不會換。最寬的那條路（和跟它幾乎同向的臂）永遠綠燈，其他永遠紅燈（355「沒有選的做法」第 1 點）。

**做了什麼**：

1. **規則**（`Map3DSignalTiming`，GamePresentation，Linux 可測）：照參考庫 TW3D 包的 `SIGNAL_TIMING`、`signalPhase` 搬秒數。
   - 週期 70 秒。
   - 主幹道：0–32 秒綠，32–35 秒黃，35–70 秒紅。
   - 橫向道路：0–36 秒紅，36–64 秒綠，64–67 秒黃，67–70 秒紅。
   - 兩次全紅：35–36 秒（1 秒）、67–70 秒（3 秒）。主幹道與橫向道路不會同時是綠或黃。
   - `light(_:at:)` 對負的秒數也照週期算（`((t % 70) + 70) % 70`，同參考）。
2. **每個路口錯開**：參考庫全城同一個時鐘。這裡每個路口用它在世界裡的位置（離世界原點的公尺數，四捨五入到 1 m）算 `map3DRandom(x, z, salt: 429)`，分成 4 組，每組晚四分之一週期（0、17、35、52 秒）。
   - 同一個路口每次同一組；場景的原點在哪（串流建的 chunk 原點不同）不影響：`Map3DRoadMarkings(_:origin:)` 帶場景的原點。
   - 一個路口的所有號誌同一組，所以主幹道和橫向道路照樣輪流。
3. **`Map3DRoadMarkings.Signal`** 不再記寫死的 `go`，改記 `road`（`.main` 主幹道／`.cross` 橫向道路）與 `group`。主幹道的判斷就是以前 `go` 的條件（和最寬的臂 `|cos| ≥ 0.7`）。
4. **畫的時候選亮哪一顆**（選 (a)，見下）：
   - 號誌照「時鐘不換燈時的樣子」放：主幹道用 `signalGo`（綠），橫向用 `signalStop`（紅），實例多帶 `Map3DInstance.group`（不進 shader 的 80 bytes）。
   - 新增 `Map3DProp.signalAmber`（黃燈亮）。三個模型外型、頂點位置完全一樣（`addSignal(_:lit:)`），只差亮的那顆。
   - `Map3DPropRuns`：chunk 的街道小物照（模型、組別）排序。畫面每個（模型、組別）一段實例；太陽陰影圖每個模型一段（燈色不影響影子，陰影圖的 draw call 不變）。
   - `Map3DSignalTiming.Models.model(_:group:clock:)`：每幀每段照時鐘選紅、黃、綠其中一個模型的頂點 buffer 畫。實例 buffer 在 chunk 建好時做一次，**不每幀重建**。
   - 時鐘：`Map3DView.updateUIView` 每個 tick 從 `world.clock` 做一個 `Map3DSignalTiming.Clock` 給 `Map3DMetalView.signalClock`。沒有時鐘（設定頁的預覽、幀時間測試）就照決策 355 的樣子。
5. **時鐘跑太快時不換燈**：一個週期換算成真實時間短於 4 秒就不換，維持主幹道綠、橫向紅。
   - 一個速度每真實秒跑 `tenthsPerTick` 個遊戲秒（決策 12：每 0.1 秒一個 tick，`x1` 是真實時間）。換燈的條件是 `70 ≥ 4 × tenthsPerTick`，即 17.5× 以下。
   - 所以 1×、10× 換燈（10× 一個週期 7 秒）；60×（1.2 秒）、600×、1200×、6000× 不換。
   - 暫停時照「恢復後的速度」（`GameClock.runningSpeed`）判斷：在 600× 暫停不會突然變成某個時刻的燈，在 10× 暫停就停在當下那個燈。
   - 3D 跟車最高 10×（決策 360），跟車時都會換燈。
6. **減少動態效果**：打開時**照樣換燈**。換燈是顏色每幾十秒變一次，不是移動，也不是閃爍（motion skill 第 3 節只停掉滑、縮放、彈、搖與自動循環的閃動）；號誌照時鐘的顏色也是遊戲狀態的一部分（之後車流會跟著停）。之後小綠人的閃爍才要在打開時停掉（不在這裡）。
7. **省電畫質**（`Map3DQuality.saving`）照舊畫號誌，也照樣換燈：`leftOutWhenSaving` 不含號誌，換燈不加三角形。

**為什麼選 (a)（實例分段、每段選模型）不選 (b)（shader 照 uniform 時間決定亮哪顆）**：
- (a) 全部在 Swift，規則與分段都在 GamePresentation，有 Linux 測試；Metal 端只是同一個 instanced pipeline 換一個頂點 buffer。
- (b) 要在每個號誌頂點標出「這是哪一顆燈」、在實例帶組別、改 `Map3DInstance` 的 80 bytes 版面（所有列車、行人、車輛的實例都跟著變）、shader 加分支與 uniform。Metal 在 Linux 編不到，只能靠 iOS CI；所有用 instanced pipeline 的東西都會被影響。
- (a) 的代價是 draw call：每個細節 chunk 的號誌從最多 2 次變最多 8 次（2 條路 × 4 組）。號誌本來就是幾十個實例一段，多出來的是 CPU 端的 draw call，不是三角形。

**五方**：

- **玩家**：路口的燈會換了，綠、黃、紅，大路與小路輪流，不同路口不一起換；高倍速時燈不閃。
- **鐵道迷**：無（號誌是道路的，不是鐵道的；週期照台北大路口的做法縮成 70 秒）。
- **開發**：規則與分段在 GamePresentation，有 Linux 測試；不動 GameCore、存檔、shader 與實例版面；每個細節 chunk 最多多 6 次 draw call、不加三角形。
- **美術**：模型外型與顏色不變（`addSignal` 本來就有三顆燈），黃燈用原本的 `signalLights[1]`；夜裡亮的那顆照樣發光。
- **音樂**：無（有聲號誌另開派工單）。

**沒有選的做法**：

1. **(b) shader 照時間決定亮哪顆**：見上。之後若要倒數數字或小綠人（要逐秒變化的貼圖），再看要不要改成 shader。
2. **全城同一個時鐘**（參考庫的做法）：整座城的燈同時變，鏡頭拉遠看很假；每個路口一個任意偏移又要每個路口一段 draw call。4 組是兩者之間。
3. **高倍速時把週期拉長**（例如照真實時間 70 秒換）：燈和遊戲時鐘、之後的車流對不上；派工單要的是不閃。
4. **每幀重建 chunk 的實例 buffer**（照燈色換模型索引）：每幀複製幾千個 80 bytes 的實例，不必要。
