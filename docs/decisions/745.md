### 745. 設站時能整平就安靜整平，不再說坡度

2026-11-14，雲端 thread session（「修好月台坡度問題」工作串），分支 `claude/project-thread-jhlqs9`。作者 2026-11-14 自己玩的回報：「第三就是老問題 月台坡度」；截圖是實景地圖的「車站」模式，地圖上的確認膠囊寫「800 公尺內：居民 33,678・工作 11,516／坡度 9‰：整平 80 公尺」，右邊路網面板寫「坡度 9‰：按 ✓ 會把這 80 公尺整平（重鋪這段軌道 NT$ 115,200）」。同一則回報也說「鋪設介面好像還是太雜」。

不動 GameCore、存檔版本、golden、replay：只改 GamePresentation 給玩家看的文字。

## 1. 查到什麼

- 整平早就自動做（決策 190）：實景地圖的地面（Copernicus DSM，含建物、取整數公尺）讓一般站距的一段幾乎都有 2–10‰ 的小坡，GameCore 的月台要水平（決策 164），所以按 ✓ 時先把月台那一段重鋪成水平，錢算進 ✓ 的價錢。
- 但每一次設站，畫面都把它說出來：膠囊多一行「坡度 N‰：整平 X 公尺」、面板多一句「按 ✓ 會把這 X 公尺整平（重鋪這段軌道 $Y）」、鋪軌預覽多一句「有坡度：在這裡設月台時會先整平」、建好的訊息多一句「已為月台整平 X 軌道，花費 $Y」。實景地圖上幾乎每一段都有坡，所以玩家每蓋一站都看到「坡度」，像是出了問題；作者 2026-10-13 就說過「我真的不想考慮……還要考量坡度」（PLAYER_FEEDBACK 54.1 #6）。
- 這就是「老問題」又出現的原因：規則早就幫玩家處理了，但字還在叫玩家處理。

## 2. 改了什麼

1. 能整平時（`PlatformLevellingPreview.cost` 有值）：
   - 地圖膠囊不再多那一行：`PlatformLevellingPreview.caption(in:)` 改回傳 `String?`，能整平時是 `nil`。
   - 路網面板只寫「在這裡設 X 的月台」（`networkDraftText()` 的月台那段）。
   - 建好的訊息不再說整平了多少、花多少（`addNetworkPlatform`）。
   - ✓ 的價錢照舊含整平的錢（決策 190、245），玩家付的錢一塊都不變。
2. 鋪軌預覽不再寫「有坡度：在這裡設月台時會先整平」（`NetworkPreview.text(in:)`）：兩端高度照舊寫（「0 m → 8 m」）。
3. 整平不了時照舊：膠囊「坡度 N‰：無法整平」、面板寫原因與「另鋪一段約 100 公尺的短軌道」（決策 510）。那時玩家真的要做點什麼，所以要說。
4. 教學的選址照舊只看能不能整平（決策 190 第 5 點），文字不受影響。

## 3. 五個角度

| 角度 | 理由 | 分數（1–5） |
| --- | --- | ---: |
| 玩家 | 設站不再每次看到「坡度」，像真的遊戲一樣點了就蓋；真的蓋不了才說 | 5 |
| 鐵道迷 | 真實的車站本來就蓋在整平過的路基上，玩家不用看到工程細節；規則不變 | 3 |
| 開發 | 只刪字，GameCore、存檔、golden 不動；測試改成「能整平時不說坡度」 | 5 |
| 美術 | 確認膠囊少一行，比較不會擋住路線（同一天另一則回報） | 4 |
| 音樂 | 無 | 1 |

## 4. 沒有選的

- **(a) 讓月台放在小坡上（例如 ≤ 10‰）**：要改 GameCore 的月台規則（決策 164）與列車在月台上的停車，跑完整 tier，舊存檔的月台還是水平的；玩家看到的結果和現在一樣（蓋得起來），所以不值得。
- **(b) 整平不收錢**：錢是重鋪軌道真的花的，免費會讓「先鋪長線、到處設站」比鋪短軌道便宜；而且價錢本來就只在 ✓ 上出現一次，不另外說就不雜。
- **(c) 只在「進階」打開時說坡度**：「進階」是路線面板的裝置偏好（決策 196），GamePresentation 的工具文字拿不到；需要看坡度的玩家可以看鋪軌預覽的兩端高度。
