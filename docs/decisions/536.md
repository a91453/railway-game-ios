## 做法

1. `RealLineStock.setKey(ofRealLine:)`（`Sources/GamePresentation/RealLineStock.swift`）：收購紀錄的 `realLine`（`"tra:NEIWAN"`）拆成系統與線，台鐵支線用 `RealBranchLine.names` 的中文名，交給 `Map3DRealTrains.formation(system:id:name:)`（由原本的 `formation(system:line:)` 拆出，只看線的 id 與名字）。所以收購前後是同一張表，不另抄一份。
2. `RealLineStock.setKeys(in:)`：每筆鐵路收購，那條線的 `assignedTrains` 全部用這個 key，包括收購時買的車與之後玩家加到那條線的車；移到別條線就回到照車種、性能挑。`Map3DTrains.Heights(world:)` 先查這張表，取代決策 466 只認三鶯線的寫法（三鶯的結果相同）。
3. 之後照舊走 `Map3DTrainSet.variant(of:number:locked:)` 與 `set(forKey:count:locked:)`：`dieselRailcar` 不論幾節都是 DR1000（`set(forKey:)` 只有 `dieselExpress` 才分 DR1000／DR3100）；`emu800` 照車號分三款，和沒收購的區間車一樣；車輛包鎖住時的退回規則不變。
4. 車名：點車的卡片（`InspectorView`）與「建設 → 列車」（`TrainControls`）多一行「DR1000 柴油客車」「淡海輕軌列車」「北捷 C371」「EMU900 區間車」（`GameWorld.boughtStockText(of:in:)`，id `train.stock`）；路線清單那一列寫「3 列 · DR1000 柴油客車 · 每 30 分」（`lineTrainsRowText`，六家、沙崙寫「EMU500／800／900 區間車」）。自己蓋的線不變。

## 性能

評估後**不換**，只換外觀與名字：
- 台鐵支線：DR1000 的性能（`dieselRailcar`，加速 1.5、減速 2.448 km/h/s、110 km/h）和收購時給的「標準」（1.5／2.5、110）只差減速 0.052，跑起來看不出差別；而且 `PerformancePreset(matching:)` 會先認成同曲線的「柴聯自強」，卡上反而寫錯。
- 輕軌、捷運：收購時用的是遊戲的車種（C、A、B），真實路線的時刻表是照這組性能排進去的（決策 400、489、493 量過每班都發得出去）；換性能要重量這些情境，也動到 `RealLineAcquisition.build` 的指令，不在這張單裡。
- 要換的話：在 `RealLineAcquisition.build` 收購時多下 `setTrainPerformance`（GameCore 已有的指令，不升存檔），重跑 `DanhaiDepotTests`、`LiujiaLineTrainsTests`、`AcquisitionReportTests`；卡上的性能名稱要先解決柴聯自強／DR1000 同曲線的問題。

## 留下的缺口

- 節數是 GameCore 的車：新北投、小碧潭支線收購後 6 節（真車 3 節），三鶯線 3 節（真車 2 節），畫面照遊戲的節數畫。要改得動 `DemoRealLines.cars(ofSystem:)` 與收購的月台長度，另派。
- 2D 地圖上的列車顏色（`TrainLivery`）沒有跟著換。
- 新北投、小碧潭支線先不加機廠（作者 2026-11-01 問，遊戲規劃決定）：兩條各只有 3 組車，過夜北投 2／新北投 1、七張 1／小碧潭 2，終點站兩條軌道就停得下；真實的北投機廠、新店機廠（小碧潭站就在它旁邊）是淡水信義線、松山新店線的機廠，等那兩條主線可以收購時再一起加。
- 安坑輕軌在出售清單裡但買不到（`metro_runs.json` 沒有它的班次）；遊戲規劃已轉給 LOOPLRT（決策 535），這裡不修。
