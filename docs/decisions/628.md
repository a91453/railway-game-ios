行車控制關掉的配置都不死結（列車互穿），所以玩家看到的「死結」都是行車控制開著（App 開新局的預設）。

**三個原因**，每個都用一個變數驗證過：

1. **待避線放在月台上**：`passingLoopPlan(along:)` 只試每條邊的正中央。玩家一次畫完的單線只有一條邊，中央剛好是中間那站的月台；`PassingLoopPlan` 只看幾何，計畫「成功」，蓋的時候 `addTrackPlatform` 才因重疊拒絕，所以「＋」整個退回、線停在 1 列。只換這一點（避開月台）後，所有「＋」配置都 3 列、死結 0。
2. **手放的列車沒有地方交會**：每站一個月台、站間單線，三列各站一站，各自等別人站著的月台，物理上無解，排程怎麼改都一樣（行車控制關掉就不死結，證明不是排程的錯）。決策 264 的提醒只在**兩條線共用**單線時才出現，一條線自己的車互卡時什麼都不說。
3. **多出的車擋路**：加了待避線後線的容量（`lineTrainsInService`，依時間算）可能還是比車數少，例如 3 列只排得進 2 列；第 3 列成了備用車，若站在單線的月台上（決策 264 把擋路的車放回路線起點），就擋住其他車。只改這一點（不放回）後「手放→修」的一般規則從 1,014 分死結變成 0。

**排除的假說**：GameCore 的路線預約（`routeWaits`）本身沒錯，行車控制下一列車一次預約到下一站，三列各佔一站時沒有任何一列能預約到下一站，這是配置問題，不是排程問題；示範地圖（高鐵 3 條線、宜蘭線 8 條線）都沒有新的誤報。

## 選的

1. **待避線避開月台**（`passingLoopPlan(along:from:to:)`）：先試每條邊的中央，但只收離同一條邊上所有月台至少 `PassingLoopPlan.reach` 的計畫；都不行時，取每條邊上「月台之間沒有月台的段落」的中點，先取兩頭是這段路線兩站的段落，再取長的。
2. **一條線自己的車也算**（`singleTrackShortfall(of:)`）：有共用的不足照舊；否則線上**站在軌道上的**車（`trainsOnTrack`）有 2 列以上時，用決策 264 的 `passingPlaceShortfall` 算它自己。只算在軌道上的：沒放上軌道的備用車不擋任何人，也不提醒（`LineLossFixesTests` 的 60 列備用車就是這樣）。
3. **在三個地方告訴玩家**：
   - 配車到線上、或在線卡設列車數時，訊息後面加一句：「單線上 A—B 沒有地方讓 N 列車交會，會互相等著不動：請在路線卡按『在這裡加待避線』。」
   - 站長的 `noPlaceToPass` 改成一般說法：「『線名』的列車在單線上沒有地方交會。點一下加待避線。」
   - 線卡本來就有的不足區塊與「在這裡加待避線」按鈕（決策 264），文字在只有自己一條線時改成「線名 的 N 列車在 A—B 的單線上沒有地方交會，會互相等著不動。在那裡加一處待避線就能交會。」
4. **一鍵加齊**：線卡的按鈕一次加上 N 列車需要的全部待避線（N−1 處，一個可復原的指令），不必按好幾次。
5. **擋路的車**：加待避線時擋路的車，照決策 264 拿下、蓋好後放回；放不回起點時試終點，再試線上任何一站從那裡開得到下一站的月台（`LineStaffing.placeAtAnyStop`）。**只按待避線**（不是「＋」也不是開新線）且線在軌道上的車已經達到它排得進的列數時，那列不放回：留在公司、不在線上也不在軌道上，訊息說「列車 3 先離開軌道：這條線在那裡能跑的列車已經都在跑了。可以配到別條線，或賣掉。」（「＋」和開新線照舊放回：它們買一列車，不該同時拿走另一列。）

決策 264 留下的「兩端都有車就拒絕」那一項在單線上改成上面第 5 點；`AutoServiceTests` 裡三個測試因此有意改寫（原本測拒絕，現在測成功與放回／離開軌道）。

## 五個角度

- **玩家**：沒玩過教學的人不知道待避線，現在「＋」自己會放好；手放卡住時配車當下、站長、線卡都說哪兩站之間要加，一鍵就好，不必懂原理。
- **鐵道迷**：真實單線就是靠交會站（行違い）錯車，N 列車在同一段單線上要 N−1 處交會；把待避線放在站間而不是壓在月台上，就是單線鐵路在站間設號誌站（信號場）的做法。
- **開發**：全在 GamePresentation，GameCore、存檔、golden、replay 都不動；沿用決策 264 的計數與按鈕，只加「自己一條線」和「避開月台」兩個分支。
- **美術**：沒有新圖；待避線的樣子照決策 204。
- **音樂**：無。

## 沒選的

- **手放配車時自動蓋待避線**：會不問就花錢，也和「配車」這個動作的意思不同；提醒加一鍵比較清楚。
- **改 GameCore 的排程，讓列車在有待避線的站等對向車**：探索顯示有交會站時行車控制本來就會在那裡等（修後全部死結 0），沒有交會站時是物理無解，改排程救不了；而且會動 golden 與 replay。
- **保留決策 264 的拒絕**（兩端都有車就不蓋）：手放的配置三站都有車，永遠蓋不成，玩家就卡住。
