## 1. 問題

管制關著時，有班次的路線靠決策 228 的行車間隔（`RunSpacing.swift` 的 `heldUp`）互相讓。每條規則都只看兩列車，三列以上可以湊成一圈各等下一列（決策 801 就是一例）。
成圈之後：

- 沒有任何東西會解開它。圈裡每一列都停著等圈裡的另一列，誰都不動，位置不變，規則的答案也就不變。
- 玩家看不到。`deadlockedTrains()` 在管制關著時直接回空的，地圖上沒有標記、沒有泡泡，整條線停擺卻沒有警告。

管制開著時這兩件事本來就有（`deadlock(memo:)` 偵測、`resolveDeadlock` 每分鐘試著解），這一則不動那一邊。

## 2. 規則

1. **認圈。** 每個整分鐘，把「正在路上、被行車間隔擋到一步都走不了」的列車列出來，每一列記下擋它的那一列與原因。
   沿著「誰擋誰」走下去會回到自己的，就是一圈（`SpacingRing.swift` 的 `spacingRings`）。排成一列等最前面那一列的不是圈。
2. **放一列。** 每一圈挑一列，這一分鐘它不用讓「只是先後順序」的那一條：
   - 先挑圈裡因為**待避**（讓後面會追上來的車先過）而等的，編號最小的那一列；
   - 沒有的話，挑因為**對向車離共用軌道比較近**而等的，編號最小的那一列。
   被放的那一列只免這一條；其他每一條規則、以及這一分鐘結束前的掃過檢查，照樣對它生效。
3. **不放的。** 圈裡每一列都是因為**前面有車**或**對向車已經在共用軌道上**而等的，就誰也不放：放了會讓兩列車上同一段軌道。這種圈只點名，不動它。
4. **點名。** 管制關著時 `deadlockedTrains()` 回圈裡的車與被它們擋在後面的車，`routeWaits()` 回每一列是被誰擋著。
   畫面用的是管制開著時已經有的東西：地圖上的死結標記、「N 列死結」、可以點到那列車的泡泡、列車卡片上的「與 X 互相卡住（死結）」。沒有新的面板。
5. **不存東西。** 每分鐘重新看一次，上一分鐘放過誰不記。存檔、讀檔、重播都不受影響。

## 3. 門檻：為什麼是「下一個整分鐘」，不是「卡了 N 分鐘」

派工單寫的是「圈持續超過一個門檻再放行，門檻請量測後訂」。量到與推得的：

- 圈不會自己散（第 1 節）。等 N 分鐘只是讓玩家多看 N 分鐘停擺。
- 現在的規則下，HEALTH 的 25 個世界在管制關著時**一個圈都沒有出現**（第 5 節），所以沒有「會自己散、不該被打擾的圈」可以拿來定 N。
- 記「這一圈站了幾分鐘」要存進存檔（新欄位、存檔版本 108），或是每次從頭推算。門檻是 0 就都不用。

所以門檻訂為：成圈後的下一個整分鐘就放。圈在畫面上最多停留一分鐘，玩家還是看得到它被點名。

## 4. 為什麼安全

- 被免掉的只有兩條「誰先」的規則。這兩條的另一方此刻也停著等（它在圈裡），所以免掉其中一方不會讓兩列同時動進同一段。
- 「前面有車」「對向車已經在共用軌道上」這兩條永遠不免，被放的車還是會被它們擋住。
- 每分鐘結束前原有的掃過檢查（這一分鐘走過的軌道有沒有別的車）照樣跑。
- 一圈一分鐘只放一列。放了之後圈就斷了，其餘的車照原來的規則接著走。
- 沒有圈的那一分鐘，這段程式什麼都不改（`testNoTurnIsWaivedWithoutARing`）；所以沒有圈的世界和以前逐位元相同（第 5 節）。

## 7. 五個角度

- 玩家：關掉行車管制後整條線停擺，以前沒有任何提示，現在地圖會標出是哪幾列、點得到，而且一分鐘內自己解開。
- 鐵道迷：真實的行車調度遇到互等也是由調度員指定一列先走；被放的只是「誰先」的順序，不會讓車闖進有車的區間。資料來源：無（規則，不是資料）。
- 開發者：不存狀態、不動存檔版本、沒有圈時逐位元不變，所以 golden 與 replay 一個值都不用動；規則集中在一個新檔，`heldUp` 只多回傳原因。
- 美術：沒有新圖，用現有的死結標記與泡泡。
- 音樂：無。

## 8. 沒選的作法

- **卡了 N 分鐘才放**：第 3 節。要存新欄位，而且圈不會自己散。
- **連「前面有車」「對向已在軌道上」也放**：不安全，會讓兩列車上同一段。這種圈只點名。
- **管制關著時也借用管制開著的 `resolveDeadlock`**：那一套靠進路預約，管制關著時沒有預約可以看。
- **新增一個「互相擋住」的面板**：現有的死結標記、泡泡與卡片文字已經能說是哪幾列、能點過去；新面板要多一輪畫面驗收，沒有多給玩家什麼。
