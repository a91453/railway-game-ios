### 659. 2D 地圖的街道只選不鋪；教學 UI 測試不把 XCTest 的 log 抄到 stderr

2026-11-08，派工單 IPAD-LAUNCH-STALL（session_01YGNNum8AkZJedsA92gfV3H，遊戲規劃第 57 任 session_01YGNNum8VrDTbqa8SHkYC4q 派），分支 `claude/ipad-launch-stall`。號碼依 #1579 的登記。GameCore、存檔版本、golden schema、GoldenScenarios、SaveFixtures、ReplayFixtures 都不動。玩家看到的地圖沒有改。

## 問題

`docs/archive/PR1983_1985_REVIEW_HANDOFF.md` L15-9 第 1 點：iPad 上地圖剛打開的前幾格之間，約 4.5 秒沒有畫面（full lane 42444107304 的 `ipad-tutorial-trace`）。那段時間裡的觸控被取消，`TutorialUITests` 為此多按了第二次。42489862739（122）也有同樣的空檔。

## 量法

- `FrameMeter`（CADisplayLink）每 2 秒寫一行「frames N in M ms, longest gap G ms」。
- `StallSampler`（`-ui-test-stall-stacks`）：主執行緒超過 1 秒沒畫一格時，停下它、沿 frame pointer 走一遍堆疊，停住期間每秒看 20 次（原本 5 次）。報告列出葉子、App 自己的函式（占 10% 以上的），2 秒以上的停頓再印最常見那一眼的整條堆疊。
- 教學的兩個 UI 測試類別每次開 App 都帶 `-ui-test-stall-stacks`；`ios-build.yml` 的 iPad job 在 `only_testing` 手動跑時也存下 trace。

## 1. 主執行緒在做什麼：多半是系統，不是 GamePresentation

修之前（b92ce6f，`TutorialUITests` 與 `TutorialJourneyUITests` 全部，run 42513125773）：36 次停頓，共 90.4 秒。依葉子分：

| 葉子 | 合計 |
| --- | ---: |
| `writev`：XCTest 自己的 log 抄到 App 的 stderr | 41.2 s |
| 等待（kevent、mach、鎖） | 20.6 s |
| CoreUI 找圖（SF Symbol、asset catalog） | 10.1 s |
| 其他 | 18.5 s |

沒有一次停頓裡，App 自己的函式占到 10% 的取樣。開 App 時的停頓是幾種第一次使用的成本疊在一起：等 RenderBox 畫完（`RBLayer displayWithBounds` → `dispatch_sync`，iPad 的 focus 系統 `UIFocusSystem updateFocusIfNeeded` 也在堆疊上）、Swift 的 `swift_conformsToProtocol` 查表、清單 `ListLabelLayout` 裡 SF Symbol 向量字形從冷的系統 catalog 讀進來（`madvise`、`_ReadPage`）、讀檔。教學中段一次 7,955 ms（135 眼裡 115 眼在 `CUIStructuredThemeStore lookupAssetForKey:`）：路線確認那一步第一次排 `UITextField`，載入它的清除鈕圖（`_UITextFieldClearButton`）。

`writev` 是測試才有的：XCTest 預設把 os_log 抄到被測 App 的 stderr（MENUSTALL 也遇過）。教學的 UI 測試每次 `app.launch()` 前設 `OS_ACTIVITY_DT_MODE=NO`。

## 2. 背景在做什麼：2D 地圖的街道計畫，算完就丟

主執行緒沒有 App 的函式，但 CPU 不只主執行緒在用。`MapView` 的 `.task(id: Map3DSceneKey)` 在背景（`.utility`）跑 `Map3DScene.seededStreets(world:)`，鋪軌、月台、建築、週數、道路一變就重跑。它呼叫 `addSeededStreets`，把每條街真的鋪出來（`Map3DRealGround.addRoads`：人行道與路面、標線、路邊物件、站牌、車流），2D 地圖卻只讀哪些邊是街（`streetEdges`），其餘全丟。

Linux 量（教學世界的 `line.open`，480 塊地、27 格道路、874 條街邊）：

| | debug | -O（release 的 `GameSim`，取 5 次最快） |
| --- | ---: | ---: |
| 修前 `seededStreets` | 16,986 ms（`addRoads` 占 16.59 s） | 306.1 ms |
| 修後 `seededStreets` | 36 ms | 1.3 ms |
| 整個 3D 場景（對照） | 20.3 s | 455.2 ms |
| 選出的街 | 同 | 105 條，修前修後一樣 |

開 App 時其他的計算都在 0–11 ms（`startTutorial`、`LandMap.tiles`、`MapWeather`、`LineMap`、`StationLabels`、`MiniMap`、`CitySkyline`、`StationPotentialMap`）。iOS 的 GamePresentation 用 -O 編（決策 624），所以 iPad 上這段大約是 -O 那一欄，乘上 Simulator 與裝置的差。它和主執行緒、render server 搶 CPU，開地圖時與每次鋪軌後各一次。

改法：`addSeededStreets` 加 `laying` 參數，`false` 時決定好 `streetEdges` 就回傳；`seededStreets(world:)` 用 `laying: false`。3D 場景照舊用預設的 `true`。`streetEdges` 只在那一行指定，所以選出的街一樣（`SeededStreetPlanTests.testTheTutorialsPlanIsTheThreeDMapsStreets` 對照 3D 場景的 `seededStreets.roads`），`testItCostsLittleOfBuildingTheScene` 從「比場景少」收緊到「不到場景的十分之一」（修前 3.92 s 對 6.8 s 會紅）。

## 沒修的

- 系統第一次使用的成本：RenderBox 的等待、SF Symbol 與 asset 的冷讀、Swift 的 protocol conformance 查表、`UITextField` 的清除鈕圖。都在系統框架裡，Simulator 的冷 catalog 比裝置慢；App 這邊能做的是提早暖身（例如開地圖前先畫一次會用到的符號），那要先在實機上量到它真的慢，這次不做。
- `TutorialUITests` 的第二次按，留著：系統的停頓還在。

## 五方

- 玩家：開地圖和每次鋪軌後，背景少做幾百毫秒到幾秒用不到的計算，畫面與觸控少被搶 CPU；地圖上的街一條不差。實機手感 UNVERIFIED。
- 鐵道迷：無。
- 開發：知道 iPad 開地圖時主執行緒卡在哪（系統，不是 App），教學 UI 測試的 trace 以後都帶堆疊，XCTest 的 log 不再卡住 App。
- 美術：無，2D 地圖畫的街與 3D 場景的街是同一組。
- 音樂：無。
