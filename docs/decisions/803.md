## 2. 手指拖的時候不出 ✕ ✓ 卡片

手指還在拖時卡片就在手指下面跟著跑，被手擋住，也擋住終點。現在放開才冒出來（`BuildConfirmLayout.pillShows`，動態照 `MotionRule.pop`，減少動態時只淡入）；旗子照舊跟著。拖的時候這一段不能鋪，上方那一列多一個警告色的三角形，原因的字放開後在卡片上說。

## 3. 上方只留一列小膠囊，卡片能鋪時只有 ✕ ✓ 與價格

- **上方**：一個小膠囊，長度｜高度。高度那一格照舊可以按住上下滑、點一下出 − ＋（決策 646），觸控範圍仍是 44 點，畫出來的膠囊 34 點高。不再有第二行：不能鋪的原因在卡片；「延續既有軌道」那一行變成一個小小的連結圖示（VoiceOver 照舊念出來）。
- **一次性的高度提示**：只在第一段出現。以前要按 ✕ 或真的滑過才消失，沒做這兩件事的人每一段都看到它；現在它離開畫面一次就算看過（`HeightSlideHint` 的說明）。
- **卡片**：能鋪時只有 ✕ ✓ 與價格。「第一段是直線…」與雙線的渡線說明不再放卡片（詳細卡裡本來就有，`BuildConfirmLayout.stretchCaption`）；沿著待售的真實路線描時的那句話與「買下這條線」留著，那是卡片上那顆按鈕的說明。不能鋪才展開原因與建議。
- **建議**最多兩顆（往上一顆、往下一顆，決策 629 本來就是）。並排放不下時用的短字以前是「24 公尺，走高架」，看不出動的是哪一端；現在是「終點 24 公尺，走高架」「兩端 4 公尺，用橋」（`NetworkHeightFix.shortTitle`）。

這樣能鋪的那一段（最常見的情況）卡片只有一列按鈕高，決策 800 留下的「軌道橫貫畫面正中時卡片無處可讓」只剩被拒絕的時候才可能發生。

## 4. 其他建造的卡片在手機橫拿時同一套左右排

`BuildConfirmLayout.arrangement` 不再只看鋪軌：畫面矮而且卡片有字時，字在左、✕ ✓ 在右。選月台位置（人口與整地的說明）、賣建物、道路、公車路線、渡輪航線、把車站加入路線、買地塊、升級軌道都一樣；字最寬 340 點、靠左對齊。**例外**：在地圖上選新路線的那張卡片照舊上下排，它旁邊已經掛著兩站比較的抽屜（決策 384），再往右排會太寬。

其他做法（沒採用；Linux 上拍不了預覽圖，這裡只有文字）：

- **副站長縮成角落的小頭像**：手機橫拿的底列已經有工具欄的腳、完成、卡片開關、復原重做、圖層鈕，頭像再小也還是排在它們後面，正好是地圖中間偏下。收起來，離開建造再回來。
- **拖的時候把原因的字留在上方**：會回到兩行，而且手指移動時字一直換；放開後卡片就說了，拖的時候只留一個三角形。

- **整個上方那一列搬進卡片**：決策 800 已經說過，高度那一格要在還沒有卡片時（手指正在拖）就看得到。

### 8.2 版面

- **原因那一條與卡片同寬**：卡片裡的東西排成一欄，每一樣都給同一個寬度，就是最寬那一樣的寬度（`BuildConfirmLayout.columnWidth`，App 裡的 `PillColumn`）。會換行的字最寬照舊 340 點，不會把卡片撐寬。✕ ✓ 比欄窄時置中。
- **兩顆建議同寬、對齊**：兩格一樣寬，並排時把那一列填滿；一列放不下兩格才上下排（`BuildConfirmLayout.equalCells`，App 裡的 `EqualCells`）。原來用 `ViewThatFits` 在三種寫法之間挑，現在按鈕只有一種寫法，不需要了。
- **手機橫拿、被拒絕又有建議時**（`Arrangement.strip`）：原因一行在上，下面一列是兩顆建議與 ✕ ✓。這一列的按鈕高 44 點（其他排法照舊 48 點），原因那一條上下各 3 點，整張卡片約 82 點高（6＋22＋4＋44＋6）。決策 803 量到上下控制項之間約 195 點：軌道橫過正中時，卡片上下各有 97 點，82 點加上與軌道的間距放得下。這個數字只有算式與測試（`testARefusalWithFixesIsOneStripOnAShortScreen`），實機沒量。
- 手機橫拿、被拒絕但沒有建議（只有原因，或原因加一行備註）：照舊字在左、✕ ✓ 在右，一列高。
- 直拿與 iPad：照舊上下排（原因、兩顆建議一列、✕ ✓），多了原因與卡片同寬、兩顆同寬。

### 8.3 道路與建物：手指拖的時候不出卡片

決策 803 只做了鋪軌。用手指拖著畫道路、拖著搬要蓋的建物時，卡片也改成放開才出（`GameSession.buildFingerDraws`、`BuildConfirmLayout.fingerDraws`）；道路的拖曳起點與建物的拖曳原位兩個狀態本來不通知畫面，現在通知，放開時卡片才會出現。動態照舊是 `MotionRule.pop`，沒有新的秒數。

### 8.4 五個角度

| 角度 | 理由 | 分數（1–5） |
| --- | --- | ---: |
| 玩家 | 被拒絕時卡片上是一行原因與兩顆一眼看完的按鈕；橫拿時卡片不再壓住正在拉的軌道；想看完整原因，詳細卡還在 | 4 |
| 鐵道迷 | 坡度上限、橋與隧道的淨空這些數字不在卡片上了，仍在詳細卡的整句裡；高度膠囊照舊顯示離地幾公尺 | 2 |
| 開發 | 短句與整句並存，來源各自補一個欄位；排法是兩個純函式加 Linux 測試；identifier 沒動；`shortTitle` 拿掉 | 3 |
| 美術 | 原因與卡片同寬、兩顆建議等寬，卡片是整齊的兩列；沒有新顏色與圖示 | 4 |
| 音樂 | 無 | 1 |

其他做法（沒採用；Linux 上拍不了預覽圖，只有文字）：

- **原因整句留著、只把字級縮小**：兩行仍是兩行，卡片不會變矮，而且小字更難讀。
- **按鈕寫「橋 +4 公尺」**：比「用橋」多一個數字，但套用後高度膠囊就顯示了；作者要的是減半。
- **橫拿時把原因放進上方的膠囊**：決策 800 才把原因從上方搬到 ✓ 旁邊，理由是 ✓ 灰掉時原因要在旁邊。
- **橫拿時所有建造卡片的按鈕都改 44 點高**：只有這一張有蓋住軌道的問題，其他卡片不動。

參考庫與外部專案：沒有重新找。決策 800、803 查過作者 `Ci/` 的建造 HUD 只有長度與價格的小膠囊，沒有被拒絕時的原因與建議；這次是本專案兩句話的長短與一張卡片的排法，短句與排法都是自己寫的。
