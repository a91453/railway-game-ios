## 看到什麼

公司蓋什麼對周圍的城市幾乎沒差：只有公園、學校、醫院三條寫死的，和決策 98 不分種類的 +NT$18/m²（只有分區地）。「蓋什麼」只剩挑最賺的一種（設計 §1.2）。

## 決定

1. **表**（`LandValueRules.industryTenths(from:to:)`，單位是「成」）：公司建物的用途（`PlacedBuildingKind.use`）→ 400 m 內城市格的用途。強 9、中 5、弱 3，工廠對住宅 −9；其餘 0。

   | 公司蓋的 ↓ ／ 城市用地 → | 住宅 | 商業 | 商務 | 工業 | 農業 | 休閒 | 文化 |
   | --- | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
   | 住宅（小住宅） | — | 9 | 3 | | | 3 | 5 |
   | 商業（商店、百貨、飯店、夜市、漁人碼頭） | 9 | — | 5 | | | 3 | |
   | 商務（辦公大樓） | 5 | 9 | — | | | | 3 |
   | 工業（第 ④ 步的工廠） | −9 | 3 | 5 | — | | | |
   | 農業（第 ④ 步的休閒農場） | | 3 | | 5 | — | 5 | |
   | 休閒（遊樂園、遊艇港、廟、鐵道博物館） | 3 | 9 | | | | — | 5 |
   | 文化（學校、醫院） | 學校醫院自己的 | 3 | | | | 5 | — |

   公園不在表裡（決策 91、361）。工業、農業兩列先寫好，第 ④ 步有那兩種建物才會生效。
2. **同一用途幾棟都只算一次**；不同用途相加，**最多 14 成**（學校＋醫院現在的上限）。「負」另外加，不受上限。
3. **地價**：每成 NT$3/m²（300 分，`industryPremiumPerTenth`；強 9 ＝ 學校的 2,700 分、中 5 ＝ 醫院的 1,500 分）。放在 `LandValue.companyPremium`：取「決策 98 的 1,800（分區地）」與「表的提升」裡高的，不相加；再加上負的。所以除了工廠旁的住宅，沒有一格比以前便宜。城市格的用途：有城市建物看建物，否則看土地格；空地沒有用途，不受影響。
4. **建物不帶動自己的地**：`companyLandValue(of:)` 算公司建物自己的地時，把它自己從表的來源拿掉（不然蓋了就漲、馬上賣就賺）。決策 98、學校醫院照舊。
5. **成長是重新分配，不是多給**：車站當天新增的居民（`homeGrowth`）與就業（新的 `jobGrowth`，兩條成長路徑 `grow` 與 `growSteered` 都用）照各格人數分；被帶動、還有空間的格乘 `10 + 成數`，其餘乘 10。分多了超過空間或超過原本的份，多的照原本的權重退給還有空間的格（`steeredShares`，就是學校醫院原本那段，抽出來共用）。車站總共長多少和以前一樣。學校、醫院對居民的 9、5 成照舊，另外加在上面。
6. 畫面：城市地圖的地價說明本來就有「鄰近公司建物 + X」那一列（`CityMap`），現在數字會是表的提升。建造預覽「會帶動附近的哪幾類」沒有做（見「下一步」）。

## 沒選的

- 表的提升與決策 98 相加：同一棟建物在分區地上會算兩次。
- 子公司之間互相加客人：會讓堆在一起永遠最好（設計 §7）。
- 負的也扣成長：設計只扣地價。
- 依距離衰減：本遊戲其他加成都是 400 m 內全額，再一種算法玩家分不出來。
