### 1014. iOS 的 PR 建置優先用作者的 Mac，不在線就退回 GitHub 的機器（MAC-RUNNER）

2026-11-26，規劃3 工作串「量測並加速 CI 時間」（CIOPT-17，分支 `claude/project-thread-3ydieb`），協調者第 5 任派工。
作者 2026-11-26：「其實也能本地吧 我不知道」「我Mac上就有Xcode只是我不知道怎麼讓他連結runner」。
號碼依 #2118 的登記：決策 1014；存檔版本、golden schema、GameCore、遊戲程式都不動。

## 1. 為什麼

帳號只有 5 台 hosted macOS runner。11-26 白天 PR 的 Swift 部分約 25 分就跑完，gate 再等 iOS 的 build job 30 到 73 分；
iOS 的 PR run 常常 50 到 99 分，多數時間在排隊（`docs/research/CI_MEASURE_2026-11-26.md` §3）。作者的 Mac 有 Xcode 27.2
與 iOS 27.2 的模擬器，可以當第 6 台。

## 2. 怎麼做

- 新的 `.github/workflows/pick-mac.yml`（`workflow_call`）先在 Linux 上花幾秒問 GitHub：標籤 `chien-mac` 的 runner 在不在線、
  有沒有在跑別的工作。在線又有空就回 `["self-hosted","macOS","chien-mac"]`，否則回 `"xcode-27"`（以前所有 macOS job 用的）。
  GitHub 自己不會從離線的 self-hosted runner 退回 hosted（job 會一直等），所以要先問。
- `ios-build.yml` 的 build job `runs-on: ${{ fromJSON(needs.pick.outputs.runs-on || '"xcode-27"') }}`。只有 pull request 與
  `only_testing` 的手動 run 可以用 Mac；full lane、`release-archive.yml`、`testflight.yml`、`ios-compilation-cache.yml` 照舊 hosted。
- 任何一步出錯（沒有 token、讀不到 runner 列表、看不懂回應）都回 hosted：Mac 只會被跳過，不會被等。
- `.github/actions/select-xcode`：在 Mac 上找版本是 27.2 的 Xcode（`Xcode_27.2.app` 或 `Xcode.app`），用 `DEVELOPER_DIR`，
  不用 `sudo xcode-select`（runner 沒有 sudo）。版本不對就停，不會用別的 Xcode 編。
- build job 最後在 Mac 上把模擬器關掉（hosted 的機器用完就丟，Mac 要還給工作室）。

## 3. 安全

railway-game-ios 是**公開** repository。Mac 會執行 PR 裡的程式碼，所以：

1. 別的 repository（fork）來的 PR 一律 hosted（`pick-mac.yml` 比對 `head.repo.full_name`）；fork 的 run 也拿不到 secret，
   沒有 token 本來就會回 hosted。
2. repository 設定「Fork pull request workflows from outside collaborators」選「Require approval for all external contributors」。
3. runner 裝在 Mac 上另一個標準使用者帳號（`cirunner`），PR 的程式碰不到作者帳號的檔案、鑰匙圈、SSH 金鑰與工作室。
4. 問 runner 狀態用的 `RUNNER_STATUS_TOKEN` 是只限這個 repository、只開 Administration: Read 的 fine-grained token
   （GITHUB_TOKEN 不能列 runner）。它只用在 Linux 的 pick job，不傳進 Mac 上的 job。
5. 簽署、上傳、App Store Connect 的 secret 只在 `testflight.yml` 的 `testflight` environment，它不會用 Mac。

## 4. 不搶工作室

- 一個 runner 一次只跑一個 job；忙的時候新的 PR 走 hosted，不排在 Mac 後面。
- 工作室要用 Mac：在 `cirunner` 帳號 `./svc.sh stop`（離線就不會被選），或 GitHub 的 Variables 設 `MAC_RUNNER=off`，不用改 workflow。
- 已經排到 Mac 的 job，runner 中途被停掉會一直等：重跑那個 run（會重新選）。

## 5. 不選的

- **全部 macOS job 都改 self-hosted**：full lane 一次要 3 台、145 分，發版也看它；一台 Mac 接不住，壞了會擋發版。
- **固定用 Mac、不退回**：作者的 Mac 關機或工作室在用時 PR 會卡一整天。
- **用 repository variable 手動切換，不問狀態**：忘了切回來就會卡住；現在 variable 只當關閉開關。
- **截圖（`website-screenshots.yml`）也用 Mac**：是今天最佔 macOS 的，但 #2726 正在改那個檔，等它合了再接（下一步 1）。

## 6. 下一步

1. `website-screenshots.yml` 也接 `pick-mac.yml`（`allow: true`，它只能手動觸發）。
2. 上線一週後量：PR 的 iOS 排隊、Mac 上 build job 的時間、工作室有沒有變慢。
3. 五個角度：玩家：無（PR 合得比較快，版本早一點出）。鐵道迷：無。開發：PR 少等 macOS；多一台要照顧的機器。美術：無。音樂：無。
