### 676. 最低版本升到 iOS 26

2026-11-11，作者在 Mac 本機 Claude Code session 交辦（「寫 然後開始進行」），分支 `claude/min-ios-26`。存檔版本、golden schema、GameCore 的行為都不動。

## 做了什麼

- `Package.swift`：`.iOS(.v17)` 改成 `.iOS("26.0")`（寫字串是因為 `swift-tools-version` 6.0 沒有 `.v26`；工具版本照 CLAUDE.md 不動）。`.macOS(.v14)` 不動。
- `RailwayGameApp/project.yml`：`deploymentTarget` 的 iOS 由 17.0 改成 26.0；`RailwayGame.xcodeproj` 跟著改。
- `RailwayGameApp/Views/Theme.swift`：三處 `if #available(iOS 26.0, *)` 的舊版退路拿掉（`hardTopScrollEdge`、兩個 `glassBackground`）。浮在地圖上的元件現在只有 Liquid Glass 一種樣子，不再有 `.regularMaterial` 的版本。
- 最低版本到 26 之後，兩處在 iOS 26 標為過時的 API 會讓建置失敗（App 把警告當錯誤），一併換掉：
  - `RealWorldPicker.swift` 的地點搜尋：`MKMapItem.placemark` 改成 `location` 與 `address?.fullAddress`。搜尋結果第二行現在是系統給的完整地址，字樣可能和以前的 `placemark.title` 略有不同。
  - `MapArt.swift` 未解鎖地塊的價錢標籤：`Text + Text` 改成 `Text` 內插；因此 String Catalog 多一個只有格式的鍵 `%@ %@`（和既有的 `%@: %@` 同類）。
- 註解與文件裡寫「iOS 17」的地方跟著改（三個測試檔、`Map3DModelFile.swift`、`docs/UI_THEME.md`、`docs/HANDOFF.md`、決策 389 的「後來」）。

沒有做的：沒有因為升版而新增任何功能。Background Assets、Metal 4、Game Center 挑戰都沒有動。

## 為什麼是 26，不是 18 或 27

作者 2026-11-11 在 App Store Connect 的 TestFlight 測試人員列表，用「系統版本」篩選逐版本查的人數（公開測試群組 373 位，加上電子郵件邀請的群組）：

| iOS 大版本 | 人數 | 佔比 |
| --- | --: | --: |
| 27 | 224 | 約 58% |
| 26 | 135 | 約 35% |
| 18 | 28 | 約 7% |
| 17 | 1 | 約 0.3% |

合計 388，比測試人員總數多十幾位：一位測試人員有兩部裝置時，兩個版本的人數各算一次，只扣得掉認得出來的。26 與 27 的人數因此略高，26 以下的 29 位是逐列核對的。

26 以下的 29 位：

| 分類 | 人數 |
| --- | --: |
| 機型能升到 iOS 26，更新系統就能繼續玩 | 25 |
| 自己另有一部 iOS 26 的裝置 | 1 |
| 機型升不上 iOS 26（iPhone XS Max 兩部、iPhone XR 一部） | 3 |

階段作業 17 次以上的有 7 位，都在能升的那邊；升不上去的 3 位合計開過 1 次。

- **18**：只多排除 1 位，但換不到東西：要顧的仍是新舊兩套外觀，最慢的 iPhone 仍是 A12。
- **27**：會一次排除約四成測試人員。
- **26**：永久排除不到 1%；舊版退路可以刪；被最低版本擋住的 Background Assets（決策 386、389 留作退路的那一項）不再被擋。

這份是 TestFlight 測試人員，比一般玩家勤於更新；上架後 App Store Connect「分析 → 活躍裝置 → 平台版本」有數字時要再對一次。

## 五個角度

- 玩家：九成三的測試人員不受影響；約 7% 要先更新系統，3 位舊機型從此裝不了新版。所以發這一版之前要先公告（見「下一步」）。
- 鐵道迷：無。
- 開發：畫面只剩一種外觀要調與測；`#available(iOS 26.0, *)` 的退路不用再寫。最慢的 iPhone 由 A12 變成 A13（iPhone 11、SE 第 2 代）；**iPad 沒有變**，iPad Air（第 3 代）、iPad（第 8 代）是 A12 且跑得了 iOS 26，名單裡都有，3D 的預算（決策 460）仍要顧到 A12。沒有加依賴。
- 美術：浮在地圖上的元件一律是 Liquid Glass，不再有材質版；之後的畫面只在這一種上檢查。
- 音樂：無。

## 查過的做法

- ImmersiveMap（https://github.com/artembobkin/ImmersiveMap ，MIT）最低 iOS 18：它是新寫的函式庫，沒有舊使用者；它 2026-11-01 之後的更新（0.11.2、0.11.3）沒有新的做法可搬，`docs/research/IMMERSIVEMAP_STUDY_2026-11-03.md` 的排序不變。沒有拿它的任何東西。
- 用 Metal 4 重寫 3D：不做。`Map3D` 是 1,070 行 shader、2 個 pass、16 個 pipeline 的前向繪製，Metal 4 解的是上千個 draw call 與上百個 pipeline 的問題。

## 已知限制與下一步

- **發版前先公告**：下一次 TestFlight 的說明（`.github/testflight-whats-new.md`）要寫「這一版起需要 iOS 26」，讓還在 iOS 17、18 的測試人員先更新系統；其中有一位回饋很多的測試人員。這個 PR 沒有改那個檔（它跟著每一版重寫）。
- 還在 iOS 17、18 的人會留在他們裝的最後一版，TestFlight 版到期後就不能玩。
- 當機記錄裡幾筆要看的都在 iOS 26 以上（iPhone 15／iOS 26.5、iPhone 17／iOS 27.2），升最低版本不會讓它們消失。
- 之後可以另案做的：Background Assets 每縣市一包（決策 389）。
