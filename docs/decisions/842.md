### 842. 第二個私有素材庫：新素材放哪只寫一處，舊庫原樣封存

2026-11-18，雲端工作串「準備第二個素材庫」（新專案協調者派工，登記 ASSETS-REPO-2），分支 `claude/project-thread-re5ii8`（三個 repo 同名）。

不動 GameCore、存檔版本、golden、replay。

## 1. 為什麼

`a91453/railway-assets-private` 在 2026-11-18 是 3.01 GB（GitHub API 3,159,568 KB；素材庫 `tools/asset_guard.py` 以 1024³ 為 1 GB 印的數字）。2026-11-15 是 2.69，三天長 0.32，每天約 0.1 GB；素材庫 `AGENTS.md`（2026-11-15）定 3.5 GB 開下一個 repo，照這速度約 11-22、23 會到。GitHub 從 5 GB 起警告，而 repo 的大小含全部歷史，在 `main` 刪檔不會變小，只有改寫歷史（規則 8 禁止）或開新 repo 才會。

## 2. 決定

1. **名字**：`a91453/railway-assets-private-2`，之後 `-3`…。和舊庫排在一起、一看就知道是接續；腳本用 `-N` 找得到最新的一個。
2. **新素材放哪只寫在 `docs/ASSET_REPOSITORIES.md`**。`CLAUDE.md`、`model-look`、`rolling-stock`、`music-review`、`ui-review`、`meshy-blender.md` 原本寫死 `a91453/railway-assets-private` 的「放到哪」改指那張表；寫「這份東西在哪」的（決策、交接、`docs/art/` 的 README、程式註解、各 kit 的重建指令）不改，因為舊庫原樣可讀、路徑都還對。
3. **不搬重檔**：舊模型、viewer、截圖、宣傳片都留在舊庫的原路徑。搬過去只是把 3 GB 再存一次。
4. **帶過去的只有小而還在改的檔**（素材庫 `tools/next_repo.py seed`，約 8 MB）：`AGENTS.md`、`CLAUDE.md`、guard 與它的 workflow、`branding/`、`docs/memory/`、`local-studio-2026-11-10/`（工作室 kit 與紀錄）、`tools/`、`research/`，加上排隊中派工單（石斗車、南港島綫、迪士尼綫，以及它們引用的東鐵綫派工單與市區綫 revision-6 的 `tools/`）的文字檔與 `ref/` 照片。`CARRIED.md` 記來源 commit。
5. **舊庫關閉但不立刻封存**：`next_repo.py close` 寫 `CLOSED.md`；guard 從此擋新的頂層資料夾與新的模型資料夾（素材庫規則 9），已開著的 PR、已在舊庫開工的工作室任務（東鐵綫第 4 輪）在舊庫做完。都收完才按 GitHub 的 Archive。
6. **3.5 GB 自動提醒**：guard 每個 PR 印大小，3.5 GB 起多印一行「該開下一個素材庫」，下次不用人去量。
7. **branding**：主檔跟著到新庫；`tools/procedural-city/build_city_view.sh` 先找旁邊有編號的素材庫 checkout，沒有才用舊的。
8. **作者要動手的只有一步**：在 GitHub 建空的私有 repo、加進專案（雲端 session 的規則不准自己建 repo）。其餘由 session 用腳本與 PR 做，Mac 上的 clone 與 `studio.py init` 經 Remote Control 做。

## 3. 五個角度

| 角度 | 理由 | 分數（1–5） |
| --- | --- | ---: |
| 玩家 | 無直接影響；做模型與截圖的工作不會因為 repo 滿了停下來 | 2 |
| 鐵道迷 | 無 | 1 |
| 開發 | 換庫只改一張表與跑兩個指令；不改寫歷史、不搬 3 GB；guard 擋住切完還開在舊庫的新資料夾，下一次到 3.5 GB 也會自己提醒 | 5 |
| 美術 | 舊輪次全在原處、路徑不變；排隊中的派工單與參考照片帶過去，工作室的人只看得到自己的 worktree 也拿得到 | 4 |
| 音樂 | 無（試聽檔一樣放收新素材的庫） | 1 |

其他選項（沒選）：
- **等到 3.5 GB 才切**：只差幾天，排隊中的三款會剛好卡在換庫中間開工。
- **把重檔也搬到新庫**：新庫一開就 3 GB，等於沒換。
- **改寫舊庫歷史或用 Git LFS**：規則 8 禁止改寫歷史；LFS 在 GitHub 另計額度與流量，工作室與雲端 session 都要多裝一套，且舊歷史一樣不會變小。
- **名字用 `railway-assets-2`**：短一點，但和舊庫排不在一起，腳本也要另外認。
- **每份 skill 直接改寫成新名字**：下一次換庫又要改一輪，漏一份就有人放錯地方。
