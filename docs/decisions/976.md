### 976. 3D 場景每一層的狀態放回自己的檔，經登錄表掛到建造器（MAP3D-LAYER-REGISTRY）

2026-11-25，雲端工作串「做 3D 圖層登錄表」（協調者派工，作者問「3d拆分怎麼辦」），分支 `claude/project-thread-1qe601`。評分在 `a91453/railway-assets-private-2` `docs/priorities/SPLIT-HOTSPOTS.md` 第一列（2.30）。號碼依 #2118 登記。

不動 GameCore、存檔版本、golden schema、golden、replay；畫面一個頂點都不變（§3）。

## 1. 問題

`Map3DScene.swift` 在 #2678 依職責拆成七個檔後，常衝突的還剩建造器（`Map3DScene.Builder`，`Map3DSceneBuilder.swift`）：Swift 的 extension 放不了存放的變數，所以每一層（車站、高架、冬季燈飾、地標、機場……）建場景時要記的東西，一百多個變數都擠在建造器本體的同一段。每加一層、每改一層要記的東西，都改到那一段，平行的 PR 就在那裡衝突。

## 2. 做了什麼

1. **每層一個狀態結構，放在那一層自己的檔**：27 層、64 個變數搬出建造器，例如車站的 `StationState`（`Map3DStations.swift`）、高架的 `ElevatedState`（`Map3DViaducts.swift`）、冬季燈飾的 `WinterState`（`Map3DWinterLights.swift`）。變數名字不變，用的地方從 `laidPlatforms` 改成 `state.platforms.laidPlatforms`。本來就是自己一個結構的三個（`Map3DRoadBridges`、`Map3DRoadGrade`、`Map3DRoadBed`）直接列進登錄表。
2. **登錄表** `Map3DSceneLayerList.swift`：`LayerStates` 一行一層（`var winter = WinterState()`），建造器只多一個 `var state = LayerStates()`。`.gitattributes` 設 `merge=union`，和列車（決策 782）、地標（決策 895）的清單一樣：兩條分支各加一層，兩行都留下，不衝突。
3. **建造器本體只留各層共用的**：場景原點與範圍、各種網格（地面、近景、遠景、特寫、陰影、街面）、正在蓋哪一種、地形、共用的計算、每一步的面數與時間，共 39 個。
4. **測試** `Map3DSceneLayerRegistryTests`：建造器存放的變數就是這 39 個（多一個就紅，訊息說新層的狀態要放哪）；登錄表每行一層、名字與型別不重複、每個狀態結構只宣告一次，而且不在登錄表或建造器的檔裡。
5. 測試裡直接讀建造器狀態的地方跟著改名字（只改路徑，斷言不動）。

加一層新的東西：在那一層的檔裡寫 `struct XState { … }`，在 `Map3DSceneLayerList.swift` 最後加一行 `var x = XState()`，用 `state.x.…`。建造器與任何測試都不用改。

搬的時候發現 `piers`（高架橋墩的腳，街道從高架下穿過時避開它）不是沒人用，放進 `ElevatedState`。

## 3. 為什麼畫面不變

只改存放的位置與名字，沒有改任何計算與順序。用一支不提交的場景摘要測試比對：台中（有、沒有建築輪廓）、台北、桃園機場（有、沒有輪廓）、高雄、彰化、日月潭、三張海外地圖（香港中環等）、種子城市兩種，共 13 個完整場景，每個區塊的每一種網格（頂點順序、索引、遠景方塊）、道具、招牌、街上的人車、平交道、站體外觀、冬季燈飾、馴鹿、貨場、月台門、每層的面數與步驟名，改之前（小清理之後的 main）與改之後完全相同（`SWIFT_DETERMINISTIC_HASHING=1`，PR 裡記數字）。

## 4. 五個角度

- 玩家：看不到差別；之後加新的 3D 層更快、少壞。
- 鐵道迷：無。
- 開發：建造器本體從一百多個變數剩 39 個；新層只動自己的檔與登錄表的一行，平行的 PR 不再在建造器衝突。
- 美術：無（畫面逐位元組相同）。
- 音樂：無。

## 5. 沒做的

- 場景組裝的步驟順序（`Map3DSceneAssembly.swift` 的 `init`）還是一個檔、一條順序：各層的先後會影響誰讓誰（例如機場建築在輪廓之後），不能讓每層自己排，所以沒拆。之後要改成登錄表排步驟，得先把每一步「要在誰之後」寫成資料。
- 共用的網格與 `props`、`signs`、`streetLife` 不搬：每層都寫它們。
