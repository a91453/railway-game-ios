### 638. 翻譯檢查改吃建置自己抽出的字串，PR 的 iOS job 不再整個 App 編第二次

2026-11-08，實作 session CI-LOC-EXPORT（session_01YGNNuoqK57WoS2Hn6cgshT，`claude/ci-loc-export`），遊戲規劃第 55 任派。號碼依 #1579 登記；存檔版本、golden schema、fixture、GameCore 都不動，只改 `ios-build.yml`、`.github/scripts/` 的翻譯檢查與 missing-button 腳本、這個決策。

### 背景

- `ios-build.yml` 的「Xcode build (iOS Simulator)」在 PR 上一個 job 31–42 分。量到的（2026-11-08）：

  | run | Build for iOS Simulator | UI smoke | Export Swift strings with Xcode | 整個 job |
  |---|---|---|---|---|
  | 42437724301 | 12.2 | 6.1 | **17.8** | 42.1 |
  | 42439105982 | 10.7 | 5.8 | **16.6** | 37.7 |
  | 42437717820 | 7.5 | 6.1 | **14.0** | 33.2 |

- `xcodebuild -exportLocalizations` 不管 `-destination` 都用 iOS 裝置 SDK（Debug-iphoneos）建一次整個 App，所以吃不到前面 Simulator 的建置（#356 試過給它同一份 DerivedData 與設定，還是全部重編）。它比建置加 smoke 還久，第 54 任才把它的逾時從 15 調到 25 分。

### 決定

1. 「Build for iOS Simulator」帶 `SWIFT_EMIT_LOC_STRINGS=YES`：Swift 編譯器在編每個檔時順手寫出它要翻譯的字串（`.stringsdata`，放在物件檔旁）。這就是 Xcode 匯出前那次建置做的抽取，只是不再多編一次。
2. 「Export Swift strings with Xcode」換成「Sync the build's Swift strings into a copy of the catalog」：只取 App target（`Debug-iphonesimulator/RailwayGame.build/`）的 `.stringsdata`，不取 UI 測試與套件的（舊的匯出也只有 App 的兩個檔），用 `xcrun xcstringstool sync` 併進 commit 版 `Localizable.xcstrings` 的副本；再把建好的 App 的 `Info.plist` 轉成 JSON。秒級，不建任何東西。
3. `check-localization.py` 加 `--synced` 模式，抓的東西和 XLIFF 模式一樣：
   - commit 的目錄每個鍵、每個 plural／device 變體的 zh-Hant 都要是 `translated` 且不空（`catalog_issues`，兩種模式共用，沒改）；
   - 程式用到、目錄沒有的鍵（sync 會把它加進副本，沒有翻譯）→ 紅，訊息同舊的「missing from committed Localizable.xcstrings」；
   - `en.lproj/InfoPlist.strings` 每個鍵在 `zh-Hant.lproj` 都要有不空的值（`CFBundleName` = `RailwayGame` 照舊例外）；
   - 建好的 Info.plist 裡玩家看得到的字串（`CFBundleDisplayName`、`…UsageDescription`、文件類型名稱等）不在 `InfoPlist.strings` → 紅。舊的匯出會把它們列成沒有 target 的 unit，這裡照樣抓；
   - 防呆：sync 若沒讀到任何 `.stringsdata`，目錄的鍵會全變 stale，這時算紅（「found none of the catalog's strings in the app's code」）；建置沒寫出 `.stringsdata` 時 sync 那一步就紅。只是不在程式裡的鍵（stale）只印提醒，和舊的一樣不算錯。
   - XLIFF 模式留著（Mac 上手動匯出時用），自測兩種都測（`check-localization-selftest.py` 多 10 個測試）。
4. `ui-smoke-missing-button.sh` 的重建也帶 `SWIFT_EMIT_LOC_STRINGS=YES`，設定和 build 步驟相同，才只重編改過的檔。
5. 翻譯檢查跑的時機不變：PR 與 full lane 都跑，`only_testing` 手動 run 不跑（決策 265）。
