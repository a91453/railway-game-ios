### 1005. 地圖檔瘦身：建物 2048、底圖 z13 不放巷道、山影到 z9（MAP-PACK-SLIM）

2026-11-26，雲端工作串「縮小地圖包下載大小」（分支 `claude/project-thread-2mh2fd`），協調者第 5 任派工。
作者覺得一區的地圖包太大（日本四包 117.7 MB）；盤點串試算後，作者：「都行 所以改這樣是會變好還是變差 精準度會改變嗎」、
「所以4096轉1024真的沒差嗎」、「都行的用你覺得最佳的方案」。號碼依 #2118 的登記：決策 1005；存檔版本、golden
schema、GameCore 都不動。

## 1. 做了什麼

不換資料、不重抓 OSM，只把已經在檔裡的資料存得粗一點，粗到畫面上看不出來。工具是 `tools/basemap/slim_tiles.py`，
就地改寫 PMTiles 檔（範圍、中心、zoom 照舊），三個指令：

| 指令 | 改什麼 | 精度 |
|---|---|---|
| `buildings` | 建物圖磚換成新格式 `footprints/3`：同 z16，每塊 2048 單位一邊（舊的 `footprints/2` 是 4096） | 每個角 0.14 m → 0.27 m（台灣）、0.12 → 0.25 m（九州）；外形本來就簡化到 0.5 m |
| `basemap` | z13 不放 `minor` 道路；z14 不動（見 §2） | 巷弄在 2D 地圖晚一級出現（z13 只有 2D 讀） |
| `terrain` | 山影 `terrain.pmtiles` 拿掉 z10 | 2D 拉到最近時山影由 z9 放大，稍糊 |

做檔的工具也改了，以後重做的檔直接是新的樣子：

- 建物：`build_footprint_tiles.encode_tile` 仍在 4096 單位裡簡化與量面積（推算樓層的 `guessed` 等用的 4096 不動），
  最後才用 `coarse_rings` 進位到 2048 寫出；`decode_tile` 兩版都讀、都還原成 4096 單位。台灣、香港、海外（福岡、羅瓦涅米）
  的建物工具都走這條路，`metadata` 的 `extent` 寫 2048。
- 底圖：`build_basemap.main` 寫完後呼叫 `slim_tiles.basemap`。
- 山影：`build_terrain.LAST_ZOOM = 9`；z0–9 的取樣不變（台灣的檔重做後與 `slim_tiles terrain` 的結果逐位元相同）。

App：`Map3DFootprints.decode` 讀 2 與 3 兩版，3 版的座標乘 2，所以後面的程式（重複建物、樓層、外形）照舊用 4096 單位。
底圖只動 z13，App 的程式只讀 z14（`Map3DBaseMap`、`RealRoadCells`、`BusRoadNetwork`），所以不用改；2D 地圖（MapLibre）
在 z13 少了巷弄，拉到 z14 就照原本畫。

## 2. 為什麼底圖 z14 不動

盤點串原本也建議 z14 座標 4096 → 2048（0.5 m → 1 m，底圖少約 5%：台灣 2.6 MB、日本四包約 3.7 MB）。PR 第一版做了，CI 兩個
3D 測試變了：3D 地圖裡兩條路的路面在 0.5–4.5 m 高差相碰的地方從 276 處變 281 處（`Map3DSceneMemoryTests`，這個數字只准往下修），
台中交流道一帶 600 m 內的公車站從 8 座變 5 座（3 km 內 71 → 68）。z14 是 3D 地圖、道路格、公車路網讀的那一級，進位 1 m 會動到
遊戲裡的路，不只是畫面；為了幾 MB 讓路面多撞幾處、站牌搬家不划算，所以 z14 維持原樣，只拿掉只有 2D 讀的 z13 巷弄。

## 3. 為什麼建物用 2048 不用 1024

盤點串原本建議 1024（約 0.5 m、建物檔少 25%）。福岡同一處拉到最近比對：兩棟牆貼牆的房子之間原本只有一條細縫，1024 會把它
撐成約 0.5 m 的白縫，3D 裡會看到兩棟之間露出地面；2048 時和原本幾乎一樣。量佐賀包：1024 每個角平均移 0.18 m、最多
0.35 m；2048 是一半。所以用 2048，建物檔少約 14%（1024 是 25%）。比較圖在專案共用資料夾 `map-pack-slim/`。

## 4. 結果

| 檔 | 之前 | 之後 |
|---|--:|--:|
| 台灣 `taiwan.pmtiles` | 53.57 MB | 51.45 MB |
| 台灣 `taiwan_buildings.pmtiles` | 29.65 MB | 26.19 MB |
| 台灣 `taiwan_terrain.pmtiles` | 9.73 MB | 3.06 MB |
| 日本四包底圖（福岡、佐賀、熊本、長崎） | 69.04 MB | 61.96 MB |
| 福岡包 `terrain.pmtiles` | 7.38 MB | 2.23 MB |
| 日本四包合計（`pack.json` 的 `bytes`） | 117.69 MB | 105.46 MB |

日本四包的建物這次沒轉（見 §5）；九州建物重做時寫成新格式，四包再少約 4 MB（試轉 30.54 → 26.41 MB），合計約 101 MB。

試轉時建物一棟都沒少（佐賀包 452,857 棟前後相同，只有 38 個點因為進位後在一直線上被拿掉）。

## 5. 這次沒動的

- 香港、羅瓦涅米包：要使用者重傳，這次不動；它們的建物下次重做時自然是新格式（`footprints/2` 照樣讀得到）。
- 日本四包的建物：決策 1001／1002 的串（補九州 Overture／PLATEAU）會重做四包建物，用這裡改過的工具直接寫成新格式，
  不用轉兩次（每轉一次公開 repo 多十幾 MB）。

## 6. 五個角度

- 玩家：下載變小、App 變小，畫面幾乎一樣；巷弄在 2D 晚一級出現，山影拉近時稍糊；3D 的路與公車站不動（所以 z14 不進位）。
- 鐵道迷：無（鐵道、車站、高度都不動）。
- 開發：一個就地改寫的工具，做檔工具都接上；App 只改建物讀檔一處。
- 美術：建物外形、牆貼牆的縫照舊（所以不選 1024）。
- 音樂：無。
