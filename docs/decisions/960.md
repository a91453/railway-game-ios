### 960. 線上有車之後也能換車型；從車隊總覽的型錄直接買一列

2026-11-24，雲端工作串 TRAIN-TYPE-PICK 的第二張 PR，分支 `claude/train-type-pick-2`（第一張是決策 959）。作者在 TestFlight 145 實機回報「設定完路線後列車怎麼更換車型」「根本沒有派車選項」「列車型錄出現買不了車」。號碼依 #2118 的登記：決策 960；存檔版本、golden schema、重播檔都不動。

## 1. 做了什麼

1. **在軌道上的單一列車**：列車卡的車種按鈕不再只在車還沒放上軌道時出現。打開型錄選一款時呼叫 `GameSession.changeTrainType(_:to:)`：
   - 車不在軌道上：照舊 `setTrainType`。
   - 車在軌道上、沒在跑一趟：新的指令 `PlayerCommand.Edit.refitTrain`，一次完成「移出軌道 → 換車種（決策 180 的改裝費）→ 放回原位 → 有路線的話回到原本的班次」。原位放不回去時，有路線的放到路線起點，沒路線的就失敗、整個指令不生效。
   - 正在跑一趟：不換，訊息說「等它在站上等下一趟時再換車型」。GameCore 的 `setTrainType` 只准沒放上軌道的車（決策 180），這裡沒有改 GameCore，只是替玩家先移出、再放回。
2. **線上已有車的路線**：路線面板的「派車」區只在路線自己的班次沒有車時顯示，有車後只剩班距。現在有車的線多一個「換車型」區：
   - 選車種（選單或型錄），按「整線換成 …」。
   - 呼叫既有的 `reformSelectedLine`，`cars` 傳 `nil`，每列保留自己的節數（`Edit.reformLine` 的 `cars` 改成 `Int?`，舊紀錄的整數照讀）。
   - 換線時選擇清空（`refitType` 是面板層級的狀態）。
3. **改編組放不回起點時放回原位**：改編組原本把每列車放到路線起點。路線的其他車已經停在那裡時，除了第一列，其他列都失敗（平溪線三列只換得到一列：「有列車的路線要經過這段軌道，請等它通過」）。現在放不回起點的，放回它原本站的地方。
4. **從車隊總覽打開的型錄**：原本是「只看」，沒有任何按鈕。現在每款有「買一列」：
   - 呼叫 `GameSession.purchaseTrain(of:cars:)`，新的指令 `Edit.purchaseTrainOfType`，用 GameCore 的 `purchaseTrain(named:as:)`，照那款的價錢與自己的性能，再加到選的節數。
   - 買了選中它，訊息說去選車站放上軌道。教學裡還沒開放的車種照舊顯示「第 N 關解鎖」。

## 2. 幾個判斷

- **放回原位，不放回起點**：玩家在路上換一列車，車留在原地最好懂；回到起點會讓班表亂掉。
- **有車的線另開一區，不把派車區一直顯示**：派車區是「買幾列、開始營運」，對已經在跑的線會誤導（會再買一批）。
- **不碰 GameCore**：在軌道上換車型由介面替玩家移出再放回，是一個指令、一次復原。GameCore 的規則（只准沒放上軌道的車）不變，golden 與重播不受影響。

## 3. 五方

- 玩家：線開了之後也找得到換車的地方，列車卡、路線面板都能換；車隊總覽的型錄能直接買。
- 鐵道迷：無（車種本身不變）。
- 開發：兩個新的介面指令、一個可省略的參數，GameCore 不動。
- 美術：路線面板多一區、列車卡多一列，用既有的元件。
- 音樂：無。

## 4. 找過什麼

參考庫的 `Ci/`（`TRAIN_TYPES` 與路線表單）只有開線時選車種，沒有「線上換車」。本專案自己寫。
