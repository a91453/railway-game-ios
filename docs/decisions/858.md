### 858. App 不再帶香港、羅瓦涅米的地圖資料：只帶清單，資料靠下載；沒變的地圖包不重傳（MAP-PACK-OUT）

2026-11-18，雲端工作串「拿掉內建地圖資料」，分支 `claude/project-thread-opekgf`，協調者派工。作者 11-18 確認 0.6.0 (139) 的「設定 → 地圖」香港、羅瓦涅米兩列都是「已下載」，決策 776 第三段與 ROVANIEMI-PACK-OUT（決策 818 §4）的前提成立；同一天補一句：「但是每上傳一次就要審核一次」（App Store Connect 上 `mappack-hongkong` 第 5、6 版同一天、同樣 13.4 MB）。號碼依 #2118 的登記。

不動 GameCore、存檔版本、golden、replay。動 GamePresentation（`MapPackDownloads`、`OverseasMaps`、`AirRoutes`、`GameLauncher` 讀實景資料與開局那幾處）、App（`MapPackDownloader`、`RailwayGameApp`、`OSMMapBackground`、`RealWorldPicker`、`SettingsView`）、`project.yml`（Xcode 專案重產）、`testflight.yml` 上傳地圖包那一步與新腳本 `testflight-map-packs.py`。

## 1. 做了什麼

1. **Release 的 App 只帶每座城市的 `pack.json`**（香港 4 KB、羅瓦涅米 3 KB），不帶地圖包的其他檔。IPA 少約 28 MB（香港 14.3 MB＋羅瓦涅米 13.4 MB）。`pack.json` 留著有兩個用途：
   - 下載到的地圖包要和它逐 byte 相同才算「這一版 App 要的那一包」（決策 776 的 `differsFromBundled`，現在比的是 App 自己那份 `pack.json`，`MapPackDownloads.use(_:locators:expected:)`）；
   - 它的 `extent` 說這座城市的地圖在哪裡，所以地圖包還沒到時，App 也認得出「這個存檔是香港的」（`OverseasPlace`）。
2. **Debug 的 App 照舊整包帶**：Simulator、UI 測試、網站截圖沒有 App Group，下載器不跑（決策 776），拿掉就沒有香港可測。`project.yml` 用一個建置腳本複製：Debug 整個 `Resources/MapPacks`，其他設定只複製各城市的 `pack.json`。`MapPack.bundled` 只在資料夾裡 `pack.json` 列的檔都在時才算 App 帶著。
3. **啟動時**（`MapPackDownloader.start`）：
   - 先看手機上已經有的（不問網路）：以前下載過的，離線也馬上能用。
   - 沒有的才去抓；抓不到（第一次開就沒網路）隔 15 秒再試，之後每次加倍，最多 5 分鐘一次。
   - 讀實景資料前最多等 5 秒下載器的回答（`waitForAnswers`）；手機上已有的地圖包幾毫秒就回答，所以平常不會多等。台灣的資料不因為海外的地圖包沒到而少。
4. **地圖包在 App 開著時才下載好**：實景資料重讀一次（`GameLauncher.reloadRealWorldData`），新遊戲清單那一列當場打開，**不用關掉 App 再開**。讀的這幾秒照用原本的資料，不會回到「讀取中」。
5. **還沒下載時玩家看到什麼**：
   - 新遊戲清單：那座城市的列照樣在，圖示是下載的箭頭，說明「香港的地圖下載中，下載完就可以玩。」或「香港的地圖還沒下載。連上網路後會自動下載。」。香港的航班還沒開時，照舊先說航班怎麼開。
   - 設定 → 地圖：「下載中／已下載／尚未下載」（Debug 帶著整包時照舊是「使用內建資料」）。
   - 台灣的地圖、自由地圖、教學、關卡完全不受影響。
6. **存檔在還沒下載的地圖上**：不開，說同一句話，存檔原樣留著；地圖包到了再按就開。原因：沒有那座城市的地面時，舊程式會把台灣的人口、水域、高度交給這一局（香港的座標在台灣的格網外，讀到的是「沒有人、沒有海」），而地塊一讀進世界就存進存檔，等於把存檔弄壞。
   - 實景資料還在讀的那幾秒就按了「繼續」的那一局：照決策 88 原有的規矩，資料沒到之前不讀地塊；讀完發現地圖包不在，這一局拿到的是「沒有地面資料」（`population(for:)` 等回 `nil`），不是台灣的，並在狀態列說地圖還沒下載。地圖包到了自動補上。
7. **航班**：地圖包沒到的城市照樣算進航點（`airRoutes`），所以「第一張地圖」照常記、在台灣開的航線照常算，不會因為香港晚幾秒到就漏記。
8. **手機上的地圖包不是這一版 App 列的那一版**（新版地圖包還在等審、玩家離線）：先問一次更新（DEBUG-138）；還是拿不到，而且 App 沒帶整包時，**用手機上那一版**，不讓玩家沒有地圖（`MapPackStatus.earlier`；設定寫「已下載」，回報問題寫 `used: not the version the app lists`）。新版到了再換。Debug 帶著整包時照舊嚴格，讀自己帶的。
9. **發版只上傳有變的地圖包**（`.github/scripts/testflight-map-packs.py`）：App Store Connect 每上傳一次就多一個版本、每個版本都要審，檔案一樣也算。所以拿每一包的清單（`AssetPacks/<城市>.json`）與資料夾（`Resources/MapPacks/<城市>`）在這個 commit 的 git 雜湊，和「上一次成功的 TestFlight run 的那個 commit」比，一樣就不傳。
   - 判斷不了就傳（沒有上一次、GitHub 沒回、那個 commit 拿不到、工作目錄裡的檔和 commit 不同）：多傳一次只是多審一次，少傳一次是玩家沒有地圖。
   - 該傳而沒傳成功，**發版在這一步停**，build 不上傳（以前只是警告，因為 App 自己帶著）。這也讓「上一次成功的 run」等於「App Store Connect 有那個 commit 的地圖包」。
   - `testflight.yml` 多一個輸入 `map_packs`：`changed`（預設）或 `all`（全部重傳）。
   - 有上傳新版時，run 的摘要會寫：外部測試與上架前，這一版地圖包要和 build 一起送審。
10. **IPA 檢查**（`testflight-verify-ipa.sh`）：IPA 裡 `MapPacks` 下有 `pack.json` 以外的檔就不上傳（防止哪天又把 28 MB 帶回去）；表上多一列「App 列了幾包」。

## 2. 五方理由

評分沿用：決策 776 第三段 2.25（§29 第 16 項）、ROVANIEMI-PACK-OUT 1.80。

- 玩家：第一次下載少約 28 MB；地圖包是 `prefetch`，裝 App 時系統就一起抓，平常開起來就在。沒抓到時看得到原因、會自己重試、好了不用重開；存檔不會被讀錯地面。
- 鐵道迷：城市的班表、站名改版可以只換地圖包；資料沒變的版本不重傳，審過的那一包一直用。
- 開發：下一座城市（福岡）只要加清單，不會讓 App 再變大；每版發版少兩次上傳與審核。代價是 Release 的下載路徑只有實機能驗（見 §4）。
- 美術：新遊戲清單多一個狀態（下載箭頭＋一句話），沿用原本那一列的樣式，不新增畫面。
- 音樂：沒有關係。

## 3. 沒有選的

- **Debug 也不帶**：Simulator 沒有 App Group，UI 測試與網站截圖會整個沒有香港、羅瓦涅米。
- **一律嚴格（手機上的版本和 App 列的不同就不用）**：新版地圖包等審的那段時間，外部測試者與離線的玩家會沒有地圖、開不了自己的存檔。存檔本身帶著整個世界，地圖包只供底圖、地面與收購時的真實路線，舊一版比沒有好。
- **沒下載也讓存檔開、之後再補地面**：玩家會在沒有海、沒有高度的地圖上蓋，之後地面補上時已經蓋的東西在海裡或山裡。
- **把下載的地圖包複製一份到 App 自己的資料夾**：離線更保險，但多佔 28 MB（決策 819 已經否決過同樣的事），而先看手機上已有的（§1 第 3 點）已經讓離線能用。
- **用雜湊記在 repo 裡、或用 Actions 的快取記上傳過哪一版**：發版的 workflow 不能寫 `main`；快取會被清掉。比上一次成功的 run 的 commit 不用存任何東西。
- **問 App Store Connect 現在有哪一版**：它的 API 不給內容雜湊，只有版本號與狀態。

## 4. 驗證

- VERIFIED（Linux 雲端，Swift 6.4.0）：`swift build --build-tests -Xswiftc -warnings-as-errors`；`MapPackDownloadsTests`、`AirRoutesTests` 等相關測試（清單見 PR）；`python3 -I .github/scripts/testflight-map-packs.py --selftest`；XcodeGen 2.46.0 重產專案。
- UNVERIFIED（要 macOS CI）：App 的 Swift 編譯與 UI 測試（`ios-build.yml`，Debug，整包帶）；Release 建置腳本只複製 `pack.json`（`release-archive.yml` 會建，但沒有檢查產物內容；真正檢查的是發版時的 IPA 檢查）；`package.sh` 只包指定的地圖包。
- **UNVERIFIED（只有實機、而且要第一次真的發版）**：
  - Release 的 App 沒帶整包時，從下載讀到地圖（手機上已有 139 抓的那一版時，應該一開就是「已下載」）；
  - 刪掉 App 重裝、離線第一次開、之後連上網路自己補上且不用重開；
  - 手機上是舊版地圖包時用舊版（§1 第 8 點）；
  - `testflight.yml` 的新步驟：第一次會和 139 的 commit 比，兩包都沒變就都不傳；`altool` 失敗時真的回非零（沒有文件，照慣例假設）。
- 萬一第一次發版後實機拿不到地圖：台灣照玩，香港、羅瓦涅米那兩列顯示「尚未下載」，存檔不會壞；退回就是 revert 這個 PR 再發一版。
