- 第二塊是模擬器剛開機那幾分鐘機器被系統的背景工作佔滿（CIOPT-16 量過「開機到第一支測試 6.9～8.0 分」）。

## 2. 怎麼做

- 新的 `.github/scripts/ui-gate.py --base <rev>`：PR 的每個檔都是下面幾種，才印 `ui=toolbar`；其他、或讀不了，`ui=gate`。
  - iOS 本來就不跑的路徑（`docs/`、`Tests/`、`tools/`…，同 `paths-ignore`）、`.gitattributes`。
  - 只有 3D 地圖、真實地圖、海外地圖包讀的資料：`RailwayGameApp/Resources/` 的 MapPacks、RealWorld、RealRailways、RealBuses、
    RealCoaches、Map3D、Models。**不含** BaseMap（空白地圖的 2D 畫面會畫它）。
  - 發版說明：`WhatsNew.swift` 只改條目（直接用 `release-notes-only.py` 的檢查）、`WhatsNewNext/new|fixed/*.txt`。
  - `Sources/GamePresentation/Map3D*.swift`，而且它在改之前、改之後宣告的頂層名字（型別、extension、函式、常數），**App 自己的 2D
    程式**（`RailwayGameApp/App/`、`RailwayGameApp/Views/`，但不含 `Views/Map3D/` 與 `CityView3D.swift`）一個都沒提到。2D 畫面會叫到的
    3D 檔（3D 畫質設定、2D 轉 3D、2D 地圖用 `Map3DScene` 種街道、2D 地圖畫的地標）照舊跑四支。
- `ios-build.yml`：changes job 先跑 `ui-gate.py --selftest`，再判斷，輸出 `ui`；build job 的介面測試那步在 `ui=toolbar` 時只跑
  `ToolbarSmokeTests/testEnglishToolbar`。這一步失敗（含 selftest 紅）就當 `gate`，四支照跑。`ui` 也進「這個改動過了沒」的 key。
- iPad 教學 job 的規則不變（只看教學自己的檔），教學的檔一定是 `gate`。
- 每晚與手動的完整檢查（full lane）不動，照樣跑全部介面測試，含打開 3D 地圖的那些。

## 3. 為什麼只留工具列那支就夠

閘門的四支都在**空白地圖的 2D 畫面**上：工具列（開 App、開新局、每個工具按得到）、大字體下回到開始畫面、教學的鋪軌與路線兩步。
四支都不開 3D 地圖、不開真實地圖、不開海外地圖包；3D 模型只有帶 `-ui-test-3d-models-first` 的測試才會在開 App 時建（閘門沒有）。
所以只改 3D 模型或地圖資料的 PR，其他三支看到的程式和工具列那支一樣：同一個啟動、同一張空白地圖。工具列那支留下來，抓的是
「改了之後 App 開不起來、按不到按鈕」。模型本身由 Linux 的測試管（三角形預算、形狀鎖、地標登錄），畫面由每晚的 full lane 管。

11-21 到 11-27 合進 main 的 187 張會跑 iOS 的 PR，照這個規則有 40 張（21%）會只跑工具列那支。不讀 App 的 2D 程式、只看檔名
`Map3D*` 的話是 49 張，少掉的 9 張多半改了 `Map3DScene*.swift`（2D 地圖在背景呼叫 `Map3DScene.seededStreets` 種街道），照舊跑四支。

## 4. 拆分有沒有用（作者問的）

- **對 Linux 的 Swift 測試有用**：決策 1012 靠名字挑測試，一個檔宣告的東西越少，挑得越準（CI-AFFECTED「給拆檔的人」）；
  拆檔也讓平行的 PR 少撞同幾行（SPLIT-HOTSPOTS 的目的）。
- **對 iOS 的編譯沒有用**：Xcode 以模組為單位重編，GamePresentation 裡拆成幾個檔都一樣整個重編（#2780 只加兩座城，975 個編譯工作
  全部重做）。要讓只改模型的 PR 少編，得把 3D 模型拆成**自己的模組**，而且只改模型時模組的介面不變，後面的模組才對得上快取。
  這是另一張單（§6），工程大、要先在 Mac 上量。
- 不必要的拆分：沒找到。11-26、11-27 拆的（資料來源頁、各地列車、門、測試）都在減少衝突或讓測試挑得準，沒有拖慢 iOS。

## 5. 驗證

- `ui-gate.py --selftest`：16 個情況（模型網格、新模型加登錄、刪模型、模型加地圖包與說明、只有資料、2D 叫得到的 3D 檔、改名前
  2D 叫過的、只有其他 GamePresentation 檔叫到的、加一個 2D 檔、加教學、BaseMap、字串表、說明條目外、這個 workflow、只有 docs、沒有改）
  在 Linux 全過（VERIFIED，雲端容器）。
- 拿 11-21 起 main 的合併逐一跑過（§3 的 40／187）（VERIFIED，雲端容器）。
- 介面測試那步的 bash 在 Linux 照 `ui=toolbar`、`ui=gate`、schedule 各跑一次，印出的 `-only-testing` 是一支、四支、全部（VERIFIED）。
- 這張 PR 自己改了 `ios-build.yml`，所以它的 iOS run 是 `gate`（四支）；第一次 `ui=toolbar` 的真跑在下一張模型 PR，
  時間寫回這裡的「後來」（UNVERIFIED，要 macOS）。

## 6. 五個角度

- 玩家：無直接影響；模型與地圖的 PR 合得快一點，新東西早一點進 TestFlight。
- 鐵道迷：無。
- 開發：模型、地圖資料、說明的 PR 在 GitHub 的 Mac 上每張少約 3.4 分，在 chien-mac 上少約一半的介面測試時間；判斷不了就照舊。
- 美術：工作室交件的模型接進遊戲時等得少一點。
- 音樂：無。

## 7. 不選的

- **只改 3D 的 PR 完全不跑介面測試**：App 開不起來（例如新模型在啟動時就被讀到而當掉）就沒有人抓到；工具列那支只要 36 秒。
- **只看檔名 `Map3D*` 就縮小**：`Map3DScene*`、`Map3DQuality` 這些 2D 畫面也會叫到，改了它們還是該跑四支。
- **追 GamePresentation 裡誰叫到誰（整串追下去）**：幾乎每個 3D 檔最後都接到 `MapView`，追下去等於沒縮；而 `MapView` 本來就在
  工具列那支跑。
- **拿掉 main 推送與每晚的完整檢查**：那是安全網（作者 11-27 同意保留）。
