## 2. 規則

1. **位置照 OpenStreetMap**（2026-11-22 由 OSM API 讀）：
   - 大佛：way 1272641026（`八卦山大佛`，13.5 m 見方，中心 24.0785735, 120.5488684）當基座中心。模型的外框多出西側 6 m 的台階，`--centre` 把外框中心移到基座中心以西 3.2 m，registration 的經度照這個位移（120.5488369）。佛像朝西（工作室照派工單做；衛星圖沒驗，見第 4 節）。
   - 龍虎塔：龍塔 way 81161400、虎塔 way 81161399（各約 16.2 × 15.9 m），兩塔中心的中點 22.6804762, 120.2924792。兩塔中心相距 21.6 m，龍塔在北、比虎塔偏東 7.1 m，所以 `--turn -19.3`（順時針 19.3°）讓模型的兩塔連線對上 OSM。派工單抄的 way 162322798、162322800 不是龍虎塔（在美國），這裡改用名字對得上的兩條。外框中心在兩塔中點以西 20.3 m（九曲橋往西伸），registration 照這個位移。
2. **匯入工具兩處小改**（舊地標的檔不重寫，位置與雜湊不變）：
   - `--nodes`：照每個節點的位移放網格（龍虎塔的兩座塔是同一個網格放兩次）；不加時照舊拒絕有變換的節點。
   - `--centre` 改成所有模型都照**第一個（近景）**的外框中心移。龍虎塔遠景沒有九曲橋，外框比近景短 27 m，各自置中會讓遠景和近景差 13.5 m，遠近切換時塔會跳。近景與遠景外框相同的地標（之前全部）結果不變。
3. **測試**：`Map3DLandmarkRegistryTests.testTheModels` 的長寬與置中只對近景要求；遠景要高度相同、腳在 0，並且在近景的外框內（可以少一段低的零件，像九曲橋）。
4. **放在地上**：兩座都 `sink` 0、`baseHeight` 0（照舊取外框四角最低的地面）。大佛的基座 3.5 m 高、在八卦山頂整平過的廣場上，取最低角不會懸空；龍虎塔的 Z = 0 是潭面，遊戲把潭畫在地面高度，取最低角就是水面。
5. 顏色全是遊戲已有的色票，照兩個資料夾 README 的色票表：
   - 大佛：`buddha` = `counters[1]`、`buddhaShade` = `dark`、`lotus` = `templeRoof`、`lotusEdge` = `templeRidge`、`lotusRim` = `gymGreen`、`base` = `stone`、`steps` = `ballast`。
   - 龍虎塔：`wall` = `gold`、`roofTile` = `timber`、`roofTrim` = `mtrTeal`（龍身）、`column` = `mtrRed`、`rail` = `stone`、`gold` = `gold`、`opening` = `dark`、`warm_lit` = `tunnelLamp`（簷下的燈）。`wall` 與 `gold` 同色，保留兩個材質名（工作室 r2 只改色、不併材質）。
6. **資料來源**：大佛的佛像是 Meshy AI 生成（工作室 `SOURCE.md`），資料來源頁的 Meshy 一項加一句「彰化八卦山的大佛：用 Meshy 的 AI 生成的佛像」。龍虎塔與大佛的基座、蓮座是為遊戲手做的，照片只拿來比對與取色、不當貼圖，不另列。
7. 軌道：八卦山頂與蓮池潭湖上都沒有遊戲的軌道（左營一帶的縱貫線在地下），`isClearOfTrack` 不會擋；沒有在場景裡跑過確認（第 4 節）。

## 3. 留下的

- 八卦山大佛的朝向沒有用衛星圖驗（工作室 README「還有哪裡不好」第 5 條）；若之後量到不是正西，用 `--turn` 轉並更新鎖檔。
- 頭偏大 11%、螺髮無顆粒、蓮座直筒等工作室列的已知缺點照原樣，遊戲大小看不出。

## 4. 五方

- 玩家：彰化八卦山多了一眼認得出的大佛，高雄蓮池潭湖上多了龍虎塔。
- 鐵道迷：兩處都是從台鐵彰化站、左營（舊城）站／新左營站看得到的地標；位置照 OSM 外框、龍虎塔的方向照兩塔的實際排法。
- 開發：只改 GamePresentation、匯入工具與它的測試；舊地標的位置、雜湊都不變；台灣地圖 8,642／60,000 個三角形。
- 美術：工作室對照片過審（model-look §1）的模型原樣接入，全用遊戲已有的色票，沒有新顏色。
- 音樂：無。
