### 889. 從舊版沿用的模型一律用色票色；之後新寫的顏色不在色票就擋（OLD-MODEL-PALETTE）

2026-11-20，雲端工作串「把沿用舊版的模型換成新版色票」。作者看到福岡塔顏色怪（後來確認遊戲裡的福岡塔已是色票色，看到的是舊版縮圖），要求：已經在遊戲裡、從舊版直接沿用的模型，都轉成新版色票，色票沒有合適的就照新版風格新增；並照「通用問題改成共用做法」加一道檢查。號碼依 #2118 的登記。

存檔版本、golden schema、GameCore、`GoldenScenarios/`、`SaveFixtures/`、`ReplayFixtures/` 都不動。只動 GamePresentation 與測試。

## 2. 改了什麼

1. **月台站名牌綠帶** #106118 → `Map3DPalette.cityRoofs[3]` #3C8A5A（綠色防水漆屋頂；博多站屋頂也是這個綠）。色票裡沒有接近舊色的綠（最近 ΔE 22），三個方案的預覽在 PR：A 這個、B `signs[3]` #4FA36B、C 新增深綠 #1F6B35。選 A：不必加新色，白天平塗下仍和白底分得開。
2. **紅色通勤車** #C9CECC → `shedWalls[2]` #C9CDC9（ΔE 1.2），#E9EBE5 → `acUnit` #E9E7DF（ΔE 2.1），看不出差別。
3. **金色** #C8A24E 正式登記為 `Map3DPalette.gold`（決策 854 香港地標派工單就「新提」的金，遊戲裡本來就在用，畫面不變）；日月潭廟改用它，香港地標表註明是它。

## 3. 檢查：`Map3DPaletteGuardTests`

- 讀 `Sources/GamePresentation/*.swift`，`Map3DPalette` 的 `enum` 與各 `extension` 區塊裡寫的顏色就是色票；區塊外用 `rgb(0x…)` 或 `rgbColor(0x…)` 寫、又不是色票的顏色，「檔名 色碼」不能出現在 `tools/palette-guard/baseline.txt` 以外。基準是 2026-11-20 的 471 個（66 個檔，大多是各列車塗裝與車站外觀，不是舊版模型），只能刪不能加：已經不在程式裡的列也會讓測試紅，提醒刪掉。新顏色要嘛用色票的，要嘛寫進 `Map3DPalette` 並寫理由。
- 上表的舊版模型另有一個測試：它們實際用的每個顏色都要在色票裡。
- 沒擋到的：直接寫成 `0xRRGGBB` 的陣列（例如香港建築的 `drawn([…])`、地標的材質表）與產生的模型檔。地標材質表由第二個測試把關；其他之後若要收進來再評分。
- 基準裡的 471 個色要不要逐檔收進色票，另行評分（assets-2 `docs/priorities/OLD-MODEL-PALETTE.md`）。

## 4. 五個角度

- 玩家：站名牌綠帶比舊貼圖的深綠亮一點，和地圖其他綠一致；其他看不出差別。
- 鐵道迷：台鐵站名牌是白底綠帶，綠帶仍是綠；通勤車紅色不變。
- 開發：一道 Linux 測試把「顏色只從色票來」變成會擋的規則，不靠派工單記得。
- 美術：所有舊版模型與新做的模型同一套色，白天、平塗 B 的看法一致。
- 音樂：無。
