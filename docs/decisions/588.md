### 588. 詳細卡片：頭太高時只固定底部，放車時車廂數與月台放在「放在這裡」正上方

## 為什麼

iPhone 只能橫放。橫放時卡片最高約 267 點（iPhone Pro；最小的 iPhone 約 240），頭（選了什麼）與腳（主要按鈕）都固定時，中間會捲的那段只剩約 70 點（決策 584 的截圖 run 41880284408、41906093384）：

- 放車時要選的車廂數、月台在中段下面，要捲才看得到。
- 英文字長，頭（「Waiting to be sent out / Next: select a station…」）更高，頭加腳超過舊規則的門檻，整張卡片一起捲，「Place … Here」跑到卡片外面。
- 渡輪、纜車模式的英文提示有五行，固定在頭上，下面的選項只剩一條窄縫（渡輪模式 run 41873942048）。

## 做了什麼

- **三種版面**（`DetailsCardLayout`，GamePresentation）：
  - `pinned` 頭與腳固定、中間捲：頭加腳之外還有約三列（132 點）時。舊規則是兩列（88 點），手機上就是那 70 點。
  - `footPinned` 只固定腳，頭跟著選項一起捲（新）：頭太高、但腳之外還有一列（44 點）時。主要按鈕一直看得到，頭往上捲走。
  - `whole` 整張捲：連腳都放不下時（舊規則照舊）。
- **不來回跳**（TestFlight 56.1 的教訓）：每種版面「進入」要的空間比「留住」要的多，差距大於頭或腳多一行字（頭固定：進 132、留 88；腳固定：進 44、留 24，月台下多一行警告約 16–20 點）。換顯示的東西時重新決定。
- **放車要選的放進腳**（`DetailsCardLayout.placesTrain`、`TrainPlacementChoices`）：列車工具選了一列還沒上軌道的車時，車廂數（價格寫在數字下面）與月台那排按鈕移到卡片腳、「放在這裡」正上方；中段剩車型、朝向、性能、時刻表。最小 iPhone 上腳約 170–190 點，仍是 `footPinned`，中英文都不必捲就看得到車廂數、月台與按鈕。
- 渡輪、纜車模式的長提示在手機上變成 `footPinned`：提示在最上面，跟選項一起捲，選項不再被擠成一條縫。iPad 卡片高，照舊頭腳都固定。
- UI 測試的識別碼：`details.scroll.middle`（頭腳固定）、`details.scroll.foot`（新，只固定腳）、`details.card` 本身捲（整張）。`testPlacementPlatformChoice` 改成不捲動，直接檢查兩個月台、車廂數與「放在這裡」都在卡片裡、按得到。
