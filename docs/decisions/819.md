### 819. 下載的地圖包每個檔各自問 `AssetPackManager` 在哪裡，不假設都在 `pack.json` 旁邊（MAPPACK-FIX）

2026-11-17，MAPPACK-FIX（雲端 session_01JMHz9YiuyqQSmoz6Bk5oTv，`claude/mappack-fix`）。bug，排在功能前面。存檔版本、golden schema、GameCore 不動。接決策 776。

## 症狀

作者 0.6.0 (136) 實機（iPhone18,1，iOS 27.3）：設定的「香港地圖」一直是「使用內建資料」，回報問題那一行是 `地圖包：mappack-hongkong not used: incomplete("airfields.json")`。`ensureLocalAvailability` 沒拋錯，`url(for: "MapPacks/hongkong/pack.json")` 也讀得到 `pack.json`，是 `MapPackDownloads.check` 在第一個檔就拒用。

## 原因

- 查過不是檔案壞掉：136（`19f3cc58`）與 `main` 的 `hongkong/pack.json` 列的 15 個檔，大小全部與實際檔案相符（`airfields.json` 70,687 B）；136 的 `testflight.yml`（run 43998784830）`mappack-hongkong.aar` 版本 3 上傳 0 錯誤 0 警告。`airfields.json` 是清單照字母排的第一個，所以「第一個就沒找到」等於「`pack.json` 旁邊什麼都沒有」。
- `MapPackDownloader` 原本拿 `url(for: pack.json)` 的資料夾當整包的資料夾。Apple 的 `url(for:)` 文件：所有 asset pack 共用一個名稱空間；問**資料夾**時，它把各包的那一段合成一個資料夾給你，問**檔案**時用的是另一套邏輯（Apple 工程師在 FB19512759 的討論裡說的「`url(for:)` uses different logic for resolving directories compared to individual files」；那個 bug 的錯誤訊息是「`asset.mov` couldn't be copied to `subdir`」，看得出問一個檔是把那一個檔放進一個資料夾）。所以問 `pack.json` 得到的資料夾只有 `pack.json`，正是實機的樣子。文件也說這個 URL 不要留過這次執行。
- 這是從文件與實機訊息推出來的，**沒有在實機重現**（Linux 與 Simulator 跑不了 Apple 代管的下載）。下面第 3 點讓下一次回報直接看得出是不是這樣。

## 決定

1. `MapPack` 可以帶「每個檔各自的 URL」（`MapPack(root:files:)`、`url(of:)`）；`file(_:_:)`、`baseMapFile`、`buildingsFile`、`terrainFile` 都經 `url(of:)`。沒給的檔照舊在 `root` 裡找，bundle 的包不變。
2. `MapPackDownloads.use(_:locators:bundled:)`：每個檔（`pack.json` 先）照順序問一串「在哪裡」，取第一個大小對的地方。`use(_:root:)` 與 `check` 是只有一個「在資料夾裡」的特例，舊行為不變。
3. App 的 `MapPackDownloader` 給兩種問法：先 `url(for: "MapPacks/<城市>/<檔名>")` 一個一個問；問不到的才問整個資料夾 `url(for: "MapPacks/<城市>")` 一次，再接檔名（Apple 對檔案 bug 建議的繞法）。
4. 拒用時多記一條線索（`MapPackDownloads.clue`），接在回報問題那一行與 log 的後面：找到幾個檔、各是哪一種問法找到的、`pack.json` 所在資料夾（只留路徑最後三段）與裡面有幾個項目、第一個沒找到的檔清單上的大小與每種問法給的位置在不在。例如：
   `mappack-hongkong not used: incomplete("airfields.json") (found 0 of 15 files (0, 0 by locator); pack.json in …/MapPacks/hongkong (1 item); airfields.json listed 70687 B, at …/MapPacks/hongkong/airfields.json absent, …)`
5. 不把香港、羅瓦涅米的地圖包移出 App（決策 776 第三段照舊等實機看到「已下載」）。

### 量了再選：每個檔各自的 URL（選這個）或在 App Group 建一個整齊的資料夾

香港包 14,296,524 B、15 個檔。

- 整齊的資料夾：複製進去要多佔 14.3 MB（每座城市一份，地圖包更新還要清舊的）；用符號連結不多佔，但連結存的就是 Apple 說「不要留過這次執行」的 URL，下次啟動前就可能失效；硬連結跨不了 Apple 存放的位置與 App Group 的權限。
- 每個檔各自的 URL：不寫任何檔（0 B），每次啟動重新問，正合 Apple 的說法；程式在 `MapPack` 多一個字典、一個 `url(of:)`，讀檔的地方本來就只經 `MapPack`。

### 各方理由

- 玩家：香港地圖改讀下載的那一份，之後香港可以不跟 App 一起更新；這一版看得到的只有設定那一列從「使用內建資料」變成「已下載」。
- 鐵道迷：沒有關係（讀到的班表、站名與 App 帶的逐 byte 相同，決策 776 的比對照舊）。
- 開發：照 Apple 文件的用法問每個檔，不靠沒寫在文件裡的資料夾結構；拒用時回報自己帶線索，不用再猜。
- 美術：沒有關係。
- 音樂：沒有關係。

## 封存時那條 ExtensionKit 警告（順便查）

`MapPackDownloader.appex is an ExtensionKit extension and must be embedded in the parent app bundle's Extensions directory, but is embedded in ../../../BuildProductsPath/Release-iphoneos/RailwayGame.app/Extensions`：專案的「Embed ExtensionKit Extensions」是 `dstSubfolderSpec = 16`、`dstPath = "$(EXTENSIONS_FOLDER_PATH)"`，就是 Xcode 自己的樣板；136 的 IPA 檢查「Map pack downloader extension」是 yes（`RailwayGame.app/Extensions/MapPackDownloader.appex` 在），下載也真的成功。這條是 Xcode 14.3 起封存時 `embeddedBinaryValidationUtility` 把封存的 `BuildProductsPath` 符號連結當成別的位置的已知誤報（Apple 開發者論壇 734556、804001 同一句，沒有人修好也沒有影響）。不改。
