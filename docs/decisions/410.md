### 410. 程序列車照 700T 與 N700S-G 的做法重建：圓角斷面、量過的車鼻、照多邊形切的塗裝、兩層圓角窗、斜面上的擋風玻璃、真的燈與對準開口的轉向架；舊的只留好的部分

2026-10-25，遊戲規劃 session_01B2kaku5NRz2J2CMzc8z3cZ 派工（#1217 合併後），實作 session_0184ajQAx9BPLKw475Jw1G5U。作者 10-25：「等等我看過後 你照 700T 與n700sg升級現有的列車建模 要結合兩者有點 然後現有建模只取好的部分 太差都可以刪除」。號碼依 #1041：決策 410；存檔版本、golden schema 不動；GameCore、SaveFixtures、ReplayFixtures 都不動。

## 改之前

程式畫的列車有兩套，都很舊：

- **樣式模型**（決策 230 的 `Map3DTrainBuilder`，`commuter`、`express`、`highSpeed`、`metro`、`peopleMover` 的頭車、中間車、集電弓車）：斷面是幾段直線拼的，車鼻用漸層把顏色抹過去，窗是貼平的深色方塊，轉向架是一塊黑箱。頭車 288–990、中間車 214–382 個三角形。營運時畫到它的只有沒有自己 set 的車種（通勤、沒有型號的列車），其餘被 set 蓋過去。
- **場景套件的電聯車與客車**（決策 318 的 `Map3DTrainSet.multipleUnit`：城際特急、紅臉特急、傾斜式特急、區間車、捷運、文湖線、柴油特急與柴油客車；莒光、藍皮等機車牽引的客車；遠景高鐵 `highSpeedFar`）：頭車是 `SceneKitCab` 自己拼的車身，再用 `CabSurface` 把擋風玻璃貼上去；中間車與客車借樣式模型的 `Map3DTrainBuilder`。頭車 936–1,709、中間車 202–430 個三角形。

#1201 的 700T（`Map3DTrainShapeRefresh.refreshHighSpeed`）與 #1217 的 N700S-G（決策 408）是現在畫得最好的兩款，但它們的做法沒有用到其他列車上。

## 做法（只改 GamePresentation）

新的共用車殼 `Map3DTrainShell`（`Sources/GamePresentation/Map3DTrainShell.swift`），樣式模型、場景套件的頭車、中間車、客車都改用它。從兩款各取的：

| 來源 | 取了什麼 | 新的位置 |
|---|---|---|
| 700T `refreshHighSpeed` 的 `surface`（超橢圓斷面） | 斷面用超橢圓：側面與頂各自的圓度（`sideRound`、`topRound`，樣式新欄位），一圈 32 段（遠景 16） | `Map3DTrainShell.section`、`point`、`flank` |
| 700T `dimensions`／`interpolate`（量過的車鼻表） | 車鼻照長度分四種（`NoseShape`：平、圓、斜、長），長鼻用 700T 的高度、寬度、下巴三張表（正規化到 0–1），其他三種是同樣做法的短表；車鼻的環越近車頭越密（`1-(1-u)^1.5`） | `NoseShape.drop`／`tuck`／`lift`、`rings` |
| 700T `nosePaintParts`、`bandHeight`（照多邊形切塗裝） | 裙、色帶、細線、車頂的交界不再是頂點漸層：每個三角形照「高度＋往車鼻下潛的量」切開，交界是一條直線；邊上的點排序後再切，兩邊的三角形共用同一個切點，不會裂 | `level`、`edges`、`paint` |
| 700T `refreshRoundedOutline`、`refreshPanel`（兩層圓角窗） | 窗：深色外框（`darkLine`）＋玻璃，兩層圓角，各凸出車身一點；門：門框、門扇、門窗三層。超過窗下緣的（門）切成約 0.22 m 高的橫條貼在曲面上，才不會陷進下半部往內收的車身 | `rounded`、`addOnFlanks`、`addOpenings` |
| 700T `screen`／`glass`（曲面擋風玻璃） | 擋風玻璃不是貼一塊平板，而是把輪廓投影到車殼的每個三角形上（從 `CabSurface.project` 改成通用的 `project`）：斜鼻、長鼻沿鼻的斜面投影，平頭沿車頭投影；外框（玻璃色 70%）＋玻璃兩層 | `project`、`screenView`、`addFace` |
| 700T 的燈罩 | 頭燈：燈罩（`lampHousing`）＋燈片，頭車白、尾車紅，亮的那個會發光；斜鼻的燈在肩上，照當地的法線貼 | `addLamps` |
| N700S-G 的轉向架對準裙部開口（決策 408 第 3 條） | 轉向架的位置照車長算（離車端 max(2 m, 0.145 × 車長)，長鼻的前轉向架在鼻後 0.4 m），裙蓋（高鐵）或車下設備箱在轉向架前後留開口；轉向架有枕樑、側框、軸箱與十角形車輪（輪的平底落在軌上），軌距照樣式（新欄位 `gauge`） | `bogieCentres`、`axles`、`addRunningGear` |
| N700S-G 的霧面平塗 | 一個三角形一個顏色、平的法線，顏色都是調色盤的 | `emit`、`model(named:)` |
| 700T `refreshPanto` | 高鐵的集電弓：整流罩＋放下的單臂；其他車種照舊的冷氣箱，加箱蓋 | `addRoof` |

場景套件的各款車頭（`SceneKitCab.front`）照舊各有自己的臉，改成 `Map3DTrainShell.Front` 的參數：斜鼻的特急（城際、紅臉、傾斜式）擋風玻璃在斜面上（第一版沿車頭投影，只落在鼻尖一小塊，改過）；紅臉特急的紅臉（`Map3DPalette.lantern`）照舊沿車頭投影；平頭（區間車、捷運、柴油客車）有中柱與窗下的深色帶；高鐵與遠景高鐵用樣式的斜鼻。`face:` 指定車頭顏色的 set（區間車、柴油客車、柴油特急）不再在做好的模型上逐頂點改色（`Map3DModelPack.Model.painting`，刪掉；車鼻的第一圈和車身混成漸層），改由車殼塗裝時把車鼻上的車身色換成車頭色（`Front.noseColour`），邊切在車鼻起點的那一圈上，是一條線。（試過照三角形中心判斷：模型最前端是車鉤，切點落在車鼻中段，邊變成鋸齒。）

遠景：`highSpeedFar`（500–900 m 的高鐵）用車殼的 `far`：16 段、窗連成一條、轉向架一塊、不畫門框，頭車 1,084、中間 543 個三角形（之前 1,709／430）。

### 留下與刪掉的

留下：

- `Map3DTrainStyle` 的資料（長、寬、高、色帶與細線的位置、窗與門的排法、車鼻長度、下潛、擋風玻璃的範圍、燈的位置），新增的欄位都有預設值。
- `Map3DTrainBuilder`（決策 230 的舊建模）**原封不動**：N700S-G 的遠景（`Map3DN700SG.model`，`n700sGFar`）是用它畫的，決策 408 要它逐位元不變。營運中其他地方都不再用它。
- `SceneKitCab` 各款車頭的臉（紅臉、平頭的中柱與深色帶、斜鼻）、`SceneKitCab.clipped`（場景套件的展示用）、`Map3DTrainSet.baked`／`lit`／遠景機制。
- 塗裝（`TrainLivery`）、各 set 的編組與長度、`Map3DTrains.modelReach`（900 m）內才畫模型、外面是方塊。

刪掉：

- 舊的直線拼成的斷面、頂點漸層的車鼻顏色、貼平的方窗、黑箱轉向架（樣式模型與場景套件的中間車、客車都不再用）。
- `SceneKitCab` 自己拼的車身與 `CabSurface`（擋風玻璃的投影搬到 `Map3DTrainShell.project`，變成通用的）。
- `Map3DModelPack.Model.painting`（車頭色改由車殼塗，上面）。
- 舊的 `highSpeedFar` 車身（#900 700T 的輕版），換成車殼的遠景。

每種營運中的車種都有模型（`Map3DModelTests.testEveryTypeWithAStyleHasItsModels` 照舊過）；沒有模型的照舊只有磁浮、輕型單軌、單軌（方塊）。

### 不動的（逐位元檢查）

把模型包每個模型的頂點（位置、法線、顏色、層）算 FNV-1a，改之前（main 6a6352b 的樹）與之後比：`refresh-*`（#1201 的 700T 與 E200）、`set-highSpeed-*`（營運的 700T）、`set-n700sG*`、`set-n700sGFar*`、`set-E200CK-head`（E200 機車）共 18 個模型一個位元都沒變；Codex 的列車包（綠色電車、綠色通勤、三節都市、五節／七節輕軌、四節捷運、七節霧藍）與兩台蒸汽機車也沒變。327 個模型裡變的 83 個全是上面「改之前」列的。檢查用的測試只在本機跑，沒有提交。

## 五個角度

- 玩家：近看列車不再是方盒子，車鼻、窗、門、輪子都看得出來，和高鐵兩款並排不會差一截。
- 鐵道迷：斷面的圓角、車鼻的輪廓、門窗的排法、轉向架的位置與軌距（台鐵 1,067 mm、高鐵與捷運 1,435 mm）照各車種的比例；燈頭白尾紅。
- 開發：兩套舊建模（`SceneKitCab` 的車身、`Map3DTrainBuilder` 的用法）收成一個共用車殼，新車種只要給樣式；舊 builder 只留給 N700S-G 遠景。
- 美術：照 700T 與 N700S-G 的畫法：霧面平塗、照多邊形切的色帶、兩層圓角窗，顏色都在調色盤裡。
- 音樂：無。

## 沒有選的

- **每款都像 700T 一樣手寫一份**（每節 5,600–9,100 個三角形）：超過預算，十幾款都要各寫，維護不了。
- **把 N700S-G 的做法（作者的模型減面）用到每款**：其他車種沒有作者的模型可減。
- **保留舊的樣式模型、只換場景套件的車**：營運時通勤、沒有型號的列車還是畫舊的，作者說太差的可以刪。
- **門窗不切成橫條**：第一版的門在曲面的下半部陷進車身，只露出上半（看起來像「T」），改成只把超過窗下緣的切條（窗不切，三角形少約 15%）。
- **門窗都切成橫條**：中間車有三款超過 2,000 個三角形。
- **特急的擋風玻璃沿車頭投影**（第一版）：斜鼻只有鼻尖朝前，玻璃只有一小塊；改成沿斜面。

## 照車輛建模手冊自檢（#1224）

#1224（`docs/art/native-vehicle-modeling/`）在這個工作做到一半時合進 main（作者 10-25：「記得請建模看pr1224那是codex製作模型的交接」）。已經做好的不整個重做，下面照 `REVIEW_CHECKLIST.md` 逐項過一次，與手冊不同的寫出理由。

**第 10 節的四種看法**：新增 `tools/train-modeling-410/review.mjs`（照 `tools/train-shape-refresh/review.mjs`）：每一款的之前與之後，從實際的原生頂點畫，同一個相機（兩版合起來的範圍），配色／白模／剪影 × 側／正／俯／斜，另加遊戲尺度的灰階小圖。43 張在私庫 `Railway/game-art-previews/docs/art/train-modeling-410/review/`。

外觀紀錄（本 session 看過的：`set-emu800`、`set-emu3000`、`set-puyuma`、`set-BLUE`、`style-highSpeed` 的四種看法；其餘各款看過配色的斜視與車頭近看）：

- **已符合**：側面的鼻長、鼻高與車頂下壓起點，白模與剪影上是連續的曲面，沒有台階或鼓包（之前的區間車、通勤車頭是方塊加漸層）；正面的肩部與頂部圓角、鼻罩與下方車鉤／裙的關係；色帶在側面接回車身時沒有上下跳（照多邊形切，§8.1 的穩定切分：一次算完分色值、交點帶著精確的值、共用邊的端點排序）；中間車沒有駕駛窗與頭燈；尾車是頭車轉 180°（照舊 `Map3DTrainSet` 的編組），沒有轉兩次；遊戲尺度灰階下車身、窗帶、車頭玻璃仍分得開；每節車輪的最低點在軌面（`Map3DModelTests`、`Map3DTrainSetTests` 量 minimum.z）。
- **仍不符合**：紅臉特急的紅臉只在鼻的下半，上半是斜面的黑罩（之前整片紅）；俯視時車頭收窄得晚、鼻尖偏寬圓，特別是城際、紅臉、傾斜式三款（之前也一樣寬，但手冊 §5 要的「最大寬度位置、車頭收窄」沒有照每款的資料量）。
- **資料不足**：各車種的轉向架中心、軸距、輪徑是照車長的通則（§「做法」），不是每款的實車資料；另一側與看不到的車下設備是通則補的，不宣稱是工程還原；手冊 §3 的逐張參考照片這次沒有逐款重看（樣式的比例沿用決策 230、318 已有的數字）。

**與手冊不同之處與理由**：

- §5.2 中央鼻罩／肩部／前唇分開控制：這裡一款車鼻只有高度、寬度、下巴三張表（`NoseShape`），沒有獨立的肩部包絡。理由：十幾款共用一個車殼，每款沒有可量的參考；700T 的肩部包絡是照它自己的照片量的，手冊也說不要把 700T 的控制點套到別的車。之後要逐款修鼻形，再加肩部包絡。
- §5.1 斷面數：一圈 32 段（遠景 16），不是 700T 的 40 段：中間車 2,000 個三角形的預算內放不下。
- G 區的退化面：車殼的扇形在點重合處（端面收口、沿投影的燈與鏡片邊切）會留下面積為零的三角形，第一次量到 7 個檔案有（之前的模型只有遠景高鐵 1 個）。`Map3DTrainShell.model(named:)` 最後丟掉面積小於 1e-7 m² 或小於最長邊平方 1e-6 倍（三點共線的細條）的三角形；重新匯出後 43 組都是 0 個退化面、沒有非有限值、最低點都在 0。受保護的模型不經過車殼，逐位元仍不變。
- §12、§13、G 區（GLB、七向透明 PNG、viewer、ZIP、Blender 獨立匯入）：這次是營運中的程序模型，不另出靜態素材包，所以沒有做；原生模型由測試與 `export.swift` 讀出。封閉有向邊與體積沒有逐款驗：車身殼本身是封閉的管加兩端封面，但窗、門、燈是凸出車身的單面板（同 700T 的做法），不是封閉體。
- F 區：前版是 main（6a6352b）上真的模型，由同一支 `export.swift` 在 main 的 checkout 匯出，不是事後重造；受保護的模型逐位元核對（上面「不動的」）。
