### 795. 聖誕塗裝：照各款車的部位套色、路線頁的開關、第 4 週任務

2026-11-16，雲端實作 session（遊戲規劃派），分支 `claude/winter-livery`。派工單 WINTER-LIVERY（決策 788 §4、790 §5 的下一步；企劃 `docs/research/WINTER_EVENT_2026-11-15.md` §2.3）。

不動 GameCore、存檔版本、golden、replay、模型包的模型與頂點（雜湊不變）。

## 1. 做了什麼

1. **照部位套色**（`Sources/GamePresentation/Map3DChristmasLivery.swift`）：模型包做好時，每節跑的車（`Map3DTrainLights.isRunning`）從自己的配方算一張「每頂點一個位元組」的表（`Map3DModelPack.christmas`）：低兩位是部位，其餘六位是包裡烘進去的遮蔽陰影（決策 439）。部位這樣分：
   - 只看**側面**（法線側向 ≥ 0.6）、車高 18–93 % 之間、`plain` 的三角形；車頂、車頭端面、地板、轉向架、窗玻璃（`Map3DTrainLights.isGlass`）、燈鏡片、發光的三角形一律不動。
   - 同一色的深淺（配方照面的方向打的陰影，差 12 % 內；灰、白差 30 % 內，不鏽鋼車與下裙）算一個色族。
   - 面積最大的色族是**車身**（暗色族只算一半，所以窗帶不會被當車身，黑色的明日號仍找得到車身）→ 紅 `christmasLivery.body`。門與車身同色，跟著變紅；只有窗玻璃是玻璃色（作者 2026-11-15 的規則）。
   - 線色帶（alpha < 1，rolling-stock §4）依高度分段：最大段 → 白 `band`，其餘段 → 金 `line`。整台用線色畫（命名編組的主色）時，那條帶就是車身。
   - 其他亮色族：占側面 12 % 以上 → 白帶；以下 → 金線。比 0.2 暗的（窗帶、框、裙）不動。
   - 不鏽鋼（決策 450 的 `trainSteel`）被漆成紅色後改回 `plain`，不再有不鏽鋼光澤。
2. **畫法**：`Map3DInstance.christmas`（不進著色器）。App 的 `Map3DModelBuffers.christmas(_:table:)` 在第一次畫到某款車的聖誕版時，從那款車原本的頂點緩衝重新上色、另做一份緩衝並留著（決策 750 的做法：只有畫到的車才上 GPU）；每格畫面裡同一模型的聖誕車排在一般車後面，一個模型分兩次 draw call。遠方的方塊車改成紅車身白帶。CPU 多留的只有那張表（每頂點 1 byte）。
3. **路線頁**：路線設定一節在「更名／線號／顏色」下面多一個「聖誕塗裝」開關，只在 `WinterEventRecords.liveryIsAvailable(at:)` 為真（活動期間，或拿過第 4 週徽章）而且是客運路線時出現。
4. **記錄**：裝置偏好 `LauncherPreferences.christmasLiveries`，照存檔列（`GameLauncher.gameRow`，決策 502）記路線號；存檔列搬家時跟著搬。還沒存過的新局先記在 `GameSession.christmasLiveryChosen`，存了就寫進去。不進存檔、不是命令。
5. **任務**：`GameLauncher.checkWinterEvent` 與目標面板的活動卡都把 `GameSession.christmasLiveryLines`（能選時、選了、還是客運線的路線）傳給 `WinterMissionFacts(world:liveried:)`，第 4 週「平安夜」做得到；拿到後 `christmasLiveryAvailable` 立刻更新，活動結束後照樣能選。沒拿到徽章的，活動結束後的第一個遊戲午夜起不再畫、不能選（選的路線還記著，下一季能選時回來）。

## 2. 五個角度

| 角度 | 理由 | 分數（1–5） |
| --- | --- | ---: |
| 玩家 | 路線頁一個開關就讓自己的車變成紅色聖誕列車，第 4 週任務終於做得到；不必一台一台選 | 4 |
| 鐵道迷 | 只換色、不換車型，車頭、窗、轉向架照原樣，和真實節慶彩繪列車的做法一樣；路線為單位，與實際「某條線跑彩繪車」相同 | 2 |
| 開發 | 不改任何模型與雜湊、不升存檔；部位表一次算好、緩衝第一次畫到才做；Linux 測試每節跑的車 | 3 |
| 美術 | 只用決策 790 的三色；門與車身同色、只有窗是玻璃；陰影照包裡烘的深淺 | 4 |
| 音樂 | 無 | 1 |

其他選項（沒選）：
- 每款車手寫部位表：一百多款車、每款都要改配方檔，和其他開著的車型 PR 全部衝突。
- 把聖誕版模型整包加進模型包：模型包在 CPU、GPU 各一份約 200 MB，跑的車翻倍不行（決策 417、MEM3D）。
- 在頂點的 `v` 寫部位、著色器換色：每款車的雜湊與 `hashes.lock.json`、`locks/*.json` 全部要改。
- 開關放設定頁（全部路線一起套）：一次全換看不出是哪條線在跑，第 4 週要的是「一條套用的路線」。
- 預設套哪些車：不預設，玩家自己選（企劃 §2.3「玩家在路線頁替某條線的車套用」）。

## 3. 參考

- `a91453/railway-reference-private`：`Web/CityView/src/world/trains.js` 的塗裝帶（rolling-stock 附錄）是 canvas 畫帶，遊戲沒有貼圖，不能直接用；沒有「整車換色」的實作。部位的分法照本專案 rolling-stock §4 的塗裝帶規則與決策 450 的玻璃、不鏽鋼判斷寫。
- 外部專案：沒有找（換色規則是這個專案配方的約定，別處沒有）。

## 4. 已知的弱點與下一步

- 部位是照顏色與面積自動分的，不是逐款看照片定的。高鐵 700T、推拉式客車、淡海與安坑輕軌、文湖線、阿里山客車的白帶面積比紅車身大；普悠瑪、太魯閣、EMU800／900、EMU3000 頭車沒有線色帶，只有紅車身與金線、沒有白帶。要逐款調就在 `Map3DChristmasLivery.parts(of:)` 加例外，或照 model-look 拍圖看過再定。
- 2D 地圖的列車沒換色（只有 3D）。
- 真實時刻表的車（決策 339）不是玩家的路線，不換。
- Metal 畫面、實機、效能 UNVERIFIED；第一次畫到某款聖誕車時會在那一格做一份緩衝（數 MB），和決策 750 第一次畫到一般車一樣。

## 後來（XMAS-LIVERY-ALL，2026-11-20）

雲端工作串「加聖誕塗裝一鍵全部套用」，分支 `claude/project-thread-anx9ot`，評分 2.50。作者問聖誕塗裝能不能自動套到所有列車；逐條路線開（上面 §2「沒有選的」第二項）在路線多的公司要開幾十次。GameCore、存檔、golden schema 不動。

- **做了什麼**：路線面板那條線的「聖誕塗裝」開關與說明下面，公司有兩條以上客運路線時多一顆按鈕：還有客運路線沒套時是「全部客運路線套用」，全都套了是「全部路線取消」。`GameSession.setChristmasLiveryOnAllPassengerLines(_:)` 一次把現有的客運路線全部寫進（或清掉）`christmasLiveryChosen`，只通知裝置一次；`allPassengerLinesWearChristmasLivery` 決定按鈕寫哪一句。活動以外（沒有徽章）一樣不能選。逐條的開關照舊，可以全部套了再關掉其中幾條。
- **沒有做的**：之後才開或才買的路線不會自動套（那是一個「一律套用」的設定，要多存一個偏好，也讓「哪條線在跑聖誕車」又看不出來）；要的話再按一次按鈕。貨運路線照舊不套。
- **五方**：玩家：幾十條路線一次套完，不用逐條開。鐵道迷：無（塗裝本身不變）。開發：只多兩個 `GameSession` 延伸成員與一顆按鈕，沿用同一份裝置紀錄，沒有新偏好。美術：無（既有卡片多一列，沿用無框按鈕）。音樂：無。
- **參考**：`a91453/railway-reference-private` 沒有節慶塗裝的整批開關（上面 §3）；外部專案沒有找，這是本專案自己的介面。
- **驗證**：`Map3DChristmasLiveryTests.testEveryPassengerLineAtOnce`（Linux）。按鈕在 iPhone 上的樣子與觸控 UNVERIFIED（既有卡片多一列，照決策 482 的分級不截圖）。
