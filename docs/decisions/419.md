### 419. 讀檔不卡畫面：解碼與舊存檔的道路在背景讀

2026-10-26，遊戲規劃 session_01TS89hbaHPJiFJycqrKiK5z 派工，實作 session_01BCNSXuGMywCQSnXQsRSLPk。號碼依 #1041：決策 419；存檔版本（74）、golden schema 不動。GameCore 不動，只動 GamePresentation、App 與測試。

**為什麼**：決策 400「續篇：讀檔的兩件小修」把資料晚到時的道路搬到背景，剩下讀檔本身：`continueGame`、`load`、`importSave` 都在主執行緒解碼，`begin` 再對路網之前存的舊存檔（土地讀過、路沒讀）在主執行緒讀路（高鐵站 8 km 的範圍 Linux debug 1.45 s、release 0.30 s）。TestFlight 87.1 有玩家回報卡頓，主執行緒卡住是嫌疑之一。

#### 做了什麼

- `GameLauncher.open(reading:world:then:)`：讀檔的四條路（繼續、讀存檔、回到之前的自動存檔、匯入；iCloud 來的存檔也是從存檔列表讀，走同一條）都經過它。
  1. 讀檔（讀檔案、解碼、回到自動存檔時先存下目前的進度）在存檔的佇列（`saveQueue`）上跑，排在已經排好的存檔後面，和以前 `afterSaves` 的順序一樣，只是不再在主執行緒等。
  2. 讀好之後，用這時 App 已有的資料，在背景算出 `begin` 會補讀的道路（`GameSession.roadsReadAhead`，#1268 的做法）。
  3. 回主執行緒，`begin` 把讀好的道路交給 `readLandRoundStations(roads:)`，世界照舊只由 `setRoads` 這個命令改，命令紀錄照舊記一筆 `.readLandRoundStations(data)`，重播在主執行緒讀出一樣的路；紀錄與重播都不變。
- 這四個方法回傳讀檔的 `Task`（`@discardableResult`）；讀檔中（`isLoadingSave`）不開第二個讀檔，回傳 `nil`。
- 讀檔中另一局開始了（例如讀檔的前 0.3 秒玩家按了新遊戲），讀好的存檔不蓋過它（`gamesBegun` 計數）。
- 讀檔失敗的訊息照舊：在開始畫面或存檔列表上方；在遊戲裡回到自動存檔失敗時在遊戲的狀態列。
- App 的 UI 測試啟動（`-ui-test-world`）要在第一個畫面之前把繼續的遊戲設好，所以那一處設 `readsSavesAtOnce`，照以前在主執行緒讀；只有那一處用。

#### 畫面

- 讀檔中整個畫面不接受點擊（`RootView` 的 `allowsHitTesting(!isLoadingSave)`，不變灰，所以快的讀檔看不出差別）。
- 讀得慢（超過 0.3 秒，`loadingScreenDelay`）才把實景地圖的讀取畫面（決策 307 的 `RealWorldLoadingView`，`realWorldLoading`）蓋上來；不新做樣式、不加新字（地名留空，畫面是公司名與「正在準備地圖…」）。淡入淡出照 `MotionRule.loadingIn`／`loadingOut`，減少動態效果時照決策 307 不動。讀完就收起。
- 存檔列表（sheet）：讀到的存檔開了就關上列表；讀取畫面上來時也關上，免得畫面被畫在 sheet 下面（同 #873–#910 審查 A7 的做法）。以前按下後當場看 `session` 決定要不要關，現在改看 `onChange`。

- 寫同一個大存檔（`encode`）1.01 s，本來就在存檔佇列上（決策 45 之後），不動。

#### 五方

- 玩家：按「繼續」或讀存檔時畫面不凍住；大多數存檔不到 0.3 秒讀完，看不到讀取畫面，慢的才看到和開實景地圖一樣的畫面，不會以為當掉。
- 鐵道迷：無（讀到的世界、路與紀錄都一樣）。
- 開發：沿用 #1260／#1268 的背景讀與 `RoadsReadAhead`；GameCore、存檔、golden、重播都不動；一個 `open` 讓四條讀檔路一樣走。
- 美術：不新做畫面，沿用決策 307 的讀取畫面；快的讀檔不閃一下。
- 音樂：無（轉場音效照舊在 `begin` 時播）。

#### 沒選的

- **讀檔一開始就蓋上讀取畫面**（參考庫的做法）：大多數存檔幾十毫秒就讀完，讀取畫面 0.7 秒淡入，會閃一下。
- **照參考庫每一步換一句**：本作讀檔只有兩步、都很短，多的字玩家來不及看；也要多翻譯幾句。
- **讀檔中只把按鈕變灰**：開始畫面每個按鈕一起變灰再變回來，也是閃。
- **等實景資料讀完才讀檔**：App 一開就按繼續時要多等資料（數秒）；決策 88、193 本來就讓遊戲先開、資料晚到再補。

#### 還沒做的

- 讀檔時土地本身（`expandLand`）仍在主執行緒讀（`readLandRoundStations` 照舊讀土地，再用讀好的路）；存檔的土地早就讀過，量到 0.0008 s，不用搬。
- `begin` 建 `GameSession` 與其他在主執行緒上的工作沒有量（#1260 量的開局其他工作合計約 0.25 s）；實機要看的話，用 Instruments 的 Time Profiler 看大存檔讀完那一刻。
- 資料在背景讀路的那段時間才到（App 一開就讀檔、資料剛好在那時到），`begin` 會用新的資料在主執行緒讀路；只差那一小段，先不處理。
