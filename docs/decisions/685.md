### 685. 3D 模型「看圖再改」的規矩，與追分車站試做

2026-11-11，Mac 本機 session LOOK-LOOP（session_01YGNNuoActmxTfeAsLPJBWL，`claude/look-loop-685`），遊戲規劃第 60 任派工（#1579）。存檔版本、golden schema、GameCore、`GoldenScenarios/`、`SaveFixtures/`、`ReplayFixtures/` 不動。

## 為什麼

作者問：為什麼我們的 3D skill 做出來品質還是不好。各 kit 的 skill 與測試只查「有沒有做錯」（面數、封底、接點、決定性），方盒子也能全過；沒有一步是「打開圖看它像不像」。

## 決定

1. **一份共用的規矩**：`.claude/skills/model-look/SKILL.md`（細節在 `references/checklist.md`），各 kit 與車輛的 skill、`art-style` 各加一行指過去，不各抄一份。內容：沒有真實照片與尺寸不開工；用遊戲鏡頭的角度與畫面上的實際大小判斷；每輪拍圖、和照片並排、對八條清單找毛病、改、記錄；清單都過且至少三輪才停；做的人不打分，交一張總覽圖給作者或另一個 session；報告最後寫還有哪裡不好。
2. **拍圖工具**：`tools/model-look/`。`shoot.mjs` 吃任何 `.m3dmodel`，出一張寬 800 px 的 JPG（遊戲大小、遊戲角度放大、照片並排，可帶改前）；`export-station.sh` 匯出車站套件的模型。畫法沿用 `tools/station-kit/renderer.js`，沒有新相依。
3. **規矩裡寫明遊戲的光是平的**（`Map3DShaders.metal` 的模型光：天空光為主，太陽只加 0.15）：立體感靠形狀進出與相鄰面的顏色差，不靠陰影。這是「光太平」那一條在這個遊戲裡的實際意思。
4. **試做：追分車站。** 挑它的理由：它在遊戲裡由套件的通用 `heritage` 站型畫（沒有決策 625、665 的站房研究），那個站型是紅磚牆、紅色四坡頂；真的追分是 1922 年的木造站房，灰瓦、兩坡頂、月台側有山牆與圓窗，顏色與屋頂都相反，認不出來；Commons 有授權清楚的照片；站房小，三輪做得完。
   - 新站型 `Map3DStationKit.Profile.coastTimber`，只給追分（目錄只改那一列）。配方 `coastTimber(_:_:_:)`：長 22 m、深 8 m、簷高 5.3 m、脊高 8.4 m（都是照片推估，不是測繪）；灰瓦兩坡頂與屋脊、兩長邊的披簷與斜撐柱、簷下的窗帶與白色站名牌（站前側）、兩端山牆的木構、月台側到脊高的山牆與圓窗、站前綠籬與月台側修剪過的樹。顏色都取自 `Map3DPalette`。
   - 做了四輪（紀錄與並排圖：`docs/art/model-look-2026-11-11/README.md`；含照片的各輪圖在私有素材庫）。
   - 測試 `testZhuifenIsATimberHallWithACrossGableOverThePlatformSide`：屋脊貫穿全長、山牆只在月台側且到脊高、兩側披簷與落地的柱；舊幾何會失敗。
5. **考題**（照 skill-creator 的做法）：`.claude/skills/model-look/evals/` 兩題（重做保安站、重做集集站），各跑有、沒有這份規矩一次，結果在 `docs/art/model-look-2026-11-11/README.md`。

## 五個角度

- 玩家：遠看分得出老木造站與一般站，地圖多一種顏色的屋頂。
- 鐵道迷：追分照真的樣子（海線木造站房的型式）；尺寸是推估，寫明了。日南、談文、大山、新埔是同型式的站房，確認照片後可以共用這個站型，這次沒有動。
- 開發：規矩只有一份；工具吃共用的 `.m3dmodel`，各 kit 不用各寫拍圖腳本。追分 2,175 個三角形（整個套件模型，含月台與廣場），原本 1,078。
- 美術：照 `art-style` 第 7 節的霧面模型、調色盤的顏色；真的是灰瓦就用灰，靠淺牆、鏽紅披簷與綠籬襯。
- 音樂：無。

## 沒做、還不好的

- 沒有放進真實地圖的場景裡拍（`tools/map3d-preview` 的世界沒有追分）；圖是套件預覽的畫法，實機與 Metal 未驗證。
- 追分最後及不及格由作者或遊戲規劃看總覽圖決定，這裡不自評。還不好的地方列在 README 最後。
