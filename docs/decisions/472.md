### 472. 車站面板分成四組、面板裡的統計畫成圖

2026-10-28，派工單 CJ，實作 session_01YGNNumLcrSFbAyyoYDWRL9（`claude/station-panel-charts`），遊戲規劃 session_01YGNNumk6UqdBm6JrBhsdZY 派。UI 健檢 N（`docs/research/UI_UX_REVIEW_2026-10-28.md` 3-28）＋作者同意的「統計用更好看的圖示化」（規劃問、作者答「我覺得不錯」「不然現在沒事做了」）。號碼依 #1041：決策 472；存檔版本、golden schema 不動。GameCore、存檔、GoldenScenarios、SaveFixtures、ReplayFixtures 不動；不加依賴（圖用系統的 Swift Charts，財務圖表已在用）；`project.yml` 不動（App 只改既有檔，新的兩個檔在 GamePresentation 套件裡）。

**為什麼**：車站面板一張表單疊了二十多段，拆除與貨運要捲很久（PLAYER_FEEDBACK #516「拆除月台找不到」）；車站、路線、路網的數字多半是一串字，看不出尖離峰、哪條線在變多、哪段最擠。

#### 1. 車站面板分四組（`StationPanelGroup`、`StationPanelPart`）

| 組 | 段落（照顯示順序） |
| --- | --- |
| 營運 | 可收購的路線、月台與天氣（決策 224）、即將到站、怎麼去、更名、營運狀態、機廠、轉乘、月台（含拆月台） |
| 旅客與運量 | 各時段進出站、旅客（昨日進出、等車、明細）、需求（預設與每日人次）、活動、各站往返人次 |
| 周邊與土地 | 商店（決策 222）、真實車站、周邊人口、土地、道路、公車 |
| 貨運與拆除 | 貨運場、拆除車站 |

- 面板最上面一排四個按鈕跳到各組（點了會展開那一組再捲過去）；一排放不下時（手機的大字）變成一個「跳到…」選單。
- 每組的標題可以點，收合或展開；收合的組記在 `@AppStorage("stationPanelFolded")`（`StationPanelFolds`，組名以逗號連接），換站、重開都留著。**一開始全部展開**，所以教學與 UI 測試找得到的按鈕都在原來的段落裡。
- 教學要面板裡的按鈕時（第 8 課的建貨運場），那一組被收合就先展開再捲（`StationPanelGroup.holding(_:)`）。
- 動畫：收合、展開與捲動用 `MotionRule.change.layout(reduceMotion:)`；減少動態效果時直接發生。箭頭跟著同一個動畫轉。
- 和以前的順序比：商店（決策 222 放在第二段）移到「周邊與土地」；旅客與需求的段落集中到「旅客與運量」；貨運與拆除仍在最後。

#### 2. 車站：各時段進出站長條圖

- 本來就有（手畫的長條）；改用 Swift Charts、財務圖表的藍（`Theme.chartBlue`），看的那一小時全色、其他 45%，和財務圖表一樣。
- 下面多一行**尖峰**（`StationFlow.rushText`）：連續幾小時、各有最忙那小時三分之二以上的人次，例如「尖峰 07:00–09:00、17:00–19:00」；一整天都差不多忙（超過一半的小時）就不寫。
- VoiceOver：上下滑換小時（原有），加上 `accessibilityChartDescriptor`（`StationFlow.chart(_:in:)`，Audio Graph 逐小時念）。
- 大字：圖的高度用 `@ScaledMetric`。

**沒畫的**：車站的每日運量趨勢線。`LineAccounts.flows` 只留今天與昨天（決策 179、222），沒有每天的歷史；要畫得多存紀錄、升存檔，派工單說不加。

#### 3. 路線清單：迷你趨勢線與最滿的車

- 每條（客運）線的列多一條小趨勢線：保留的每一天（最多 30 天，`LineAccounts.keptDays`）的運量（`LineReport.sparkline`，至少兩天才畫），旁邊一條最滿列車的條（`LineReport.loadGauge`：昨天的，沒有昨天就用今天到目前的），照列車載客條的規則：墨色，超過 100% 才變紅，滿到 100% 就是滿格。
- 下面一行字：「運量比前一週多 12%」（最近 7 天對前 7 天，`LineReport.ridersChangePercent`，要 14 天才有）與「昨日最滿 87%」。不只靠顏色。
- VoiceOver：趨勢線是旁邊那句話的圖，所以念那句話；選中路線下面的每日運量圖本來就有 Audio Graph。

#### 4. 路網分析：最擠區間排行

- 「最擠區間」頁的清單上面加一張橫向長條：有列車的區間中最擠的前 8 個（`NetworkFlowReport.rankedSections`），各在最擠那小時佔座位的百分比，100% 處一條虛線；超過的用 `Theme.error`，條尾寫出百分比。
- 同名的兩個區間（兩條線走同兩站之間）在名字後面加那個小時分開（Audio Graph 的分類不能重複）。
- 沒有列車的區間沒有百分比，不進圖，照樣列在下面。
- `ChartAxis` 多一種 `.percent`（Audio Graph 念「116%」）。

**沒做的**：「各線」頁每列已經有一條比例條，沒有再加圖。

#### 參考

- 參考庫：`Ci/` 的 `drawStationFlowAdjustCanvas`（各時段長條，原本就照它）與 `flowDashboard*`（路線報表，決策 179、416 已搬）。沒有尖峰、趨勢、排行圖可以搬。
- 外面：Apple 的 Swift Charts 與 Audio Graphs（系統框架，不是依賴）；dataviz skill 的「一張圖一種單位、不只靠顏色、迷你圖不放座標軸」。沒有搬程式碼。

#### 其他做法（預覽：`docs/art/station-panel-groups-472.png`）

- **B 分頁**（上方分段控制，一次只看一組）：最短，但教學第 8 課的建貨運場與 UI 測試（貨運、拆除、月台）都要先切分頁，面板改版又最容易弄紅 full lane（HANDOFF §1.3 的坑）。
- **C 只加「跳到」選單**：順序不動、不收合；最安全，但二十段仍是一長串，沒有分組。
- 選 **A 分組＋跳到＋可收合、預設全開**：分組看得到，常用的在前，跳得過去；預設全開，教學與測試找到的位置不變。

#### 五方

- 玩家：找拆除、貨運、尖峰不用一直捲；一眼看出哪站幾點擠、哪條線在變多、哪段坐不下，知道要在哪裡加車。
- 鐵道迷：尖離峰、最滿列車的滿載率、區間的最擠小時，是看實際營運的方式（台鐵、捷運的運量報表都這樣看）。
- 開發：只改 GamePresentation 與 App 既有檔，資料整理有 Linux 測試；不加紀錄、不升存檔、不加依賴；預設全開，UI 測試與教學的路徑不變。
- 美術：顏色只用色票（`chartBlue`、`error`、`textPrimary`），和財務圖表同一套畫法，深淺色都算過對比（UI_THEME）。
- 音樂：車站時段圖與路網排行有 Audio Graph，VoiceOver 玩家用音高聽尖峰與排行；路線列的趨勢念成一句話。
