### 546. 打開 3D 不等列車模型包：模型包分給每個核心做、遊戲開了一會兒先在背景做、場景先顯示

2026-11-02，派工單 OPEN3D（106；session_01YGNNunVxxTjzneuBjw86MX，遊戲規劃第 42 任 session_01YGNNum8LvQvgmgwxKHRvQ7 派），分支 `claude/open3d-model-pack`。號碼依 #1579 的登記：決策 546（545 留給 FLANE5 若需要）。存檔版本、golden schema、GoldenScenarios、SaveFixtures、ReplayFixtures、GameCore 都不動；模型的頂點、`tools/train-models/hashes.lock.json` 都不動。

## 問題

FLANE5（#1693）量到：3D 的列車模型包（`Map3DView.models`，`Map3DModelPack.standard` 加上公車、垃圾車、樹的檔案，696 個模型、4,794,234 個頂點、一份 192 MB）在玩家第一次打開 3D 時才做，Linux Debug 約 33 s CPU；Simulator 上開 3D 後約 65 s 才回應。3D 畫面在模型包做完以前只有轉圈（`built == nil || !modelsReady`），場景早就建好了也一樣等。

## 做了什麼

1. **模型包分給每個核心做**（`Map3DParallel.map`，`Sources/GamePresentation/Map3DParallel.swift`）：
   - 配方分成組（每個車型一組、每個編組一組、街道設施四組、各靜態模型一組），每組在空著的核心上做，做完照原本的順序接起來；
   - 玻璃標記、陰影的重複判斷（雜湊）與套用、車燈與窗戶，每個模型在空著的核心上做；窗戶模型的編號照車的順序排，跟以前一樣。
   - 每個模型只由一個工作算，算法沒有改，所以結果到位元都一樣。
2. **3D 畫面先顯示場景**：場景建好就畫，模型包還沒好時列車畫成方塊、街道設施先不畫（`Map3DMetalView` 本來就這樣處理沒有模型的情況），模型包好了就換上。轉圈只等場景。主執行緒在模型包做好以前不讀 `Map3DView.models`（讀了會等它做完）。
3. **先在背景做**（`Map3DTrainModels`，App）：
   - 遊戲開了 8 秒後（開局的頭幾步先讓給它），3D 開著（`shows3D`）而且這台不是記憶體小的（決策 460 的 `keepsSceneBuilt`）就用低優先（`.utility`）先做；
   - 2D 地圖捏近、停一下要先建 3D 場景時（決策 269），也一起做；
   - 打開 3D 時若還沒開始，就用 3D 的優先（`.userInitiated`）做；低優先做到一半的，打開 3D 等它時系統會把它提高。
   - UI 測試（`-ui-testing`）不先做：Simulator 會被它佔住，沒開 3D 的測試也會變慢。

## 證明模型沒變

`Map3DModelPackLockTests`（Linux）：

- `testEveryModelIsAsLocked`：`standard` 與 `studies` 的每個模型，每個頂點欄位的 FNV-1a 與三角形數都等於 `hashes.lock.json`（`export.swift` 的同一個雜湊），名字一個不多一個不少；

## 沒做的與為什麼

| 選項 | 為什麼沒做 |
| --- | --- |
| 只做畫面上會出現的車種、其餘延後 | 渲染器、街景、號誌、行人號誌、車燈都用「模型在包裡的索引」找模型，包要一次給全；拆開要改這些地方與 Metal 的緩衝。做完整包已經不到 1 秒（4 核），收益小、風險大。 |
| 模型包存成檔、同一版 App 不重做 | 一份 192 MB，寫到裝置上要 192 MB 空間，讀回來也要時間（約等於現在重做）；而且要處理版本、損壞、清除。 |
| 讓單一模型做得更快（改配方） | 要逐個配方改，結果很容易不再位元相同；分核心已經夠快。 |

## 五方

- 玩家：打開 3D 立刻看到城市，列車先是方塊、一下子就換成模型；通常遊戲開了一會兒模型包已經做好，打開就有。
- 鐵道迷：無（模型、塗裝、編組一個位元都沒變）。
- 開發：只動做模型包的地方與 3D 畫面接模型的幾行；測試鎖住每個模型與順序；不加相依套件。
- 美術：模型不變；載入時街道設施晚一點出現、列車先是方塊，是載入中的樣子，模型包好了就跟以前一樣。
- 音樂：無。

## 參考與開源

- 參考庫（a91453/railway-reference-private，ea6f787）：`Railway/taiwan-rail-reference-clean/source/rail-3d/integration/map3d.js` 的 `geometry(id)` 是畫面要用到某個車型才去讀它的幾何（`pending` 讓同一個車型只讀一次，`cache` 最多留 18 個、沒在用的丟掉）。這是「只做看得到的車種」那一條；我們的渲染器用索引找模型（上表），沒有搬。搬了它「同一件事只做一次」的作法：`Map3DTrainModels` 只有一個進行中的工作，3D 畫面、2D 捏近、開局先做都等同一個。`commuter_journey_reference_clean` 的 `TrainFactory.js`、`tw3d-reference-clean` 的 `metro-trains.js` 是一次建好幾台車，沒有可以用的。對照表在 PR。
- 開源：分工照 GCD 的 `DispatchQueue.concurrentPerform`（系統內建，不是新相依）。沒有取用外部程式碼。
