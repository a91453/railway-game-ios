### 決定

1. **第四個 iPhone job `map`**（`FULL_LANE_MAP_JOB`：`MapInteractionTests`）。`ui-full-lane` 的 matrix 是 `[second, lessons, map]`、`max-parallel: 2`：build job 加兩個 partition，full lane 同時最多還是 3 台 macOS（決策 582），PR 一直有 2 台。第三個 partition 等前兩個有一個跑完才開始。
2. **重新分配**：`RealWorldMapUITests`（15.8–18.1 分）從 build job 搬到 second；lessons 原本的四支 `StartSaveFlowSmokeTests`（5.9–8.7 分）回 build job。預估最多：build 約 52、second 51、lessons 54、map 46，上限 75，各留 20 分以上。
3. **等待方式**（不跳過、不停用）：
   - `HUDAlignmentUITests.testTheNewsSettingsHelpAndAchievementsKeepTheLines`：`hud.menu` 改用 `openMenu(showing:)`，選單沒開就再點（最多 3 次），和其他測試開選單一樣。
   - `HUDAlignmentUITests.testTheStationMastersBubbleKeepsTheLines`：啟動時給 `-speaking-ms 60000`，泡泡留一分鐘。`StationMasterCorner.speakingTime` 讀這個參數，只有 Debug build 有，跟 `-story-card-ms` 一樣；玩家的版本還是 7 秒。
   - `MapInteractionTests.testAGamePausedBeforeTheThreeDMapResumesThere`：點「3D」10 秒沒開、按鈕還點得到就再點一次。

### 時間

整輪 full lane 變長：matrix 最長約 15＋54＋15＋46 ≈ 130 分，iPad 等它再跑約 35 分，合計約 2 小時 45 分，在決策 582 的 3 小時線內。夜間跑，換到的是每個 job 都留 20 分。

- **iPad job 等三組 iPhone UI job 全部跑完**：它的 `needs` 是 `[changes, ui-full-lane]`，matrix 的三個 partition 都結束（紅綠都算）才開始。所以同一時間是 build job 加兩個 partition，或 build job 已結束時 iPad 加最多兩個 partition 之外的一個：最多 3 台。PR 與 `only_testing` 不跑 `ui-full-lane`，iPad 照舊在 `changes` 後馬上開始。
- **夜間排程不會重疊**：`ios-full-lane.yml` 每天只在 02:17（台灣）起一次，2 小時 45 分遠短於 24 小時；而且它起之前會檢查 main 上還有沒有 ios-build.yml 的 full run 在排隊或在跑（「A full run is still going」那段），有就不起，這條不看時間長短，照樣擋得住。手動跑不等，所以發版前與二分時，手動起之前先看有沒有一輪還在跑。
- **`full-lane-watch.yml` 認得新 job**：`tools/ci-watch/full_lane_watch.py` 用 run 的 jobs API 讀每個 job 的名字與結果（`failed_jobs` 取 `conclusion` 是 failure 或 timed_out 的名字），不寫死 job 名；新的「Xcode UI tests, map (iOS Simulator)」紅了一樣會被列出。自測裡的 second、lessons 名稱只是測試資料，不用改。
