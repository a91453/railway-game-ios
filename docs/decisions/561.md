### 561. 桃園機場捷運的列車畫成 1000 型與 2000 型

2026-11-03，作者交辦遊戲規劃第 43 任（session_01YGNNunC2SwRgFTbo4rham5，`claude/tymc-trains`）：「真實桃園捷運 pro 已經在做了，你可以先幫我接入，就是只讓遊戲有車輛、能跑就好了」。號碼依 #1579：決策 561；存檔版本、golden schema 不動。GameCore、`GoldenScenarios/`、`SaveFixtures/`、`ReplayFixtures/`、`TrainPack` 不動，只動 GamePresentation、測試、`tools/train-models/hashes.lock.json`、截圖測試與文件。收購、時刻表、機廠是 TYMCLIST2（#1743，決策 556）的，這裡不碰。

**為什麼**：Codex 的 #1700 做了機場捷運 1000 型（普通車）與 2000 型（直達車）的原生模型 `Map3DTaoyuanAirport`（九種角色，近景與 `far`），只註冊在 `Map3DModelPack.studies`，遊戲裡看不到；實景地圖上的機場捷運一律畫成通用捷運車（`metroGeneric`，決策 483 起）四節。#1700 的交接（`docs/art/taoyuan-airport/README.md`「實際遊戲接點」）寫明缺的是：`RealTimetableTrip.kind` 分得出普通（1）與直達（2），但 `RealTrainTraffic.Runs` 依發車排序後沒帶 kind，3D 不知道哪一班是直達。

**做了什麼**：

1. **兩個新的 set**（`Map3DTrainSet.taoyuanAirport(_:far:roles:)`）：`taoyuanAirport1000` 與 `taoyuanAirport2000`，各有 `Far`。照 #1700 的 `tools/taoyuan-airport/assembly.json`：
   - 普通車四節 DMC1 MC1 MC2 DMC2；直達車五節 DME1 ME1 ME3 ME4 DMB（ME4 是第四節的 ME1，DMB 是行李駕駛車）。
   - 尾車轉 180°（`turned`），中間車依序不轉（`cycleFromFront`，slot `.middle`、`.centre`、`.fourth`）。
   - 每節用自己的長度（`ownLengths`：駕駛車 20.78 m、其他 20.25 m，普通車 82.06 m、直達車 102.31 m）。
   - 頭車前端、尾車後端的燈罩發光（`litLenses(_:front:)`，同決策 560），頭白尾紅照決策 449。沒有集電弓（第三軌）。
   - pack 還沒有這兩款的模型時畫通用捷運車（`fallback: "metroGeneric"`）。
   - `nearOnly` 加這兩個 key：500 m 內近景，500–900 m 遠景（#1700 的 `far`），900 m 外盒子。
   - 放在 `all` 最後（決策 560 的 EMU700 之後），前面的模型不動，鎖逐行相同。
2. **哪一班是哪一款**：
   - `Map3DRealTrains.formation(system: "tymc")` 由 `metroGeneric` 四節改成 `taoyuanAirport1000` 四節。
   - 時刻表裡帶 kind 的班表（只有機場捷運的 `tymc_times.json` 有 `kinds`），`RealTrainTraffic` 每一班用它在班表裡的序號當 key，直達車前面加 `E`（`expressKey(trip:kind:)`）。沒有 kind 的班表照舊（依發車排序的序號）。
   - `formation(of:system:place:locked:)`：機場捷運的直達班次（`isExpress(place:)`）畫成 `taoyuanAirport2000` 五節。
   - 玩家收購的機場捷運（`RealLineStock`）上的列車一律畫成 1000 型：玩家的車每站都停，沒有直達車。名稱「機場捷運 1000 型」／“Airport MRT Type 1000”。
3. **列車展示**：加「桃園機場捷運 1000 型（普通車）」四節、「桃園機場捷運 2000 型（直達車）」五節，固定編組。通用捷運車（決策 483 的「捷運列車（桃園）」）不再畫任何一條線，只在 pack 還沒有機捷模型時代替它們（`fallback`），照決策 558 的規則不列在展示裡（`testEveryNearSetIsInTheCatalogOnce`）。玩家先前選進展示的它會被略過。

**缺口與下一步**：

1. **直達車的行李車方向**：真車的 DMB 固定在台北端。遊戲的編組永遠是頭車在行進方向前面，所以往台北的直達車 DMB 會在最後。要對，得讓 `Map3DRealTrains` 依行進方向把編組倒過來，現在沒有這個機制。
2. **外觀接受**：#1700 的模型作者還沒說可以（#1700 README「使用者外觀接受：UNVERIFIED」）。作者若要改，改 `Map3DTaoyuanAirport` 的配方後這兩個 set 跟著變，鎖裡的行照規則更新。
3. **真車尾燈**：#1700 的尾燈畫成暗紅 `0x8D444D`，不是決策 449 認的鏡片色，所以尾端發光的是頭燈鏡片，每格的頭白尾紅由 449 點。
4. 實機外觀、幀數：UNVERIFIED，等 TestFlight。

**沒選的**：

- **依車次號照比例分 1000／2000**（像決策 558 的文湖線）：時刻表本來就分得出普通與直達，照真的分比較對；而且直達車只停五站，讓普通車畫成直達車不對。
- **玩家收購的線也混入 2000**：玩家的車每站停，直達車的外觀會誤導。
- **2000 也是四節**：真車五節（四節客車加一節行李車）。

**五方**（音樂「無」）：

- 玩家：實景地圖上的機場捷運從通用捷運車換成藍色的普通車與紫色的直達車，看得出哪一班是直達；列車展示多兩款。操作不變。
- 鐵道迷：普通車四節、直達車五節照真車編組（#1700 查的官方尺寸與車序）；哪一班是直達照時刻表，不是猜的。DMB 在往台北的班次會在尾端，真車固定在台北端，記在缺口。
- 開發：只動 GamePresentation，模型原樣用 #1700 的；新的 key 加在最後，鎖逐行相同；時刻表的 kind 只影響有 kind 的班表，其他線的 key 不變。
- 美術：顏色、外型都是 #1700 的；近景、遠景都接上，截圖第三級，等遊戲規劃看過才合。
- 音樂：無。
