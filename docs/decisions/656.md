## 1. 版面看視窗，不看裝置（L15-6）

- **問題**：決策 643 的兩條 iPad 規則（下半卡只開全高、教學框兩座城鎮）看的是 `userInterfaceIdiom`。iPad 的分割畫面、Slide Over、很小的台前調度視窗其實跟 iPhone 一樣窄，卻照 iPad 處理：下半卡從底下長到全高，地圖整個被蓋住；教學框城鎮時縮得很遠。
- **改法**：
  - 新的 `WindowLayout`（`DeviceFamily.swift`）：iPhone 一律 `.narrow`；iPad 與 Mac 在視窗的 `horizontalSizeClass` 是 compact 時 `.narrow`，regular 時 `.wide`。iPhone 橫拿（大的 iPhone 是 regular）照舊算窄，保留 iPhone 原本的行為。
  - App 在視窗的根（`AppRoot`）讀 size class，放進環境值 `windowLayout` 傳下去。不在 sheet 裡讀，因為 sheet 自己的 size class 是卡片的，不是視窗的。
  - `SheetHeight.offered(in:)` 與 `WindowLayout.framesTheLessonsTowns` 改看 `WindowLayout`。窄視窗的卡片開半高、可以拉到全高；寬視窗只有全高。
  - 框城鎮再多一道保險：`PlanCamera.lessonFraming(_:clearOf:)` 算出框好的縮放，400 點超過 5 km 就不框（`farthestLessonFramingMetres`）。量到的數字（lesson 1，`WindowLayoutTests`）：13 吋 iPad 橫拿 2.7 km、直拿 4.2 km、11 吋橫拿 3.7 km；iPhone 橫拿 9.4 km、1/3 分割畫面（440 點寬）7.6 km、Slide Over 9.7 km。5 km 落在中間。決策 643 說 9 km 時第一段軌道長到買不起。
- **決策 643 的缺口**：它只寫了 iPhone 橫拿，沒寫分割畫面與台前調度。這裡補上。

## 2. 教學不列月台，只在蓋車站那幾步（L15-7）

## 4. 倍速提示在任何蓋住 2D 地圖的畫面下都等（L13-2）

- **問題**：決策 464 的提示是 2D 地圖倍速旁的 popover。它在別的呈現底下自己跳出來時，UIKit 會把上面那層收起。#1922 只在 3D 打開時擋住，但 2D 上還有車隊總覽、列車名冊、路線圖、各個面板等 sheet 與 fullScreenCover。
- **確認**：只讀程式與決策 464 續寫查到的機制（同一個 `_UICurrentContextPresentationController` 路徑，不限 3D）。Simulator 上要重現得先讓遊戲真的跑不到倍速 20 秒，CI 的 Simulator 做不穩，所以**沒有在 Simulator 上重現**（UNVERIFIED）。修法只讓提示多等，不改它出現時的樣子，所以先修。
- **改法**：`GameSession.coverOpened()` 給一個號碼、`coverClosed(_:)` 收回；只要還有號碼沒收回，提示就不出來（和 3D 一樣，收掉的不算玩家關掉）。App 的 `coversTheMap(_:)` 掛在 2D 地圖上每一個 sheet 與 fullScreenCover 的內容上：`ContentView` 的面板、列車展示、城市視角、過關卡、收購、車站收購、新路線確認；HUD 的問題回報；車隊總覽與檢視面板的名冊；路線面板的車種型錄、運行圖、名冊；車站面板的兩個選站；收到的共享路網。3D 自己的 cover 照舊用 `setMap3DOpen`；sheet 裡再開的 sheet 本來就在外層底下，掛了也無妨。
- **取捨**：iPhone 上面板是下半卡，打開面板時提示也會等。提示只是建議，晚一點出來不影響玩。
