- **日期**：沿用決策 211 的表（香港天文台公曆農曆對照表，2025–2100，之後每 19 年一輪），`tools/holiday-calendar/build_taiwan_lunar_dates.py` 多一個 `festivals` 模式，多印元宵與三月初一兩欄（原四欄重印後與現有表逐字相同）。遊戲的月是 30 天，日期放在同月同日。
- **地點與車站**：存檔 `demandEvents.sites` 記每個節慶在地圖上的位置（世界座標）；畫面層 `FestivalCatalog` 把真實座標放上實景地圖（新遊戲在放景點的地方一併放）。每天午夜，離某節慶開始剛好是預告天數時，在離地點 1.6 km（景點範圍的兩倍）內、有客運線停靠且收客的最近 3 站各開一個 `DemandEvent`（`kind: .festival`，多一欄 `festival`）。空白地圖沒有真實座標，不放。
- **劇本節慶跟農曆**：`ScenarioEvent` 多一個可省略的 `follows: FestivalKind?`；有它就用該節慶每年的日期，沒有就照決策 90 的「每年第 N 天」。平溪挑戰改成 `follows: .lanternFestival`；第 0 年（2026 元宵 = 3/3 = 第 62 天）與原來相同，其後每年移動。
- **玩家看得到的**：站長提示「N 天後是〇〇，A、B 的旅客會多 X%（人潮多在 20:00 到 24:00）。先加開列車吧」（`StationMasterAdvice.namedFestivalComing`，也進新聞紀錄，鍵 `festival:<名稱>`）；車站面板的活動列用節慶名。
