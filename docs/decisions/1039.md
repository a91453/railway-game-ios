### 1039. 待避計畫的會車與待避沒變就沿用（TICK-PLAN-KEEP）

2026-11-27，雲端工作串「讓台灣大地圖跑滿 60 倍」（協調者派工，`docs/handoff/TICK-HOLDERS-BY-CLAIM.md`「還留下什麼」第 2 點）。和決策 1038 同一張 PR。
只改 GameCore 的備忘（memo）與測試，規則一條都沒改：存檔版本、golden schema、`GoldenScenarios/`、`SaveFixtures/`、`ReplayFixtures/` 都不動。

**問題。** 交通管制開著時，待避計畫（`trafficPlan(memo:)`，決策 59、294、366）每當有車發車、到站或經過一站（`TrafficPlanKey` 變了）就整份重算；台灣全買 190 列車，幾乎每一秒都重算。
main `8e185c34` 台灣全買・寫實 08 時，它佔 24 %：其中會車（`inferTrafficMeets`）與最多八輪的待避（`planTrafficOvertakes`）約四分之三，決策 366 的等間隔線待避（`planHeadwayOvertakes`）約四分之一。

**做了什麼。**

1. 會車與待避讀的東西列成一把鑰匙（`TrafficCoreKey`）：每個班次的 run（`TrafficParts.Run`：列車、第幾輪、時刻表、週期、車長、性能，決定它的點）、有沒有在跑、是不是在往或停在第一站，以及只有當它在第一站的月台軌上時，它的位置、拖尾的軌道與移動。
   上一份會車與待避的結果（決策 366 之前、排序之前）連同鑰匙記在備忘裡（`DirectionMemo.trafficCore`）。鑰匙相同就直接用那份，只把班次裡的列車換成現在的列車，再照舊算決策 366 的待避、排序。鑰匙不同就照舊算，記下新的。
2. 一站的月台軌（`trafficPlatformEdges(of:parts:)`）記在 `TrafficParts` 裡，算鑰匙時不必每次問路網。
3. 待避的排序拆成 `trafficWaitOrder`，稽核與測試用同一個。

**為什麼結果一樣。**

- 會車與待避（`inferTrafficMeets`、`planTrafficOvertakes`）只讀每個班次的點（由 run 決定，記在 `TrafficParts.points`）、run 本身，以及列車的這幾樣：`execution` 是不是 `nil`、`execution?.stop == 0`，和列車在它第一站月台軌上時的位置、拖尾與移動（`trafficHasSiding`、`trafficMoves` 的第 0 點、`trafficTrack` 與 `keptTrafficTrack` 的第 0 點：站在第一站的車留在它站的那一股）。列車的時刻（`times`）、經過紀錄（`trafficVisits`）與在別處的位置，只有決策 366 讀（`progress(of:)`），它每次都照舊算。
- 鑰匙包含了上面每一樣，所以鑰匙相同時，重算會走同樣的步驟、得到同樣的待避、同樣的錨點，留在 `TrafficParts` 的東西（軌道、側線、名目時間、最近幾種 run 的股道）也是同樣的答案（都是它們自己鍵的純函式）。換上現在的列車，等於重算時班次帶的列車。
- 一份備忘只活一次 `advance`（或一次問題），路網、時刻表、路線在裡面不變。
- 稽核：`answerAudit` 開著時，每用一次記下的結果（`trafficCoresKept` 計數），就用全新的 `TrafficParts`、`PathMemo` 不帶記下的結果整份重算一次（不含決策 366），`precondition` 班次的點、列車與排序後的待避都相等。`SavedWorldTickReportTests` 的 `SAVED_WORLD_AUDIT=1` 那行多印這個數。
- 測試：`TrafficCoreKeptTests` 在 `LocalPassTests` 的線上（站站停讓快車，一整天來回）每秒問一次計畫，每次都和整份重算比待避與點，並要求至少有一次沿用、至少兩次重算。
- 硬證明：全買世界新舊 build 每 60 tick 的世界雜湊逐行相同，見下表。

**這張 PR 仍不夠讓台灣 60 倍跑滿**：尖峰一個 tick 仍約 2.5–2.7 s（60 倍要一秒一個 tick）。剩下的在 `docs/handoff/TICK-HOLDERS-BY-CLAIM.md`「接手」一節。

**五個角度。**

- 玩家：台灣全買（尤其寫實規則）尖峰時每分鐘的計算少四分之一左右，60 倍更接近跑得滿；世界一個位元都沒變，班次與存檔照舊。
- 鐵道迷：無（會車、待避、等間隔線待避的規則都沒動）。
- 開發：待避計畫多一層有稽核的沿用；鑰匙寫明會車與待避讀了列車的哪些東西，之後改它們要讀新的東西時，鑰匙也要加（稽核會抓）。
- 美術：無。
- 音樂：無。

**還沒做的**（交接在 `docs/handoff/TICK-HOLDERS-BY-CLAIM.md`）：

1. 決策 366 的等間隔線待避（`planHeadwayOvertakes`）每次都算，台灣寫實約 5 %：它讀每列車的時刻與經過，要沿用得另找鑰匙。
2. 鑰匙變了的那些秒（有車在第一站月台軌上移動、或發車、到第一站）仍整份重算；可以只重算鑰匙變了的那幾個班次的會車（`inferTrafficMeets(_:only:)` 已經能只算一部分），但待避的八輪互相影響，要另外證明。
