### 513. 隧道可以在地下 1,024 公尺；鋪軌被擋時說出是哪一個條件

2026-10-30，派工單 GEOMSG（session_01YGNNuoRrRTXXysd6fhDuj8，遊戲規劃第 36 任派），分支 `geomsg-track-reason`，目標 100.1。存檔版本、golden schema、SaveFixtures、ReplayFixtures 都不動。改了一個 GameCore 常數（`RailwayNetwork.heightRange` 的下限）。

## 問題

作者 99.1 實機（iPhone 橫拿，實景地圖，宜蘭南澳附近）：用鋪設工具從山邊沿真實鐵路往南拉一段，預覽是彎曲的長線，卡片寫「0 公尺｜高度 97 公尺 → 65 公尺」，警告是 `GameError.invalidTrackGeometry` 那句什麼原因都列的話（地圖內、高度差 64 公尺以內、起終點不同、線形平順）。作者問：高度差要不要放寬？

## 在 Linux 重現（`TrackGeometryProblemTests`）

南澳站在北迴線上的位置往南 3 公里起、拉回 1 公里處（描線，單線，真實地形 `taiwan_heights.dat`、真實橋隧 `rail_structures.json`）：

- 第一段的起點高 96 公尺，地面 279 公尺。描線照決策 279 讓新的端點站在真實隧道裡（`TrackRise.Carried`，`carriedEnds.start`），所以這一點在**地面下 183 公尺**。
- `GameWorld.buildTrackNode(at:)` 的 `isInWorld` 要求端點在 `RailwayNetwork.heightRange`（±4,096 單位，±64 公尺）之內，於是丟 `invalidTrackGeometry`。
- 不是 cusp，也不是 `TrackGeometry.maximumRise`（128 公尺）：這一段的線形本身建得出來（`TrackGeometry` 不是 nil）。
- 卡片的 0 公尺：描線預覽（`tracePreview`）的長度只加「建得起來的段」，第一段就被擋時是 0；終點高度用的是第一段的終點（65 公尺），不是整段的終點。BUILDMSG（#1565）的「被擋時顯示直線距離」只在單段的 `preview(from:to:)`，描線不走那裡。

改之前這個測試是紅的（訊息是那句總括的話、長度 0、建不起來），改之後是綠的。

沿南澳、和仁、崇德各站前後約 15 公里，每 1 公里描一段 2 公里（兩個方向），量描線端點離地面最深的地方：南澳 407 公尺、和仁 439 公尺、崇德 319 公尺。這段北迴線上，改了之後沒有一段再因為深度被擋；還被擋的幾段是坡度（40‰）的問題，不是深度。

## 做法

1. **GameCore**：`RailwayNetwork.heightRange` 從 `-4_096...4_096` 改成 `-65_536...4_096`：端點最高離地 64 公尺（不變），最深在地下 1,024 公尺（原本 64 公尺）。只有這一個常數。`TrackGeometry.maximumRise`（一段最多升降 128 公尺）、坡度上限、`TrackSections` 的高架上限 `highestDeck`（64 公尺）都不動。
   - 溢位：高度的乘法由每一段的 `maximumRise` 與 `maximumSlopingLength` 管，與端點離地多深無關；65,536 單位離 `WorldCoordinate.limit`（2^29）還很遠。
   - 存檔：讀檔時的檢查（`GameWorld` 的 `isInWorld`）用同一個範圍，範圍只變寬，所以舊存檔都讀得回來，存檔格式不變，版本不升。新的存檔如果有地下超過 64 公尺的端點，舊版的 App 讀不回（舊版本來就不保證讀新存檔）。
   - golden、replay：fixture 裡沒有任何端點在地下超過 64 公尺（`"z"` 最低 -1,024 單位），規則只是讓原本被拒的指令可以建，期望值一個都沒動。`ContinuousTrackTests`、`VerticalRailwayTests`、`TrackSectionTests` 原本斷言地下 64 公尺 +1 單位被拒，改成地下 1,024 公尺 +1 單位被拒、地下 64 公尺 +1 單位可以建。
   - 鋪設工具自己的高度選單（`NetworkBuilding.heightRange`，±64 公尺、每格 2 公尺）不動：玩家手動鋪的隧道照舊最深 64 公尺；更深的只有描線沿真實隧道時才會出現。
2. **說出是哪一個條件**（GamePresentation，`TrackGeometryProblem.swift`）：GameCore 丟 `invalidTrackGeometry` 時，用 GameCore 同樣的順序再問一次（`buildTrackNode` 的新端點：地圖內、離地多高、地下多深、那一點已經有端點；`buildTrackEdge`：同一點、控制點在地圖內、`TrackGeometry` 建不建得出來），各給一句兩種語言的話：
   - 「有一端會離地面 X 公尺，軌道最高只能離地 64 公尺。」
   - 「有一端會在地面下 X 公尺，軌道最深只能到地下 1024 公尺。」
   - 「那一點已經有軌道的端點，請改點那個端點。」
   - 線形本身的四種（超出地圖、同一點、高低差太大、彎不過去）用 BUILDMSG 的 `NetworkBuilding.GeometryProblem`，不另寫一套。
   - 接在描線（`tracePlan`，問的是描線之前的世界，因為被擋的那段可能已經在 draft 裡留下第一個端點）與單段預覽（`preview(from:to:)`）的錯誤訊息。都對不上時照舊是 `playerMessage(in:)`；那句總括的話改成「離地最高 64 公尺、地下最深 1,024 公尺」。
3. **0 公尺**：描線第一段就被擋時，長度是整條描線畫出來的長度（`drawnLength(of:)`），終點高度是整段的終點，不再是 0 公尺與第一段的終點。

## 五個角度

- 玩家：沿真實鐵路描線進山不再莫名被擋；真的被擋時，卡片說的是那一個原因與那一個數字，長度也是看得到的那條線。
- 鐵道迷：真實山岳隧道上方的岩層常有數百公尺（雪山隧道最深處約 700 公尺；遊戲自己的資料量到北迴線和仁一帶約 440 公尺），64 公尺擋掉的是真實存在的隧道；高架和橋離地 64 公尺的上限照真實鐵路維持。隧道位置來自決策 279 的橋隧資料（參考庫 `level-profiles.json`，國土測繪中心「臺灣鐵路」補正）。
- 開發：GameCore 只改一個常數的下限，存檔格式、golden、replay 都不動；原因的判斷放 GamePresentation，用 GameCore 同樣的檢查順序，Linux 測試釘住。
- 美術：無（3D 地圖的隧道照舊畫在地下，看不到深度）。
- 音樂：無。

其他選項：
- A 維持 ±64 公尺、只改訊息：作者這段還是鋪不上，而真實的北迴線就是這樣走的。不選。
- B 地下不設上限（只剩 `WorldCoordinate.limit`）：沒有實際需要，數字沒有界線不好測、也不好說給玩家聽。不選。
- C 地下 512 公尺：量到的最深是 439 公尺，餘裕太小，中央山脈的線（南迴、阿里山）還沒量。不選。
- **D 地下 1,024 公尺（選這個）**：量到的最深的兩倍多，是 2 的次方（65,536 單位），說得出口。
