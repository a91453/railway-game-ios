### 434. 演示模式的列車展示

2026-10-27，遊戲規劃 session_01YGNNuovwuBJPdZWXamkhEp 派工（派工單 U），實作 session_01YGNNupMJ7itVvEU4wNzbcm（`claude/train-showcase-434`）。號碼依 #1041：決策 434；存檔版本、golden schema 不動。GameCore、`GoldenScenarios/`、`SaveFixtures/`、`ReplayFixtures/`、`TrainPack`（列車包與解鎖）、列車模型的外形與 `Map3DModels.swift` 的註冊順序都不動；只動 GamePresentation、App、測試與文件。

**為什麼**：遊戲裡的 3D 列車越來越多（決策 408、432、433），但要看某一款車，只能開一局遊戲、蓋線、等車跑過鏡頭。演示模式（決策 351）需要一個地方把車並排擺好，隨意轉、拉近、拍照；10/31 之後列車包的預覽也要一個同樣的畫面。

**做了什麼**：

1. **入口**：設定 →「關於」，「畫面節奏測試」下面一列「列車展示」（`settings.trainShowcase`），條件與「畫面節奏測試」相同：`TestBuild.isTest`，且演示模式已顯出（版本列點五下）或已打開。正式版看不到。開成全螢幕（`TrainShowcaseScreen`），右上「關閉」回設定。
2. **圖鑑**（`Map3DShowcase.catalog`，GamePresentation）：`Map3DTrainSet.all` 裡每一個不是遠景（`…Far`）的 set 一筆，共 30 筆；測試（`Map3DShowcaseTests.testEveryNearSetIsInTheCatalogOnce`）逐一核對，之後新增一個 set 而沒加進圖鑑，測試會紅。每筆有中英文名字、分類（台鐵、高鐵、捷運、輕軌、其他）、預設輛數與輛數的上下限（固定編組的車只有一個數）。名字取 `DisplayText`／`PerformanceText` 已有的說法，沒有的自己寫；分類內新車在前（例：台鐵 EMU3000、EMU800、普悠瑪、太魯閣在前，藍皮、復興在後）。名字不寫 key、模型名稱或三角形數。
3. **擺法**（`Map3DShowcase.layout(keys:cars:far:)`）：
   - 一列車一條軌道，相鄰兩條相距 9 m（夠兩列 3.2 m 寬的車並排，中間看得到道碴），車頭都對齊在 x = 0、朝 +x，車身往 −x 排。
   - 自帶長度的 set（`ownLengths`，例：EMU3000、700T、EMU800）照 `Map3DModelPack.layout(forType:count:)` 首尾相接；其他 set 每輛 20 m、中心距 20.5 m，與 3D 地圖上跑的一樣。
   - 「遠景」開關改用那個 set 的 `far` 模型（有的話），沒有遠景模型的 set 不變。
   - 地面（`Map3DShowcase.ground`）：一塊平地，每條軌道底下一條道碴與兩根鋼軌，軌距照分類（高鐵、捷運、輕軌 1,435 mm，其他 1,067 mm）。不畫第三軌、架空線、城市。
4. **一次最多 8 列**（`Map3DShowcase.mostRows`）：8 列寬 63 m，俯瞰時手機直放也看得清每一列；預設五列約 24 萬個三角形（`tools/map3d-preview` 量），8 列長編組也在百萬左右，不會超過 3D 地圖平常的量。選滿了，挑選單上面一句說明「一次最多展示 8 列。要加別的車，先取消一列。」，其他車的勾選列變灰。
5. **預設的車**：EMU3000、EMU800、台北捷運 C341、台灣高鐵 700T、普悠瑪。台鐵的新舊城際車、捷運、高鐵各有代表，五列都是現在遊戲裡畫得最細的車。
6. **光線**：白天、黃昏、夜晚三段，直接用 3D 地圖的 `Map3DLighting(minute:)`（14:00、18:00、21:00），與遊戲裡同一個時刻看到的一樣；夜晚車頭燈亮。不另做燈光。
7. **鏡頭**（`Map3DShowcase.camera(_:rows:viewport:)`）：
   - 三個預設：「車頭特寫」（第一列車頭斜前方，方位 −120°、約 18 m）、「側面」（第一列車頭端約三輛的側面）、「俯瞰」（全部的車）。
   - 手勢：一指拖動繞著轉、兩指捏合拉近拉遠（6–1,500 m，比 3D 地圖最近的 60 m 近，才站得到駕駛台旁邊）、兩指拖動平移。
   - 轉盤（自己慢慢轉一圈約 18 秒）預設關；系統的「減少動態效果」打開時不會自己打開，也會把已打開的轉盤關掉。
8. **隱藏按鈕與拍照**：「隱藏按鈕」只留下畫面，點畫面一下按鈕回來（點的是一層蓋滿畫面的透明點擊層，見下面「修正」）。「拍照」沿用決策 403 的拍照與分享（`Map3DPreviewScreen.credited`、`Map3DSnapshotSheet`，由 private 改為 internal 讓這裡也能用），角落的署名是「沿線」／"Along the Line"。
9. **只重做變了的部分**：挑選、輛數、遠景改了才重算列與地面（`TrainShowcaseStage` 比對 `rows`）；換光線只換 `lighting`；鏡頭預設只動鏡頭。

**參考庫**：`Railway/taiwan-rail-reference-clean/source/train-garage.js`（與 `train-garage-catalog.js`）就是網站的「車庫」：一列車擺在平地上轉著看。照搬了它的數字：起始方位 −0.55、仰角 0.39 rad；拖動每像素橫 0.012、縱 0.008 rad；仰角限在 0.08–1.48 rad；自轉 0.35 rad/s、預設關、減少動態效果時關。它一次只擺一列、有清晨／白天／黃昏／夜晚四段；這裡改成並排多列（演示要一次比較好幾款），光線用遊戲自己的三段（與 3D 地圖一致）。它的示範組 emu3000、e200、e1000、700t、blue、temu2000 參考過，預設改成遊戲裡模型最細的五款。

**之後列車包預覽要用的介面（10/31 以後）**：`Map3DShowcase.layout(keys:cars:far:)`（傳列車包裡那幾個 set 的 key）、`Map3DShowcase.ground(_:)`、`Map3DShowcase.frame(_:)`、`Map3DShowcase.camera(_:rows:viewport:)`，畫面用 App 的 `TrainShowcaseStage`（`rows`、`cameraView`、`light` 從外面給）。購買頁本身這次不做。付費列車包裡的車在預覽上不寫真實的車名（決策 338 續二），名字從列車包自己的資料來，不用這份圖鑑的 `chinese`／`english`。

**不採用**：
- **用現有 3D 地圖開一局新遊戲擺車**：要擺車就得經 GameCore 的指令蓋線、買車、排班，挑不了任意一款（被列車包鎖的、只在實景跑的都擺不出來），也要動存檔與 GameCore。
- **在 3D 地圖上加一個「展示」圖層**：地圖的串流、城市、號誌都會跟著算，畫面很擠，只為看車划不來。
- **一次只擺一列（照搬參考的車庫）**：演示時最常做的是比較兩三款車，一列一列換看不出差別。
- **不設上限**：選到二三十列時舊機器會掉格，俯瞰也小到看不清。
- **轉盤預設開**：一打開畫面就在動，與決策 253 的動態規則不合，減少動態效果的人更不舒服。

**五方**：
- 玩家：在設定裡就能把喜歡的車擺出來轉著看、拍照分享，不用先玩到那款車。
- 鐵道迷：軌距照真實（高鐵、捷運 1,435 mm，台鐵 1,067 mm），編組輛數照各車的真實範圍，固定編組的車不能拆。
- 開發者：只在 GamePresentation 加一個純計算的列舉，Linux 上測得到；不碰 GameCore、存檔；之後列車包預覽直接用同一套。
- 美術：平地、道碴、鋼軌，什麼都不多，車本身是主角；光線與 3D 地圖同一套，看到的就是遊戲裡的樣子。
- 音樂：無。

**驗證**：`Tests/GamePresentationTests/Map3DShowcaseTests.swift`（在 origin/main 上沒有 `Map3DShowcase`，編不過）；UI 測試 `TrainShowcaseUITests`（開展示 → 隱藏 → 按鈕不見 → 點畫面 → 回來），只在 full lane 跑，不進 gate。實機的樣子與畫面幀率沒有驗過。

**修正（2026-10-27，TestFlight 91 之後）**：91 的 full lane（run 40502803331）第一次跑 `TrainShowcaseUITests`，隱藏後點畫面，按鈕沒有回來：Metal view 上的 `UITapGestureRecognizer` 沒收到點擊。改成和放空模式（決策 414）一樣：隱藏時蓋一層全螢幕透明的點擊層（`contentShape` 加 `onTapGesture`，`trainShowcase.reveal`，VoiceOver 念「顯示按鈕」也按得到），拿掉 Metal view 上的點擊辨識。代價是隱藏時不能轉鏡頭或拉近；轉台照轉，構圖要在隱藏前先調好。
- 玩家：點一下就回來，用 VoiceOver 的人也不會卡在沒有按鈕的畫面。
- 鐵道迷：無。
- 開發：和放空模式同一種寫法，已經有 UI 測試證明它收得到點擊；不用查 SwiftUI 和 UIKit 手勢搶點擊的細節。
- 美術：無，畫面不變。
- 音樂：無。
- 沒選的方案：留著 UIKit 的點擊辨識，另外在畫面上加 SwiftUI 的 `simultaneousGesture`。好處是隱藏時還能轉鏡頭，但沒有實機和 Simulator 可以先驗，這次又是第一次跑就紅，所以不選。
