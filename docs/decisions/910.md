## 1. 解死結的救援：一步一檔＋順位表（第 1 刀）

`GameWorld.resolveDeadlock(memo:)`（決策 58 的 Stage V2）原本先寫了五段救援，最後一行再用 `??` 接六段；每修一個死結（決策 556、577、740、808、816…）就在同一行再接一段，所有修死結的工作串都改同一行。

1. **一步一檔**：`Sources/GameCore/Railway/DeadlockRescue/<步驟>.swift`，每檔一個 `extension GameWorld` 的 `mutating func <步驟>(in:memo:) -> TrainID?`。原本寫在 `resolveDeadlock` 裡的五段搬成同樣形式的函式（`serviceTakingAnyListedPlatform`、`serviceSettingOffForAPassingPlace`、`spareSteppingAside`、`serviceTurningBackShort`、`serviceTakingAFreeBerthAgainstTheWay`），內容照舊。
2. **順位表**：`DeadlockRescueList.swift`，一步一列 `DeadlockRescue(order:decision:name:)`。照 `order` 由小到大試，第一個讓一列車動的就結束這一分鐘，和原本一樣一次只動一列。原本夾在中間的那個檢查（沒有到點的列車、困住的又沒有空車就整段結束）也是一列（`goesOnOnlyIf`）。
3. **合併**：表檔在 `.gitattributes` 設 `merge=union`（同決策 782 的列車表、895 的地標表），兩個分支各加一列，合併時兩列都留。union 可能把兩列的先後放反，所以**順序看 `order` 數字，不看列的先後**（表讀進來時照 `order` 排）。
4. **測試**：`DeadlockRescueListTests` 擋三件事：`order` 不重複、名字不重複、原本的 13 步照原本的先後都在。
5. **加新的一步**：新增一個檔，在表裡加一列，`order` 取它前後兩步中間的數（原本的步驟間隔 100）。

## 2. RouteReservation 依段落拆四檔（第 2 刀）

`Sources/GameCore/Railway/RouteReservation.swift`（決策 32 的 Stage T）有 2,500 多行，原本就用 `// MARK:` 分成幾段；改路線預約的 PR 都改這一個檔。照原本的段落切開，順序與內容不變：

1. `RouteReservation.swift`：檔頭說明、型別、查詢（Queries）。
2. `RouteNeeds.swift`：一條路線要哪些軌道資源（needs、反向、待避）。
3. `RouteFollowing.swift`：列車沿路線跟車、放掉走過的資源。
4. `RouteResources.swift`：`EdgeTable` 與 `TrackResource`／`RailwayNetwork` 的擴充。

跨檔要用的成員把 `private`／`fileprivate` 拿掉；巢狀型別裡的 `private` 照舊。整檔一起拿掉而不是只拿掉會報錯的，是因為有幾組同名多載（`waits(_:forAnyIn:)`、`authorityEnvelopes(of:along:)`）：只放開一個時，別檔的呼叫會靜靜地改叫到另一個，行為就變了；全部放開，每個呼叫解析到的函式和原本同一個。
