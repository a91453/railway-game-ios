### 667. full lane 的 build job 也先經 XCTest 開一次 App（XCTest 暖身），再跑 UI smoke

2026-11-09，派工單 LAUNCH-TIMEOUT（session_01YGNNunZw5P948dG6PSGhmg，遊戲規劃第 57 任 session_01YGNNum8VrDTbqa8SHkYC4q 派），分支 `claude/launch-timeout`。號碼依 #1579：決策 667。存檔版本、golden schema、GameCore、App 都不動；只改 `.github/workflows/ios-build.yml` 的 build job。證據與比較在 `docs/research/LAUNCH_TIMEOUT_2026-11-09.md`。

**為什麼**：11-08 夜的 full lane（run 42527935599，main fa31385）只有 build job 紅。UI smoke 第一個開 App 的 class（`CoverageShortcutUITests`）開 App 85 s 逾時；下一支 Xcode 讓 App 繼續時，App 的行程已經不在（`Failed to send signal 19 … 3`），等滿 8 分鐘；第三支也開不起來；runner 重開以後，其餘 45 支照平常的時間全綠。前兩晚綠的 build job，第一次經 XCTest 開 App 也要 17–47 s。另外三個 iPhone job 早就為同樣的症狀加了「Warm up XCTest's first launch」（cd93d78、0149127 那幾次），build job 一直沒有。#1993 只改 iPad job；#1998 改的 `StallSampler` 和 3D 街道不在開 App 的路上，其他 test 的時間也跟前兩晚一樣。所以不是這兩個 PR 讓 App 變慢。

**做法**：build job 在「Warm up the app's first launch」之後，加 `ui-full-lane` 同一個「Warm up XCTest's first launch」步驟：先 terminate App，只跑 `StartSaveFlowSmokeTests/testTheAppOpensOnItsStartScreen`，8 分鐘上限，`continue-on-error`，失敗只留警告，result bundle 叫 `ui-smoke-warm-up.xcresult`。條件是 `github.event_name != 'pull_request'`，所以 full lane（nightly 與手動）和 `only_testing` 的手動 run 都跑，PR 的 gate 不跑。沒有跳過、停用或隔離任何測試，那三支照樣在 UI smoke 裡跑。

**沒選的**：
- 調長 XCTest 開 App 的時限：xcodebuild 沒有可以設這個時限的選項，而且時限過了以後壞的是 Xcode 和模擬器之間開 App 的那條路（下一支也開不起來），調長時限擋不住。
- 讓第一個開 App 的 class 改成別支：只是換一支紅。
- PR 的 gate 也暖身：gate 約 6 分鐘（決策 199），多 2–3 分鐘；PR 的 run 還沒看到這個症狀。之後 PR 的 gate 也出現，再加。

**五個角度**：
- 玩家：無直接影響；full lane 穩，發版不會被 CI 的偶發紅擋住。
- 鐵道迷：無。
- 開發者：只多一個照抄的步驟，full lane 的 build job 多 2–3 分鐘（115 分鐘時限內，11-08 夜整個 job 約 63 分鐘）；以後 full lane 的 build job 紅，比較可能是真的壞了。
- 美術：無。
- 音樂：無。

**驗證**：本分支的 `only_testing` run（`CoverageShortcutUITests FinanceCompositionUITests LoadChartUITests`）結果見 PR。之後幾晚 full lane 的 build job：暖身步驟綠，UI smoke 第一個開 App 的 class 不再出現「Failed to launch … via Xcode」。macOS 的部分本機（Linux）驗不了。

**以後怎麼認**：開 App 失敗落在 job **第一個**開 App 的 class，runner 重開以後全綠，是第一次經 XCTest 開 App 太慢。先看暖身步驟花了多久、有沒有警告。落在 job 中間、已經開過好幾次 App 以後，才懷疑 App 變慢或當掉（看 App trace，比較同一支 test 在綠的晚上的開 App 時間）。
