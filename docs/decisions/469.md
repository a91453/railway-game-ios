### 469. 手機上看板下那一排照寬度收起來，建造數字列有窄的排法

2026-10-28，遊戲規劃 session_01YGNNumoD1XSP8eSkjabCvp 派工單 CD，實作 session_01YGNNuphFRU9bQ2b4Tq1DwJ（`claude/phone-crowding`）。號碼依 #1041：決策 469；存檔版本、golden schema 不動。GameCore、存檔、GoldenScenarios、SaveFixtures、ReplayFixtures 都不動。

**問題**（UI 健檢 `docs/research/UI_UX_REVIEW_2026-10-28.md` 的 D：2-3、2-20、2-22；PLAYER_FEEDBACK「手機畫面太擠」已 4 人）：看板下那一排（跳過夜晚、圖層條、下一步、跟隨列）每個元件都是固定寬：圖層條 299 點、跳過夜晚約 190 點。iPhone 只能橫拿（決策 106），細節卡佔 35%：iPhone 17 Pro（安全區內 750 點）開著細節卡只剩 457 點，夜晚時跳過夜晚、圖層條、下一步共 573 點，就伸到細節卡底下；iPhone SE（667 點）只剩 404 點，跳過夜晚加圖層條（499 點）也放不下（決策 305 記為未驗證）。建造時的數字列（長度、高度、費用）也只有一排。

**做了什麼**：

1. `MapTopRow`（`Sources/GamePresentation/MapTopRow.swift`，測試 `MapTopRowTests`）：給這排能用的寬度（螢幕減兩邊 10 點，再減開著的細節卡或面板），依序試，第一個放得下的就用：
   1. 全部照舊；
   2. 圖層條收成一顆「圖層」鈕（52 點，點了開完整圖層表，和「更多」同一個識別名）；
   3. 再收起下一步（目標面板裡一樣看得到）；
   4. 再讓跳過夜晚只留圖示（時間在上面的看板裡，VoiceOver 照樣讀全名）。
   跟隨列不收：它本來就照剩下的寬度換五種排法（決策 226、251），這裡只留它最窄的 110 點。跳過夜晚的全寬由 App 量（字級會變），收成圖示時照樣量，才知道什麼時候放得回去。
2. 換排法時這排照 `MotionRule.change` 讓位；減少動態效果時直接換。沒有新的秒數。
3. 建造數字列（`MapConstructionHUD`）用 `ViewThatFits`：一排放不下時三個數字上下排。「接上軌道」那行的英文改成大寫開頭，和其他行一致。
4. 只有放不下時才收：iPhone 橫拿、開著細節卡，白天自由模式的圖層條加下一步（373 點）放得下，照舊；iPad 四個方向的一般寬度照舊。只有原本會伸到細節卡底下的情況（夜晚、跟車、最大字級，或 iPad 直拿開細節卡又是夜晚）圖層條才收成鈕。不改支援的方向，地圖的按鈕位置照決策 300、350。

**五方**：
- 玩家：橫拿手機開細節卡時（夜晚、跟車、大字）圖層條不再壓在卡片上，這排從 299 點縮成 52 點的一顆鈕；要緊的時間、錢、速度一直在看板上不動，正在跟的車和跳過夜晚最後才收。
- 鐵道迷：無。
- 開發：判斷在 GamePresentation，Linux 測試涵蓋 iPhone SE、17 Pro 橫拿與 iPad；收起來的鈕沿用「更多」的識別名，點它的 UI 測試不用改。
- 美術：收起來的鈕就是圖層條的一格，同樣的玻璃與圖示，不新增圖。
- 音樂：無。

**其他選項（沒採用）**：
- A 先收下一步再收圖層條：順序只影響放得下其中一個的時候（例如 SE 開細節卡、自由模式的夜晚）；下一步只剩旗子和進度，比五顆圖層鈕省，留著。
- B 這排換行成兩排：地圖露出更少，正是玩家說的太擠。
- C 窄的時候把圖層條搬到地圖左下（決策 226 的圓鈕）：位置會跟著狀態跳，玩家找不到；左下已有站長與擴建鈕。
- D 細節卡開著就整排藏起來：跟隨列與跳過夜晚也會不見。
