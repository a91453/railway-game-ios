### 473. 載入畫面顯示實際完成的步驟，並能回到上一個畫面

2026-10-29，派工單 M，實作 session_01YGNNukvbEqFLMsPED4XHuY（`claude/loading-progress-m`），遊戲規劃 session_01YGNNumk6UqdBm6JrBhsdZY 派。UI 健檢 M（`docs/research/UI_UX_REVIEW_2026-10-28.md` 的 2-23，§3 第 11 名）。號碼依 #1041：決策 473；存檔版本、golden schema 不動。只改 GamePresentation 與 App；GameCore、存檔、GoldenScenarios、SaveFixtures、ReplayFixtures 不動。

**為什麼**：決策 307 的載入畫面只有「正在準備地圖…」，沒有進度，也不能離開。高鐵示範在模擬器上要讀幾十秒的道路（決策 400 續篇量過 28–58 秒），慢的時候看起來像當機，而且玩家只能等。

**會等的地方**（從程式找的，都走這個畫面）：

| 載入 | 入口 | 步驟 |
| --- | --- | --- |
| 實景新局（台灣，按塊買） | `openRealWorldGame(at:)` | 計算人口與工作 → 鋪開地圖 → 整理地形高低（有高度檔、選真實地形時） |
| 實景新局（台灣外、示範模式） | 同上 | 鋪開地圖 →（整理地形高低） |
| 高鐵示範、宜蘭線示範 | `openHighSpeedDemo`、`openTRADemo` | 鋪設路線與列車 → 讀入道路 |
| 實景示範、平溪線挑戰 | `beginReadingRoads` | 讀入道路 |
| 讀存檔（讀超過 0.3 秒才出現，決策 419） | `load`、`loadAutosave`、`importSave` | 讀取存檔 → 讀入道路 |

**做法**：
- `RealWorldLoading` 多了 `steps`、`done`、`stepShare`、`backTo`。進度 = (完成的步數 + 正在跑那步已完成的份) ÷ 步數；只往前，不倒退。**沒有計時、沒有估計**：一步做完（它的工作回來了）才算完成。唯一算「一步裡的份」的是讀入道路：`RealRoadCells.read` 每讀一張圖磚就把「讀過幾張 ÷ 共幾張」寫到 `LoadingMeter`，launcher 每 0.25 秒看一次。
- `newWorld(at:)` 拆成 `ridersStep(at:)`、`layOutWorld(at:)`、`grounded`，呼叫一樣、順序一樣，`startNewGame` 與測試用的 `newWorld` 結果不變；`openRealWorldGame` 一步一步在背景跑。
- `GameLauncher.LoadingRun`：一次載入的步驟與 meter。`step(_:)` 在背景跑一步，回來時若已取消就回 `nil`，流程就此結束、不碰 launcher 的狀態（之後開的新載入有自己的 run，不會被舊的蓋掉）。
- 「回開始畫面」（從遊戲裡讀存檔時是「回到遊戲」）：`cancelLoading()` 立刻收掉畫面，把這次載入設的旗標放回去（`isOpeningHighSpeedDemo`、`isOpeningTRADemo`、`isReadingRoadsToBegin`、`isLoadingSave`），並把 meter 標成取消。
- **取消後還會跑多久**：讀道路在下一張圖磚停（結果丟掉，世界不會留下讀一半的道路）；其他步驟（GameCore 的建世界、示範的鋪線、存檔佇列上的讀寫）不能從中間停，最多跑完**正在跑的那一步**，結果丟掉，下一步不開始。GameCore 不動是派工的條件；要讓那幾步也能中途停，得在 GameCore 加檢查點。
- 存檔佇列上的讀寫不中斷：讀檔前會先把正在玩的那局存進自動存檔欄（決策 192），那是完整的一次存檔，取消後留著無害。
- 高鐵與宜蘭線示範原本讓示範選單一直開著（「正在蓋高鐵…」）直到遊戲開始，載入畫面被蓋在選單下面，按不到取消（UI 測試 `testTheLoadingScreenGoesBackToTheStartScreen` 在 run 40805205366 抓到）。現在和實景示範一樣，按下就關掉選單，載入畫面露出來。
- 進度條用 `ProgressView`、`Theme.primary`，變化用 `MotionRule.change.layout(reduceMotion:)`（減少動態時直接跳到新值）；按鈕用 `ThemeSelectableButtonStyle`（外框、44 點高）。不加新的動畫規則、不加圖示。

**參考**：
| 參考 | 這裡 |
| --- | --- |
| `Railway/slop-taipei-reference-clean/source/Taipei_Basin_3D_Clean/js/taipei-progress.js` 的 `createBuildProgress`：一步做完才 `complete(id)`，分數只增不減，「沒有平滑、沒有依時間估計，卡住就停在卡住的那一步」 | `RealWorldLoading.advanced()`、`fraction`、`counting(_:)`：同一個原則；參考依量到的時間給每步權重，這裡先等分（下一步） |
| `Railway/tw3d-reference-clean/source/js/main.js` 的 `setLoadingProgress`／`reportLoad`：進度條＋「步驟文字 百分比」 | `RealWorldLoadingView.progress`：條＋「第 2 步，共 3 步：讀入道路」，百分比給 VoiceOver |
| 參考庫的載入畫面都沒有取消（網頁重新整理即可） | `cancelLoading()` 是這裡自己寫的 |

外面的專案沒有搬東西進來；取消與進度的寫法照 Apple HIG「Progress indicators」（能知道多少就用確定的進度條；讓人能取消）。

**下一步**：
- 依實際量到的每步時間給權重（參考的做法），讓條在花時間的地方走得多。
- GameCore 建世界若加檢查點，取消就能在步驟中間停。
- 進入遊戲後第一次開 3D 地圖有自己的 `ProgressView`（`Map3DPreviewScreen`），沒有步驟也不能取消，這次沒動。

**五方**：
- 玩家：慢的時候看得到它在做哪一步、做到哪，不再像當機；不想等可以回去。
- 鐵道迷：無。
- 開發：步驟與進度在 GamePresentation，有 Linux 測試；不動 GameCore 與存檔；取消後不留半套世界，最多跑完正在跑的一步。
- 美術：沿用色票與既有按鈕樣式，不加圖示；條只在步驟真的完成時動。
- 音樂：無。

## 續篇：讀取畫面在 iPhone 橫拿的版面

2026-10-30，派工單 LOADFIX（`loadfix-landscape`）。作者實機回報「iPhone歪圖」：橫拿時路線圖最上面的列車圓被切掉，「回開始畫面」只露出上半截。原因：直排的 220×220 路線圖加公司名、地點、說明、進度條、按鈕與間距約 460 點，比橫拿可用的高度（約 390 點以下）高。存檔、golden 不動，沒有新決策號。

**做法**：`RealWorldLoadingView` 在 `verticalSizeClass == .compact`（iPhone 橫拿）時改成左右排：路線圖在左，文字、進度與按鈕在右（`AnyLayout`，換方向時狀態不重設）。路線圖的邊長由 GamePresentation 的 `LoadingLayout.mapSide(height:sideBySide:)` 算：直拿與 iPad 仍是 220；橫拿時不超過可用高度減上下各 16 點，最小 120。按鈕維持 44 點高。有 Linux 測試（`LoadingLayoutTests`）。

**沒選的**：
- (b) 只把路線圖縮小（約 120）：直排的文字與按鈕仍約 330 點，加上 120 與間距還是接近 390，小螢幕與大字級仍會切，而且圖變得很小。
- (c) `ViewThatFits`：只在放不下時換版面，但放得下與放不下的邊界取決於字級，不同裝置看到不同排法，也沒有地方放「圖多大」的規則去測。

**五方**：
- 玩家：橫拿時整個畫面都看得到，列車不被切、按鈕整個能按；直拿與 iPad 看到的和以前一樣。
- 鐵道迷：無。
- 開發：邊長規則在 GamePresentation，有 Linux 測試；SwiftUI 只換排法，交 iOS CI；GameCore、存檔不動。
- 美術：同一張圖、同一組色票，橫拿時圖在左、字在右，兩塊各占一半，沒有新元素。
- 音樂：無。
