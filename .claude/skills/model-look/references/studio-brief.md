# 交給本地工作室：派工單範本、交件自查、接回遊戲

第一次走完整條路的是香港機場鐵路列車（決策 780，2026-11-15）。它的派工單在
`a91453/railway-assets-private` 的 `game-art-previews/docs/art/mtr-airport-line-2026-11/README.md`，
審查退回的紀錄在同一處 `revision-4/review/`，Blender 腳本在 `revision-4/tools/build.py`。新的模型照抄它。

## 1. 派工單（放素材庫 `game-art-previews/docs/art/<資料夾>/README.md`）

依序寫：

1. **是什麼、為什麼做**：優先清單的項目與分數、決策號。
2. **命名**：用路線或用途描述，不用車隊暱稱或會被誤認成別的遊戲的名字；不放公司商標、標誌、文字。
3. **找過哪裡**（model-look §1）：作者舊版素材、私有素材庫、參考庫各找到什麼；有用的複製進工作室的 `brief/`
   （工作室的 AI 只看得到自己的 worktree 與 `brief/`）。
4. **憑什麼被認出來**：三到五條。
5. **尺寸表**：量到的寫來源，推估的註明。
6. **哪幾種要做**：外觀一樣的合成一種（列車通常是駕駛室車、中間車、集電弓車、特殊車），每種近景與遠景（`-far`）。
7. **材質表**：材質名、sRGB、**遊戲裡的色**、用在哪。一個材質＝一個色票色，沒有 UV、沒有貼圖。
   **色一律從 `Map3DPalette`（建築用 `cityOfficeWalls`、`cityConcreteWalls`、`cityRoofs`、`hallWalls` 等）與舊材質對照表
   `tools/texture-palette/t003/building-map.csv` 取**，表裡寫出是哪一格；遊戲沒有的色標「新提」並寫原因（例：遊戲沒有金色）。
   不可以自己挑一組色（香港地標第一版派工單就是自挑 12 色，2026-11-15 改回）。
   寫表之前先 `grep` 一次 `Map3DPalette`：舊派工單的「新提」可能已經進遊戲（`steel` #8A9099、`dark` #2B2F36 是 2026-11-15 進的），
   要寫成格位名。兩個幾乎同色的材質（例：`glassBlueGrey` #8A949E 與 `steelGrey` #8A9099）同一個模型不要都用。
   「只有真窗用玻璃色」寫成可數的檢查：玻璃材質在窗以外的零件上的面數 = 0。兩個淺色分不開時不加新色，用深一格的板縫把面分開。
8. **座標**：前方 +X、上 +Z、地面（軌面）Z = 0、中心 X = 0、公尺；匯出前把物件的變換 Apply 掉。
9. **三角形預算**：近景與遠景各多少；遠景同框（同長、同高、貼地），顏色是近景的子集。
10. **看三輪**（model-look §2–4）：7 向圖＋遊戲大小圖，和照片並排。
11. **交件**：素材庫的哪個 branch、`revision-N/` 放什麼、跑 `tools/asset_guard.py`，不合併。

## 2. 交件前自查（寫進派工單，要做的人交件前自己數）

機場鐵路列車第一次審查退回的五條，加上清晨亮窗重修（mtr-airport-express-r2，2026-11-15）退回的幾條，每條都要報數字：

| 查什麼 | 要的結果 |
| --- | --- |
| 朝內的面（側、頂、頭、底各數） | 0；合併共點後重算法線，不要對斷開的面各自翻 |
| 站出車身的板（門、窗、框）埋進曲面 | 0；順著車身剖面的折點分段，整片站出約 1.5–2.5 cm |
| 該有的零件（例：中間車兩端、駕駛室車後端的連結器） | 都在 |
| 零面積三角形 | 0 |
| 塗裝起止位置 | 和側面照片同一處（寫明從哪裡開始） |
| 近遠景同框 | 長、寬、高差 ≤ 1 mm |
| 清晨亮窗（只把遊戲會亮的玻璃換 #F2D9A0 拍一張） | 門是車身色、只有門上小窗亮；客室窗一格一格，不是一整條；單塊亮玻璃 ≤ 0.7 m²（rolling-stock §4） |
| 共面／重疊面（車頂零件、端牆、接縫） | 0；疊在車頂上的零件至少凸出 2 cm，不用貼面薄片畫格子（rolling-stock §4） |
| 駕駛室玻璃（照遊戲規則：每個三角形最大 x 與有燈那端 − 2.8 m 比） | 清晨亮 0 塊；駕駛室側門的窗用深色 |
| 門框重疊；客室門與駕駛室門的間距 | 0；≥ 0.5 m 車身，門板取所在位置的車身色 |
| 車頭與車身接縫兩側斷面頂點最大差 | ≤ 1 mm（遊戲兩面都畫，縫會露出車內） |
| 寫「不變」的尺寸 | 給基準值與容差（例：寬 3.091–3.096 m、長 ± 2 mm），量到的數字在範圍內 |
| 交件清單 | 規定的圖都在、7 向 PNG 四角 alpha 0；README 的數字由 `check.py` 印出，不手寫 |

## 3. 工作室流程的卡點

- 做的人 commit 之後不一定會通知審查；去看它的 branch，或請它交件。
- 審查的座位卡在舊登記時，由 Mac 上的 session 跑 `studio.py takeover --task <任務> --role <角色>`，不要請作者打指令。
- 審查只寫「通過／退回＋毛病清單」；退回時把清單原樣交回做的人，下一輪再審。
- 工作室不用時就收掉（吃額度）。
- 開工後才加的規格，已經在做的人不會讀到（mtr-airport-express-r2 的 §7 車頂共面就漏了一輪）：規格寫完再開做的位置，臨時加的寫進下一輪的開場檔。
- 審查要自己寫一份照遊戲規則的檢查（亮窗、重疊面、車頂淨高、開關背面剔除比對），不信做的人的 `check.py`；做的人下一輪把審查的工具併進自己的 `check.py`，審查仍留自己的一份，並用做的人的 `build.py` 重建、比對交出的 GLB 逐位元組相同。
- 派工單裡的範圍（例：窗格寬約 1.0–1.3 m）寫明是硬門檻還是參考，和其他上限（單塊亮窗 ≤ 0.7 m²）衝突時哪個優先；寫明遠景從多遠開始用、那時一節車約幾像素。
- 審查列「建議」或「請協調者定」的項目，協調者逐條回修或不修，寫進下一輪做的人的開場檔或交件 README。

## 4. 接回遊戲（雲端 session）

1. `tools/train-models/glb_to_swift.py`（用法在它開頭）：材質名照 `--materials` 的順序變成色票索引，
   glTF 軸轉成遊戲軸，寫出 `Sources/GamePresentation/Map3D<名字>Mesh.swift`。
2. 照決策 782 的註冊表接（`rolling-stock` skill §2.1）：模型的 enum（`meshPalette` 與 `--materials` 同順序）、
   這款車自己的色票（`extension Map3DPalette`）、set 與遠景 set（`extension Map3DTrainSet`）、
   `static let registration = Map3DTrainRegistration(...)`（列車展示的列、三角形與長度範圍）都寫在車自己的
   `Map3D<名字>.swift`；`Map3DTrainRegistryList.swift` 最後加一行；雜湊鎖寫在 `tools/train-models/locks/<id>.json`；
   這款車自己的測試、決策、`docs/art/<資料夾>/`（總覽圖不含照片）。範例是 `Map3DMTRAirportLine.swift`。
3. `Map3DScene.swift`、`Map3DTrainSets.swift`、`Map3DShowcase.swift`、`hashes.lock.json` 與模型包大小、雜湊測試都**不用改**，
   所以兩款車可以同時接，不會衝突（清單那一行由 `.gitattributes` 的 `merge=union` 自動合併）。
4. 工作室做、審查已通過的模型不用拍 CI 截圖（ui-review §3），CI 綠就合。

## 5. 建築與地標（第一次：香港地標十棟，2026-11-15；滙豐重做 2026-11-16，決策 793）

派工單：`a91453/railway-assets-private` 的 `game-art-previews/docs/art/hk-landmarks-2026-11/README.md`。
和列車不同、或這次踩到的：

**底稿**

- 先找**測量來的外形**當底稿，從它減面，不重新捏：香港用地政總署 3D Visualisation Map 的無貼圖模型（`GLTF0`，
  一棟一個 `.gltf`）；台灣用 OSM 的建物輪廓與高度，或作者舊版的模型。比例、高度、位置就不會錯。
- 底稿先在雲端處理好再交工作室：併點、去零面積與重複三角形、底面中心放原點、地面 Z = 0、軸是 +X 東 +Y 北 +Z 上
  （Blender 匯入後）；一份 `landmarks.json` 記來源 ID、經緯度、底的高程、原始檔 sha256。腳本在派工單的 `tools/`。
- 底稿裡可能混了別的東西：滙豐的底稿有約 7.5 萬面是行道樹，先刪掉再減。
- 地政總署的下載（`download.map.gov.hk`）**雲端容器抓得到**，Mac 檔案工具的 VM 抓不到（403）。

**派工單要多寫的**

- 每棟一行：檔名、高、底稿三角形、近景預算（列車的「哪幾種要做」改成這張表）。十棟近景合計也給上限。
- 招牌、標誌、文字一律不做（銀行、商場頂上的字）。
- **結構複雜的要先拆「主體＋特徵零件」再各自減面**，派工單裡就點名哪幾棟（香港：滙豐的桁架、國金二期的冠、
  會展的翼形屋頂）。整棟直接 Decimate，簡單方柱沒事，這幾棟會崩。
- **不准整棟用盒子重建**：第 1 輪滙豐減完超預算，第 2 輪改用盒體重建，面數漂亮但被審查判「認不出來」。
  超預算就回底稿、分零件做，不換做法。
- **結構複雜的那一棟，照滙豐重做（決策 793）的寫法**，派工單在素材庫 `hk-landmarks-2026-11/revision-9/studio-brief.md`：
  - 協調者**先量底稿再寫派工單**：按高度分段數三角形（滙豐離地 0–5 m 有 8 萬面是樹）、列大片水平面的高度（桁架層）、
    量建築在地圖上斜擺幾度（滙豐 15.45°）。
  - **一張零件表**：每類零件是什麼形狀（薄板、桿、墩加臂、稜柱）、用什麼做法（減面，或照底稿某個高度的截面拉成稜柱）、
    面數的分配參考（滙豐：玻璃 600、板縫與窗框 1,800、樓層線 2,000、桁架 1,600、柱塔 2,400、屋頂 800、基座 300）。
    只給整棟上限時，做的人分不出哪裡該省，三輪都交不出來；有這張表，16 分鐘做完三輪。
  - 分配參考寫明「是上限不是目標、是參考不是門檻」，旁邊寫**這棟最該花面數的地方**；硬門檻只有整棟的近景上限與遠景 ≤ 一半。
  - 不要寫「把這團碎片做成一個盒」：做的人會把斜的薄板做成實心大盒、把起重機包成浮空的盒。寫它實際的形狀與範圍。
  - 寫明每個立面該看到什麼（側面也有窗帶與分層）；「缺面回底稿找那一面，不要用擴大體積補」。
  - 底稿不等於規格：規格要「底層架空」時，底稿架空層裡的牆與電扶梯要先拿掉再比剪影。
  - README 只放一張摘要表，完整數字留 `stats.json`。
- **遠景另外驗**：近景過了不代表遠景對；第 2 次審查退回的一半是遠景走形與缺口。遠景要和近景一樣出 7 向圖。

**交件前自查（建築多加兩條，和 §2 一起報數字）**

| 查什麼 | 要的結果 |
| --- | --- |
| 輪廓：和底稿比 | 整棟減面的：成品與底稿互相的距離目標 ≤ 0.5 m（冠、屋頂 ≤ 1 m），分高度段報。**拆零件重做的**（滙豐）：距離只當診斷（底稿有內部樓板與內牆，重做成稜柱的零件本來就差 1–3 m），門檻改成**剪影 IoU**：前、側、俯三個正交方向、4 px/m，近景 ≥ 0.93、遠景 ≥ 0.90；不過時把多出來的面積分給零件（審查的 `attrib.py`），不要猜 |
| 浮空零件 | 0；量法：零件表面每 0.1 m 取點，離別的零件 ≤ 0.2 m 算相接，從地面沿相接關係走得到才不算浮空（審查的 `floating.py`）。「往下的射線打得到東西」不算支承 |
| 跨空的長斜片（減面常見的毛病） | 0；寬（對最長邊的高）> 2 m 的三角形裡，(a) 法線與水平夾 10°–80° 的斜面、(b) 不順著建築軸向的牆。**在建築自己的座標量**（斜擺的樓在世界軸上每面牆都是斜的）；不用零件名排除 |
| 色帶、線條、窗框埋進牆面 | 0（從正面量）；整片站出牆面約 0.3 m（建築比列車大，2 cm 遠看不到） |
| 同平面不同色的面（相距 5 cm 內，含完全貼合）：遊戲裡會閃 | `tools/hk-landmarks/coplanar_check.py` 的 `overlap` = 0（相距 0.5 mm–5 cm、在平面上真的重疊 > 1 cm² 的對數）**與 `flush` = 0**（相距 < 0.5 mm、完全貼合的；2026-11-16 才加，之前沒算：長江中心近景 524、環球貿易廣場近景 48、滙豐近景 20）；`boxes` 是只看外框的舊數，只當線索。貼片要站出時取 **8 cm**：遊戲把頂點存成公分整數，站出 1–2 cm 的取整後會貼回牆；測試的外框容差是 0.5 m，最外層的牆上不能站出 0.3 m |
| 遊戲大小圖 | 每棟各自約 150 px 高、放在城市背景裡，不要十棟擠一張 |

**工作室流程（建築這次新踩到的，§3 之外）**

- Antigravity 開工前確認是自動允許：Antigravity 的 `/config` 把 Tool Execution Policy 設成 always-proceed
  （settings.json 的 `"toolPermission": "always-proceed"`），deny 照擋。跳出核准請求時**先放寬權限，不要中途換人**；
  真要關一個做到一半的 session，先查狀態、把沒 commit 的檔備份。
- Antigravity 看圖回 400（`INVALID_MEDIA`）：Blender 存的 JPEG 內嵌的 ICC 編號是 0，Gemini 讀不了；看圖前先
  `sips -s format png <圖> --out <暫存>.png`（assets #125）。
- 每輪先寫 `revision-N/README.md` 才開下一輪（這次連開三輪沒寫紀錄）。
- **重開審查前先 `studio.py takeover`**：不然新開的審查看到座位還掛著上一個 session，會一開就停在等人接手，
  介面上看起來像沒在跑。

- **做的人三輪後不過也要 commit 並交接**，`check` 開頭寫「未全過」；不寫這句，它會自己判不過就停在那裡，協調者只看得到狀態變成等待。
- **審查的開場檔要三件事**：逐項判斷做的人自報不過的是真毛病還是量法問題；每條毛病寫到「零件名＋局部座標＋應該怎樣」；
  清單分成「不修不能進遊戲」與「可列已知缺點」，剩下的面數該花在哪裡排順序。返工的開場檔就照抄。
- 第三輪審查的結論分兩層：第一行照硬門檻，下面寫建不建議進遊戲。協調者照第二層定，已知缺點原樣抄進決策。
  三輪後只剩一兩個盒要補時，協調者自己改重建腳本、重建、**用審查的工具**再量一次，改動 commit 並寫進 README，不再開一輪。
- 返工重開做的位置（已有 commit）：`conductor.py close` → `studio.py takeover` → 備份 `.studio/` → `git worktree remove --force` →
  branch 改名 `backup/…` → 開場檔整份重寫 → `conductor.py open --base <40 碼 sha>` → `studio.py roster --set`。
  審查的座位重開：close → `git worktree remove --force` → `git branch -D` → open → `roster --set`（不用 takeover）。
- Mac 的系統 `python3` 沒有 numpy：量測用 Blender 內建的 `/Applications/Blender.app/Contents/Resources/5.3/python/bin/python3.13 -I`，寫進開場檔。
- 素材庫一個模型資料夾只能有一輪留重檔：只重做其中一棟時，開新的 `revision-N/`，其餘的 GLB 用 `git mv` 搬過去；
  審查的圖只留最後一輪報告引用到的（每輪上限 21 張），PNG 轉 JPEG。
- **修補已進遊戲的模型**（香港地標共面閃爍，2026-11-16，派工單與兩次審查在素材庫 `hk-landmarks-2026-11/revision-10/`）：
  - 「不變」要寫成可數的門檻，而且不只外框：外框每軸差、三向剪影 IoU、**看穿**（修前修後同鏡頭的 z-buffer，多個俯角方向，看得更深的像素 = 0）、
    每色看得到的像素差（≤ 0.1%）。第 1 輪只量外框與剪影，切牆開的洞在輪廓裡面，全過了。
  - 共面的間距量**重疊範圍內的真實間距**，不是兩個平面到原點的距離差（斜 1–3° 的兩片會被當成貼合）；只動 < 5 cm 的部分。
  - 寫「修前從外面看得到的那一色留在上面」，不要寫「面積小的是貼片」。
  - 門檻用鏡頭看得到的量（看得到的面後面 2 mm 內有別色的像素），對數只當線索並同時報面積：藏在構件裡的重疊修了看不出來，還可能修出新的。
  - 請審查**逐棟**給「可進／可進並列缺點／不可進」，過的先進遊戲，不可進的那棟留修前的檔（素材庫新一輪照搬原檔）。
  - 做的人的整棟並排圖（一格 220 px）看不出修補的差異：派工單要寫「對點名的座標出近照、洋紅背景」。

- **曲面屋頂、焊成一團的底稿**（會展，決策 798；派工單、兩次審查在素材庫 `hk-landmarks-2026-11/revision-11/`）：
  - 派工單寫明：**曲面屋頂每一片各自重做**：取那一片的外圈輪廓（沿邊每 3–5 m 一點），在輪廓裡鋪規則網格（會展：主屋頂沿長向 6 m、橫向 4 m，小片 4 m），
    每個格點往**那一片**底稿取高度；脊線、摺線落在網格線上；兩片之間有高低差的地方就是分界。屋頂不准 Decimate，嫌面多就放大格子。
    **不准整棟一起減面**（上一輪整棟 Decimate，曲面屋頂變成跨 50–100 m 的斜片，遠景走形）。屋頂以下照底稿分高度取截面拉成稜柱。
  - 協調者量底稿時先數**連通件**：會展 41,250 面裡 32,798 面焊成一件，靠連通件拆不出零件。派工單要給拆法：在建築自己的座標（會展斜 4.7°）
    按高度段與法線朝向分（水平面、緩斜面＝屋頂、垂直面），並列出每片屋頂的高度範圍與它的外圈。
  - **牆頂接到正上方那片屋頂的底面**，寫成「正上方最高的那片」，不是「最近的一片」：兩片屋頂疊著時，做的人用低的那片底面體積去裁牆，
    把穿過低屋頂往上到高屋頂的那段牆也裁掉，正側面留下約 9 m 的縫。審查用海面高度的正東、正西剪影（IoU ≥ 0.93）和「側面看不看得穿」抓這條。
  - **遠景另外裁一次**：近景各段的頂蓋被屋頂底面裁過，遠景併段（北 7 段併成 3 段）後又冒出屋頂 3–4 m。派工單寫「遠景用遠景自己的屋頂底面重裁」，
    審查分近遠報屋頂穿出的**面積與高出多少**（近遠都要 < 1 m²），不只報像素比例。
  - 預算先在派工單寫死**不花面數的地方**：藏在牆裡的背面（白帶的背面就吃了 2,654 面）、看不到的底蓋、屋頂底面（用頂面一半的格密度，輪廓點不減）。
    會展第一次交件超預算 2,050 面，審查列的四招全是這三類加上簡化容差。
  - 屋頂頂面一旦審過，返工的開場檔寫「頂面和上一輪逐三角形相同，只准動點名的格點」，`check.py` 多一條比對；不然修牆時屋頂會跟著走樣。
  - 協調者的時間表：做一輪加審一輪約 1.5–2 小時。協調者 session 要停（壓縮、換帳號）時，返工輪已經開了也要把

## 6. 車站（第一次：淡水信義線高架四型，2026-11-17，決策 827）

派工單：`a91453/railway-assets-private` 的 `game-art-previews/docs/art/tpe-mrt-elevated-2026-11/README.md`（§12 是修缺點的第 4 輪）；
接回遊戲：`Sources/GamePresentation/Map3DTaipeiMRTStations.swift`、`tools/tpe-mrt-stations/glb_to_swift.py`。和建築不同、或這次踩到的：

**開工前**

- **先看照片再寫特徵**：OSM 外框＋開源底稿做出來的是紅磚盒，照片一看是宮殿式金黃兩坡頂、劍潭的索、北投的鋼桁架。派工單的
  「憑什麼被認出來」與材質表要在第 1 輪前照照片改好，不要讓工作室照底稿的印象做。
- **同型的站合成一型**（七站一個 standard），特別的站（劍潭、北投、新北投終點）各一型；派工單列出每型套哪幾站、各站 OSM 量的長寬。
- **開源底稿只當大形**（Slop New York，MIT）：派工單寫「改成遊戲風格，不照搬」，聲明只寫原作（作者 2026-11-17），放 `SOURCE.md` 與遊戲的資料來源頁。

**軌道與淨空（車站特有，派工單 §4 寫成硬門檻）**

- 模型的軌面固定一個高度（這次 Z = 9.0 m），淨空盒寫成數字：軌面下 1.2 到上 3.9 m、每型的半寬（standard 8.5、劍潭 9.5、北投 18、新北投 8）。
  **盒子沿長向不限 X**（第 1 輪被退回的就是站體兩端外擋到進站的軌道）；終點站另寫盒子止於哪個 X（新北投的終點牆從 X 53 起）。
- 站體**不帶軌道與月台**，套在遊戲自己鋪的軌道上（外殼 3.55 對內建軌道 2.35，作者問過）。模型自己的高架面與墩柱會和遊戲的高架橋重疊，派工單要先說拿不拿掉。
- **不要走決策 625 的 `Map3DTrainRoom` 挖法**：它把蓋住 25% 以上的零件畫成肋條，劍潭只剩 45.5%、新北投 3.9%（整站不畫），屋頂變骨架。
  工作室專做、量過淨空的站，遊戲只信模型自己的淨空，用測試把關。審查請它用遊戲現行切法與只切淨空盒各模擬一次，這個數字決定接法。

**審查常退的點（第 1–3 輪）**

- 淨空沿長向沒做到底（第 1 輪）。
- 特徵太小、遊戲大小看不出：北投四角的石材站體、新北投牌樓（第 2 輪放大，沿長向出簷仍不夠 → 第 4 輪）。

- 遠景少了特徵（劍潭索夾遠景要有）、天窗太窄。
- 底稿是實心盒：先改成柱列加屋頂再做細部；照片和底稿不同時照照片。
- 「出簷 ≥ X m」要寫清楚是**沿長向還是橫向**（第 3 輪牌樓兩個方向混在一起，橫向 1.5 m 過了、沿長向只有 0.1 m）。
- 量共面與閃爍先把座標取到公分整數再量（遊戲存公分），原始與取公分各報一次。
- **數字都過、遊戲大小仍分不開的色**（第 3 輪過了才發現）：相鄰兩色 ΔE 太小（北投 #C4C8D6 屋頂對 #C9CCD5 石材）、
  大片玻璃用窗的深色變成黑格、照片日照色在色票上最近的那格放在近白地面上太淡（金頂 #EBD099）。派工單要寫「相鄰材質在遊戲大小要分得開」，
  大片玻璃另給亮的材質，色票挑格看遊戲大小的圖，不只看 ΔE 最近。

**接回遊戲**

- **對齊遊戲的月台軌道，不對 OSM**：OSM 站體和遊戲線形橫向差 5–8 m，淨空每邊只有 8.5 m。方向取最長月台的弦、中點取月台中點的平均；
  月台離弦超過 1 m（彎站）、離真站超過 80 m、軌面離地不到 5 m 都退回 kit 站。
