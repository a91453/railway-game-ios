# 做機廠：先量三格，再看前人試過什麼

機廠的工作做了十幾次（三鶯、淡海、安坑、文湖兩座、機捷兩座、高雄輕軌、高鐵六家、香港兩座），
死結類的修法試錯過幾十種。每一次的數字都在決策裡，但散在二十幾份。這裡只留**結論與出處**：
動手前讀這一頁，要細節再開那一份決策。查 bug 的通用做法在 `diagnosing-bugs`，動到收購價在
`economy-balance`；這一頁只講機廠特有的。

這一頁是 2026-11-17 整理的（決策 829）。做完一張機廠的工作，把新的教訓加一列在對應的小節，
寫決策號，不要另開文件。

## 0. 三件最常忘的事

1. **「機廠滿」「清晨漏班」幾乎都不是股數不夠。** 加股數量過，更糟（第 3 節）。先看那幾分鐘
   每一列車在哪（第 6 節的 `DEPOT_RETURN_WATCH`），再決定要改什麼。
2. **一格變好不算數。** 機捷的三個世界（新線、舊線、改建線）乘上兩種規則，小改動就會翻。
   簡化＋管制是新局的預設，這一格**不可以比 `main` 多漏班**。量齊了才能說收不收。
3. **GameCore 的入出庫規則先不要動。** 能用 GamePresentation（鋪在哪、幾股、哪些班次）解的先用它；
   要動 GameCore，先看第 5 節哪些路已經有人走到死巷。死結同一時間只歸一個 session 修
   （NEXT_PRIORITIES §29.17 的規則）。

## 3. 股數與容量

- **一股停一列**（`tools/rail-depots/README.md`）：所以遊戲的股比真實多、比真實短（決策 602）。
- 股數是**這座機廠晚上要收幾列**，不是真實容量：三峽真實可停 33 列，遊戲鋪 4 股；
  香港兩座照列車數（港鐵沒有公開容量）。
- **照真實把股數加多，量過會變差**（決策 829，機捷）：蘆竹 16 → 23、青埔 12 → 15，舊線簡化＋管制
  沒發的班 6 → 11/333；只加到 18，新線簡化＋管制 4 → 6/333。股數一多，進出庫的班就多（舊線
  進庫 88 → 116），清晨要同時出庫的車也多，而出庫的提前量只算一列自己的路程。
  所以「機廠滿」要先修清晨出庫的排隊（`docs/priorities/DEPOT-REAL.md` 的 DEPOT-DAWN-QUEUE），再回來加股數。
- 數 OSM 的停車股道時，**用點名的 way id 範圍**數（`tools/rail-depots/tymc_yard_tracks.py`），
  不要用幾何分群：第一版分群把一排拆成兩排、漏掉青埔的股道，數成 24、19，其實是 23、15。

## 4. 班次要跟著機廠一起換

- **只加機廠、不換班次**：安坑舊時刻表 7 列全卡，第二天 182 班全漏（決策 557）。
- **把回送全拿掉**：淡海第二天晚上紅樹林最後 3 班沒車，有車晚 325 分（決策 489）。機廠不服務的
  那一端，回送要留。
- 有機廠之後，時刻表裡的回送班不排（由機廠規則派空車），所以**班數會變**：東涌綫 282 → 274。
  比「沒發的班」時分母不同，寫前後各自的分母；測試斷言 `line.runs.count` 等於時刻表班數減回送班數。
- 車停在中途站、車頭朝反方向，隔天早上會逆著對向的車開：決策 816 第一版把一列車送到青衣，
  多出 16 分鐘死結。過夜的位置只放端點或機廠。

**清晨出庫來不及不是提前量的問題**（決策 841）：出庫車被前一列出庫車擋住，因為跟車規則
（`isLeading`）不讓車跟在終點落在它路上、或自己也在跟車的車後面，清晨同方向的出庫車只能一列等一列。
先用 `TRACE_DEPOT`（`c70b059`）看那幾分鐘每一站的判斷是「沒到時間」還是「被誰擋」，再決定改什麼。

還沒有人試的方向（都是推測）：出庫車能跟出庫車（前車停不同股道、或到站後讓出）；清晨遠站的出庫車先走、
近站的跟在後面；整夜停在月台的車清晨直接接最近的那一班；進庫的路很長時不要整條訂下來
（小蠔灣的渡線；決策 850 改的是放開擋路的車，claim 仍是整條）。

寫法上的坑：加在 `resolveDeadlock` 裡的新一步要寫成獨立的 `@inline(never)` 函式，
直接寫進去會把 WebAssembly 的堆疊用完（決策 577）。

## 6. 怎麼量

量測用 `DepotReturnReportTests`（GamePresentationTests，只在要求時跑）：

```sh
swift build --build-tests -Xswiftc -warnings-as-errors
# 擬實；加 DEPOT_RETURN_SIMPLE=1 DEPOT_RETURN_CONTROLLED=1 是簡化＋管制
DEPOT_RETURN_REPORT=1 DEPOT_RETURN_EPISODES=1 DEPOT_RETURN_CHECKSUM=1 \
  swift test --skip-build --filter DepotReturnReportTests/testTheTaoyuanAirportLineBoughtBefore
# 看某幾分鐘某座機廠附近每一列車在做什麼（時鐘的秒數；106200 是第二天 05:30）
DEPOT_RETURN_WATCH=106200-108600 DEPOT_RETURN_WATCH_AT=蘆竹 …
# 看卡住的車各自在等誰
DEPOT_RETURN_STUCK_MIN=1 …
```

- **要量的格子**：動到共用的鋪法或 GameCore 的規則，機捷三個世界（`testTheTaoyuanAirportLine`、
  `…BoughtBefore`、`…Rebuilt`）各跑擬實與簡化＋管制，再加這次改的那條線。管制關掉的那一格出過
  318/333（決策 801），動到出庫或讓車的規則時也要跑。
- **沒動到的線雜湊要與 `main` 相同**。`main` 的基準在 `DEADLOCK-D2.md` 與決策 829 §4；`main` 動過
  GameCore 就自己在 `main` 上重量一次，不要抄舊的。
- **平行跑**：把 `.build/debug/GamePresentationTests-test-runner` 與 `GamePresentationTests.so` 複製到
  暫存目錄，各自 `<runner> GamePresentationTests.DepotReturnReportTests/<test>`，改程式重建時不會
  蓋掉正在跑的。機捷舊線單跑約 7 分鐘。
- **數的時機**：班要等過了最晚發車時間才算沒發（決策 547：第三天 00:00 就數，把還沒到點的班也
  算進去）。報告每分鐘取樣，不到一分鐘就自己解開的等待也算一分鐘（`DEADLOCK-D2.md`）。
- **線中間的機廠接在對向正線那一側時**（要橫過另一條正線才進得去，例如小蠔灣），空車整段一口氣開，跟車的 claim 會一路訂到渡線；簡＋控要量第一天下午與半夜收班（決策 836 的死結在 14:25，決策 850 的在 00:03、00:10）。
- **尖峰漏班先看終點站的咽喉**：簡＋控（沒有閉塞區間）下一列車出發就訂到下一站，進站車會把終點的渡線鎖住整個區間的時間（決策 849 之前的金鐘）。`DEPOT_RETURN_WATCH_AT=<終點>` 看等出站的車在等誰、等的是不是節點或交叉。
- **不要先怪機廠**：文湖早上的死結怪過機廠，二分後是第二條正線的坡道把手（決策 543）；香港
  尖峰尾多漏的一兩班，逐分鐘看當下沒有車在車廠（決策 829）。先看那幾分鐘，再下結論。
- **死結、久停、沒發的總表**用 `DeadlockSweepReportTests`（GameCoreTests，`DEADLOCK_SWEEP=<存檔>`，用法在 `docs/handoff/DEADLOCK-SWEEP.md`）：對任何 `SavedGame` 走兩天，
  印死結（幾列、在哪、被誰擋）、久停、每天沒發的班與世界雜湊；`DEADLOCK_SWEEP_SPEED=fast` 對 `normal` 比雜湊能找出「整批≠逐分」。`main` `2bc10d3` 各世界的基準在決策 877 §3、§4：
  畫面上寫死結的只在機捷（擬實新線兩天 42 次、改建線 39、舊線 31，多數在機場第一、第二航廈站），其餘單線、線組、香港與羅瓦涅米全買都是 0。
- 沒做到的照實寫：哪一格變差、哪一格沒量、成因是量到的還是推測。
- **線中間的機廠離終點站不到 1 km 時，先想線尾**（決策 898，橋本）：出庫的空車不套進站號誌（`homeLimit` 不套空車、路線也不到 1 km），一離開停車股就把站前咽喉訂到月台，約 3 分鐘；尖峰 3 分 15 秒一班的線，擬實下每出一列就少發一班、追不回來（126 → 71 班晚、尖峰空檔 +9 分）。同一座機廠改接在線尾（`beyond:`），出庫車從月台後面進站，兩種規則都是 0。
- **折返沒有餘裕的排班，一擋就晚到尖峰結束**：工具算出「剛好夠」的車數時，每一圈的餘裕可能只有一分鐘。量誤點前先算一圈的餘裕（班距 × 車數 − 來回車程 − 兩端最短折返）；不夠就在機廠那一端留恢復時間（`extract_branch_runs.RECOVERY`），不要兩端都加。
- **機廠那一端以外不要留夜車**（決策 898）：離機廠遠的端點留的夜車會被收回機廠（決策 221），清晨空車開回去時整段路訂到那個端點，擋住它的頭幾班。整天從機廠那一端排車：另一端的每一班都是開來的車折返。
- **賣掉再買回的測試要跑**（`RealLineBoughtAgainTests`）：第一次買時還沒讀進世界的水格不會擋軌道，買回時才擋；橋本線中間那一版的走行線從河床穿過去，就是這個測試抓到的（機廠沒鋪回去，站數少 1）。走行線要過河時，隧道要在水面下 10 m，爬回地面要有 3 % 的長度，放不下就換位置。

## 7. 存檔、價格、資料

- **已經買下的線不自動補機廠**：玩家的舊存檔照舊（決策 829；`RealLineDepotAddition` 只會加線尾
  之外的機廠）。要補是另一張工作，不是順手改。
- `SaveFixtures/`、`ReplayFixtures/`、golden 的期望值不改。只改收購鋪軌時三者都不該動；動了就是
  改到別的東西。
- **收購價會跟著變**（多了機廠的軌道與月台）：PR 寫前後（香港南港島綫 ＋6.8%、東涌綫 ＋3.3%），
  照 `economy-balance` 判。
- 位置從整包的 OpenStreetMap 讀（台灣 `asia/taiwan.pbf`、香港 `asia/china/hong_kong.pbf`，pyosmium），
  way id 與那一份檔的 sha256 寫進 `tools/rail-depots/README.md`。營運單位大多不公開可停列數；
  沒有來源的數字寫「沒有公開」，不要寫成真實容量。
- 寫進決策的每一句事實都要有工具的輸出或來源：決策 829 的初稿寫錯過康城站與車廠的位置關係，
  是照印象寫的。
- 作者的存檔與問題回報在私庫，不進這個公開庫；決策裡只寫重現指令與雜湊。
