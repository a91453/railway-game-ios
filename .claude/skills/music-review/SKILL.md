# 遊戲音樂的做法與審查

2026-11-17 第一次審音樂（MUSIC-WINTER／MUSIC-REFRESH，決策 815）。作者在上班，不能聽聲音，由遊戲規劃用量測來判。這份是那次的做法與經驗。耳朵仍是最後一關：量測過了，作者有空時再用 iPhone 聽試聽檔。

## 1. 先量，再判

```sh
python3 -I tools/audio/measure_music.py RailwayGameApp/Resources/Audio/music-loop.caf [...]
```

它會印出長度、響度（LUFS）、響度範圍（LRA）、真峰值（dBTP）、五個頻段的能量占比、每秒音量的範圍，以及循環接縫的跳動。改版前的檔一起量，數字並排放進 PR。

| 項目 | 目標 | 為什麼 |
| --- | --- | --- |
| 響度 | 所有背景音樂 −16 LUFS，相差 ≤ 0.5 LU（`MUSIC_LUFS`，決策 815） | 換曲時玩家不用調音量；手機遊戲常見的大小 |
| 真峰值 | ≤ −1 dBTP | 轉成 AAC 之後不破音 |
| 120 Hz 以下 | ≤ 10% | iPhone 喇叭幾乎放不出來；舊主題曲 73% 在這裡，聽起來就是悶 |
| 1–4 kHz | 參考 ≥ 15%（亮的曲子） | 旋律、鐘琴、鈴鐺在手機上靠這段聽清楚。冬季曲第一版只有 4%，300–1000 Hz 占 71%，像在箱子裡；改後是 33%。**柔和的曲子不用過這條**：不能為了過線加重泛音或敲擊（主題曲第三版因此變尖，見下一列） |
| 2–5 kHz、能量重心 | 柔和的曲子 2–5 kHz ≲ 1%、重心 ≲ 750 Hz | 量「尖不尖」。主題曲第三版第一次試聽 2–5 kHz 2.8%、重心 853 Hz，作者說尖銳；柔和版 0.25%、約 700 Hz。`measure_music.py` 不印這兩個，用頻譜自己算 |
| 300–1000 Hz | ≤ 60% | 超過就悶、發箱子聲 |
| LRA | 2–5 LU | 背景音樂不要忽大忽小；段落之間仍要有起伏 |
| 每秒音量 | 最大與最小相差 ≤ 12 dB | 安靜段太小，玩家會以為音樂斷了 |
| 循環接縫 | 跳動 ≤ 全曲第 99 百分位 | 超過就可能「喀」一聲 |
| 旋律比伴奏 | +3 到 +5 dB（用分軌量） | 聽得出旋律，又不蓋過列車聲與介面音效 |

## 2. 聽膩

經營遊戲一開就是幾個小時，最常見的抱怨是聽膩，不是不好聽。

- 一首循環至少 60 秒。舊主題曲 38 秒太短。
- 大家熟悉的旋律（例如〈Jingle Bells〉）最容易聽膩，不要單獨連播好幾週。冬季曲因此改成和主題曲輪流。
- 長期目標是 3–4 首輪播，或依城市大小、日夜加層（配樂第三階段，NEXT_PRIORITIES §29.14 第 6 項）。

## 3. 同一家族

- 走 MML → 樂譜 → 分軌（決策 219）；循環配樂用同一套取樣樂器演奏（§3.2），音效與到站鈴用 `make_game_audio.py` 的合成器。
- 調性和到站鈴相容（C 大調），速度、和弦能接上配樂第三階段。
- 保留鐵軌接縫聲，這是「坐在車上」的招牌聲音。
- 新音色一次最多兩種（決策 219 §2.1）。

## 3.1 和畫風一致，不要俗氣（2026-11-18，THEME-PLAIN）

作者聽了第二版主題曲說「很俗氣」「不符合我呈現出的美術風格」。數字全過也會俗，寫之前先對這張表：

| 俗氣的來源 | 換成 |
| --- | --- |
| I – vi – IV – V、每幾小節 V7 推回 I | 不用屬和弦；兩、四小節換一個和弦（I、IV、vi、IV(#11) 這類），循環沒有「結束感」 |
| 照拍子排好的五聲音階短句（兒歌感） | 不寫洗腦旋律；一個小音型在拍子上錯開，或很慢的長音 |
| 鐘琴、亮的撥弦當主角 | 鋼琴、弦樂撥弦、鋼片琴、豎琴、輕的弦樂長音；亮的音色只點綴 |
| 八分音符琶音一直跑＋回聲，塞滿 | 留白；律動交給一個有重音的音型（例如 3+3+2，像車輪） |

畫風是扁平、柔和、圓角（art-style §1）：音色圓潤、音少、伴奏不塞滿。季節曲是例外，它本來就要熱鬧。

「不俗」不等於「慢、暗」。主題曲第四版（軟槌律動）去掉了俗，作者卻說「沉重憂鬱」，要「稍微典雅活潑」。對照表：

| 作者說 | 原因 | 往這邊改 |
| --- | --- | --- |
| 俗氣 | 上表 | 上表 |
| 尖銳 | 敲擊太快（< 10 毫秒）、亮的泛音留太久；為了過 1–4 kHz 線加了亮度 | 降泛音與敲擊，不先降音量；不為量測加亮 |
| 沉重、憂鬱 | 小調色彩（Am、#11）、長音多、低音域、沒有拍點 | 大調；分解的、斷奏的伴奏；旋律在中高音域；拍子清楚（3/4 小步舞曲、4/4 阿爾貝提低音） |
| 粗糙、音質不好 | 合成器的正弦波音色、沒有空間、IMA4 的嘶聲 | 取樣樂器、殘響、母帶、無損格式（§3.2） |

主題曲最後選的是 D：3/4、150 bpm 的小步舞曲，低音在第一拍、第二三拍輕點和弦音，旋律走在一步步往下的低音上（C B A G F E D G C），中段轉 F 與 D 小調再回來。亮來自大調與音域，不靠高頻。

## 3.2 音色與製作：取樣樂器（2026-11-18）

合成器寫得出旋律，做不出「好聽的音色」。作者聽得出粗糙，量測聽不出。循環配樂改用真實錄音的樂器取樣（`tools/audio/sampled_music.py`，`tools/audio/README.md`「取樣樂器」）：

1. **音色庫**：鋼琴、撥弦、豎琴、弦樂長音用室內樂音色庫（`tools/audio/chamber_bank.py`，2026-11-18：Salamander Grand Piano 16 層力度〔CC BY 3.0〕、VSCO 2 CE 的室內樂聲部〔CC0〕，從釘住的 commit 下載、逐檔核對 SHA-256、組成 SoundFont）；其他樂器用 GeneralUser GS（SoundFont，授權允許用在遊戲）。都不提交。General MIDI 的編號：鋼琴 0、鋼片琴 8、管鐘 14、弦樂 49、撥弦 45、豎琴 46。打擊樂通道的鈴鐺 83。
2. **演奏器**：npm `spessasynth_core`（Apache-2.0），關掉它自己的殘響與合唱，輸出可重現。
3. **整首演奏兩遍，取第二遍**：第二遍已經帶著第一遍的餘音，就是循環時聽到的樣子，接縫自然無縫。
4. **空間**：一個小廳的殘響（約 1.9 秒、高頻衰減較快），繞圈卷積；量 0.3 左右。沒有殘響的取樣樂器聽起來像在錄音室裡乾乾的。
5. **母帶**：60 Hz 以下切掉（手機放不出來，只吃掉音量），9 kHz 以上緩降（去掉取樣的嘶聲與鈴鐺的刺）。
6. **峰值限制**：取樣樂器同一拍的起音會讓峰值遠高於響度。用繞圈的限制器壓到 0.85，不要調低樂器去湊；壓了多少用真峰值確認（≤ −1 dBTP）。
7. **存檔**：循環檔用 ALAC（16-bit 無損）。IMA4 在安靜的鋼琴底下有約 43 dB 訊噪比的嘶聲，安靜的曲子一定聽得到；AAC 有編碼延遲，循環會有空隙。代價是檔案大（主題曲約 5.6 MB）。只播一遍的檔用 AAC 192 kb/s（約十分之一大）。
8. **演奏，不是輸入**：照寫的力度、對齊格線直接播，作者會覺得「像電腦」。`played()` 加三件事：樂句起伏（每 4 小節往中間漸強、句尾收）與第一拍稍重；伴奏前後差幾毫秒（旋律 3、和弦音 4、低音 6、長音 10，和弦的幾個音差太多會像亂撥）；鋼琴的延音踏板只踩第一拍之後一兩拍（整小節踩住會把音階糊成一團）。全部用固定種子，每圈一樣。
9. **輪流播的換曲**：循環檔不能拿來播一遍（開頭帶著上一圈的餘音、結尾截斷在餘音中間）。另做「播一遍」的版本：從安靜開始演奏一遍，最後和弦與殘響自然響 3 秒；App 播完停 1.5 秒再接下一首。不要在終止式上淡出（聽起來像被調小聲），拍子速度不同的兩首不要交叉。

編制的經驗：

- 旋律一個主奏樂器（鋼琴或鋼片琴），伴奏用短的（撥弦、豎琴），長音很輕地墊在下面（弦樂音量約旋律的一半）；三層各有自己的音域，不互相蓋。
- 同一首可以換段落換樂器（冬季曲主歌鋼琴、副歌鋼片琴），比整首一個音色耐聽。
- 管鐘、鈴鐺這類亮的只放高聲部或點綴，音量壓低，左右分開。
- 試編制時一次做兩三種（例如鋼琴＋撥弦、鋼片琴＋豎琴）並排給作者聽，比描述音色有用。

## 3.3 試聽到定案的循環

（每一輪都把改前、改後放在同一頁，換曲的話另做一段「前一首結尾＋停頓＋後一首開頭」。）

1. 先寫旋律與和聲（任何音色都行），作者接受了旋律再談音色；兩件事分開問。
2. 每一輪都做成一頁試聽（Artifact，每首一列、標出推薦、改版前的也放），檔案用 mp3；同時放 `/mnt/project-files/` 給作者在手機上聽。
3. 作者說的形容詞照 §3.1 的對照表找原因，改一個方向就好，不要一次全換。
4. 量測只用來擋明顯的錯（太大聲、破音、接縫、頻段偏），不拿來證明好聽。作者問「為什麼判斷通過」時，老實說量測量不到什麼。

## 7. 這次踩到的

- 新型別取名 `MusicTrack`，和 AudioToolbox 的 `MusicTrack` 同名。App 同時匯入 AVFoundation，Xcode 建置失敗（Linux 看不到）。音訊相關的新型別名，先查 Apple 的音訊框架有沒有同名的。後來改名 `MusicTune`。
- 冬季曲第一版的響度、峰值、接縫都合格，但頻段偏在中低，鈴鐺不亮。只看響度會漏掉，所以要看頻段占比。
- 主題曲第三版（軟槌律動）為了過 1–4 kHz ≥ 15% 加了亮的泛音，作者說尖銳。量測的線是參考，不是目標；柔和的曲子不用過。
- 合成器的音色量測全過，作者仍說「粗糙」：耳朵聽的是音色與空間，量測只看大小與頻段。音色的問題換取樣樂器，不在合成器上修。
- 速度要讓每個 tick 是整數個取樣（48,000 × 60 是 tempo × 960 的倍數：75、100、120、150 可以），長度是 64 個取樣的整數倍。
- MML 的長度只能是整數 tick 的音符（例如 0.75 拍 `8.`、0.375 拍 `16.`），0.9 拍這種寫不出來。
- 冬季曲改成取樣樂器後峰值 0.95，`level_to` 拒絕；降樂器音量沒用（起音疊在一起），加了限制器才過。

- **換音色庫的三個坑**（2026-11-18，THEME-BANK）：(1) 間隔擺放的一對麥克風（Salamander 相距約 12 公分）兩聲道的相關從音到音在 −0.8 到 +0.6 之間跳，手機單喇叭聽到的相加會一個音大一個音小，只取一支；量 `np.corrcoef(L, R)` 就看得出來。(2) 室內樂聲部是一個音一個音錄的，相鄰取樣差到 10 dB，要逐音拉平。(3) 換了音色庫，每一軌單獨演奏的響度要量，照差的 dB 重算 CC7（新值 = 舊值 × 10^(−dB÷40)），不然混音就不是作者聽過的那一版。比較時也看能量重心與 2–5 kHz，確定沒有變尖。

## 8. 下次作曲的起點（2026-11-18 定案的主題曲）

作者經過五輪才定案；下次從這裡開始，可以少走三輪：

- **風格**：大調、3/4 小步舞曲或 4/4 古典小奏鳴曲的「典雅、輕快」；不要流行歌的 I–vi–IV–V、兒歌式五聲短句、鐘琴主角，也不要慢而暗的氛圍曲（會被說沉重）。
- **骨架**：旋律走在一條一步步往下的低音上（C B A G F E D G C），中段轉到 IV 與 ii（F、D 小調）再回來；64 小節左右、75 秒以上。
- **編制**：鋼琴旋律；撥弦低音在第一拍、第二三拍輕點和弦音；很輕的弦樂長音；鐵軌接縫一小節一次。取樣樂器、小廳殘響 0.3、峰值限制、ALAC。
- **流程**：先用任何音色給兩三個旋律候選，作者選了旋律再做音色與演奏；作者用形容詞回饋時對 §3.1 的表；每輪都附改前的試聽。
- **音色庫**（2026-11-18 升級）：鋼琴、撥弦、弦樂、豎琴已是真實錄音的室內樂音色庫（§3.2 第 1 點）；鋼片琴、管鐘、鈴鐺仍是 GeneralUser GS，之後找到更好的再換。
