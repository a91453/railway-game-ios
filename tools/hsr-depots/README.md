# 高鐵的真實機廠（OSM）

`build_hsr_depots.py` 從 OpenStreetMap（ODbL 1.0）找出台灣高鐵停車的地方：接在高鐵正線上的 yard、siding、spur 群聚，以及每一群的位置、出入的正線轉轍器、並排幾股、能停的長度。輸出是 `hsr_depots.json`。用途是高鐵示範的真實機廠（`docs/research/NEXT_PRIORITIES_2026-10-12.md` §5 第 6 項、§13 第 8 名）：夜裡列車進南港、烏日、左營的機廠，不再疊在南港的月台上。

```sh
pip install osmium            # BSD 2-Clause，決策 93
curl -LO https://osmtoday.com/asia/taiwan.pbf
python3 -I tools/hsr-depots/build_hsr_depots.py taiwan.pbf \
  RailwayGameApp/Resources/RealRailways/track_stations.geojson \
  tools/hsr-depots/hsr_depots.json
```

約 45 秒。和其他資料工具讀同一份整包檔，不問 Overpass（CLAUDE.md）。

## 怎麼找

1. **正線**：`railway=rail`、軌距 1435 mm（沒寫就算），`highspeed=yes` 或營運者、名稱寫著「高速鐵路」「高鐵」，而且沒有 `service`。
2. **側線**：`service=yard|siding|spur|crossover` 的軌道，從正線的節點開始沿共用的節點走得到的（參考 `topology.js` 的原則：軌道靠共用的節點相接，不靠座標接近）。所以機廠裡沒標營運者的股道也算，台鐵與捷運的不算。
3. **群聚**：側線在正線以外的節點相接的，算同一群。只在正線上相會、但中心相距不到 300 m 的群（南港的兩條盡頭線，一條接一條正線）合成一群。`yard` 加 `spur` 不到 1 km 的群（車站的待避線、渡線）不算機廠。
4. **股數**：沿群的主軸（各點的主成分方向），每 10 m 畫一條橫線，數它穿過幾條 yard／spur 軌道，取最多的。**能停的長度**：股數至少有一半的那段，沿主軸的長度。
5. **名稱**：最近的高鐵站（`track_stations.geojson`），以及包住群中心的 `landuse=railway` 區（名稱有「高鐵」的）。
6. **轉轍器**：群的軌道和正線共用的節點。

粗體是派工的三個：

- **南港**：OSM 在南港站東邊只有兩條各約 1.3 km 的盡頭線（`service=yard`，營運者台灣高速鐵路），從南港站東端的兩條正線各分出一條，往汐止的方向延伸，沒有命名的基地區。高鐵的列車十二節約 304 m，一股可以停四組，兩股八組。示範夜裡在南港有 9 組（決策 197）。實景鐵道的 README（`tools/real-railways/`）提到的「高鐵南港端約 1.4 km：TDX 的線畫進車輛基地」就是這兩條。
- **烏日**：台中站南邊約 2 km、正線西側的高鐵烏日基地，19 股並排、一股約 680 m（兩組）。四個轉轍器在 24.0995–24.1196（台中站南北兩側的正線上）。
- **左營**：左營站北邊約 1.5 km、正線東側的高鐵左營基地，19 股、一股約 1,200 m（三到四組）。

橫線數股數時，梯形咽喉的斜線也可能被算進去，所以數字是上限（沒有和衛星影像核對）。即使少算幾股，也夠示範夜裡的車數：台中 6 組、左營 19 組。
